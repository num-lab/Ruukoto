# Agent Note: Two independently running Agent products replace fixed coding and chat roles

Status: implemented

Original identifier: ADR 0017.

[The personal product entry](../simplification/2026-10-18-personal-product-entry.md) partly supersedes this design: personal runtime, storage, and local protocol now belong independently to durable. Shared-runtime personal profiles/clients, development sessions, imports, workflows, and GitHub reviews below are historical retained implementations, not claims about the new entry. [Personal native execution](2026-10-12-personal-native-sandbox.md) supersedes container deployment. [Coding Scheduled](../feature/2026-10-25-code-scheduled.md) supersedes the original exclusion of Coding scheduling without changing independent profiles or ownership of personal schedules.

## Problem

The old main/coding/chat backend coupled local coding, personal-server work, and group chat. Fixed coding duplicated the development product, while core chat constrained a general personal assistant to group use. Development machines and personal servers need independent run/stop/upgrade lifecycles while preserving history, provenance, and authorization.

## Decision

Ruukoto has two products in one repository. `ruukoto-code` runs on development machines, primarily through TUI, for agentic coding on macOS/Linux. `ruukoto` runs on a dedicated Linux server, primarily through owner-bound private IM, for varied personal work. Either product can install/run/upgrade independently; stopping or disconnecting one does not prevent the other's local work. Dedicated app packages own entry points and product-specific wiring. The original shared-package organization is recorded in [workspace packaging](2026-10-11-in-repo-workspace-packages.md); it does not require today's personal durable product to share runtime/storage/protocol.

Product identity is host-fixed. In the shared implementation core `meta.product.type` binds a data directory and cross-product opening fails with `product_mismatch`. Original daily roots were `~/.ruukoto` and `~/.ruukoto-code`, with `RUUKOTO_*_DIR` / `RUUKOTO_CODE_*_DIR`, separate locks/sockets/pending files, and common control identity variable names `RUUKOTO_OWNER_TOKEN` / `RUUKOTO_OWNER_TOKEN_FILE`. The personal root/protocol has since changed as specified below. The former `ruukoto-dev` name is now `ruukoto-code` across bin, identity, profile, and environment prefix. Repository-development instances have their own [launcher decision](../process/2026-10-09-dev-launchers.md).

Retire fixed coding and core chat roles. The legacy orchestrator bootstraps only main; general analysis/modification and legacy GitHub review use generic SubAgents. Remove `coding_delegate`, old delegation/retry logic, and GitHub's fixed-coding takeover. Keep old role rows/sessions/tasks read-only and reject new tasks. Upgrade cancels queued retired-role tasks; recovery interrupts in-flight ones, records one result/wakeup, and never replays them. `coding_result`, old `AgentRoleId`/CHECK values, and `qq_group` remain read-compatible because they identify actual history.

QQ group handling is an optional independent program owning its sessions/history/send state and providing bounded results to personal; it may remain in this repository. Disabling it must not stop main. Core ignores group messages and retains archived group data, `chat_result_*`, and pre-send source checks; see [core group retirement](../simplification/2026-10-02-retire-core-group-chat.md). A formal extension and its interface remain future scope.

Both products use one-level SubAgents: main talks to the owner; SubAgents do not and cannot spawn another level. Communication is limited to current collaborators on the same work under the same main, never new permissions. No direct cross-user-session/workspace/machine Agent communication is introduced. A work delegation spans turns/tasks, each with its own execution, tools, directories, data scope, and effective authorization; one-shot approval never carries over. Completion makes a SubAgent idle, retaining identity/context for same-main, same-user-session reuse on the old or a new work, with collaboration eligibility recalculated. Only explicit main/owner close closes it; completion, TUI exit, and idle timeout do not. Idle requires no live model/tool process; close preserves history/artifacts.

Whole-work cancellation stops active/queued child tasks but not other work. Late results remain recorded without restarting canceled work; unintegrated copies/artifacts survive. Details belong to [work delegation](2026-10-03-work-delegation-subagent-task.md), [reuse/close](../feature/2026-10-04-subagent-reuse-close.md), [messaging](../feature/2026-10-05-subagent-messaging.md), [cancellation](../feature/2026-10-04-cancel-work.md), and [restart recovery](2026-10-05-subagent-restart-recovery.md). Personal durable implementations must follow their own linked successor decisions rather than be inferred from shared-runtime plumbing.

Coding organizes workspace -> sessions. The owner selects a development root that can include multiple repositories; temporary worktrees are execution copies. [Legacy organization](2026-10-03-legacy-workspace-org-attribution.md) preserves source identity. Daily TUI lazily starts the local backend, which continues after TUI exit until explicitly stopped. Crash records support recovery without replaying unknown effects; see [detached task lifetime](2026-09-19-detach-terminal-from-task-runtime.md).

Only one Agent writes a work-file set at a time. Parallel coding uses separate Git worktrees, then main integrates and verifies; non-Git writes serialize. Independent context is not file isolation. [Worktrees](2026-10-04-subagent-worktrees.md) fixes first write targets, parent/child directory occupancy, taskId release, host git execution through workers, and copy retention without deletion. [Result integration](../feature/2026-10-05-integrate-worktree-results.md) owns full-work diffs, preflight-before-apply, zero-write conflicts, already/empty results, and ledger evidence. Main may delegate writes; canceled/closed work remains retrievable and integrable.

Personal has one continuing owner/main conversation shared across private QQ and Telegram, with separate SubAgent contexts so main can respond while long work continues. Accepted work's final success/failure is summarized to the original entry/owner, with timely approval notifications and optional progress, never broadcast. Changed/disabled bindings never redirect; temporary offline waits; unknown send effects never auto-retry. The legacy [IM final-report decision](../feature/2026-10-02-im-approval-and-final-report.md) owns its transactions, owner_reply slots, idempotency, and cancellation exclusion. Legacy [GitHub review](../feature/2026-09-24-github-event-review.md) has a separate host-registered work/SubAgent, task-scoped read-only MCP, and fixed notification, not IM final-report authority.

Personal server management uses explicitly authorized operations. The original shared path verifies approval against the original owner private entry, supports bounded inspectable/revocable [standing permissions](../feature/2026-10-03-standing-permissions.md), and uses a [fixed service helper](2026-10-03-service-management-helper.md), not arbitrary standing root authority. Personal durable wiring is separately decided. Restricted Coding execution must enforce a real macOS/Linux boundary and fail rather than silently degrade. Full access is an explicit owner choice and now follows [current-account full access](../feature/2026-10-12-full-access-current-account.md), not the retired dedicated-account design.

Cross-product sharing is limited to selected personal preferences and general experience: Agent proposes, owner confirms publication/changes; local accumulation works offline. Project conventions keep their scope. Full history, schedules, and task progress do not sync by default; shared memory grants no automatic source-history/artifact access. Sync transport, conflicts, revocation, and offline copies remain to be decided. General email/GitHub-comment communication, shared memory transport, and the formal QQ extension are not delivered by this note.

## Compatibility and current applicability

The fixed-role direction in historical offline `.scratch/daily-agent/spec.md` is superseded, not erased. [Legacy Coding import](2026-10-04-legacy-instance-import.md) records read-only source snapshots, retained IDs, allowlisted content, no credentials/replay, receipts, and revert. [Original personal import](2026-10-05-personal-instance-import.md) records identity/credential-conflict checks, non-replaying handoff, and target-activity rollback barriers, but is not supported by the new durable entry. Likewise [retaining personal development sessions](../feature/2026-10-05-ruukoto-keeps-dev-sessions.md) describes the old personal assembly. Developer-launcher exit stops that development run, unlike daily Coding TUI exit.

Full history and bounded context remain separate; one main conversation does not serialize all background work. Retiring roles never relaxes data identity, group-data isolation, sending, or owner authentication.

Coding declares `defaultExecution: native`, `allowedExecution: [native]`; formal CLI/server reject old local/container arguments/environment overrides with migration guidance. Library tests can still inject local. Personal formal bin/start with no arguments opens the same menu; `serve` runs the foreground backend. Its new root is `~/.ruukoto-durable/` or `RUUKOTO_PERSONAL_DIR`, with no old protocol/data import compatibility. Its development directory is fixed and exiting stops that backend. [Native execution](2026-10-10-native-execution-sandbox.md), personal entry, and personal native decisions own present platform requirements. [Generic scheduled tasks](../feature/2026-10-12-generic-scheduled-tasks.md) owns legacy independent execution/run provenance/cancellation; Coding's separate coordinator is its own successor.

## Alternatives considered

- **Keep main/coding/chat in one backend.** Reuses old delegation and group paths with less migration, but conflicts with separate development/server deployment and interaction; fixed coding duplicates the coding product and core chat blocks independent evolution. Split products, generic SubAgents, and an optional extension instead.
- **Close SubAgents on completion.** Aligns identity and task lifetime and was an early interview suggestion, but the owner explicitly requires reusing the same Agent. Keep idle identity/context until explicit close and recompute collaborator eligibility on new work.
- **Immediately ship separate packages.** Independent artifacts are useful, but initial independent run/restart needs were met by one code package with two bins. The later workspace-package split was justified by missing product-specific ownership and drifting module boundaries, not a newly invented requirement for separate shipment.

Original decisions and confirmed Q1-Q19 scenarios are historical offline `.scratch/agent-direction/spec.md` and issue `01-independent-products.md`; they do not certify all future capabilities.

## Consequences

Local work does not depend on cross-product connectivity. Shared components retain their contracts where still used, without forcing personal durable into them. Migration must preserve each old role's responsibility, source, and authorization rather than globally rename or rewrite history. Read-compatibility identifiers remain; execution and deployment require per-product verification. Native prerequisites fail explicitly when absent. Sharing and extension/channel work still have delivery gaps; [architecture](../../../../docs/architecture.md) is the current capability/module description.

## Verification

Historical product-entry evidence: passing `npx tsc --noEmit`, test/71 then 14/14, and 10 macOS real-bin/file/socket/SQLite smoke cases with mock models for two concurrent backends, independent stop, and cross-product rejection. Full checks had existing TUI failures/concurrency jitter, not all green. A cross-product environment inheritance bug that stopped the wrong backend gained a real dual-backend regression.

Historical role-retirement evidence: passing typecheck, test/67 4/4, and old/new real backend/control/SQLite smoke runs with mock models on macOS and tx, each 5/5. Full suite: 889 total, 886 passed, one skipped, two failures (clean-baseline DNS timeout and collaboration load jitter passing alone). No real QQ/Telegram/GitHub.

Native evidence is held by its decision: two-platform SDK worker runs each 10/10, SubAgent/worktree each 8/8, with shared approval regressions separate. macOS unknown descendants conservatively reject and retain occupancy, not complete reclamation. The 88-case ledger recovery, 90-case conservative failures, and hard-link counterexample remain distinct evidence, not a combined all-pass claim. Historical personal container evidence does not verify current native/durable delivery. No runtime/platform tests are rerun in this documentation migration.
