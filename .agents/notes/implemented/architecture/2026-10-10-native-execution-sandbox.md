# Agent Note: Native restricted execution and retained occupancy for unverified macOS descendants

Status: implemented

[Personal native execution](2026-10-12-personal-native-sandbox.md) extends these primitives to personal and retires Docker delivery. [The personal entry](../simplification/2026-10-18-personal-product-entry.md) uses independent durable wiring; shared Coding ToolRouter/Runtime/worker statements do not describe that entry. [Persistent Linux claims](2026-10-17-native-linux-execution-identity.md) owns cross-process unit/cgroup verification. [Atomic startup-marker publication](../bug-fix/2026-10-24-native-marker-atomic-publish.md) strengthens publication without relaxing strict content or unverified-stop checks. [Current-account full access](../feature/2026-10-12-full-access-current-account.md) supersedes the original dedicated-account rule.

## Problem

Restricted Coding work must use the development machine's actual toolchain, paths, ACLs, and directory identities. [Task containers](2026-09-20-tool-worker-per-task-container.md) add a macOS Linux VM with mount-permission and inode-remapping differences; another container runtime does not remove those costs. Native execution must still isolate backend data, model credentials, control plane, other tasks, and ungranted material, including main/SubAgent/worktree creation, shared read-only Git, and integration.

Platform capability must be distinguished from deployment mistakes. Seatbelt needs real paths: `/tmp` versus `/private/tmp` can silently mismatch a rule. Ubuntu 24.04 userns AppArmor profiles match executable paths: a temporary bwrap lacks `/usr/bin/bwrap` permission. Neither bad probe proves the platform mechanism unusable. Original counterexamples/corrections are historical offline `.scratch/agent-direction/issues/26-native-sandbox.md`.

This macOS implementation has no inescapable kernel process-membership set: posix_spawn attributes can change PGID/SID, kqueue NOTE_TRACK returns ENOTSUP, and a vanished launchd job does not prove escaped descendants exited. Linux PID namespaces/cgroups supply membership. macOS requires an explicit tradeoff between unprivileged operation and certain reclamation.

## Decision

Connect native launchers directly to `WorkerLauncher`, not a new cross-platform sandbox runtime. Confirm, auto-review, and Plan share restriction; worker protocol, SDK tools, approval consumption, operation ledger, and task cleanup keep their existing owners. Missing capability fails, never Docker/local/free-backend fallback. Both platforms preserve actual host account UID/GID, supplementary groups, ACLs, and workspace ownership. Linux restriction comes from read-only mounts, full namespaces, capability removal, and seccomp, not container UID mapping. Work-copy preflight uses actual-account `accessSync`.

### Shared authorization, identity, and temporary data

- `LaunchSpec` is launch authority. Workspace requires host-pinned dev/ino. Workspace/grants/read roots use verified real paths; aliases or identity mismatch reject before unit creation. Reject writable grants nested in a read-only ancestor; preserve read-only children inside writable workspaces. Rule/mount order must not broaden authority. [Registered device numbers](../bug-fix/2026-10-18-directory-device-number.md) owns across-start verification and current-start conversion.
- Reuse `approved-ops.ts` physical protection: compare root and target ancestors by dev/ino as well as paths, rejecting mount/physical aliases and directory grants containing protected ancestors. Native grants/dependencies/workspace and approved file operations share this check. Check target/ancestor inodes against children inside protected trees to reject bind/hard-link aliases. Runtime dependencies use [batched checks](../bug-fix/2026-10-18-batch-native-protection-checks.md), rechecking pinned identity and observed directory changes within one synchronous call.
- Seatbelt/read-only binds cannot identify a preexisting hard link's other writable name. `assertNativeFileLinks` traverses explicit grant trees, deduplicating directories by dev/ino and entries by parent dev/ino plus real basename. `/System/Volumes/Data` aliases must not double-count; explicit filenames must exactly occur in parent readdir, so APFS case/Unicode-equivalent names are not extra grants. For nlink > 1, all entries must be authorized at the same access level. Reject more links than authorized entries, read/write conflicts on an object/entry/directory, or recheck changes; allow normal same-permission internal links. Recheck at launch and before each call; on failure stop the old unit before rejecting. Do not recursively follow symlinks or scan protected/credential/full-host trees here; protected-tree identity checks are separate. Cost grows with grant entries/scopes/link verification and is not constant for large repositories.
- Runtime protects code, data, agent, and control roots. Only trusted built `worker/worker.mjs` and actual required `node_modules` get read-only code exceptions, not whole source root/HOME/Data volume. Expose exact tool versions, dynamic libraries, and required SDK roots. Unknown layouts get the actual executable only, not an inferred parent data directory.
- PATH contains actual Node, selected host tool directories, and system tools. Keep symlink/library source and real target without opening all `/opt/homebrew` or custom tool parents. macOS gets system read roots, selected Xcode/CommandLineTools roots, and exact license plist, not all `/Applications` or `/Library/Developer`. Set `GIT_CONFIG_NOSYSTEM=1`.
- Before native launch, `ToolWorkerHost.startUnit` saves realpath/stat dev/ino for all grantedPaths without changing public LaunchSpec fields. Every `call` rechecks workspace, identity-bearing read roots, and all grants, including replaced read-only grants. Identity change requests stop before rejecting dispatch; the same host record retains the stop result and occupancy despite changed directories/closed handles. Worker init also checks workspace/read-root dev/ino. The former Docker Desktop exception is retired, not a current native exception.
- Each unit has a random 0700 temp directory and independent HOME/TMPDIR. Restricted workers inherit no credentials, proxies, SSH agent, control-plane, or systemd-bus environment; only the host's fixed `GIT_CONFIG_*` bundle is allowed. Worktree patch/numstat/errors use random `mktemp -d` inside that TMPDIR, not shared fixed `/tmp/ruukoto-integrate.*`; an EXIT trap must not delete evidence early. Remove temporary data only after verified stop; otherwise retain it with occupancy.

### Linux namespaces, BPF, and cgroups

Launch bwrap under `systemd-run --user --scope --property Delegate=yes`. `--unshare-all --die-with-parent --new-session --clearenv --cap-drop ALL` isolates files, PID, network, IPC, and other namespaces. Base root, `/tmp`, and `/dev` are read-only; only authorized writes and the unit temp directory are writable. `/proc` exposes sandbox PIDs; bwrap `--dev` supplies required devices such as `/dev/null`.

Network namespaces alone do not block host pathname Unix sockets in bind mounts. Syscall BPF supports Linux x64/arm64, verifies audit architecture, rejects foreign ABI/x32, and blocks `socket`, `connect`, `sendto`, `sendmsg`, `sendmmsg`, and `io_uring_setup`, covering TCP/UDP and abstract/path Unix sockets. Retain `socketpair` for libuv child stdio without bypassing send restrictions. bwrap consumes/closes the filter FD; trusted Node writes/closes the startup-marker FD before SDK load; tool code inherits no extra host FDs.

Require formal `/usr/bin/bwrap`, cgroup v2, a creatable/delegated user scope, and writable scope `cgroup.kill`. Ubuntu userns hardening additionally requires a loaded AppArmor userns profile matching that path; package installation alone does not prove permission. Do not globally disable `apparmor_restrict_unprivileged_userns` or make bwrap setuid. Verify the real restricted Node marker, user-scope identity, and cgroup stop ability.

Stop tears down PID namespace and uses exact-scope `cgroup.kill` plus systemctl kill/stop. Return true only after successful unit-exit query, host launcher exit, and empty cgroup. Missing trusted scope/cgroup identity, failed query, or uncertain members never proves exit.

### macOS Seatbelt and host identity supervision

Use deny-default `sandbox-exec`. Real workspace/write grants are writable; read grants/data roots are not. Network, external Mach/shared-memory IPC, and backend process information are denied by default. Allow required file reads and ancestor metadata only: literal `/` read serves dyld without granting subpaths; literal `/var` metadata serves developer-tool alias resolution. Direct setsid/setpgid syscalls are denied, but this does not prove posix_spawn cannot detach.

A host C supervisor runs outside restriction without root/dedicated UID. libproc flavor 18 yields BSD/unique identity with a checked 192-byte ABI. Lifetime identity is PID, microsecond birth time, and uniqueid; after exec reacquire pidversion. A failed no-result query gets at most three same-PID retries with requested 1ms sleeps, not guaranteed wall-clock timing. Only complete valid identity or definite ESRCH settles it; persistent failure, short struct, wrong PID, or zero uniqueid remains unknown. Retrying never clears prior uncertainty or changes baseline/member/orphan/gap rules. `proc_signal_with_audittoken` atomically verifies PID/pidversion while signaling, preventing query/signal PID-reuse races. Preflight `--check` sends with an intentionally wrong own pidversion to prove kernel rejection. Missing ABI/atomic-signal support prevents launch. See [Apple proc_info_private.h](https://github.com/apple-oss-distributions/xnu/blob/main/bsd/sys/proc_info_private.h).

Before fork, snapshot same-UID identities. Child waits on a private registration gate, creates a new session before release, and closes status/control/gate FDs; worker inherits only 0/1/2. Launcher waits for supervisor started and a unit-unique file written by trusted Node before loading tools, not a worker-inherited host status channel that could fake restricted startup.

Sample same-UID processes approximately every 10ms, accumulating lifetime identities by current parent uniqueid and observed original-group membership. Current parent uniqueid changes on adoption and is not original-parent identity. Compare new lifetimes to root initial uniqueid (monotonic at fork, preserved on exec), not rollback-prone wall time. Stop verified members with TERM then KILL, never unverified killpg. Require 100ms of complete snapshots after stop; query each known member individually instead of treating UID-list absence as exit. An observation gap over 250ms, identity/signal failure, or final unknown new orphan keeps false.

Never signal/claim an unknown same-UID orphan by command name. Exclude only a process whose current parent uniqueid equals the pre-start PID 1 uniqueid AND kernel-saved original-parent pidversion equals PID 1 pidversion; merely having launchd as current parent does not exclude adopted descendants. `p_orig_ppidversion` is saved on fork and preserved through exec; `p_puniqueid` changes on adoption. See [proc_info.c](https://github.com/apple-oss-distributions/xnu/blob/main/bsd/kern/proc_info.c) and [kern_fork.c](https://github.com/apple-oss-distributions/xnu/blob/main/bsd/kern/kern_fork.c).

PID 1 has another UID, so flavor 18 returns EPERM. Read its complete 56-byte unique identity using cross-UID flavor 17, without argv/environment/credentials; failure disables the exclusion and remains conservative. Historical read-only verification found PID 1 uniqueid=1/pidversion=615 and falsely rejected mdworker_shared processes with the same saved parent version: the fix uses identity, not a name exemption, and preserves original false logs.

Pidversion is a wrapping 32-bit global fork/exec counter, not permanently unique. Original-parent version alone does not justify a general preexisting-parent whitelist. Enable PID 1 exclusion only when root initial unsigned version exceeds the PID 1 snapshot. If a sampled non-baseline lifetime born no earlier than root, or a known member, has current unsigned version below root initial version, permanently record `pidversion_counter_wrapped` and return unverified. External processes born between baseline and fork are not rejected solely for lower versions. `--check` tests UINT32_MAX-to-1, ordinary order, and signed-boundary arithmetic, not a forced kernel wrap. No observed wrap is not a lifetime uniqueness guarantee; gaps/unknown identities still return false. See [kern_exec.c](https://github.com/apple-oss-distributions/xnu/blob/main/bsd/kern/kern_exec.c).

Polling is not kernel membership. A short-lived intermediate parent can disappear between samples while an untracked posix_spawn descendant survives. Report unverified and retain occupancy; do not claim it was killed. Inherited file/network restrictions remain, but it can consume resources or modify authorized workspace files, so do not launch a replacement there. Supervisor abnormal exit without a stop receipt is also unverified, regardless of its own PID disappearing.

### Failure ownership and entry migration

Use typed `ExecutionError.code`; `execution_unavailable` distinguishes `binary_missing`, `policy_missing`, `sandbox_rejected`, and `worker_failed`. Trusted Node markers distinguish pre-sandbox rejection from worker failure without parsing stderr. Errors after unit creation carry `ExecutionError.unit` so cleanup receives identity.

Launchers supply stop conclusions; [shared lifecycle](../bug-fix/2026-10-11-preserve-unverified-worker-stop.md) applies them to ready/init failure, startup cancellation, concurrent/repeated stop, ordinary tasks, and temporary worktree workers. False/exception preserves occupancy, known results, and evidence and emits `task.tool_process_unreaped`. Replacement after mode/grant change fails `mode_switch_unverified`; unknown effects never replay. Host never runs repository Git directly; [worktrees](2026-10-04-subagent-worktrees.md) and [integration](../feature/2026-10-05-integrate-worktree-results.md) keep result/authorization ownership.

Formal Coding default/allowed backend is native only. Reject explicit container/local CLI or `RUUKOTO_EXECUTION_BACKEND` overrides with remove/change guidance rather than automatically rewrite configuration. Daily lazy backend, explicit server, and developer entry use the same host declaration, not model/task/config-page changes. Library tests may inject local.

Upgrade stops old backend/units before replacing checkout, installing dependencies, rebuilding, and removing old overrides. Reopen the same profile: preserve sessions, work copies, approvals, artifacts, and abnormal occupancy. Never rebuild the data directory or replace an active task's execution environment online. Missing native capability still fails. Personal service/user-manager/bus/cgroup prerequisites and independent entry are owned by successor notes; historical container/dedicated-account text is not current deployment guidance.

## Alternatives considered

- **Linux Landlock:** unprivileged/inherited without namespaces or admin profiles; ABI 4 probes denied external files/TCP. UDP, abstract Unix sockets, host PIDs, and SysV IPC gaps fail default no-network/IPC requirements, so not a fallback.
- **Dedicated macOS UID plus privileged helper:** gives inescapable UID membership and certain cleanup, but requires root daemon/setuid and changes work-copy ownership. The owner chose unprivileged polling with retained occupancy. Revisit this first if prerequisites change.
- **Process groups, launchd, or kqueue alone:** small existing mechanisms, but real detached heartbeat survived PGID/SID escape and successful bootout; NOTE_TRACK is unsupported. They do not prove stop.
- **Disable userns hardening globally or make bwrap setuid:** easier deployment, but broader machine privilege or an extra privileged entry with reduced bwrap features. A fixed-path profile is narrower.
- **User-systemd `IPAddressDeny=any`:** one-line reuse of cgroups, but real unprivileged user units could still network. It cannot replace namespace+BPF.
- **Podman, Apple container, lima, or Docker Desktop:** proven container boundaries/cleanup and cheap launcher reuse, but macOS still needs a VM and retains toolchain/permission/inode differences. The original personal container exception was later superseded separately.
- **Read entire tool parent/HOME:** supports unknown layouts, but exposes data/credentials. Use exact versions/libraries and fail unverifiable dependencies so the owner can adjust installation or grants.

## Consequences

Native work retains real tools/identities and shared lifecycle; Linux namespace+cgroup proves detached-member cleanup. Linux needs bwrap/profile, user systemd, and cgroup v2; macOS needs a C build and private libproc ABI checks. Unknown tool layouts may fail rather than open broad data roots.

macOS survivors may write authorized files and consume CPU/memory. Retained occupancy blocks new work and can conservatively false-reject unrelated same-UID orphans. Faster polling or command-name filtering cannot make cleanup certain. `sandbox-exec` is deprecated: removal/policy changes make this backend explicitly unavailable. If certain reclamation becomes mandatory, revisit privileged identity isolation or withdraw restricted macOS support, never silently fall back.

Real evidence covers macOS 27 arm64 and Ubuntu 24.04 x64 only. Linux arm64 BPF has targeted branch tests, not real-platform acceptance. Other distributions/LSMs/old AppArmor ABIs/tool layouts need separate verification. Authorized workspaces/read dependencies may already contain secrets; the sandbox does not inspect content sensitivity.
