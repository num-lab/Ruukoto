# Agent Note: 工作流步骤复核来源并汇入冻结成果

Status: implemented

## 问题

[运行基础](2026-10-13-workflow-runtime-and-store.md)保存步骤与宿主执行，却不能证明真实 Driver 得到来源能力，也不能把普通工作副本的实时差异当作已验证成果。[确认规格](../../../../.scratch/agent-workflow/spec.md)要求来源交集、普通委派独立、修改与验证分离，以及验证结论对应实际汇入的字节。

## 决定

Runtime 默认装配真实 `WorkflowSteps`，测试仍可注入执行器。宿主以执行表、运行、来源、工作、SubAgent、Session 和 Task 共同解析步骤画像；参数不能提供宿主身份。来源固定实际装配类别、启动时资料授权 ID、工作区身份与配置摘要，模式和模型沿运行固定。当前资料授权、配置、入口代次及目录身份在模型发送、工具意图、真实调用和宿主 Git 调用前复核；新资料授权不扩大旧运行，撤销阻断依赖闭包内缓存结果的再次使用。配置摘要只记录散列，不复制凭据；应用实例身份属于配置，业务 schema 修订不冒充权限换代。

普通 SubAgent 保持原画像。步骤没有下一层委派；个人来源的编码资格仅来自已有受控编码委派工具，不将整 coding 类别复制给 main。分析步骤读取钉定的来源工作区，编码写入须先取得 Git 独立副本；非 Git 修改在 worker 和模型前拒绝，分析与获准业务工具仍可用。步骤有独立 JSONL；显式资料读取、技能目录、步骤参数、依赖值与宿主工作目录均可由任务、选择记录及原文快照重建，不自动复制主聊天。

修改完成后核实 Driver 和宿主任务均停止，在副本占用下提取原始补丁字节，保存定稿产物、SHA-256、长度、基线及运行/步骤/工作/任务归属。验证步骤新建 Agent 与按相同基线、冻结补丁构建的独立副本，只开放编码验证工具。验证 worker 始终使用原生沙箱，来源完全访问也在这里收窄；来源附加路径转只读，不开放绕过 worker 的宿主文件写入口。原生执行不可用时明确失败，保留成果，不回退到无隔离执行。

验证记录来自独立真实 Task 的完成输出与工具账本，绑定冻结摘要、基线、产物和验证任务；工具失败或效果未知不能被模型的 `passed:true` 覆盖。JSON 格式失败保留原输出，既有写入不能自动重跑。脚本传入通过文本、普通 `subagent_integrate`、普通继续或复用不能放行工作流成果。

汇总宿主任务从运行授权派生，在整个冻结套用和组合检查期间持有源、副本及目标占用。每份补丁先比较当前副本字节与冻结字节，再套用冻结文件；变化要求重新验证。冲突只拒绝该份，此前套用保留；组合检查失败可见，不宣称回滚。检查后再次复核副本摘要。启动先登记可停止句柄，实际身份只更新原句柄；取消后的迟到身份仍保存，停止 false 保留原任务、账本与全部占用。宿主准备或冻结的未知效果同样阻止 Agent 重新尝试。

schema 为 37，新增来源授权快照与步骤冻结/验证字段；旧库按既有约定拒绝启动，不补造来源资格。产品模型工具与交互入口、最终回报和外部联合验收仍由[后续工单](../../../../.scratch/agent-workflow/implementation-plan.md)持有。

## 既有笔记审计

[工作流提案](../../proposed/feature/2026-10-12-agent-workflows.md)、[执行基础](2026-10-13-workflow-runtime-and-store.md)与[工作副本](2026-10-04-subagent-worktrees.md)部分重叠，本篇持有真实步骤与冻结汇总，其他理由仍保留并互链。[完全访问](../feature/2026-10-12-full-access-current-account.md)与[原生沙箱](2026-10-12-personal-native-sandbox.md)部分重叠，只对独立验证步骤收窄执行，普通完全访问、普通委派与停止规则保持。MCP、服务和调度决定各自持有审批及效果分类；本篇不复制其凭据或长期批准。不涉及归档修改或整篇吸收。

## 备选方案

- 放宽普通 SubAgent 白名单最省接线；会同时扩大已有委派与历史上下文的范围，因此通过明确工作流绑定独立装配。
- 汇总时重新生成差异能直接复用普通入口；验证后修改和续派会使旧结论放行新字节，因此冻结原始补丁并核对当前摘要。
- 验证者沿来源完全访问只改变 cwd，环境最接近修改者；绝对路径与宿主文件工具仍能写回待审成果，因此验证者的命令使用原生沙箱且关闭宿主写旁路。
- 每次 worker 后释放副本占用符合普通汇总；多份套用与组合检查之间会出现新写入窗口，因此工作流由同一短期宿主任务持有整段占用。

## 后果

两个产品共享真实 Driver 与工具审批，普通委派保持原能力。冻结成果与独立验证使脚本无法伪造汇入资格；代价是保留多份副本、产物、宿主任务与原生验证环境，不能靠模型自述或脚本返回声明整体成功。定向证据与未验证环境见[验收工单](../../../../.scratch/agent-workflow/issues/04-step-capabilities.md)；模拟模型与真实 worker 不证明真实模型或 IM 产品验收通过。
