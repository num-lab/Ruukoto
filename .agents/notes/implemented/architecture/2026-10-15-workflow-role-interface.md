# Agent Note: 工作流共用角色并显式保存派发接口版本

Status: implemented

## 问题

[可配置角色规格](../../../../.scratch/subagent-roles/spec.md)要求普通委派与工作流共享职责、来源能力和当前目标内容；旧 analyze/modify/verify 同时决定能力与成果处理，既不能选择同一角色，也不能把验证资格安全地归还宿主。直接把旧脚本的默认 analyze 解释成 general 会扩大历史定义的工具范围；仅删 mode 又会丢掉冻结验证及恢复依据。

## 决定

普通 `subagent_delegate` 与工作流 `agent` 共用 role，首次省略为 general；普通身份沿固定定义，工作流各步骤按运行启动时固定的完整角色目录选择。target 独立表达代码目标，无目标沿独立目录执行来源工具。工作流目标要求 Git，并沿[当前工作区快照](2026-10-15-current-workspace-snapshots.md)捕获基线、冻结子增量；普通与工作流仍各自持有调度、取消、结果消费与最终报告。

verify 引用本运行已冻结的目标步骤，必须声明依赖并与 target 互斥。角色可以是 general、reviewer 或自定义定义，均叠加宿主 confirm、来源保护和五个编码验证工具；显式角色要求与步骤收窄冲突则启动前失败。验证使用同一捕获基线和冻结补丁的新副本，不因角色覆盖获得原目录写入资格。

验证资格同时需要独立 Task、冻结产物/摘要/基线、合法输出和非空真实编码工具账本；任一操作失败、缺结果或效果未知都不能由 passed:true 覆盖。汇入重新核实两步 Task 的角色/来源/目标、工作与运行归属、停止事实和验证账本，再沿冻结机制比较实际字节、目标完整受影响文件与组合检查。普通汇入、续派和复用不能接管工作流成果。

恢复、排队启动及结果消费也核实已完成 Agent 的角色定义、执行快照与目标基线，不能只依赖下次 Driver 启动校验。记录缺失或损坏时暂停受影响运行并保留原 Task、尝试、账本和成果，不从当前角色文件补回、不重跑旧步骤；私有基线与持久快照分别保留已有具体错误码。

宿主注入的工作流执行器继续持有自己的执行与账本合同，不伪造 Driver 记录。Driver 专属快照核实沿与 preflight 相同的可信装配回调进入恢复、调用与消费；默认真实 Driver 始终安装严格校验，不能根据记录缺失临时跳过。冻结汇入仍直接核实两步实际 Driver 证据，注入返回的 passed 文本不能取得该资格。

## 接口版本与命名文件

派发接口版本为 2，定义与运行保存 interfaceVersion。新定义摘要包含版本和脚本，旧接口保持原脚本摘要；相同正文显式保存新版也形成独立定义，不覆写已引用记录。当前命名文件由保存入口写入首行 `// ruukoto-workflow-interface: 2`，余下为完整脚本；元数据与正文通过同一个文件原子替换，避免两个文件之间的版本撕裂。

无标记文件按旧接口登记可查询历史，不作为新版启动。拥有者或模型读取原摘要、改用 role/target/verify 后显式保存新版本；不扫描任意 JavaScript 字串推测权限，不自动改写脚本。旧运行仍可查询与取消，新启动和恢复要求版本一致且摘要正确。原键回执只返回已接受事实，不重放旧效果。

普通工具、Runtime 委派和工作流调用均明确拒绝任意旧 mode 字段。临时脚本在具体调用校验时失败，此调用未执行；此前完成步骤仍保留真实副作用，不能把整段脚本说成无效果，也不能换键重做未知操作。角色文件的 permissions.mode 继续表示访问策略，与已移除的派发 mode 不同。

schema 45 与控制协议 26 按现有严格策略拒绝旧库和客户端，不迁移授权或历史 JSONL。两方向导入继续拒绝含工作流执行绑定的源，纯定义历史不随普通资料导入；不为版本字段增加一条丢掉绑定的兼容通路。

## 既有笔记审计

按 workflow、角色、mode、冻结与接口版本检索 proposed、implemented 和 rejected；归档不修改。[角色与目标分离](../../implemented/architecture/2026-10-14-configurable-subagent-roles.md)的派发接口部分由本篇落实，整体决定已转 implemented，组合产品验收仍由原工单持有。[角色快照](2026-10-14-subagent-role-snapshots.md)、[共同来源](2026-10-15-subagent-source-capabilities.md)与[当前基线](2026-10-15-current-workspace-snapshots.md)部分重叠，沿用其加载、授权和捕获决定。[真实步骤与冻结成果](2026-10-13-workflow-step-capabilities.md)中旧模式和独立画像选择被部分取代，冻结、停止及汇入职责保留；[定义库与可信入口](../feature/2026-10-13-workflow-library-and-controls.md)新增显式接口版本，路径保护、原键、文件/SQLite 非原子及渐进交互决定保留。其他命中为普通委派历史、调度、审批与归档，不吸收或改写。

## 备选方案

- 保留旧 mode 并映射到默认角色最少改调用方，但会把旧 analyze 自动扩大为 general，违反直接替换且不补授权的决定。
- 按脚本文本查找 mode 可以提前提示旧定义，却会误判字符串、动态属性及无关变量；因此命名定义用明确元数据，临时调用在参数边界拒绝。
- 将接口版本放 sidecar 可以不改变文件正文，但保存会引入两份文件之间的竞态与崩溃组合；首行元数据沿现有单文件替换即可同时固定版本和正文。
- 给所有宿主注入执行器强加 Driver 预检能统一记录，但会把独立执行适配器改成隐含依赖模型 Driver、改变其既有合同；因此沿可信宿主装配选择验证责任，默认真实执行始终严格。
- 只相信已保存的 passed 记录可以少读账本，但零工具声明及恢复时丢失角色/执行记录仍能取得汇入资格；因此实际调用非空，消费前重新核实记录和账本。

## 后果

开发说明新增共享角色与接口版本回归的文件定位后为 9536 个非空白字符，原有内容均属于环境、入口与测试导航，无需迁入决策层；将该页上限由 9500 调为 9600，保留现有入口与新回归导航。README 通过压缩同义导航措辞保留原上限。

同一角色能用于普通审查与工作流；冻结验证继续由宿主持有，源码当前脏内容与子增量不混淆。代价是旧命名文件需要显式保存升级，旧档案需匹配代码查阅；缺失记录保留现场而不能自动恢复。离线真实 Driver/worker、独立审查及未验证范围由[实施工单](../../../../.scratch/subagent-roles/issues/04-workflow-integration.md)持有，真实模型、IM 与组合产品验收继续交联合验收，不把模拟模型认作真实模型通过。
