# Agent Note: 子工作逐次绑定固定检查并等待原执行停止

Status: implemented

## 问题

[持久检查归属](2026-10-17-personal-durable-inspection.md)只允许主会话工具与服务审批前检查。[长期子工作](2026-10-17-personal-background-work.md)仍为空工具，直接下放检查会把子会话输入当作拥有者来源，也会在框架已停而 helper 未核实时释放身份。Pi abort handler 的异常会成为不能二次取消释放的 faulted，不能用抛错表示待核实。

## 决定

子会话只增加已有固定只读 `service_inspect` 与本会话证据读取，不下放服务写入、任意命令、MCP、再委派或长期授权。每次新检查在原接纳事务核实活动 WorkTask、单工作占用、取消、原入口、委托暂停及当前 generation/tool；当前 child inputs 必须由本工作初始或追加说明的稳定键受理，不依赖后续补写的 Submission 引用。三模式均以宿主白名单限定只读检查，不从历史上下文或新默认模式扩权。

检查不可改接纳保存工作引用、原权限/入口、实际 child inputs 及映射后的主会话来源：原拥有者输入、本轮委托说明与当时已接纳的 input notes。所有新说明均保存不可改接纳，恢复按检查 admission 之前的说明重建快照，不把后来追加算进旧操作。检查证据仍写原子会话；恢复逐会话核对最新接纳、工作/权限、工具和输入关系，缺失不补猜。

正常收尾与取消均先收齐子会话及后台执行，再观察未核实检查 document。订阅后复核，最后释放事务再次拒绝未核实检查；占用清空前原 WorkTask 持续等待，关闭中断后重启重接原 Task。停止证明仍由 Harness 提交，不使用已取消的 tool invocation。模型 cancel 只登记并返回当时状态，避免主聊天等待外部停止；可信宿主 `work.cancel` 明确等待最终停止。整项取消与报告自然沿原 WorkTask/来源等待，其他委托和聊天继续。

`personal-subagent-service-inspect` 同时登记主/子会话，旧程序缺扩展即拒绝；空闲旧档案的全部子配置与主标记在同 commit 升级，未决旧输入/工作先拒绝，不能半升级。未配置服务的子会话保持空工具。

## 既有笔记审计

按 durable、子工具、停止、检查及空工具检索 active notes。迁移提案、长期后台工作、模型工作、只读检查和 durable 检查归属部分重叠，保留各自原决定并互链；本篇取代其中“子会话固定空工具、不下放检查”的部分。追加说明笔记继续持有轮次，所有新说明追加不可改接纳的事实同步原位。服务写入与 helper 同组停止证明保持原边界。无完全吸收或失效提案。

## 备选方案

- 框架 idle 或工具 Task 终态后立即释放：实现最少，但后台崩溃或停止应答不可信时原检查仍可运行，不能复用身份。
- 停止未核实时抛错，待重核后再次 abort：能立刻应答，但 Pi 会保存 faulted；terminal Task 的 abort 不再调用 handler，无法安全重接收尾。
- 给每种工具新增外部执行状态机：可提前覆盖命令/MCP，但其后代、回执和权限尚无实际消费者；本片复用固定检查与原 WorkTask，不泛化 OS 证明。

## 后果

子工作首次拥有受控只读外部工具，原来源与停止证据可重建，取消和重启不自动重查。代价是未核实执行可长期占用身份，需要可信宿主修复部署后重核；CLI/Telegram 的原接纳停止重核入口见[拥有者检查控制](2026-10-17-personal-inspection-stop-controls.md)。固定同组检查的证明不能用于任意命令或主动脱组后代，未知写入及整项服务写操作归属继续由总方案实施。实际验收、独立审查及真实环境缺口见[实施记录](../../../../.scratch/personal-pi-durable/issues/18-subagent-inspection.md)。
