# Agent Note: 个人应用数据以原生工具键核实双库结果

Status: implemented

## 问题

[个人迁移](../../proposed/architecture/2026-10-17-personal-pi-durable.md)保留独立应用数据SQLite，但旧工具适配绑定core Task/ApprovalGate。业务库提交与durable结果之间没有共同事务；直接重跑写API可能重复业务或因当前目录变化无法读取原结果。

## 决定

六个应用数据工具复用共享参数、AppDataStore和有界查询；durable工具Task是每次逻辑调用的稳定操作身份，接纳快照固定完整参数、原来源/权限及应用库身份，执行前落盘，写后按原键核实审计。完整参数指纹及整份回执内容校验随业务回执同事务保存，不把同一模型轮次或拥有者输入当成操作键。恢复只补记已提交/已知未提交结果，已开始的修改绝不重发。

每次打开绑定库校验文件、存储版本、实例身份、目录与审计；查询子进程再核对身份。首次建库先与主扩展同commit保存固定库身份和初始化意图，随后在应用库初始化事务中写同一身份，最后解除初始化标记；中断沿原意图完成首次建库，没有业务调用可在此期间执行。已有但身份不符的库拒绝接管。缺库/换库/损坏回执使应用数据停止，已开始的操作保持未知并暂停所属来源、子工作、委托/定时报告；其他独立聊天和工作继续。拥有者恢复原库后通过原记录重核，不能建立新库证明旧操作未发生。人工重核仅接受已终态原工具，避免start落盘而原工具尚未进入SQLite时提前判未提交；内部核实只在本次同步写已结束或启动调度前进行。查无回执时核对审计数量/最大修订和业务revision，缺少审计行不视为未提交。

破坏性迁移、多行更新/删除与重写沿[现行完全访问决定](../../implemented/feature/2026-10-12-full-access-current-account.md)：confirm与auto-review逐次人工批准，full_access免逐次审批。批准绑定完整参数、原入口、权限和schema/revision，消费与开始记录在durable同commit；实际业务事务再次校验revision。批准期间不持有业务库锁。审批和结果是持久entry，恢复双向核对索引、工具调用、来源与各项证据，未知记录版本拒绝恢复。

主/独立定时会话有业务资格；子工作由委派appData显式给予，按当前工作记录复核，身份复用不继承。定时创建范围固定库身份；封组汇总仅开放app_data_query，通过活动只读工具及原定时范围核实，不放开写门。双平台宿主菜单和本机引导管理只引用程序保存的原操作，不要求拥有者输入内部键。

## 既有笔记审计

按应用数据、回执、op_id和个人durable检索implemented/proposed，rejected目录不存在。[旧应用数据空间](../../implemented/architecture/2026-09-23-main-app-data-space.md)、[来源工具](../../implemented/architecture/2026-10-17-personal-tools-access-artifacts.md)、[独立定时](../../implemented/architecture/2026-10-18-personal-durable-scheduled-work.md)与迁移提案部分重叠，各自保留共享装配、来源和调度职责并互链；full_access沿取代旧例外的现行决定。记忆、服务、MCP、实例导入及旧Runtime仅为其他消费者，不吸收或删除其决定。

## 备选方案

- 直接复用旧工具适配：可少写审批装配，但引入旧任务/项目状态和另一版本SDK对象；只复用无运行状态的存储、参数与查询。
- 依赖写API自身幂等：正常重试简单，但旧回执不含完整参数，而且当前目录/容量预检早于回执读取；durable恢复直接核实原回执，不进入新写路径。
- 合并业务与durable数据库：可同事务提交，却破坏业务库隔离并耦合上游schema；保留两库及明确的提交窗口。

## 验证

真实SQLite证明完整参数同键一致、多调用分别执行、破坏性与批量操作三模式、批准后权限/revision失效、查询预算/关系校验及原生来源。强杀业务提交后结果提交前的进程，重启只有一次业务变更；缺库/换库/坏回执不重建或重放。子资格复用和定时只读汇总分别验证；真实模型/IM与体验另记外部证据。

## 后果

两库无原子提交，业务库损坏时只能保留未知，须恢复可信原库再核实。数据目录依赖宿主保护，应用数据API资格不等于后台账户文件隔离。真实环境缺口不能由离线替身消除。

工程检查与独立审查的实际结果见[工单](../../../../.scratch/personal-pi-durable/issues/34-app-data.md)。回执新增字段保存在已有operation JSON中，旧调用未提供指纹时格式和幂等行为保持，业务SQLite表结构版本不变。
