# Agent Note: 个人请求保留配置选择并按对象发布后续版本

Status: implemented

## 问题

个人后台捕获启动时的模型、MCP 和搜索配置。直接修改同名 provider 或把新文件整体覆盖运行选择，会改变旧请求的地址、让其他服务提前生效，或使搜索更新撤销无关资料与 HTTP 操作。Skills 虽已保存正文快照，发送前又与当前清单比较，正常停用会否定已经准备的原请求。

本篇只持有模型、Skills、MCP 与搜索的运行选择；设置保存、格式迁移、IM 与命令/服务迁移仍由[配置更新规格](../../../../.scratch/configuration-updates/spec.md)和[整体提案](../../proposed/architecture/2026-10-25-operation-scoped-configuration.md)持有，不代表整体工单完成。

## 决定

模型新增配置版本时使用该不可复用版本生成 provider ID，先登记到原 MutableModels，再在同一短事务配置主、子和定时会话的后续模型选择。冷启动先恢复全部持久配置版本，保留迁移前 personal provider 的原基线；已开始 generation 按原 provider/modelId 恢复，不从当前文件重新路由。自动审查、图片能力和新委派读取当前运行选择。旧 provider 保留至后台关闭，避免提前释放 poll、abort 或恢复引用。

Skills 准备后按不可变 snapshotEntry 核实原正文与引用，不再要求当前清单相同。新 skill 加载仍核实对应托管包已启用、内容版本和原目录选择；已保存的加载结果继续返回原文本。停用影响后续请求和新加载，不擦除原参考。

MCP 模块发布指定服务，保留其他服务的实际选择；文件候选里尚未生效的服务不被顺带发布。原调用保存配置版本，模型响应中的新调用从原请求证据取得该服务版本，变更后不能悄悄改发新端点。发送前和计划校验共同消费不可变保存链，只排除服务 label 与宿主 generation；端点、权限、服务集合、工具定义等任一步变化都截断资格，改回也不恢复。索引从已核实版本派生，不另存权威兼容账本；没有完整旧链时只接受原配置精确相同。

普通 HTTP MCP 调用的结果未知不阻止新配置保存或发布，原请求、凭据引用、未知事实及同来源/端点占用继续保留，不据新配置重发或解除占用。电脑连接的目标或工具变更则等待该连接与相关动作的停止边界；不会把它扩大成普通服务或整个后台的等待。

多个 MCP 服务共享一个运行选择对象，读取实际配置、合成当前服务候选、提交选择与替换内存对象在短提交段内串行；电脑停止和连接关闭在提交段外等待。原操作重核若该服务已是候选配置，只确认该服务选择，不重写全局配置或复用其他服务已经使用过的 generation。

Web Search 使用独立配置文件和当前选择，沿原 ToolDoc、原生 Task、次数上限及产物证据执行，不依赖资料目录。旧 tools.search 是初始选择，新保存只改变搜索；尚未开始的旧响应必须匹配原搜索版本，在途搜索保留原凭据引用和结果。文件与 HTTP 操作继续使用原配置和授权。内部保存版本进入原请求证据，普通工具结果不增加版本输入。

设置意图尚未核实或候选尚未发布时，只暂停受影响目标的新接纳。模型与 Skills 在下一请求准备前检查，MCP 按服务检查，搜索在新搜索接纳处检查；已准备或已开始的原操作按原选择结束。共享 Storage 错误继续向上失败，不能作为单对象连接故障吞掉。

## 备选方案

- 覆盖 personal 同名 provider：代码最少，但 SDK generation 只保存 provider/modelId，旧请求恢复会使用新地址或凭据；按唯一保存版本登记。
- MCP 保存后一并发布整个候选文件：可直接复用单一 config，但 A 待生效时 B 保存会把 A 提前发布；模块按服务替换实际选择。
- 搜索独立写另一套工具状态：避免调整可选的资料配置类型，但会复制原生调用归属、额度和产物恢复；继续使用原 ToolDoc，搜索接纳另存自己的配置选择。
- Skills 发送前校验最新清单：可以立即撤回旧参考，但已经固定的请求会被无关清单变化否定；保留原参考，在新加载处收窄资格。

## 后果

在线保存不需要关闭整个后台，原模型、调用和产物仍有可核实的配置归属。代价是后台生命周期内保留出现过的 provider，以及恢复时校验配置链；不增加历史物理回收或自动业务重试。真实模型、真实 MCP/IM 和客户端体验验收仍需独立环境，回环服务与故障注入只证明对应执行路径。
