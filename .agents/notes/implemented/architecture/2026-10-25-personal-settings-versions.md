# Agent Note: 设置保存与对象生效分别留证据

Status: implemented

## 问题

普通配置曾借停止后台取得档案锁，再保存并启动；运行对象捕获启动配置，历史恢复则把当前文件当作旧操作的身份。直接删停机检查会引入第二写入者、保存后不生效和旧请求改发，文件替换与 SQLite 提交之间也没有原子性。

## 决定

个人设置由现有档案写入者统一接纳：在线复用 Harness，离线持同一档案锁并用 SDK 公共 createSession 提交，不创建 Harness 或自动启动。声明式配置不依赖原模型凭据、systemd 或无关工作；工具执行仍由原模块检查实际授权与环境。

v2 写请求固定操作键、档案身份、期望文件修订与判别操作，v1 查询兼容但拒绝新写。操作 family 追加阶段事实，配置版本 family 保存不可变候选和完整前驱链；当前索引只保存引用。回执区分未保存、已保存、等待、生效失败、已生效、待核实及已取代，不公开候选正文或秘密引用。相同内容保存复用既有版本，不生成新的执行身份。

写序为持久意图、单文件原子替换并 fsync、提交保存事实、发布对应对象、提交生效回执。意图未替换时原键核实为未保存，不重写文件；文件等于候选或有完整后继保存链时仅恢复幂等发布。未知文件封闭该文件，已证明保存后按对象收窄；MCP 的整文件修订与服务生效选择分别记录，B 保存不顺带发布 A 的候选。发布等待不占全局保存互斥，同对象的撤回与发布串行。

配置与内存对象之间不宣称原子。查询不能只凭数据库选择指针推断对象已发布，必须经模块的幂等发布或实际对象核实；旧键与已取代候选不能重新选回旧版本。共享 Storage 失效仍关闭整个实例，不降成单个对象的普通失败。停止前等待在途配置提交；客户端断线不取消已接纳操作，不自动换键重存或重放旧模型、工具、IM 发送和服务操作。

设置读取分别给出文件修订、各 scope 的实际生效版本和原操作回执；两类事实按稳定索引每页32项并返回后继偏移，桌面收齐后再判断对象是否可写，旧未结操作不会因后续保存而消失。整文件 MCP 发布覆盖既有显式 scope，包括已删除服务的选择。已生效文件被外部删除、改写或损坏时，只暂停该文件的新接纳并报告 fileIssues，不改历史生效回执或伪造用户操作；恢复原字节后重新核实。

实际控制入口冷启动先只读核实已有 durable 格式与完整版本链。当前文件不符最后保存事实时，用原持久选择引导对应模块，再由设置恢复暂停该目标；不覆盖坏文件、不把外改内容当新选择。尚无有效模型选择时仅可用已证明保存的模型版本引导，仍暂停新请求。没有配置初始化证明或完整历史的旧档案继续拒绝，开发实例启用 IM 的提前拒绝仍在恢复之前。

格式能力以 PERSONAL_FORMAT.configuration 标记。迁移先持久发布旧程序拒绝的 profile.json 迁移标记，再在单事务内提交原配置基线、格式及无根配置初始化证明，最后完成标记。无根配置初始化只允许由 Harness.root 正常创建根；旧库缺根而没有证明仍拒绝。迁移标记与配置摘要只允许核实原格式未提交或同迁移已提交两种状态，历史 entries 不改写。

remote 的 v2 维护接纳只保存档案、操作键与摘要的关联；实际保存/生效回执由档案持有。Electron/MyGo 复用同一 Host，按对象保存待核实关联，页面可离线保存、核实原更改及撤回已证明保存的候选。旧 maintenance.json 的阶段解析、查询与显式恢复继续使用原解释；新写不再启动旧停存启分支。

## 既有决定

按配置、settings、maintenance、generation 与 migration 检索现行笔记；[总提案](../../proposed/architecture/2026-10-25-operation-scoped-configuration.md)所列笔记均为部分重叠，保留身份、权限、凭据引用和未知效果的独立约束。本篇收窄[设置管理](../feature/2026-10-21-personal-settings.md)、[SSH 维护](../feature/2026-10-21-personal-settings-ssh.md)与[个人设置页面](../feature/2026-10-21-desktop-personal-pages.md)中的普通保存停机条件，不取代显式系统服务管理。请求选择、执行迁移与 IM 分别由[请求配置](2026-10-25-personal-request-configuration.md)、[执行配置版本](2026-10-25-personal-execution-configuration-versions.md)及[平台切换](2026-10-25-personal-im-updates.md)持有，没有完全吸收或需归档的旧笔记。

[HTTPS 连接](2026-10-24-personal-tailscale-https.md)、[本机管理](2026-10-17-personal-local-management.md)、[个人 MCP](2026-10-17-personal-durable-mcp.md)及[托管技能](../feature/2026-10-21-managed-skills.md)中的普通保存全局停机条件同样由本篇收窄；它们的认证、原引用与未知效果边界继续适用。

## 备选方案

- 只移除停机和空闲检查，改动最少；旧闭包不更新且历史可能被 current 污染，拒绝。
- 保存后自动重启，可复用启动装配；仍打断无关工作并依赖旧环境，不满足目标，拒绝。
- 用另一份文件账本或 remote 回执作为生效权威，易于展示；会产生两份权威，复用档案内 durable family。
- 按整文件封闭所有服务，恢复简单；已证明保存后没有必要阻塞另一服务，只有文件结果未知时采用。

## 后果

保存不再要求全局停机，但必须保留真实存在过的配置版本与阶段事实。启动先恢复原选择并核实待生效操作，再接纳新业务；正常代码升级仍可重启一次。候选等待时可显式撤回，原保存事实保留并记录取代关系；未知结果须先核实。行为、工程证据与外部验收分别记录在[实施工单](../../../../.scratch/configuration-updates/issues/01-remove-global-restrictions.md)，笔记的 implemented 不代替产品验收。
