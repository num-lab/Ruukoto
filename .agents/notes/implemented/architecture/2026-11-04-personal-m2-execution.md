# Agent Note: Carry Personal work requirements and resource ownership through every waiting capability

Status: implemented

## Problem

[M1 amendments](2026-11-04-personal-work-amendments.md) invalidate older unstarted ordinary operations and bind effects to the instructions actually included in a model request. Optional MCP, application data, commands and services did not share that guarantee. Browser and computer connections belonged to main, while persistent processes outlived replies without an assignment identity. Child model execution alone also left synchronous application SQLite work on the host event loop. [Issue #41](https://github.com/num-lab/Ruukoto/issues/41), under [#34](https://github.com/num-lab/Ruukoto/issues/34), requires coverage of every enabled waiting family.

## Decision

Main coordinates, queries and reports; child work performs waiting business calls. Ordinary tools, MCP calls, app-data, service inspection/restart, commands, browser operations and process startup are omitted from main requests and return handled execution errors if still called. Source-bound result and management queries keep their existing authority. Independent scheduled conversations retain their captured capability scope.

Every accepted work amendment supersedes the original work's unstarted operations across all those families, including approved unconsumed decisions. Supersession preserves the exact admission, parameters, decision and original permission, records known nonexecution and wakes the child to read saved instructions at the next model boundary. Admission and consumption both check the actual recorded request snapshot and the current live input membership. Started effects remain governed by their own result, stopping and recovery facts; an amendment neither undoes nor replays them.

WorkTask version 4 qualifies browser, Cua and persistent-process work from original full-access authority and enabled host composition. The qualification has an immutable host entry and random controlled identity; model arguments cannot grant it. Scheduled child work can obtain browser qualification only through the original schedule's browser scope. Computer and persistent-process qualification remains unavailable to schedules. Live older WorkTasks must settle with their original version before activation; completed old history keeps its earlier evidence rules.

Browser and Cua use a persistent FIFO of assignment claims for each instance resource: one browser resource and one Cua resource per configured sandbox identity. Later assignments retain their original source and queue without preemption. Acquisition precedes execution. Normal completion and cancellation collect the exact owned execution, then release claims in the WorkTask's terminal transaction after rechecking accepted notes, cancellation, stopping and effect requirements. An amendment accepted during cleanup keeps the same claim and returns to instruction supervision. Every family's release evidence is prepared before any release entry starts the transaction's write phase. Unknown stopping keeps the original WorkTask live and resource claimed; an explicit original-execution recheck can provide the missing proof. Recovery verifies reciprocal admissions, original model requests, acquisition order, participant records and release evidence, including immutable entries whose projections were deleted.

Healthy human takeover stays bound to the original operation, resource and observation generation. Browser continuation consumes a fresh original-entry choice once and obtains a new snapshot; old references are discarded. Connection management reads the current child owner's browser. External stopping captures its binding generation and original operation IDs before cleanup; a missing or closed binding gives no stop target, and delayed evidence cannot mark a reused child's later operation stopped. Cua pauses retain each takeover's immutable history, require a fresh screenshot and acceptance of that exact observation, and keep the resource while the choice is pending. Pausing during an in-flight call does not bypass this sequence if the call later returns. Unknown Cua actions retain the established stop/observe/accept recovery. A later CLI stop failure can be rechecked without changing an accepted takeover. Automatic cleanup stops only the original CLI; stopping the whole Linux sandbox still requires the explicit existing owner choice. The existing singleton Cua connection can refuse another configured target while occupied or closing; cleanup holds its captured execution through exact stopping, and a refused call cannot close or clear the current owner's connection. A queued successor for the same resource waits for the original recovery or cleanup call to finish, then rechecks its original admission, active work and instructions before reserving the connection.

Persistent processes retain their independent task lifetime across ordinary child replies. Whole-assignment cancellation requests stop only for processes carrying that work's original identity, including after its WorkTask has completed. Reused SubAgents cannot stop another assignment's process. Legacy processes retain their historical source, and directory claims still prevent conflicting file or command effects until the exact process stops.

Application SQLite preparation, versions, queries, writes and receipt reads run in fixed per-job worker threads. Threads receive only the application database identity and operation, with an empty environment and no core-storage handle. Each Personal SQLite handle uses the native one-second busy timeout before its first metadata read, so simultaneous openings can finish WAL recovery without being misclassified as database corruption. An expired constructor lock wait is a typed busy failure; business writes are never replayed. The shared store's omitted timeout retains the native zero-wait default for Coding. A result becomes usable after exact worker exit; abort, deadline and profile close request termination and join the same worker. An active native SQLite call can delay that exit without blocking main or establishing the write's effect. Host exit ends all writer threads, so recovery reads original receipts after stopping instead of replaying writes. Inspection and receipt/query jobs request termination after two seconds; initialization and writes after ten seconds. Approval is a short durable decision, version inspection occurs outside the Session transaction, and the application write transaction rechecks the approved revision. Manual recheck registers an independent host task, leaving main free while it reads the original receipt.

Canceling a schedule occurrence persists the original owner authority and cancels its derived work while preserving future triggers. Canceling the schedule remains a separate action. A later plan cancellation preserves an already recorded run cancellation instead of replacing its immutable authority. Duplicate cancellation validates the current caller without creating another proof. Member reads occur before authority entries are appended, respecting the durable transaction's read-before-write rule.

Work queries expose canonical MCP, app-data, browser, process and resource facts alongside existing ordinary-tool, command and service results. Result queries page each family in groups of eight with `factsOffset` and `nextFactsOffset`, independently of answer text. Summary and progress queries show the first fact page. Paged results include per-family total, pending and unknown counts across all records, preserving off-page blockers and historical unresolved ordinary MCP effects after manual finalization. Healthy Cua takeover is pending, while an accepted recovery retains its original unknown history without claiming that it still blocks execution. Process facts contain identity, state, stopping, reason and creation time; original command and output details remain in process management. Queued, owned, stopped, effect unknown and superseded facts are inspectable independently of a child's old answer. This extends M2 coordination; complete cross-family desktop decision cards and question flows remain owned by M3.

## Relationship to Earlier Decisions

This decision partially supersedes Personal main-only/child-exclusion eligibility in [browser/media](2026-10-18-personal-browser-media.md), [app-data](2026-10-18-personal-durable-app-data.md), [background processes](../feature/2026-10-21-personal-background-processes.md) and the Personal connection ownership in [official Cua](2026-10-23-cua-official-mcp.md). Their original permission, media, receipt, managed execution and no-replay guarantees remain. It extends M1 request freshness to [MCP](2026-10-17-personal-durable-mcp.md), [commands](2026-10-17-personal-durable-commands.md), [services](2026-10-17-personal-subagent-service-operations.md) and [inspection](2026-10-17-personal-subagent-inspection.md), and adds occurrence-only cancellation to [scheduled work](2026-10-18-personal-durable-scheduled-work.md). Coding composition and its resource ownership remain separate.

## Alternatives considered

- Keeping waiting calls in main saves delegation calls but prevents later owner inputs from reaching main during external waits. Reuse existing independent child work.
- Inferring whether an amendment is compatible with each old approval can preserve more approvals, but introduces another semantic decision and misses delayed responses. Apply the already approved conservative rule once per family.
- Preempting a browser or computer owner reduces queue latency but can discard unsaved state and release an execution that has not stopped. Persist FIFO ownership and exact stopping evidence.
- Owning persistent processes by the child reply gives automatic cleanup but stops long-running services at ordinary completion. Keep the existing independent process task and attach assignment cancellation authority.
- A database child process reuses the legacy query shape, but can survive a host crash and race receipt recovery with an orphan writer. Fixed worker threads preserve process-lifetime stopping while moving synchronous SQLite off main.

## Consequences

Amendments can replace an approval even for an additive requirement; progress questions must use queries. Interactive queues can remain occupied until original stopping or effects are verified. SQLite receipt recovery does not make the application and durable databases atomic. This change adds a fixed app-data worker bundle to build and package verification, without a new dependency, general SQL tool or executor database.

Offline regression suites, real isolated Linux browser/computer/process checks and real-model routing are separate acceptance evidence in #41. Raw execution, screenshots and credentials stay outside the repository. Capability acceptance applies to the verified combined source and enabled profile, rather than to the earlier file-focused milestone or a silently reduced production profile.
