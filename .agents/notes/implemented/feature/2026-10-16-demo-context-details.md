# Agent Note: Demo Context 分类详情

Status: implemented

## 问题

拥有者要求 Context 详情采用附件布局：顶部百分比及紧凑用量、中间分段条、下方三类用量。此前[环形入口决定](2026-10-16-demo-context-component.md)仅展示 Context 标题、总量和单色进度，无法表达分类。

## 决定

沿用现有 Hover Card／Progress 和无数字环形入口，仅替换详情内容。顶部为「% of context used」及约数用量／容量，下方按 System prompt、Tool definitions、Messages 列出灰、紫、蓝色块与约数；相同颜色用于进度条。Portal 仍受视口限宽，使用当前 Neutral 明暗配色，不新增操作或依赖。按后续批注，详情收紧至 280px 宽、12px 内边距／字号和区块间隔，分类行距 8px；入口按 start／-16px 偏移对齐弹层，使环形中心位于左侧约 30px，接近视口边缘时沿用原生碰撞避让。

保持 32,000／200,000 的模拟总量，补充 1,500 system 与 5,300 tool token，Messages 由已用总量扣除这两项得到，避免保存第二份合计。普通新会话和新工作区首个会话三类均归零；发送核实不改用量。分类仅为样例，不代表真实 prompt 或 provider 统计。

Progress 的 Indicator 沿用全宽平移，只给其可见末段设置分类渐变；色标起点加上未用比例，避免低用量时只露出最后一类颜色。详情内容提取为无状态渲染函数，便于单独检查 Portal 内数值、0 值和分类；不改官方原语。只有详情显示百分比，入口仍只显示灰色环。

## 备选方案

- 直接使用附件的 18.7K／1M 作为总量：更接近示例数字，但会改掉既有会话容量；本轮只调整布局并补齐分类样例。
- 增加第二层进度条组件或改官方 Progress：能直接按三段宽度排列，但增加重复原语；局部渐变即可沿用现有数值与无障碍语义。

## 后果

仅可变 demo 的详情、分类 fixture、两处新建初始化与对应检查受影响；正式 Desktop、后台和冻结稿不变。三类色块与分段条需要一起核对，0 用量仍显示三行零值且条带为空。工程与浏览器证据见[工单](../../../../.scratch/desktop-shadcn/issues/03-ai-elements-demo.md)，布局由拥有者审阅。
