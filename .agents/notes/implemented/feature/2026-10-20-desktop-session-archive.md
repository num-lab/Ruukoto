# Agent Note: 会话存档只影响列表可见性

Status: implemented

后续提案：[Desktop 应用内 Spotlight](../../proposed/feature/2026-10-21-desktop-spotlight-search.md)拟让已存档会话可被显式搜索并打开，保留存档标记；尚未改变本篇现行行为。

## 问题

工作区树把全部普通开发会话一直列在左栏，长期使用后旧会话与常用会话混在一起，列表越来越难扫。拥有者要的是「把这个会话收起来」的轻量操作，以及一个能找回来、能撤销的地方。

难点在「存档」这个词的边界：会话已经有明确的状态语义（任务状态机、排队暂停、SubAgent 与定时执行会话），再叠一层「已删除/已失效」会让执行、历史、授权与通知都要重新判定。

## 决定

`Session.archivedAt`（`null` = 未存档）是唯一的存档事实，存在 `sessions.archived_at`，随 `session.archive_changed` 事件提交；schema 升到 46，控制面协议升到 33。

- **只改列表可见性**：存档不改 `projectId`、`cwd`、历史文件、任务归属、排队状态或模型设置。工作区树过滤掉 `archivedAt !== null` 的会话，历史、任务、审批、通知与文件树全按会话 id 照常工作。
- **入口**：工作区会话行悬停或键盘聚焦时右侧浮现 `Archive` 键；点击即存档，并把该会话从顶部标签里关掉，免得列表与标签互相矛盾。
- **找回**：设置新增「已存档会话」分类，按存档时间倒序列出名称、所属工作区与存档日期，每行一个 `Archive` 图标 + 「取消存档」按钮。
- **谁不能存档**：只有 `dev` 与 `main` 会话可以存档。SubAgent、定时与工作流步骤会话属于宿主独立执行，隐藏后没有可见入口，运行时直接拒绝。
- **幂等与冲突**：同值重复调用不写事件；写入沿用 `withTx`，与事件同一事务提交。`setSessionArchived` 不要求会话空闲——运行中的任务继续跑，存档只影响它出现在哪。
- **分支沿用**：从已存档会话建分支时，分支继承 `archivedAt`，否则复制一份就重新出现在列表里。

## 备选方案

- **物理删除或归档历史文件**：会破坏「会话 JSONL 是消息历史唯一权威副本」与已提交会话不可删除的约定，也无法恢复；存档只是标记，取消即恢复。
- **用队列暂停表示「收起」**：暂停有明确的执行语义（阻止后续任务运行），拿来做可见性会让存档的会话真的不能继续工作。
- **存在 `meta` 键值里（不改 schema）**：存档是逐会话的行级事实，放在 meta JSON 里要整块读写、无法按会话索引，还会与快照里的 `sessions` 分家；拥有者已明确不需要兼容已有数据库，直接加列更简单。
- **在协议里只带事件、不带快照字段**：重连后客户端无从得知哪些会话已存档，必须在 `Session` 上暴露并进快照。

## 后果

列表可以保持精简，取消存档完全可逆，历史与执行语义不变。代价是 schema 升到 46：旧数据目录按既有纪律被新程序拒绝打开，需要新建档案；`Session` 多一个可空字段，所有字面构造（含测试夹具与 TUI 演示数据）都要补 `archivedAt`。存档状态只有布尔语义，时间戳仅用于排序与展示，不参与任何权限或一致性判断。存档登记随 `sessions` 行一起复制，跨实例导入后保持原可见性。
