# Agent Note: Code 设置按配置位置管理模型凭据

Status: implemented

显示名、唯一 ID 排序与真正新增模型的保存采用[非执行配置检查](../simplification/2026-10-25-configuration-checks.md)；本文其余配置来源、凭据、修订与旧任务选择约束继续适用。

[非执行配置检查](../simplification/2026-10-25-configuration-checks.md)放行显示名、模型排序和真实新增 ID；执行字段、内置覆盖、重复 ID 与引用校验仍保留。

## 问题

桌面只有会话模型选择，无法管理提供方目录与实例默认值。存储凭据删除后，SDK 仍可能回退到目录、环境或其他来源；把 auth.json 中条目不存在解释为「已无凭据」会误导拥有者。完整认证解析又可能展开环境模板、执行命令或刷新 OAuth，不能为打开设置而执行。

## 决定

Code 设置复用现有模型文件；在线修订核对、应用门闩、模型栈和重建回滚由 [RuntimeModels](../architecture/2026-10-23-runtime-models.md) 持有。Desktop 与 TUI 在线／离线列表共用 model-config 的纯元数据读取，列出存储条目类型、目录 apiKey 与具体 headers 位置；只在 SDK 能直接证明时列运行时覆盖，不把配置位置存在解释为认证有效。旧 configured 字段只表示存储条目存在。成员与真实 thinkingLevels 来自 SDK 注册信息；未知档位明确展示，不通过认证过滤或猜测档位。

存储 API Key 的保存／移除只作用于 auth.json 中所选提供方；OAuth 替换／移除明确说明不撤销远端令牌。目录秘密按 provider、model、modelOverrides 选定单字段修改，回写完整脱敏目录以保留其他高级配置与占位符。环境由后台启动环境维护，设置不修改进程环境。秘密提交后清空，待核实记录只保留操作、原实例与修订，不保存秘密正文。

设置表单自行保存读取修订、草稿及原提交，注册到已有导航保护。冲突保留草稿并读回当前值；应答丢失不自动重发，通过原实例只读核实位置，秘密内容与实际认证仍未验证。模型连接测试由用户点击直接执行，取消额外确认窗和成功提示；模型名旁黄、绿、红点分别表示未测试、成功、失败，失败详情保留在圆点提示中。结果仅属于原提供方、模型及配置修订，草稿变动或修订变化后回到未测试，不以旧成功代表新配置。实例默认值只影响后续会话，目录事件失效会话与新聊天菜单，旧分页不能覆盖新目录，运行时默认值也随事件读回。

总览直接展示后台默认模型、Effort 与摘要模型，选择即保存，模型选择框为 240px、Effort 为 80px，控制区右对齐；窄窗按内容宽度换行。添加与编辑提供方使用同一完整弹窗，连接、存储 Key、模型能力和高级目录秘密都在窗内编辑，API 类型从 SDK 支持项选择，已有自定义类型保留。新提供方内部标识自动生成，模型 ID 由拥有者填写；删除提供方按钮固定在左下角并用红色显示，保存位于右下角。普通说明、自动保存／保存中／草稿状态文案与默认保存成功提示按拥有者要求移除，OAuth 替换和移除后果、实际错误、冲突及未知结果仍可见。

提供方弹窗叉号直接放弃草稿并退出，不再要求先保存。已经发出的操作仍保留原 pending 与总览核实入口，关闭不会撤销已受理写入；若目录提交期间关闭，目录核实完成后不再继续保存存储 Key。目录和存储 Key 沿用两个已有修订操作：目录确有变化时先保存并成功读回，再用新修订提交本轮局部暂存的 Key；仅换 Key 时跳过目录。首步失败或结果未知立即停止，第二步失败明确保留目录已保存的事实，不回滚目录或自动重发，秘密须重新主动输入。

环境、运行时覆盖与凭据命令输出没有可靠的完整秘密字典；管理路径对 SDK／远端错误使用固定、可行动的诊断，保留安全错误码与回滚事实，不展示上游原始正文。目录对象重建与单字段编辑保留包括原型同名键在内的 JSON 自有字段，原值存在性只按自有属性判断，避免无关编辑丢请求头或引入继承值。

TUI 目录请求头同样使用遮蔽输入。一个编辑动作结束前暂存模型配置事件，保持打开编辑时的目录与修订；结束后统一失效并刷新。这样另一客户端在输入期间改成 OAuth 或修改目录时，原操作仍按旧修订冲突，不会被后台事件换成新修订后覆盖未经确认的来源。

## 既有笔记审计

按 desktop、模型配置、凭据与 model.config_changed 检索 proposed／implemented，未发现 rejected 同题决定。[设置管理提案](../../proposed/feature/2026-10-21-desktop-settings-management.md)部分落地于本篇，其余 Skills、MCP 与 Personal 保留提案；[设置容器](2026-10-21-desktop-settings-shell.md)继续持有导航与表单职责，不重复定义；[桌面定稿](../../implemented/architecture/2026-10-15-desktop-shadcn-demo.md)保留视觉依据，本篇扩展其模型管理能力。

## 备选方案

- 用 auth.json configured 作为认证状态最简单，但目录或环境回退仍可生效，无法表达操作实际范围。
- 列表调用 SDK 完整认证解析能获得更多当前信息，但会触发秘密命令、OAuth 刷新或网络；保留给执行及主动连接测试。
- 提供方和默认值分级进入详情能缩短单页，但默认／摘要只有一个设置，提供方字段又需要反复跳转；采用总览直接选择与同窗编辑，减少操作层级。
- 另建统一凭据存储可以归一来源，但会替代既有配置并扩大迁移与安全范围，现阶段没有必要。

## 后果

两个配置界面使用相同来源语义，避免凭据回退被误报为删除失败或提供方不可用。纯元数据不能证明环境与远端认证有效，主动测试仍有独立价值。验证使用隔离配置、模拟提供方和真实本机控制面；真实模型、Electron／MyGo 体验与退出重开仍需各自环境证据。
