# Agent Note: Coding 会话后台持有独立目录占用

Status: implemented

## 问题

普通 bash 在调用或 Task 结束时回收临时执行，开发服务无法供后续工具与下一拥有者轮访问。仅保留进程组会丢失启动、输出与恢复身份；沿原 Task 占用则会被终态或恢复队列误释放。

## 决定

Coding 为完全访问的真实普通开发输入开放 process_start/status/output/stop，后台归会话，独立于原 Task 和 Driver 临时 worker。普通 bash 保留前台语义，Plan、受限输入、子工作、工作流和内部汇总没有启动资格；普通拥有者的受限新轮仍可查询原记录和请求可信停止，不能继承完全访问浏览器。

启动先保存 starting，在串行工具边界核实临时 worker 和后代退出，再同事务将根占用从 task_id 转给 process_id、保存参考快照和当前轮 conversation 阶段。实际 launch 前只认领一次；恢复和重复原操作不派发命令。交接后 Task 终态、取消、agent_wait 和 resume_queue 都不能释放独立占用。首版同会话也须先停后台再写代码，保留单写入者；未曾 agent_wait 的新会话直接沿后台参考快照接纳观测轮，不重新加载工作目录指令、技能或 MCP。

后台观测阶段只开放本会话状态、日志、停止、提问及仍有效的完全访问浏览器；装配、发送前和实际调用共用该结论。观测身份保留到目录重新取得，避免后台刚停止便把 status 关闭而无法恢复业务工具。提问 pending 后只留无外部效果状态/日志，按原协议结束本轮。原后台来源或目录身份失效时登记停止，依赖失效参考的模型请求停止；改变会话默认模式不撤销原执行。

Linux 复用原 machine/boot/scope/InvocationID/cgroup dev/ino 身份与指纹，按已核实目录 FD 停止。macOS 监督器的持久模式保存机器、boot、证据目录 dev/ino、随机 token、指纹及 supervisor uniqueid/start/pidversion；恢复只用匹配身份的内核原子信号，受管执行和已确认后代停止、双管道 EOF 都成立才写私有成功停止回执。完全访问只对已核实范围判断未知孤儿：历史受管 PGID、SID 及已知成员 PID 形成保守拒绝集合，每次完整采样累计当前归属，根命令建立自身组和会话前不累计宿主范围；集合不用于发信号。这样浏览器另行创建的 daemon 不会被认作本执行未知后代；已纳管祖先换组或换会话后的普通子孙仍保持保守。受限旧模式继续全 UID 未知孤儿核实。监督器强杀且无回执保持 stop_unverified，不按裸 PID 补杀。完全访问不保证收回主动脱离执行单元的进程或外部服务。

独立 worker 复用 data/result 字节协议，启动回执、主命令退出、输出排空和整单元停止分别记录。主命令退出只保存 code/signal，不主动清理仍存活的后代；后台保留至显式停止或生命周期停止。stdout/stderr 合计最多16 MiB，短写继续写剩余部分，写失败或预算耗尽保存已捕获字节、标 partial 并停止。日志为私有普通文件，查询核实文件身份、长度及 SHA-256；32 KiB 页同时给文本和 base64，解码展示不改变原字节。缺输出排空证明或宿主崩溃保留 partial，停止不证明外部业务效果或回滚。

“结束本会话后台”以持久原请求键保存接纳事件水位和目标执行集合，拦住此前已接纳但尚未交接的启动；重取原请求不扩大到后来新启动。关闭窗口、存档、切会话与断开不执行停止。客户端发送前保存键，未知结果只查状态，由拥有者显式重核原键；原目录不可读或记录损坏时不能新建关闭键。查询代次只筛除过期查询，停止/结束应答按原会话和实例核对，实时状态刷新不能丢掉动作结果，旧会话迟到应答不能污染新会话。应用关闭收齐原执行；重启只核实停止，不恢复服务。

schema49、控制协议37继续精确版本拒绝，旧档案保留供匹配版本查阅。协议37同时包含[桌面搜索](2026-10-21-desktop-spotlight-search.md)、持久提问与会话后台，避免只具备其中一侧能力的客户端或后台以相同版本握手。含后台记录或关闭屏障的离线导入明确拒绝，不丢事实后启用。SQLite 状态与事件同事务，日志、平台证据和会话 JSONL 不宣称跨文件原子。

## 既有笔记审计

[个人会话后台](2026-10-21-personal-background-processes.md)另建durable记录与主/子/定时来源门禁，共用本篇的低层执行、日志和停止原语；不复用Coding业务Store。

部分落实[后台生命周期提案](../../proposed/feature/2026-10-14-bash-background-lifecycle.md)的 Coding 切片，个人 durable 接入仍为提案。保留[完全访问](2026-10-12-full-access-current-account.md)的账户信任和脱离回收限制、[停止未核实保留](../bug-fix/2026-10-11-preserve-unverified-worker-stop.md)的事实传播、[等待与报告](../architecture/2026-10-14-agent-wait-and-report-ownership.md)的参考快照和原 Task 让出，以及[Linux 持久身份](../architecture/2026-10-17-native-linux-execution-identity.md)原语；本篇扩展会话独立占用和浏览器观测，不取代它们的其他决定。检索未发现可完全吸收或需要归档的同类记录。

## 备选方案

- 删除普通 bash 收尾回收：改动少，但继承管道会卡住调用，Task 终态仍丢进程归属，恢复也没有可信身份，因此保留前台并新增显式工具。
- 复用原 Task 键或后台与前台共占用：可少改查询并支持热更新，但终态/恢复会误释放，任意 Shell 不能证明同目录单写入者；拥有者确认首版先停后改。
- 统一重写跨平台执行框架：接口看似一致，但 Linux 已有可核实原语，macOS 已有身份监督器；按平台补持久模式并复用协议更小，避免改旧执行边界。
- 重试丢答时新建关闭请求：客户端代码少，但会误停原关闭之后的新执行；保留原目标集合和稳定键，显式重核原请求。

## 后果

后台服务可跨工具与拥有者消息存活，单写入者、停止证据和恢复零重放继续成立。代价是停止未核实时会持续占用目录，macOS 无监督器回执不能自动解除；日志保留没有全局磁盘配额。真实平台、离线故障注入、独立审查及真实模型/浏览器/客户端的覆盖范围由[有效工单](../../../../.scratch/agent-tool-completion/issues/03-coding-background-processes.md)和证据持有，不以静态检查或退出码声称业务成功。个人接入不在本切片内。
