# Agent Note: Personal 三类设置保留原档案与维护关联

Status: implemented

## 问题

[设置管理规划](../../proposed/feature/2026-10-21-desktop-settings-management.md)覆盖两端，但 Code 的提供方目录、工作区、凭据存储和本机选择器不能套用到 Personal。新 [SSH 管理连接](2026-10-21-personal-settings-ssh.md)与旧个人聊天的快照、在线状态和实例身份也无对应关系。

## 决定

三页沿现有分类浮窗与 Code / PA 页签，使用同一 Host 的受限设置入口；每页打开查询远端档案，同一控制器已有读取时共享该查询，以返回的 profile 钉定归属，不以旧聊天连接判定在线或使管理请求失效。页面内草稿只存内存；导航沿[容器保护](2026-10-21-desktop-settings-shell.md)，迟到应答由本页轮次丢弃，返回其他档案的应答拒绝安装。只复用已有 UI 原语、样式与两端相同的安全技能正文渲染，不建立配置 provider。

模型只编辑实际单模型字段与环境变量引用，前端按原解析器定位字段错误；显式测试独立联网，编辑后丢弃旧测试结论。Skills 区分外部库配置修订与托管清单修订；远端目录逐层选择与预览，导入身份由程序取得，外部来源只读，逻辑移除保留包与旧引用。MCP 使用真实单服务字段、显式匿名或远端私有凭据文件；原允许列表先分页取得完整工具定义，不把摘要列表写回。工具只选择是否允许，不伪造 Code 的副作用分类；远端标注不免审批。旧配置迁入单独确认，迁入前不允许新增无法表示停用状态的服务。Host 前检按一项配置读取，MCP 服务及完整工具按小页读取，避免合法大配置在分页开始前就撞响应限额。

每项配置写入先展示作用范围与影响，由拥有者选择停止、保存并启动。容器的保存并继续保留原导航，暂隐藏离开确认并展示维护确认；只有保存与启动核实成功后完成原导航，取消则回到原离开选择。实际预检、停止核实、锁内保存与恢复由 Host 负责；忙时只展示待处理事项，不取消工作。已保存未启动与未知结果保留 pending，页面只能读取原配置、显式恢复原服务或结束人工核实，不重新提交。只读、离线、缺凭据、配置冲突都保留可比较草稿。

[机器入口](2026-10-21-personal-settings.md)的托管变更补齐统一 saved/target 回执；原清单已经提交时 Host 能继续原维护流程，仍不将配置保存当作模型或 MCP 测试通过。个人聊天继续使用 IM 与 CLI，设置连通不宣称新桌面聊天可用。[Cua管理](../../implemented/architecture/2026-10-23-cua-official-mcp.md)补充固定沙箱选择与在线暂停／恢复，电脑控制不走配置停存启。

## 既有笔记审计

按 Personal、设置、SSH、Skills、MCP 检索 active notes；上述规划、容器、SSH、机器入口与[托管技能](2026-10-21-managed-skills.md)、[Code Skills](2026-10-21-desktop-code-skills.md)部分重叠，各自保留原协议、存储和运行约束，本篇只持有 Personal 页面接线。个人基础、技能历史与 MCP 笔记继续持有旧引用和审批语义；其余聊天与通用渐进交互记录不变。没有完全吸收或需要归档的笔记。

## 备选方案

- 将 Personal 转成 Code 的配置 provider：能共享表单和状态，但会伪造目录、工作区、凭据与热保存能力，选择独立真实字段与共同展示原语。
- 沿用旧 Personal 在线状态：不用额外读取，但两套控制协议与身份不同，会让未接入的旧聊天屏蔽有效管理连接，选择管理 Host 返回的原档案事实。
- 保存时自动停机：交互更短，但拥有者看不到运行影响，也无法区分保存与测试，选择显式维护确认和可继续的恢复动作。

## 后果

两壳通过共用 Host 管理三类真实配置，不增加桥方法、依赖或本机秘密存储。代价是 Personal 单项写入仍需受支持的原系统服务与环境，维护期间不能切走；未知结果需人工比较，不承诺自动恢复草稿或回滚。自动化状态、协议与浏览器替身只能证明工程行为，真实 Linux 固定服务、真实凭据和原生双壳产品体验由工单保留验收缺口。
