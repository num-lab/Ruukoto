# Agent Note: Coding 以 wait 统一等待入口

Status: implemented

## 问题

`agent_wait` 已等待 SubAgent 任务与工作流，不能等待独立会话后台。拥有者要求以通用 `wait` 取代专属名称，覆盖三类后台工作。

## 决定

模型只装配 `wait`。参数为同来源 task／workflow 的目标数组，或单个 process 目标；默认60秒、上限300秒。任务与工作流沿原持久等待、目录让出和报告认领，不改内部类型或表名。历史 JSONL、账本与导入继续识别 `agent_wait`，旧等待仍为 no_effect，不能因改名把恢复事实改成未知效果。

进程等待复用本会话后台记录，先订阅提交后事件再查询，反复核对任务活动、权限版本与取消；finally 清理计时器、订阅及活动等待。可信新输入提交后同时能中断进程等待，沿原 Driver 停止路径结束父轮，目标后台不受级联影响。

进程 stopped 且 stopVerified 返回 result；stop_unverified 返回 attention。主命令正常退出且尚未登记停止意图时立即返回 attention=command_exited，保留退出码与 stopVerified=false，指引 process_stop 后再 wait；不把主进程退出当作后代已停止，不由等待暗中杀进程。已登记停止意图则继续等待停止证明。超时和中断不释放后台占用；已无活动后台且当前轮未中断时，经过原 restoreWorkspace 取得目录才恢复业务工具。

进程结果使用相同 reason／targets 结构但不含报告权，只有 task／workflow 可消费旧持久报告；同一任务复用 SDK call ID 不能让进程结果冒充旧任务结果。进程等待不新建持久等待表，重启沿原工具与任务中断恢复，不重放工作。

## 既有笔记审计

按 agent_wait、后台等待检索 proposed／implemented／rejected。部分取代[等待与报告归属](../architecture/2026-10-14-agent-wait-and-report-ownership.md)的模型工具名称，保留持久状态与来源规则；补充[会话后台](2026-10-21-coding-background-processes.md)的只读等待入口，独立占用和停止证明不变。个人后台提案与本次 Code 范围无关，保留。

## 备选方案

- 将 process 加入旧 AgentWaitTarget 和报告表：能混合任意目标，但后台没有原工作流报告权，扩大导入、恢复及汇总契约；本次在工具入口统一分派。
- 只改名并轮询 process_status：可以查询状态，但仍让模型重复请求，且不能及时打断父轮；使用已有事件通知。
- 主命令退出就自动停止后代：较快产生 stopped，但可能杀掉仍工作的服务；等待只返回真实事实，停止由显式动作触发。

## 后果

模型使用一个等待工具，原后台生命周期与唯一报告机制保持；进程与其他目标不能混在一次调用。真实 macOS 短命令、新输入与取消、权限和跨会话负例，以及旧 JSONL／新进程结果同 call ID 的恢复由定向测试覆盖。Linux、真实模型与最终组合证据见[工单](../../../../.scratch/agent-tools-next/issues/01-code-tools.md)。
