# Agent Note: One Coding wait entry for tasks, workflows and processes

Status: implemented

## Problem

`agent_wait` handled SubAgent tasks/workflows but not independent session backgrounds. The owner requested a general `wait` covering all three.

## Decision

Models receive only `wait`. Accept an array of same-source task/workflow targets or one process target, default 60 seconds and maximum 300. Tasks/workflows retain durable waits, workspace yielding and report claims without renaming internal types/tables. Historical JSONL/ledger/import still recognize `agent_wait`; old waits remain `no_effect`, not unknown effects due to renaming.

Process waits reuse session background records, subscribing to post-commit events before querying. Recheck task activity, permission revision and cancellation; finally clear timers/subscriptions/active wait. Committed trusted new input interrupts via existing Driver stop, ending the parent turn without cascading to the background target.

`stopped` plus `stopVerified` returns result; `stop_unverified` returns attention. Normal main-command exit without recorded stop intent immediately returns `attention=command_exited`, preserving exit code and `stopVerified=false` and directing explicit process_stop then wait. Main exit is not descendant-stop proof and wait never secretly kills. With stop intent, continue waiting for evidence. Timeout/interruption retains background occupation. Once no active background remains and the current turn is not interrupted, original restoreWorkspace must reacquire the directory before business tools resume.

Process results share reason/targets shape but no report entitlement; only tasks/workflows consume durable reports. Reusing SDK call IDs cannot make a process result appear to be an old task result. No process-wait table is added; restart follows existing tool/task interruption recovery without replay.

This changes the model-facing name in [wait/report ownership](../architecture/2026-10-14-agent-wait-and-report-ownership.md), not its durable/source contract, and adds read-only waiting to [session backgrounds](2026-10-21-coding-background-processes.md) without changing occupation/stop evidence.

## Alternatives considered

- Adding processes to AgentWaitTarget/report tables permits arbitrary mixing but expands import/recovery/report contracts for work without report rights.
- Renaming then polling process_status still makes repeated model calls and cannot promptly interrupt the parent; use events.
- Auto-stopping descendants on main exit produces stopped sooner but may kill ongoing services. Waiting reports facts; explicit actions stop.

## Consequences

One model tool preserves original lifecycles/report uniqueness, but processes cannot mix with other targets in one call. Targeted tests cover real macOS short commands, input/cancel, permissions/cross-session negatives and old JSONL/new-process same-call-ID recovery. Historical Linux/model/combined evidence remains in the offline Code tools work item.
