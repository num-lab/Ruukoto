# Agent Note: Apply the Desktop visual reference to live controls

Status: implemented

[Single-product cutover](../architecture/2026-11-10-single-product.md) supersedes this note’s Personal, dual-product and legacy-import scope. Retained software-work constraints below remain active; retired-product mechanisms and evidence are historical, not current commands, compatibility requirements or acceptance passes.

## Problem

The owner selected the PA remote visual preview as the Desktop reference. It includes simpler settings surfaces, a visible connection path, larger conversation controls and a single Scheduled form, but its actions and data are simulated. Copying its application wholesale would replace current requests, recovery and attachment behavior with fixtures.

## Decision

Port the visual composition onto existing renderer components and state owners. This partially supersedes the navigation, native settings Select and dialog dimensions in [settings demo design](2026-10-28-desktop-settings-demo-design.md), the segmented control in [Effort slider](2026-10-24-desktop-effort-slider.md), and the four-step form in [Scheduled interface](2026-11-01-desktop-scheduled-interface.md). Their state ownership, configuration scopes, run history and recovery rules remain. [Settings shell](2026-10-21-desktop-settings-shell.md), [computer and Web Search](2026-10-25-desktop-computer-websearch-settings.md) and [Personal direct saving](../../archived/simplification/2026-10-28-desktop-personal-direct-save.md) continue to own the corresponding operations.

Desktop navigation groups appearance, local computer, Web Search, PA remote connection and archives. Code and PA retain their own model, Skills and MCP entries; PA also retains its supported remote computer page. Settings use borderless cards, full-width content, primary add actions and keyboard-accessible whole-row disclosure. The modal stays below the macOS title area, with a maximum 1120 by 760 size and independent navigation/content scrolling. Portaled Select menus reuse installed Radix primitives and settings tokens. Every business value receives the same prefix at the primitive boundary so a selectable empty value such as Custom remains distinct and reversible.

The PA connection page separates address, pairing and maintenance, retaining default permissions and legacy verification. The diagram represents the configured Tailscale path, not an independent Tailscale diagnostic. A healthy connection requires online transport and backend identity matching the saved origin, remote ID and profile ID/directory. Unverified operations and reconnecting never show success. Unsubmitted address edits do not replace the diagram's saved target; a rejected maintenance action does not declare a healthy original connection broken.

Provider, MCP and computer add forms edit real drafts. Saving, unknown outcomes and rereading remain under their original state owners; settings omit persistent refresh controls. Pages read on entry, and read failures or unknown/conflicting operations expose only their retry or original-outcome verification actions so a lost write response cannot trap the user behind a disabled Back action. Personal computer/call status is loaded after its configuration read, including cached page reopening. New computer drafts retain their computer type through reread and discard. Web Search presents an editable single credential row but never reconstructs a secret from a mask; CLI-owned bindings remain read-only and removal retains confirmation.

The main window reuses existing Search, tab ordering, inspector, process and question actions under the reference's geometry. The sidebar toggle stays at x=84 beside the native traffic lights in both states, partially superseding the moving endpoint in [continuous sidebar-toggle motion](../bug-fix/2026-10-17-desktop-sidebar-toggle.md). It remains the final permanent sibling after the native drag regions, retaining focus and hit testing. Both sidebar toggles use 26px controls and 17px icons. The four top navigation actions and Settings move continuously between their expanded and collapsed insets; labels fade and slide while the stable controls remain reachable. Sidebar and tab attention markers represent effective pending approvals or pending owner questions in that session; ordinary task activity does not need an amber marker. MessageScroller viewports use the common scrollbar styling, with native `scrollbar-width: auto` so Chromium does not replace the shared WebKit thumb rules; automatic scrolling retains the primitive's temporary hiding behavior. MyGo exposes the native sidebar material through its transparent frontend WebView and uses a transparent native root during loading and resizing. The right inspector starts collapsed at every window width; explicit toggles and opening content retain their existing behavior. Conversation and inspector tabs retain drag ordering with the normal hover cursor. Context retains its numberless ring and category details, opens on click through Popover and uses a circular hover background. Queue pause/count prose is absent. With no active task, a nonempty paused queue and an empty draft, the existing send button shows Play and resumes through the original model and stopping confirmations. Text or attachments restore ArrowUp and submit an ordinary queued Task without resuming; active execution retains Stop. There is no separate resume button, and an empty paused queue remains paused until new input is queued and explicitly resumed. Personal starts with a one-line composer and expands for wrapped text or attachments. The dedicated attachment-failure notice and its retry/discard buttons are absent; Plus still reselects attachments, and failed drafts remain blocked until that preparation succeeds. Removing attachment chips or editing text does not clear the persisted failure. Model effort uses a keyboard-operable range over the selected model's actual supported levels. Pointer movement previews locally and release submits once; cancellation, window focus loss or a changed model, supported levels or availability invalidates that gesture. The native range owns pointer tracking: explicit pointer capture blocks WebKit's native thumb dragging, while native tracking retains release events outside the range and window. Keyboard changes retain the original guarded write. Scheduled uses one form with the existing validation and original-request lifecycle; visual simplification does not relax workspace, rule, model, permission or conflict checks. PA bubble motion follows a visible live arrival rather than component mounting, partially superseding the mount-triggered animation in [Personal message layout](../../archived/feature/2026-11-01-desktop-personal-message-bubbles.md). PersonalState grants one animation for a new local send or a completed live message; snapshot/history reads and arrivals while the page is hidden do not grant one. The renderer consumes that opportunity after commit, including under reduced motion, so remounts cannot replay it. A local display key follows the request into canonical history without using text matching; unresolved canonical request identity defers its animation until association is known. The existing Personal message layout retains history and message semantics; actual input measurement supplies the new pill/expanded geometry. No fictional workflow graph, terminal output or context usage category is introduced.

## Alternatives considered

Copying the preview would provide exact static appearance quickly but discard current backend and recovery behavior. Port only the rendered structure and final styles, eliminating the preview's repeated override layers. Limiting the work to the PA settings page would be smaller but omit the owner's selected main-window and settings interactions. Removing every read action would reduce controls further but prevent inspection of an unresolved submission; retain exception-only verification. Keeping hover-open Context would reuse the earlier primitive but conflicts with the owner's click-only follow-up. A separate queue resume control permits immediate recovery of empty paused queues but adds an action the owner explicitly removed; the send button uses the draft and queued work to select its action. Merging both computer pages under a new target selector would match the preview's navigation count, but introduce unnecessary target and draft switching; retain the supported PA entry.

## Consequences

The visual reference governs layout while current backend facts govern controls, errors and availability. Additional permissions, remote computer management and recovery actions remain visible when relevant, so the production interface intentionally contains capabilities absent from the static preview. The earlier frozen demo remains intact, with shared primitives and retained behavior checks; its complete stylesheet prefix no longer constrains the revised production layout. Focused state/render tests and controlled browser interaction establish renderer evidence; actual macOS hosts, credentials and remote-server operations require their own acceptance. Work and evidence are tracked in [Issue 54](https://github.com/num-lab/Ruukoto/issues/54).
