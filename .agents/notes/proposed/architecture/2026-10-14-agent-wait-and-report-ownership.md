# Agent Note: 等待让出执行资源并固定结果回报归属

Status: proposed

## 问题

模型发起 SubAgent 或工作流后只有查询与结束当前对话，拥有者难以判断是否仍在工作。现有父任务持有目录至终态，工作流准备、冻结和汇总也需要该目录；直接阻塞等待会互等。最终汇总排在来源会话 FIFO，等 reported 会卡住，而等运行终态后让父轮总结又会与独立汇总重复。

内部 `[工作流最终回报]` 经普通 Task.input/sdk.prompt 进入历史，被 TUI 显示为用户输入，还进入输入框历史与置顶要求。隐藏这条提示必须与保留模型输入及最终总结同时成立。

## 方案

两个产品共享宿主 `agent_wait`，固定一个或多个任务/运行目标，采用提交后事件加持久查询；任一可消费结果、需人工介入、超时或可信新输入中断时返回事实。SubAgent 等本次任务，不等身份关闭；工作流区分终态、停止核实与送达。完整规则见[计划第二节](../../../../.scratch/agent-workflow/experience-plan.md#二等待工具与调度)。

Driver 在工具安全边界禁止并行执行，核实受管执行停止后让出占用，恢复工作目录访问前重新取得目录并核实权限、身份和资料。新输入成功入队后撤销旧等待资格，后台工作按原授权继续；不启动两个同会话 Driver。重启中断旧等待，依据持久事实补送结果，不自动重放业务工具。

子任务仍持目录时，新消息及需人工介入不能等整目录空闲才处理。Runtime/Driver 增加内部对话阶段，仅装配已记录且仍获授权的输入快照，不访问工作目录、不启动 worker；等待与宿主查询使用显式允许清单，其余工具默认禁用，业务执行前再取得目录。阶段、工具集合及模型说明可重建，不新增拥有者访问模式。普通 dev 当前只在下一轮注入子结果，曾被等待覆盖的目标因此另存自动补报资格，结果晚于新输入轮结束也能按原键补建汇总，未等待过的普通委派不扩范围。

结果消费与最终报告认领独立持久化，工作流按 runId/terminalVersion 仲裁。活动父轮可以认领结果、继续处理并完成一次总结；原独立汇总是无有效认领时的后备。不能把普通父任务写进 `delivery.taskId`，因为该字段还界定无工具汇总身份。已排队汇总转交与父等待认领须 CAS，已开始或完成的报告不授予第二份报告权；中断/失败/重启按记录释放未完成认领并核实已落盘回复，不能直接再生成或重发。

先保存工具结果与消息标记，再在模型实际接受该结果时记消费；SQLite 与 JSONL 不宣称原子，恢复按标记补记。普通 dev 注入、main 唤醒和 workflow 汇总复用同一消费/归属事实。多个目标的一份父总结映射到多个运行，只登记一份该轮外发；IM/调度继续核实原来源、代次与发送键，失败或未知发送不自动重发。

多目标及同父轮的后续认领限同原始发起任务/事件、原回复目标代次，定时来源同调度运行，跨来源整批拒绝。已消费来源与依赖闭包独立绑定父轮，后续每次模型请求和实际外发持续重核，不因父轮不是无工具汇总身份而漏检。普通 owner_reply 与认领报告在结果事务合并到一份 outbox，保留原事件关联，不由两个终态回调各发一次。

内部汇总输入按现有持久任务绑定派生展示分类，新建的普通子任务补报则使用其持久补报资格；分类随任务与历史页返回，普通聊天、↑ 历史和置顶要求统一过滤。旧 JSONL 保留原文，分支沿可信任务来源继承分类；不能按标题、请求键前缀或客户端事件到达次序决定隐藏。

## 既有笔记审计

部分取代[工作流业务回答与最终送达](../../implemented/feature/2026-10-13-workflow-owner-input-and-delivery.md)中的无条件独立汇总路径，保留唯一最终回报、来源复核与 outbox 不重发。[工作流总决定](../../implemented/feature/2026-10-12-agent-workflows.md)的后台运行和主聊天可继续仍有效。[委派模型](../../implemented/architecture/2026-10-03-work-delegation-subagent-task.md)与[SubAgent 复用](../../implemented/feature/2026-10-04-subagent-reuse-close.md)部分重叠，继续区分任务、Agent 和工作。[完整历史](../../implemented/architecture/2026-09-19-preserve-session-history.md)仍有效，只改可信展示投影；其余原生执行、重启、占用笔记不降低约束。检索未发现可直接复用的模型等待提案，无完全吸收或删除。

## 备选方案

- 普通 Promise 等待、定时轮询状态：工具代码少；父目录会阻止子执行，SDK abort 也可能卡住，不能满足修改工作流与新输入打断。
- 让出父轮后只等原独立汇总通知：最贴近现有送达机制；拥有者 Q8 确认主 Agent 要在等待返回后继续检查与后续步骤，不能用单纯通知代替。
- 把原汇总 taskId 改成父任务，或并发启动同会话汇总 Driver：可少建一类记录；前者混淆权限身份及外发归属，后者破坏单写入者和 FIFO，因此用独立报告认领。
- 直接切 SDK display:false 的 custom_message：SDK 原生支持隐藏；当前历史读取、检索与上下文分组只完整支持普通消息，需要更大存储/上下文改造，仅修展示分类更小。
- 仅用提示词禁止重复总结：改动少；无法解决崩溃、认领竞争及多来源外发，不作为唯一性保证。

## 验收标准

[09](../../../../.scratch/agent-workflow/issues/09-internal-report-visibility.md)证明可信隐藏与完整历史；[10](../../../../.scratch/agent-workflow/issues/10-agent-wait.md)先证明真实目录让出、输入竞争和报告仲裁，再实现全路径。测试覆盖非 Git 修改、原生/完全访问停止、权限变化、待人工且仍有分支、等待超时、先完成后订阅、完成与新输入同到、父轮失败及重启补记；旧父注入与最终汇总不得重复消费或发送。

## 风险

这是任务生命周期、执行边界和送达格式的改动，不能以新增工具 schema 作为完成标准。会话 JSONL 与核心库有崩溃窗口，报告已生成但关联缺失时必须核实原文，未知状态可见。资源释放或恢复证明不足会造成并发写或停住工作；机制验证是实施首项，并要求独立复核。需要 schema/协议变更时同步导入与严格版本兼容，不暗中重写旧记录。
