# Agent Note: 执行单元的停止未核实结果保留到任务收尾

Status: proposed

## 问题

[工单 27](../../../../.scratch/agent-direction/issues/27-preserve-unverified-worker-stop.md)核实：ready 失败丢弃 stop 结果，重复 stop 因句柄清空返回成功，Driver 清空登记且部分终态先于回收，worktree 临时 worker 没有登记。这些路径把“退出未核实”转换为可释放目录占用，与[工具工作进程](../../implemented/architecture/2026-09-20-tool-worker-per-task-container.md)既有约定冲突，也使[原生沙箱](../architecture/2026-10-10-native-execution-sandbox.md)的 macOS 残留报告失去依据。

## 方案

一个执行单元从 launch 到 ready/init、调用及停止保留同一份宿主记录。记录区分尚未创建单元、已创建且退出已核实、已创建但退出未核实；通信句柄为空不代表退出。并发和重复停止共享一次停止 Promise 及最终结论；停止异常归为未核实，同时保留用于诊断的 code 与原因，不自动重试成成功。

任务登记先于异步启动，每次启动有独立身份。starting 与实际单元引用同一结论，ready 失败和迟到成功均不能逃离取消路径。launcher 如果产生单元后再失败，必须保留可回收身份；只有能证明没有创建单元的拒绝才是无需回收。

Driver 聚合全部受管单元的结果，单个失败不阻断其余清理。所有自然、异常、取消与切换收尾先等待聚合，再经现有 `Store.endTask` 决定占用；未核实记录不能因清空 registry 丢失。终态、`task.tool_process_unreaped` 与占用在同一事务内处理。任务结果与退出核实是两个事实：已收到的结果保留，效果未知的操作不重放。

worktree 创建和汇总由实际发起的父任务持有临时执行记录；Runtime 经注入回调连接 Driver registry，`WorkCopyManager` 只传递归属和结果，不承担第二套任务调度。Git 返回成功也必须核实停止后才允许继续依赖该执行的工作；失败保留父目录占用与副本现场。拥有者沿现有核实恢复入口释放遗留占用。

`killProcessGroup` 核实原进程组，不能只看主 PID。它不证明脱离组的后代退出；平台级后代回收仍归原生沙箱提案，本修复不把 local 提升为隔离后端。

## 既有笔记审计

- 工具工作进程笔记：部分重叠，保留其后端与占用规则，本篇补停止事实的传递和时序，互链。
- 原生沙箱提案：部分重叠，本篇提供其所依赖的未核实传播；平台策略、macOS 裁定与真实边界验收仍归原篇，互链。
- 检索命中的 worktree、改动汇总、SubAgent 重启恢复、取消工作、显式访问模式及长期授权笔记：与本篇的停止记录选择无关；既有归属、成果保留、恢复和批准语义作为约束沿用，不取代原决定。

## 备选方案

- 只在 `ToolWorkerHost.stop` 缓存 boolean：改动最小，能修重复调用；不能保住 start rejected、Driver 忽略结果与临时 worker 未登记，因此不足以阻止误释放。
- 每个 stop 调用重新尝试、句柄消失即成功：容易沿用现有清理代码，也可能回收瞬时故障后的进程；但没有持久身份和整单元证据时会把未知改成成功，重复清理还可能竞争，故不选。
- 给临时 worker 另建独立管理器：Runtime 可以自行覆盖后台停止；但它仍需参与父任务取消、模式变化和占用终态，形成两套生命周期。传递父任务身份并复用登记即可覆盖，故不选。

## 验收标准

工单 27 的可控 launcher、任务终态、模式切换及临时 worktree 用例全部通过；并发/重复 stop 保留相同结论，false/异常留下占用和事件，同目录新任务不能启动。真实同组进程用心跳验证主 PID 先退出时仍回收后代。模拟结论与真实容器/systemd/native 证据分别记录。

## 风险

保守保留会让暂时无法核实的执行阻塞目录，拥有者需要确认后恢复；这是避免残留进程与新任务并发写入的代价。缓存核实结果不替代后端的真实停止能力，跨后台重启仍依赖已有持久占用恢复，不能仅靠内存登记证明旧进程退出。
