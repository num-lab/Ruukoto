# Agent Note: 用共享宿主工具接入有会话归属的 agent-browser

Status: proposed

## 问题

两个产品的主 Agent 需要直接打开网站、操作并看截图，也要复用已有登录态。main 没有 bash/MCP；普通开发会话的 bash 每次结束回收原进程组，Driver 按任务清理 registry。只安装 CLI 和 skill 不能覆盖 main，也不能保证跨轮保留页面、核实取消结果及退出时保留拥有者窗口。

已确认范围与实施步骤见[工单](../../../../.scratch/agent-browser/issues/01-integrate-agent-browser.md)，版本与源码事实见[调查](../../../../.scratch/agent-browser/research.md)。本篇尚未实现，受管路线必须先用真实探针验证。

## 方案

共享 browser 宿主工具族内部调用固定版本 agent-browser CLI；Runtime 持有按 Ruukoto 会话分区的浏览器管理器，任务只认领当前调用。首版仅开放完全访问的拥有者 main / 普通开发会话，类别、任务收窄、发送前检查及调用门共同约束身份和有效模式；main 不因此获得 bash 或通用本地 MCP。

工具使用类型化网页动作、上游 snapshot 元素引用和参数数组；可执行程序、配置来源、namespace、profile、截图目录由宿主控制。只覆盖导航、常见表单交互、标签切换、截图和生命周期，避免把 CLI 管理参数变成模型可覆盖的进程配置。

独立浏览器按产品档案和会话隔离 profile/socket/会话名，跨任务保留进程；默认空闲 60 分钟回收并保留 profile，拥有者已在 Q15 确认。附接只连接本机显式目标或人工允许的 Chrome 调试入口，Cookie 属于被接管浏览器，不能宣称独立资料隔离；同一浏览器一次只给一个 Ruukoto 会话自动化。退出关闭自有浏览器，对附接仅断开，保留用户窗口和标签。

绑定、代次、进程身份与停止结论需跨后台重启可查，状态和事件沿 core 同事务保存；Chromium profile 文件不参与该原子承诺。重启不重放工具或恢复原页面，后续新任务使用保留的登录资料打开。停止未核实则保持不可用，不能另起实例并声称旧执行结束。

人工登录复用有头窗口、Chrome 调试授权或官方 dashboard；Linux 经 SSH loopback 转发。人工操作期间暂停自动化，新消息再继续，密码不经过模型输入。dashboard 的实例选择、端口与会话隔离须实测，不纳入其额外模型聊天功能。

截图用现有 ArtifactStore 保存不可变原图并登记工具产物引用，视觉块走既有 JSONL/prompt 快照链路，实际模型输入可重建。落盘失败、超限和纯文本模型明确报告。现有 read-artifact CLI 只有单片输出，增加完整文件导出时复用分页协议、校验完整字节数与图片哈希，保留既有切片语义。

完全访问沿用当前账户和免操作审批，仍复核任务、权限版本、目标和绑定代次。点击/提交发出后无法核实效果时记 `effect_unknown`，不重发；导航也可触发网页副作用，不能按名字当作只读。网页内容作为工具资料记录，不成为改变浏览器配置的授权。

### 先行技术前提

原版 v0.39.0 的 `send_command` 在响应丢失等情况下重发完整命令，daemon 未见按 ID 去重，MCP 走相同 CLI，也未找到关闭重试的公开选项。因此该未经修复的路线不能满足不重放效果未知操作的契约；宿主只调用一次或记录未知效果均不足以补救。

官方 [PR #2085](https://github.com/vercel-labs/agent-browser/pull/2085) 已合入，调查时尚未进入正式 release。拥有者在 Q13–Q14 选择等待正式发布，不维护补丁、不自行构建未发布提交。先做准备和生命周期调查；包含修复的正式 release 发布后重新固定版本与校验值，在命令执行后丢弃响应，核实提交一次且返回结果未知，才可进入功能接入。导航、点击、填写与提交同属需等待的状态变化，不能靠改称只读绕过版本前置。

普通 CLI 还可因配置指纹或连接失败重建 daemon 并脱离原进程组，内部前台入口不足以保证宿主受管。阶段 0 必须在两平台核实会话复用、停止身份、崩溃恢复、附接断开、跨产品占用和人工登录；无法成立就退回本提案重新选路，不复制私有指纹算法或牺牲附接不关窗要求。

交付版本使用包含修复的官方 release 原生二进制及校验值，保持 Ruukoto Node 22/24 矩阵；v0.39.0 仅作为调查与重发反例基线。不能把上游 npm 的 Node >=24 声明视为已兼容；依赖由拥有者准备，模型任务不自动安装或提权。

## 备选方案

官方 CLI + skill 最省代码，能直接服务完全访问的普通开发会话；但不能覆盖 main 直接调用、跨轮归属和附接停止，补齐仍需宿主接入，故不足以完成本需求。

官方 stdio MCP 可复用工具定义与截图图片块；但仓库只接远程 HTTP，main 不开放 MCP。扩通用 stdio 还需改存储、配置入口、进程权限与生命周期、图片整形，且官方 MCP 内部仍调用 CLI，不能消除 daemon 问题。当前只需浏览器，选专属宿主工具；出现多个本地 MCP 服务需求时再讨论通用传输。

每任务新建和关闭浏览器最贴近现有 registry，停止与隔离简单；但违背跨轮继续页面要求，仅保存 Cookie 也不能保留当时页面，因此将浏览器生命周期与任务调用分开。

维护一个只修重发的最小上游补丁可以保留完整目标而不等待发布；直接构建官方修复提交甚至不需要自有补丁。但两者都增加构建与版本维护，拥有者在 Q13–Q14 选择官方正式 release，所以当前只推进准备，功能交付等待发版及真实探针，不削减原定操作能力。

## 验收标准

- 两个产品主入口在完全访问完成受控网页流程；受限、Plan、SubAgent、scheduled、workflow 未被顺带开放，模式变化不可旁路。
- macOS/Linux 真实浏览器两轮延续页面；profile 跨关闭保留登录；两会话独立；冷恢复不重放提交，停止未核实可见。
- 附接断开不关用户窗口/标签，重复接管拒绝；Linux 官方人工入口完成登录、暂停、继续。
- 提交后丢响应的服务端计数保持一次，断线/取消记未知效果；未发出记已知未执行。
- 截图进入实际模型请求并从历史重建；超过 API 单页上限的图片完整导出、哈希一致；纯文本、超限、落盘失败与导出中断不伪装成功。

## 风险

原版 CLI 的重发是已知冲突，正式修复 release 的时间不由本项目控制；daemon 归属、跨产品占用与 dashboard 隔离也未运行验证，是先行阻断。上游升级可能改变行为，需固定版本并重跑探针。现有 Chrome 接管需要用户启用调试，不能承诺任意窗口无准备接管。

会话级浏览器占用内存和磁盘；空闲回收丢失页面现场，保留登录不等于恢复页面。profile 是敏感用户资料，不自动删除或跨产品共享；完全访问的同账户权限仍适用。

真实网站可能要求验证码、硬件认证或拒绝自动化，需人工介入；受控页面通过不能证明所有网站可操作。图像占用上下文，沿现有上限明确处理，不以文本悄悄替代。
