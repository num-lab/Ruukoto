# Agent Note: Desktop 应用内 Spotlight 搜索与历史定位

Status: proposed

## 问题

工作区和会话积累后，拥有者需要凭名称或聊天中的一句话找回旧会话，并立即到达原消息。当前侧栏筛选只查名称，旧聊天内容必须先打开正确会话再逐页查找；已经存档或不在最新历史窗口中的内容尤其难找。

拥有者已选择应用内 ⌘K 搜索全部工作区会话及聊天内容，并接受完整方案；本提案负责把搜索结果和可核实的原消息位置连起来。已确认范围、界面、步骤与验收的唯一入口是[工单](../../../../.scratch/desktop-search/issues/01-spotlight-search.md)。

## 方案

搜索使用当前 Code 实例的普通开发会话，包含存档，按工作区组织归属显示。名称候选通过既有会话摘要接口新增的可选普通聊天 scope，由后台判定资格后完整返回，客户端即时匹配；现有快照缺少调度身份绑定，不能独立拿来过滤搜索候选。聊天正文走现有拥有者 `search_history` 和 JSONL 位置索引；初版不建立另一份历史正文数据库，不调用模型。新增 GUI 搜索范围时保留旧 CLI、TUI 和 Agent 的默认全文提取语义；已有跨会话续页缺陷在共享扫描器修正。

聊天搜索只匹配用户文字和 Agent 可展示正文。工具参数、工具结果、思考和内部报告有不同的显示与权限语义，不把它们当普通聊天片段。字面检索支持中文，英文 ASCII 大小写归一化；索引仍是可重建的位置元数据，JSONL 保持唯一权威副本。

选择正文结果后，以 `sessionId + entryId` 进入该条目附近的连续历史窗口。窗口独立于接收实时事件的最新 SessionView，保留前后两个分页方向和返回最新。命中在收起的执行记录中时主动展开；同一历史条目对应多个流式段时按真实条目身份定位，不把投影键当条目 id。

### 为什么复用现有检索，但先设性能闸口

后台已经拥有跨项目搜索、稳定条目身份、原文片段和可继续扫描响应，复用可以避免另造搜索存储、恢复流程和协议。但当前实现先同步全部会话索引，再同步扫描原文，不能因为 GUI 做了 debounce 就称为快速搜索。

实施先建立冷／热索引和并发状态请求基线，再把必要的索引与扫描操作分批、有界执行。预算覆盖准备索引、取元数据和读正文，不能只限制最终匹配数；只允许当前页在途，过期查询不再续扫。GUI 续页须能表示索引尚未准备完的状态：首条扫描前预算耗尽也必须返回可推进的进度页，不以空命中中止。单条巨大 JSON 的同步解析仍可能超过响应预算，性能不达标时必须修订架构并复审，而不是展示扫描图标后宣称达到 Spotlight 体验。具体量级和阈值只记录在工单，避免两处标准漂移。

### 为什么使用独立的历史窗口

当前 `appendEntryView` 把单条正文并入最新投影，最新窗口已有 300 条时可能裁掉远古命中；即使保留，也会把最新页与一个孤立旧条目之间的历史空白画成连续对话。不断从最新页向前翻直到命中虽然复用最多，但其耗时随距离增长，而且现有历史读取每次解析整个 JSONL。

扩展既有 `read_history` 的 around／after 能直接读取目标附近的连续页。历史窗口复用 EventFlow 的消息与任务展示，不把整个任务事件重放到窗口里。实时事件继续更新正常投影；旧历史不会因新回复滚走，返回最新即可重新加入实时对话。

### 存档、工作区与产品范围

存档只影响侧栏列表，搜索是找回入口；打开搜索结果不改变 `archivedAt`，允许已存档会话因显式搜索打开而临时出现在标签。再次执行存档仍按既有规则关闭标签。这是[会话存档决定](../../implemented/feature/2026-10-20-desktop-session-archive.md)的展示补充，不改变会话、历史或任务资格。

名称与正文命中按既有[工作区组织归属 helper](../../../../packages/control/src/session-attribution.ts)计算归属，不能以用户正在查看的工作区限制拥有者全局查询，也不能把组织归属当作来源资料身份。

当前 Desktop 不支持新个人 durable 的历史协议；Personal 是独立存储和产品装配。应用内可从 PA 页面唤出 Code 搜索，但列表明确说明搜索 Code 工作区；本功能不借 Spotlight 建立 Code／Personal 跨产品资料合并。

### 失败处理与安全保证

| 失败或状态 | 归属与处理 | 失败后保证 |
| --- | --- | --- |
| 尚有未扫描条目或历史正在首次落盘 | 检索返回可继续状态；GUI 展示搜索进度。 | 不把部分扫描或尚无文件解释为全库零命中。 |
| 完整记录损坏、已登记来源丢失或读取权限失败 | 存储边界抛带 code 的历史错误，GUI scope 在 runtime 汇成带会话和 code 的来源问题，继续其他可读会话；GUI 保留已得结果并显示范围不完整与重试。 | 不忽略损坏命中，不修改源文件；扫描到末尾仍不声称来源全覆盖。 |
| 目标不存在、正文分片断续或来源文件身份变化 | 定位停止安装新窗口；GUI 保留原会话位置并允许重搜／重试。 | 不以跳到最新页代替命中定位，不把新旧文件拼成历史。 |
| 查询、快照代次或数据实例已变化 | 搜索与定位控制器拒绝迟到应答；旧轮次不再续读。 | 旧搜索不覆盖当前输入或其他实例，不串入旧历史。 |
| 离线或协议不支持 | GUI 展示无法查询并提供重连或既有更新引导。 | 不离线扫描磁盘，不向其他目标改发。 |

搜索只经已认证的 control 读取拥有者资料，desktop 不打开数据库或 JSONL，不开放任意路径。索引进度和对应派生条目在同一短事务写入，历史文件只读；这不构成 SQLite 与 JSONL 原子提交的声明。GUI 查询缓存只在内存存在，随数据实例变化清空，不新增敏感搜索日志。

按 Spotlight、全局搜索、search_history、历史索引、history-index、全文、desktop、会话存档检索 active notes 与历史工单。proposed 未发现同题搜索方案，rejected 目录当前不存在，不动 archived 记录。

- [会话存档](../../implemented/feature/2026-10-20-desktop-session-archive.md)：部分重叠，新增显式搜索可打开已存档会话的展示例外；双方互链，既有决定保持原文。
- [桌面客户端提案](../architecture/2026-10-15-desktop-client.md)：客户端分层依据，本提案沿用 Host／bridge／renderer，不重新规定连接与身份。
- [个人资料归属](../../implemented/architecture/2026-10-18-personal-memory-skills-history.md)：独立产品历史的约束依据，不把旧搜索接到新个人 durable。
- 工具全文预览、完成后执行记录和上下文压缩笔记：属于展示或上下文选择；相关条目继续沿用现有行为，本次没有同题决定需要吸收或拒绝。

## 备选方案

- 只把侧栏名称筛选放进 ⌘K 弹窗：接入最少、响应直接，但找不到聊天正文，不能满足拥有者已经确认的需求。
- 每次打开弹窗把全部历史下载到 renderer 后本地搜索：交互实现集中、后续搜索不经控制面，但要跨边界搬运全部历史，启动成本与内存随历史增长，还需维护与实时输出的同步。只下载命中片段与必要上下文。
- 首版直接建立 SQLite FTS 或向量检索：全文索引能避免反复扫原文，向量可支持语义查找，但会新增正文派生存储、中文匹配选择、索引重建和新鲜度机制；当前需求只要求关键词找回。先验证现有扫描路线，若性能不满足工单阈值，再凭证据提出索引架构修订；不为减代码牺牲响应要求。
- 只对命中调用 read_history_entry，再追加到最新对话流：几乎完全复用现成单条补读，但可能立即被裁剪，且掩盖历史断层。必须读取连续上下文，并清楚区分历史窗口和实时会话。
- 注册操作系统全局快捷键或建设命令面板：能进一步充当启动器，但拥有者已选择应用内搜索。首版聚焦会话与聊天导航，保持 Electron／MyGo 共享实现。

## 验收标准

按[工单验收表](../../../../.scratch/desktop-search/issues/01-spotlight-search.md#验收与证据)逐项建立证据：跨工作区与存档覆盖、正文范围、跨会话续页、迟到应答、旧消息上下文与收起记录定位、双壳键盘与输入法、冷／热检索和后台响应延迟。源码调查、合成脚本、浏览器验证与真实应用验证分别记录，不互相替代。

方案独立审查通过且拥有者已确认范围、体验取舍和性能标准，工单可交实施。实现后更新模块文档与用户入口，再转 implemented；本提案当前不宣称功能可用。

## 风险

历史增长和单条巨大消息可能使扫描方案无法满足响应标准；索引准备也可能比匹配更昂贵。性能验证必须在 UI 接入前完成，必要时先修订检索架构，避免做完弹窗后才发现后台卡顿。

历史窗口涉及长期使用的投影与任务分组，旧消息不能通过全任务重放挤出窗口；必须用远古命中、跨任务边界和实时追加验证。扩大共享历史 API 时要同时核对 TUI 与 Inspector 的旧调用。

正文搜索按完整落盘记录提供结果，流式尚未落盘片段需要稍后重搜；本轮不是固定时刻的数据库快照查询。一次查询遍历期间新增内容不保证被全部纳入，稳定语料必须不重不漏。

存档会话可被显式搜索打开的例外会改变用户对标签的预期，结果和会话页需保留存档标识。拥有者已确认从 Code 或 PA 页面打开的搜索均只覆盖 Code 工作区；界面不能写「全部聊天」却漏掉另一个产品。
