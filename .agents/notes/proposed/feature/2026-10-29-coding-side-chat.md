# Agent Note: Coding 侧聊以独立宿主身份执行无工具问答

Status: proposed

## 问题

拥有者需要在 Code 主任务继续执行时讨论旁支问题，并让侧聊保留自己的多轮上下文。产品要求见[规格](../../../../.scratch/coding-side-chat/spec.md)，实施入口见[工单](../../../../.scratch/coding-side-chat/issues/01-side-chat.md)。普通 `/branch` 已能固定历史，但会切换用户会话、与父任务争用工作目录，并默认开放项目历史检索、记忆写入和 coding 工具，不能直接满足隔离与并行要求。

## 方案

### 宿主身份与快照发布

由宿主持久绑定父普通 Code 会话与侧聊，父会话唯一、侧聊 ID 唯一；分类为具名的 `side` 会话身份，不伪装 `dev` 或 SubAgent。身份与父子关系随查询、事件和重连快照提供给客户端，不能由消息正文、任务参数或模式选择创建或改写。仅普通 Code 会话可创建侧聊，侧聊不能嵌套，也不能成为普通分支来源。

首次 `/side` 在后台固定来源安全历史，复用[分支快照](../../implemented/feature/2026-10-11-branch-session-snapshot.md)的读取、来源核实、文件准备与发布机制。只抽出两者实际共用的准备与发布步骤，不另建通用会话派生框架。父子唯一约束必须覆盖发布前的准备记录：两个客户端不能分别固定两个来源快照再竞相发布；原请求重试固定原前缀，新请求打开已存在侧聊时只返回原绑定。

准备文件在发布前刷盘，侧聊会话、身份绑定、完成回执和创建事件在同一 SQLite 事务发布，提交后应答与广播。文件与 SQLite 不承诺原子；恢复依据准备回执核实原文件，不能重新取父会话最新历史。空来源使用独立空 JSONL，完整坏行或已发布侧聊文件缺失明确拒绝。实现可按现有 Store 选择最少的表或列，不能省略持久唯一绑定或恢复依据。

### 执行与模型输入

复用现有 Driver、SDK 会话、任务账本、流式事件、压缩和用量记录。`side` 映射固定空工具画像，SDK 显式 `tools: []`，不装 MCP 或默认工具；路由执行也按身份拒绝。使用简短侧聊问答系统提示，说明来源只到首次安全历史、资料不足由用户补充；不让旧快照中的 coding 指令驱动新的工具或工作管理行为。新增模型可见输入继续记录到实际请求快照与选择记录。

侧聊任务有自己的生命周期，不申请工作目录、不启动执行环境，也不复用带等待和资源重取语义的 `conversation` 阶段。普通 submit 按宿主身份分流，保留任务幂等、模型配置门闩、取消、终态和重启规则，跳过 coding launcher、目录占用与执行权限前提；客户端不能传一个通用的「跳过占用」开关。后台事务最多接纳一个未终结的侧聊任务，UI 只负责保留下一条草稿。

重启恢复要显式处理侧聊的接纳窗口：除 running／awaiting_confirmation 外，queued 也终结为 interrupted，不重放；不能进入普通会话保留 queued、等待拥有者恢复队列的路径。确认没有侧聊执行占用后，侧聊保持可接纳新输入，父会话的暂停与占用核实继续独立。否则一个尚未开始的回答就会永久挡住无队列控制入口的侧聊。

Driver 的 ContextSendBlocked／ContextOverflow 目前会调用 `pauseQueue`；侧聊不沿用该执行队列暂停，失败任务终结后允许新的显式提交，仍执行全部发送前校验。资料损坏、配置不符或预算仍不足则继续明确拒绝；不自动重发，也不自动释放异常执行占用。不为侧聊新增恢复队列或手动压缩命令。

模型与推理档位在每次侧聊提交时从父会话当前选择取得并固定到新任务；同一请求键重放不能重新选择。侧聊不提供权限模式切换，不能继承父会话的执行能力。配置更新与 provider 限流仍走已有失败语义，不绕开任务系统另起裸模型请求。

侧聊装配固定来源历史与自身后续历史，不建立主任务继续、工作清单、结果送达或唤醒关系。`loadPinnedContext` 不读项目指令、记忆与继续来源；不加载技能／角色目录、不展开 `/skill`、不加入历史派生清单、Plan 或资源阶段提示，Driver 不领取父结果与报告。关闭 Jev 筛选，避免额外服务外发或每轮配置变化。普通 JSONL 不包含原参考块，首版只继承安全历史，不承诺继承父会话完整模型输入。

禁止外部参考输入与本会话压缩分别按侧聊身份处理，不能把 `restricted: true` 原样当成完整侧聊实现：它会禁用现有压缩，但没有排除所有清单／报告输入。保留 `handleContext → assemble → prepareSend → capturePromptSnapshot → afterSend` 的预算、配对、图片、记录与用量链，全部以侧聊自己的会话 ID 运行；真实 payload 验证输入与工具清单。

### 默认资料隔离

集中以目标会话身份判断 Agent 是否可读侧聊资料，覆盖 Driver 的 `dataSessionReadable`、产物访问和 AccessScope 的 `sourceRefAccessible`。历史搜索全集、指定会话／任务／条目读取、直接产物 ID、记忆来源核实及自动注入使用同一决定，拒绝从另一路读回。无需新建侧聊记忆库：空工具画像本身禁止记忆写入；仍须防止其他 Agent 将侧聊资料作为可读记忆来源。

不创建父结果送达登记。普通会话列表、工作区聊天、普通搜索及普通分支入口排除 `side`；拥有者侧聊读取、prompt 与用量查看继续使用已认证控制面。快照仍可携带侧聊身份和任务供重连恢复，不把 owner 的全部事件流误当成模型输入而删除。

### TUI

复用现有悬浮层定位与 SessionView 的历史、草稿和滚动状态，单独持有侧聊焦点，不调用 `switchSession(sideId)`。聊天输入不能沿用列表把 q 当退出键的规则；全局 Ctrl+C、Tab 与翻页键必须先分流到当前焦点，工作流侧栏不能抢侧聊按键。侧聊只提供自己的中断动作，不能调用会根据当前主视图推断目标的普通 `/interrupt`；回答期间的发送限制不能屏蔽中断控制。窄终端必须为输入留出高度，并保持主任务状态可见；不新增左右分屏与工作流侧栏协调机制。

### 版本与相邻工作

持久身份与协议改变时递增 schema／控制协议版本，沿[Code 严格版本切换](../../implemented/simplification/2026-10-24-code-instance-mcp.md)处理；不暗加旧库迁移或跨实例侧聊导入。新档案不自动延续旧会话，原 SQLite、JSONL、产物和凭据保持原地；切换前沿现有规则核实旧任务与受管进程，不把新档案当停止证明。

[消息控制](./2026-10-28-coding-message-control.md)仍在同工作区实施。`/side` 必须在普通提交／steer 解析之前独立分流；不能借侧聊送出主会话消息、使主任务等待解除或改写父审批。实施前以该功能最终代码重新核实 submit、schema 和协议版本，不基于本次调研行号机械打补丁。

## 既有笔记审计

- 会话分支快照：部分重叠，复用安全前缀与跨文件发布，互链；侧聊另有身份、固定空工具与资料隔离，不取代普通分支行为。
- 完整保留会话历史、工作委托与 SubAgent、原生受限执行：沿用既有历史权威、任务归属及保护根约束，本篇不重定义这些决定。
- 主 Agent 等待与报告认领：本篇不采用其对话阶段与送达语义，机制无重叠，不扩大旁路资格。
- Coding 消息重排与引导、Code 严格版本切换：沿用其输入分流与版本约束，不修改正在实施的提案。
- 以侧聊、侧边对话、side chat、`/side` 检索 proposed／implemented／rejected，未发现同功能旧提案需要吸收或归档；宽泛命中的桌面演示、个人助手与定时能力不在本功能范围。

## 备选方案

- 直接把普通 `/branch` 显示成悬浮层：能复用最多代码；普通身份仍有工具、目录占用和项目可读资料，会破坏并行与隔离。保留它的快照机制，增加宿主可判别的侧聊身份。
- 在主任务里临时发送旁问，随后删除消息：不用新增会话；无法保证不进入下一请求，也会混入任务引导、审批和 JSONL 权威，故不采用。
- 以 SubAgent 执行侧聊：已有独立上下文和并发；SubAgent 不直接与拥有者对话，并有委派与结果回传语义，不符合产品归属。
- 客户端内存保存并直接调模型：代码路径短；退出后不可恢复，也绕开请求幂等、模型配置锁、审计与后台生命周期，故复用正式任务链。
- 允许只读文件与搜索：更容易回答新资料问题；会扩大工具、执行和并发边界，已确认首版只基于已有上下文问答，不加入。
- 每次追问同步父对话：侧聊可追上最新进展；引入变化中的上下文与隐式新输入，已确认选择首次固定快照。

## 验收标准

产品行为逐项按规格 R1–R12；工程反例与真实环境要求见工单的验收矩阵。至少证明：主任务持有目录且等待审批时侧聊仍发出空工具请求；主任务／审批不变；安全前缀、重开和重启使用原快照；双客户端只有一个侧聊和一个未终结任务；搜索、直接历史／产物和记忆来源都不能读回；侧聊缺失历史不被重建为空白。TUI 与真实模型验收缺前提时保持待验收。

## 风险

固定快照会过时，模型上下文预算仍可能压缩来源内容；侧聊磁盘记录与主会话同样需要保留。并行增加模型费用并可能遇到 provider 限流。仅过滤搜索会遗漏直接 ID 和记忆来源，复用默认上下文也可能带入父进展，二者须用实际请求与读取负例证明。TUI 焦点和高度处理需要真实终端验收。schema 切换沿现有不兼容策略，不能声称旧档案自动续用；应用资料隔离不提供完全访问下的 OS 保密保证。
