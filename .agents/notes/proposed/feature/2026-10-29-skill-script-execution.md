# Agent Note: 技能脚本直接执行且源码默认不进入上下文

Status: proposed

## 问题

技能目录、正文和引用包装目前要求脚本只作为文本返回、不能原地执行。模型要利用脚本时只能读取源码并理解实现，增加工具往返与上下文占用。现有发现没有自动加载附带脚本；需要改变的是使用方式、脚本寻址与执行环境可见性，不能把已有的按需读取误记为自动注入。

旧禁令由[原技能工单](../../../../.scratch/personal-agent/issues/22-skills.md)确认，针对当时容器看不到技能目录、执行账户权限和解释器缺失。现在两产品已有命令执行工具，但技能真实目录仍只保存在宿主，受限命令环境未开放该资源；仅删除提示词禁令不足以完成需求。

## 方案

拥有者确认的目标、实施步骤与证据由[工单](../../../../.scratch/skill-script-execution/issues/01-execute-without-source.md)持有。本提案采用现有 `bash` / `run_command` 执行脚本，`skill` 工具继续只读加载，个人主会话仍通过子 Agent 执行命令。

### 模型使用方式

技能目录仍先提供名称与描述。按需正文和 `/skill:名称` 展开附带目标技能的真实目录，作为解析相对脚本路径的依据；正文、参数说明和运行结果足够使用脚本，默认无需读取源码。用户要求审计或排障确有需要时，仍可经现有引用读取取得源码；引用文件的路径、realpath、UTF-8 与 64 KiB 限制保留。

脚本经现有命令工具运行，`skill` 不执行命令、不改变其无效果账本或 Personal 的安全重放属性。更新目录、正文、引用包装以及两产品工具描述中的旧禁令，并在当前工具说明明确现行执行方式，使带旧禁令的历史恢复请求仍得到当前可行动的指引。脚本自身的标准输出、错误或堆栈可能包含源码；本决定不承诺源码绝不出现。

真实目录只随目标技能加载或显式展开进入历史，不批量注入所有宿主路径，不扫描脚本正文来生成说明，不增加脚本类型识别、入口清单或模板替换语法。脚本仍以当前任务或预配置命令目录为初始工作目录，输出写入原获准位置；提供技能目录不等于默认切入该只读目录。仅显式调用的技能仍不能由模型自主加载；个人主会话可将显式展开取得的具体命令、参数和目标交给子 Agent，无需复制源码或扩大引用读取资格。

### 执行资源与权限

Coding 使用当前任务钉版技能库中的目录候选，Personal 使用发起该命令的原模型请求所选技能快照。按最终 `LaunchSpec.mode` 为受限环境一次性开放这些技能的真实目录，只读访问，覆盖脚本及同包资源。技能说明固定与脚本执行时版本分离：脚本和资源取执行时磁盘内容，不复制或钉版整包。真正完全访问保持原启动参数与文件范围；来源任务为完全访问而验证步骤实际降为受限时，仍须补齐技能只读根。

各技能目录分别使用 realpath，不以整个 HOME 或 `~/.agents/skills/` 的单一挂载替代；拒绝新增会覆盖文件系统根或宿主 HOME 的候选，包括指向这些位置或其祖先的技能符号链接。归一和去重后，已被原工作区或既有授权完整覆盖的目录沿原权限，不重复加只读限制；技能根包含原可写根而无法整根只读时，将该新增技能资源标为不可用。不存在、受保护或文件别名冲突的技能根逐项诊断并排除，其余普通命令继续；不能吞掉原工作区、原授权或原 readScope 的校验失败。现有受保护路径、目录身份和硬链接检查继续适用。

命令确保 worker 前从原目录候选重核可用技能根，最终根及目录身份参加 worker 复用判定。资源集合变化时先核实旧执行单元已停止，再建立替代环境；停止未核实仍保留占用并拒绝替代执行。最后复核之后发生的并发目录变化仍可使本次执行明确失败，不能把已开始操作的失败解释为可自动过滤重试。

新增的是技能包的只读文件可见性，不是新执行权限。原工具资格、工作区与写授权、联网、凭据、审批、超时、输出捕获、停止和效果未知规则继续生效。解释器、外部依赖或凭据不可见时按普通命令失败，由现有执行层报告受影响操作与下一步；不自动安装环境、开放外部路径或重放效果未知命令。

### 历史与恢复

新增模型可见目录随技能加载结果或显式展开保存，不重写已提交历史。Personal 的旧显式展开核实依赖精确重新生成；保留冻结的旧格式生成路径，只精确接受可重建的旧格式或新格式，拒绝任意篡改，不引入通用迁移框架。

Personal 命令通过 `personalModelRequestSelection` 从原 tool 的 assistant/generation 定位 `references.skills.snapshotEntry`，核实原库并在接纳、准备证据中保存原快照引用、采用的最终目录和身份。接纳后重启或后续请求刷新技能时，仍核实原选择与原 `spec/input/fingerprint`，不能读取会变化的 `PersonalSkillsDoc.current` 或重新发现当前库替换它；已开始命令只核实原执行。无新增字段的旧命令按原零技能根结构核实，不补当前目录。旧快照、加载结果、显式展开和哈希保持原字节；旧程序无法理解新证据时应明确拒绝，不降级恢复。

### 既有笔记审计

按技能、skills、skillBlock、readRoots 与执行边界检索 proposed、implemented、rejected。本提案与[HOME 发现](../../implemented/simplification/2026-10-28-home-skills-discovery.md)、[个人技能与历史](../../implemented/architecture/2026-10-18-personal-memory-skills-history.md)部分重叠并互链，保留固定来源、发现/正文快照、旧字节与按需文本读取规则，只提议增加执行寻址与技能资源可见性；当前行为在实施前仍沿原记录。[请求配置](../../implemented/architecture/2026-10-25-personal-request-configuration.md)、[原生执行](../../implemented/architecture/2026-10-10-native-execution-sandbox.md)、[个人原生边界](../../implemented/architecture/2026-10-12-personal-native-sandbox.md)、[子来源能力](../../implemented/architecture/2026-10-15-subagent-source-capabilities.md)和[工作流步骤能力](../../implemented/architecture/2026-10-13-workflow-step-capabilities.md)继续持有原请求、身份、授权与停止约束，不被取代。

## 备选方案

- 新增专用技能执行入口，只开放当次指定的技能包：寻址更稳定、暴露资源更少，但需新增工具资格、命令接纳与恢复证据，且与已有命令工具重复。拥有者选择复用命令工具，并接受当前发现的各技能目录只读可见。
- 仅删除提示词禁令：改动最少，完全访问下可能已能运行，但受限命令仍看不到 HOME 技能，模型也缺少可执行路径，无法满足两产品目标。
- 任务开始时复制完整技能包：可固定脚本与资源版本，但增加复制、依赖布局、存储和生命周期问题。拥有者选择保持引用文件使用时取磁盘内容的规则。
- 禁止所有源码读取：能防止模型主动读取实现，但妨碍拥有者审计和必要排障，也不能阻止脚本自己输出源码。拥有者选择默认不读、必要时可读。

## 验收标准

- 正文加载、显式调用及正常执行请求不含脚本独有源码标记，不发生源码预读；真实脚本产生可核实结果，能读同包资源并写入原工作区，技能包未被写入。按需源码读取仍可用。
- 现有主/子与来源工具资格不扩大；受限环境只增加选定技能目录读取，网络与包外资料仍受限；原授权完整覆盖时不收窄原权限。最终完全访问与实际降为受限的验证步骤分别覆盖。
- 符号链接技能、目录相等/嵌套、坏根诊断隔离、目录变化与安全重建均有最窄回归；原授权无效仍失败，停止未核实不创建替代 worker，已开始或效果未知操作不重放。
- Personal 新命令固定原请求选择，后续技能刷新不替换它；旧/新快照、旧展开、旧无字段命令和篡改反例可重启核实。带历史禁令的 Code 请求保留历史字节并获得当前执行说明。
- 离线请求快照、macOS/Linux 实际受限脚本执行和两产品真实模型闭环分别留证；记录模型实际收到的工具与系统提示估算及执行链路上下文差异，不用离线模拟宣称模型会遵循新方式，也不承诺固定节省比例。具体用例、命令与证据缺口由工单持有。

## 风险

全库只读可见会让命令读取尚未加载技能包中的其他文件，目录名即使未进入模型也不是文件权限限制。原生文件别名检查会遍历新增根，含大 assets 或虚拟环境的库可能增加普通命令准备成本；实施验收记录代表性技能库的启动观察，必要时再单独重访按次执行入口，不能无证据声称没有成本。

固定正文不固定脚本：拥有者修改文件会影响随后执行。依赖位于技能根外、使用不同宿主账户、脚本假设特定 cwd 或需要写入包内时仍可能失败；Personal 不自动获得 Coding 的宿主 node_modules。首次升级必须验证旧展开与命令证据兼容，不能通过重写历史消除失败。
