# 同步图解页

`docs/visual/*.html` 是随代码维护的图解页。读者靠它理解机制，所以页面上的每句话、每条边、每个表格单元都必须在**当前代码**里成立。test/67 只能拦下「代码结构变了，页面没跟上」，拦不下「页面说错了」。页面说得对不对，靠下面的步骤保证。

开始前先读两样东西：`CONTEXT.md`，页面只用其中的术语；`docs/visual/style.css` 顶部注释，里面列出可用组件与语义色。

## 步骤

### 1. 定位

列出本次改动过的 `src/`、`deploy/` 文件（`git diff --name-only <基点>`），再列出改动带来的**可观察变化**：状态与转换、事件类型、表与列、op、错误码、上限与超时、调用顺序、事务边界、失败时的处理。

- 对每个文件：`grep -l <文件路径> docs/visual/*.html`。
- 对每个变化：`grep -n <符号或取值> docs/visual/*.html`，旧名和删掉的取值也要搜。页面经常提到某个事实，「源码」行里却没有列出它所在的文件。
- 两种搜索都没命中，说明页面还没写这个机制。按下面的「归属页」表决定写在哪一页，或者判定它是实现细节，不必上页面。

完成标准：有一张清单，每个可观察变化都对应到「页面#section」，或者注明「无命中，不上页面：理由」。

### 2. 读整节

清单里的每个 section，都从 `<h2>` 读到 `</section>`：正文、图（含 `aria-label`）、figcaption、表格、callout，以及 `<details>` 里的失败分支。同一个事实常在图、表、正文里各说一次，只改搜到的那一行，页面就会自相矛盾。

完成标准：清单每一项都补上「本节里说到这件事的全部位置」。

### 3. 改

按下面的「写法规则」改。要改图或时序图，先读 [drawing.md](drawing.md)。

### 4. 核实

对每个改过的 section，给其中**每一条事实**（不只是你改的那句）找到能证明它的代码位置：文件与函数，必要时加行号。下面这些高风险说法要逐条看：

- 箭头方向，谁调用谁；
- 「同一事务」「先……再……」；
- 状态转换的条件与触发者；
- 事件名、错误码、表名、列名，必须与代码逐字一致；
- 数字，要能指出来自哪个常量；
- 「只」「总是」「从不」「所有」这类绝对说法。

找不到证据的说法，要么改到能证明的程度，要么删掉。ADR、runtime.md、README 与代码不一致时，页面按代码写，把不一致记下来，第 6 步汇报。

完成标准：改过的 section 里，每条说法都对应一个代码位置。

### 5. 检查

- 跑 `npx tsx --test test/67-visual-docs.test.ts`，必须全绿。它核对四件事：源码锚点存在；覆盖清单里的取值出现在页面的 `<code>` 里；站内链接与锚点有效；index.html 链到每一页。失败行以「页面：问题」开头，逐行修页面；测试本身保持原样。
- 改过图、表格或时序图时，运行 `.agents/skills/visual-docs/shoot.sh docs/visual/<页面>.html`，再用读图工具把输出的切片逐张看一遍（脚本会自动展开 `<details>`）。要找的问题：文字重叠或超出框、箭头指错或穿过节点、表格被截断、图太挤或太空。改完再渲染一次确认。
- 环境里没有 Chrome、Pillow 或读图工具时，跳过渲染，在汇报里写明。

完成标准：测试全绿；每张改过的图都看过切片，没有上述问题。

### 6. 汇报

写进工单的 `## Comments`，没有工单就写进最终回复：

- 改了哪些页面的哪些 section；
- 文档与代码的不一致：原说法、代码事实、代码位置；
- 核实时发现的代码问题。同步页面的任务只记录这些问题、不改代码；需要修的，按 `docs/agents/issue-tracker.md` 登记成工单。

## 写法规则

### 按代码写

页面描述的是当前代码的行为，而不是计划中的行为。尚未实现的部分写成「首版限制」或「已知限制」（`aside.callout.limit`）。`CONTEXT.md` 里标为「（旧架构）」的概念（逻辑角色等），页面上同样标明是旧架构的现行实现。

### 归属页

每个主题只在归属页详述。其他页面提到它时，用一句话加链接 `<a href="页面.html#section">`。改一个事实时搜一遍全站，让所有提到它的地方说法一致。

| 主题 | 归属页 |
|---|---|
| 任务状态与转换、停止、重启、模式切换、排队与目录占用 | task-lifecycle.html |
| 工具分派、可用性、访问模式、审批与自动审查、长期授权、工具账本 | tool-call-path.html |
| 上下文选择、预算、压缩、发送前复核、SubAgent 的上下文 | context-pipeline.html |
| 目录与文件、权威来源、核心库表与 schema 迁移、工作区迁移 | storage-layout.html |
| 按需拉起后台、认证与握手、快照与事件流、op 与事件目录、协议版本 | control-protocol.html |
| 产品与进程、系统身份、执行后端及其失败方式、服务 helper、秘密 | deployment.html |
| 工作委托与 SubAgent、子任务回传、旧架构角色、GitHub 评审、群聊结果 | orchestrator.html |
| 入站登记与去重、派发与启动前的门、IM 审批命令、owner 回复登记 | inbound-events.html |
| 通知 outbox、发送循环、调度计划与新闻计划、IM 回执、QQ 群回复账本 | outbox.html |
| 先记意图、只执行一次、三种「没有结果」的跨模块对照 | once-only.html |

### 源码锚点

写法：`<code class="src" data-src="src/runtime/runtime.ts#runQueueLoop">runtime.ts · runQueueLoop</code>`。

- `#` 之后的文本必须在该文件里逐字存在。写之前先 `grep -n "<文本>" <文件>` 确认。
- 优先用能唯一定位的写法，例如 `private async checkDeadlines`、`export async function ensureBackend`、`class ApprovalGate`。
- 不带参数签名，不写行号。只想指向文件时，省略 `#…`。
- 每个数字（上限、超时、版本、水位）都来自代码常量，旁边给出该常量的锚点。

### 覆盖检查

test/67 的 `COVERAGE` 把源码里的枚举映射到页面，例如类型的字符串取值、表名、op、事件类型、名称数组常量、版本常量。每个取值都必须逐字出现在对应页面的某个 `<code>` 里；只出现在 SVG 文字或普通正文里，不算覆盖。

- 代码新增了一个取值：写进归属页，并放进 `<code>`。状态取值用 `<code class="st ok">`，颜色按语义选。
- 代码新增了一类页面会完整列出的取值（新的状态类型、新的名称数组常量），或者新增了一个含建表语句的文件：在 `COVERAGE` 里给归属页加一项来源。能解析哪些写法，看 `valuesOf`。

### 页头与总览

- 页头 `dl.meta` 的「源码」行，列出本页描述的全部主要源文件，包括 `deploy/` 下的文件。维护者靠 `grep -l` 按文件找页面，漏列一个文件，改它的人就找不到这一页。
- 「决策」行列出相关 ADR，「相关页面」行列出相关页面的链接。
- 一节的范围变了（新增或删掉一节、机制被替换），同步该页的 lede 和 index.html 里对应卡片的说明。
- 改了 section 的 `id`，要修全站指向旧 `#id` 的链接（测试会报出来）。

### 组件

- 只用 style.css 顶部注释列出的类和语义色，页面里不写 `<style>`。行内 style 只用于时序图的 `--n`、`--from`、`--to`，以及 `max-width`。
- 确实缺组件时，在 style.css 里加类，并在顶部注释补一句说明。
- 状态机的一条转换会出现在三处：图上的边、边标签、转换表的行。三者共用同一个 `data-k`，表行加 `tabindex="0"`，改一处就三处一起改。

### 文字

- 用中文短句直说。figcaption 写这张图的结论和读法，不要把图上的内容再念一遍。
- 计数会随代码过时，例如「七个状态」，所以不写；除非这个数字本身就是代码里的常量，并且附上常量锚点。
- 标题里不写工单号；需要交代出处时，写在正文里。
- `ol.steps` 只用于顺序本身就是信息的过程。
