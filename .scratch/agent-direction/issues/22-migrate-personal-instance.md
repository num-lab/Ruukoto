# 22 — 把旧主会话和服务状态迁入 Personal Agent

**What to build:** 拥有者将旧 main 的会话、应用数据、调度及平台状态迁入独立 Personal Agent，保留旧角色档案和发送事实。

**Blocked by:** [01 — 两个产品独立安装和启动](01-independent-products.md)；[19 — 把现有 GitHub 评审迁移到通用 SubAgent](19-github-subagent-review.md)；[20 — 退出核心群聊并保全旧群资料](20-retire-core-group-chat.md)

依据：[已确认规格](../spec.md) 与 [ADR 0017](../../../docs/adr/0017-two-agent-products.md)。

## 验收标准

- [ ] 预览并确认源/目标实例及个人数据归属，核对备份与未完成任务；不覆盖未核实的目标数据。
- [ ] 主会话、应用数据、调度、平台绑定和必要凭据在新实例可用；旧 coding/chat 历史、结果与发送记录保持可核查。
- [ ] 切换时明确交接平台连接和调度的执行归属，旧新实例不能同时消费同一入站或继续发送同一批通知。
- [ ] 来源资料落在另一实例时保留来源、授权和映射；无法核验的派生记忆或发送引用不自动使用，明确列出待处理项，不靠扩大读取或共享凭据恢复可读性。
- [ ] 中断后可继续，重复迁移不重复创建；审批、排队任务及 pending/在途/unknown 发送均按实际效果处理，不当作新请求重放。
- [ ] 用代表性个人数据演练恢复和回退；回退也保留切换期间新增的执行及发送事实，不用旧备份重发已有副作用。
- [ ] 完成相关端到端检查、类型检查及仓库要求的验证；同步本次行为涉及的运行说明和图解，验证记录区分模拟结果与真实环境结果。
