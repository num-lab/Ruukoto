# 28 — 为 ruukoto-code 增加 `/branch`，从当前会话建立新会话

**What to build:** 在 Coding Agent 的 TUI 中提供 `/branch [名称]`，从当前普通开发会话的已落盘历史建立一个独立会话，继承适用的上下文状态和会话默认设置，成功后自动切换，等待拥有者输入。

**Blocked by:** 无。2026-10-09 通过两轮 grilling 确认 Q1—Q13，拥有者两次答复“全部按照推荐”，授权登记工单。本单记录待实现行为，不表示功能已经存在。

依据：[领域术语](../../../CONTEXT.md)、[ADR 0001：完整历史](../../../docs/adr/0001-preserve-session-history.md)、[ADR 0016：上下文压缩](../../../docs/adr/0016-lossy-context-compaction.md)、[ADR 0017：两个产品与工作区](../../../docs/adr/0017-two-agent-products.md)、[ADR 0018：资料身份与组织归属](../../../docs/adr/0018-legacy-workspace-org-attribution.md)。

## 目标与范围

拥有者可在已有对话的基础上尝试另一条思路，两个会话各自保留后续历史。执行 `/branch` 不产生模型请求，不提交任务，也不重放复制历史里的工具调用。

父子使用同一工作目录，文件改动继续共享；会话分支不创建 Git 分支或 worktree，不保存或恢复文件快照，同目录任务继续按现有目录占用规则串行。本单不提供选择旧消息作为分支点的界面、跨工作区分支、历史合并、自动结果回传、CLI 或 IM 命令。

分支会话仍是普通开发会话，可继续按相同规则建立分支。来源关系用于追溯及核实资料引用，不构成 SubAgent 身份或新的任务执行权限。

## 已确认行为

### 命令、命名与切换

- `/branch [名称]` 要求当前已选择 Coding Agent 的普通开发会话。SubAgent、main、已退役归档会话及其他不可写来源明确拒绝；不能只靠 TUI 隐藏入口保护身份。
- 支持普通工作区会话和已映射到工作区的旧会话。尚未映射到工作区的旧会话提示先完成已有映射流程；目录失效、被替换或不再符合执行范围时拒绝，不静默改用其他目录。
- 名称是新会话的持久展示字段，支持中文及名称内空格。显式同名允许，以会话 ID 区分；不会覆盖已有会话。省略时后台生成“父标题 · 分支 N”，同一来源下并发创建的自动编号不同。同一个创建请求重试沿用原名称与编号。
- 创建后及首次提交后，分支名称均能在现有会话列表中显示。父标题为空时使用现有未命名会话的展示规则，不要求父会话已有任务标题。
- 成功后自动切换到新会话，显示来源会话和实际分支点，拥有者仍可从原列表切回父会话。新会话编辑器从空输入开始，等待拥有者提交；不复制父会话草稿、滚动位置等客户端状态。
- 失败时保留父会话选择和草稿，显示具体原因；不切到半成品会话。命令回显及结果沿现有命令历史机制留在发起会话，不作为模型消息复制到新会话。

### 历史快照与活动任务

后台处理命令时固定一次来源历史快照及其边界，复制分支点之前的完整消息历史；不使用当前模型上下文、滚动摘要、TUI 已加载页或任务结果摘要替代原历史。后续来源追加不进入新会话，父子后续各自写入独立 JSONL。

一致点按消息和工具批次确定，不能仅依据 `task.status`：

- 纳入完整写入 JSONL 的用户、assistant 和工具结果消息。已完整落盘的用户消息可以成为末条，不要求等到 assistant 回答。
- 来源正在运行、等待审批或存在排队任务时也允许分支。末尾尚在执行且未配对完成的工具批次整体回退到之前的安全边界；活动任务中较早已闭合的批次可保留。批次配对要区分任务及调用轮次，不能用整个文件的工具调用 ID 集合判断，因为跨任务可能复用 ID。
- 较早中断、取消或失败任务中的缺配对记录作为历史事实保留，模型视图沿用已有孤儿工具记录清理。这是完整历史原则的必要边界，不能因一次旧中断丢弃其后所有正常对话。
- 排队输入仅存在于任务行、尚未落盘的输入和流式输出片段不纳入。首次模型响应前若尚无可复制的落盘消息，拒绝并提示等待落盘或使用 `/new`；不能把空历史误报为完整分支。
- 严格解析完整 JSONL 行，损坏完整行明确报错；未换行的部分尾记录排除。回退或排除尾部时，结果说明实际分支点与未纳入内容；无法验证安全边界时拒绝。

复制保持消息内容、顺序、条目 ID 和来源关联可追溯，新会话有独立的 Ruukoto ID、pi ID、header 和历史文件。分支操作自身不修改、补换行或修复源文件；来源正在执行时允许其正常追加，但不能把它的正常写入算作分支操作写入。

不复制源任务行、任务队列或暂停状态、工具操作账本、审批及单次批准、目录占用、运行中 SDK、工作委托、SubAgent 身份和待投递通知。原任务、审批、锁及 SubAgent 工作继续归原会话；新会话在用户提交后建立自己的任务。

### 会话设置与共享配置

- 继承来源 `projectId`、`workspaceProjectId`、工作目录及其核实后的目录身份。已映射旧会话不得仿照 `/new` 改用展示目标作为资料身份，否则会改变指令、记忆、MCP、凭据与资料授权范围。
- 独立复制会话默认模型、思考档位、默认运行模式及 `confirmTools`，包括来源已选择的 plan、auto-review 或 full_access；条件更新版本属于新会话，不能把来源版本直接当作新会话已发生的修改。TUI 自动切换不得用不完整投影或其他会话设置覆盖后台已继承的值。
- 项目指令、Web Search、MCP、Jev、记忆、资料授权及凭据继续由同一个项目配置来源管理，后续变更共同生效，不为分支另建配置副本。来源单次审批、任务级 `grantedPaths` 和临时授权不继承。
- 读取资料与新任务执行继续核实当前有效范围；已撤销、过期或失效的授权不会通过来源关系恢复。分支不得扩大资料身份、工具能力或系统权限。
- 分支时不复制模型选择记录、prompt 调用记录和累计用量；新会话累计 token 用量从零开始，后续只统计自己实际发出的模型调用。

### 压缩点与工作清单

继承与所复制历史相符的 active 压缩点，建立独立记录与新 ID，保留生成来源。覆盖范围或指纹不匹配、已失效的压缩点不继承，分支后续按现有上下文机制重新处理。父会话后续替换或作废压缩点不影响分支，分支的压缩也不影响父会话；完整历史始终保留可查。

工作清单取所复制历史中最近一次成功 `todo_write` 的完整参数，父子后续各自更新；不取分支点之后的来源清单。新会话的模型上下文和 `/todo` 展示须一致，不能因为没有复制原 `tool_ops` 而丢失清单。`in_progress` 保留为步骤状态，不启动原任务；没有清单时沿用现有空清单行为。

### 原任务、产物与 SubAgent 结果引用

保留原任务、会话、产物及工作 ID 作为来源事实。来源任务可以被查阅，但不得投影为新会话自己的活动任务、队列、累计统计或操作入口。

- 快照里已有的产物引用按原资料身份只读查询，保持原归属及读取边界；附件集合不得从用户或模型正文里的任意 ID 自动授予资格。正在追加的 partial 产物如果进入来源读取范围，必须固定快照字节上限和当时状态，不能借读取把分支后的输出引入快照。
- 已包含的图片引用继续指向原不可变产物。历史图片进入新会话模型上下文时，应允许宿主核实的来源引用，重新校验归属、当前资料范围、MIME、大小及哈希；不能仅因引用的 `sessionId` 属于来源而报错，也不能放宽为任意其他会话的图片可读。来源缺失或图片损坏明确报错，不静默删图或发送缺图请求；不新增 TUI 图片上传能力。
- 分支点已有的已完成 SubAgent 结果可按原工作 ID 只读查阅，结果范围由宿主固定到快照内已有的结果任务和产物。只记录 work ID 不够：原工作后来继续执行或 Agent 被复用后，新任务及结果不能自动进入分支的来源结果集合。
- 来源只读资格仅用于资料及已完成结果查询，不用于原工作的继续委派、Agent 复用、消息、取消、关闭或改动汇总。新会话可按现有规则委派自己的新工作。拥有者原有控制面权限继续按原 ID 核实，不因建立分支而失效。
- A → B → C 的连续分支须保留快照内已核实的祖先来源资格及原引用边界，不能只允许直接父会话导致 C 中仍指向 A 的资料无法读取；也不能以祖先关系开放其全部资料或分支之后的新结果。

现有项目内普通资料读取范围继续按原规则管理；本单限制的是分支自动继承的历史、附件和来源结果集合，不把共享项目的资料授权改造成新的全量时间快照。

## 已核实实现基础与涉及范围

现有 `/new` 通过创建空会话再切换实现，没有复制历史、来源关系或独立展示名称。消息权威副本是 pi JSONL，压缩点保存在 SQLite；清单在历史里，但当前 TUI 主要经工具操作记录恢复参数。

实现优先复用仓内严格历史解析、目录与身份校验、资料授权、压缩指纹、命令表和会话切换能力；不新增依赖，不建设通用分支图界面或第二套配置系统。预计涉及以下路径，具体落点由实现时阅读调用方确定：

- `src/tui/commands.ts`、`app.ts`、`state.ts`、会话摘要/列表及清单展示：注册、补全、帮助、请求、完整元数据安装、切换、名称、来源和历史读取。`/artifact` 也要能定位已有来源引用，不能仅查新会话任务列表。
- `src/control/ops.ts`、`server.ts`、`protocol.ts` 与 `src/runtime/runtime.ts`：增加薄的已认证分支操作，后台确定身份、快照、设置及创建结果，统一处理重启和失败。
- `src/core/types.ts`、`db.ts`、`store.ts`、`history.ts` 与会话文件打开路径：持久名称、来源会话/分支点/资料边界、独立历史、清单参数恢复和创建幂等；按实际数据形状补迁移及相关 fixtures。
- `src/agent/context-assembly.ts`、`inbound-images.ts`、`subagent-tools.ts` 及资料读取接线：压缩点继承、来源图片校验、固定结果范围和只读来源核实；原工作管理入口继续使用原会话归属校验。
- 会话创建应答、实时事件、重连快照与相关配置界面/演示数据：新字段及默认设置一致投影。旧会话迁移后名称与来源为空，继续使用原展示和读取规则；检查既有实例导入的字段清单与回退账本，避免丢失新增来源事实或绕过来源校验，不新增跨实例分支入口。

安装的 pi 0.85.1 提供 `forkFrom` 和 `createBranchedSession`，但不能直接认定满足仓库语义：前者可能静默跳过损坏行并给源文件补换行，后者会修改所持 manager 的会话 ID 和文件。源 Driver 及源历史保护、严格解析和宿主元数据边界须先核实，再选择最小可用实现。

## 创建一致性与失败恢复

创建请求使用持久幂等键。同键同参返回同一分支及原快照，同键异参明确冲突；明确再次执行命令产生新键、新会话。应答丢失时按原键核实，不生成新键盲目重建，也不把结果未知直接报告为未创建。

JSONL 与 SQLite 没有跨文件事务，不能宣称两者原子提交。实现须安排文件准备、元数据登记、应答及启动恢复，使复制失败、数据库失败或进程崩溃不会留下可选但缺历史的会话；遗留准备文件或未完成登记须可清理或核实恢复。禁止为回滚删除来源资料，成功分支的来源信息不能依赖 TUI 客户端文件保存。

创建应答、持久事件和快照必须一致展示新名称、来源、工作区归属、模型/模式及各自版本。另一已连接客户端和退出重进的客户端看到相同状态；只有发起客户端执行自动切换，其他客户端不被事件强制切换。

## 验收标准

- [ ] 分支拥有独立的宿主/pi ID、header 和 JSONL，消息内容、顺序、条目 ID、实际分支点可核对；后续父子各自追加。空历史拒绝；复制操作不发模型请求、不提交任务，新会话用量为零。
- [ ] 完整落盘用户消息可作末条；流式未落盘内容、排队输入、部分尾行和尾部未完成工具批次不复制；回退有明确提示。跨任务复用工具 ID 不误判配对；旧中断残留保留，后来的正常对话仍可分支；完整行损坏明确失败且不修改源文件。

- [ ] 模型、思考档位、confirm/auto-review/full_access/plan 默认模式及 `confirmTools` 正确继承；项目身份与展示归属正确，共享项目配置后续修改按原规则生效，临时授权与批准不继承，撤销后不借来源恢复权限。
- [ ] 有效压缩点独立继承；不匹配或覆盖越界的压缩点按无继承处理；父子后续压缩互不修改对方记录。工作清单在模型上下文及 `/todo` 中恢复一致，父子各自更新，来源在分支点之后的清单不被引入。

- [ ] 分支点已有的已完成 SubAgent 结果只读可查，原工作后续新执行、复用和结果不进入快照结果集合；分支 Agent 操作原工作的继续、消息、取消、关闭和汇总均被拒绝，自己的新委派正常可用。无关会话不能借来源关系取得结果。
- [ ] 创建应答、两个已连接客户端、实时事件及重连快照一致恢复名称、来源、模型、模式、归属和版本；自动切换不触发错误的 CAS 更新，其他客户端不强制切换。
- [ ] 同键重试返回同一会话与分支点，同键异参冲突，明确再次执行创建另一个分支；应答丢失可按原键核实。注入历史写入失败、元数据登记失败及后台崩溃窗口，恢复后无可选半成品、无源数据删除或工具重放。
- [ ] 旧会话迁移及受影响的实例导入保留原资料与标识，新增字段有兼容默认值；受影响的类型检查、相关回归和文档检查通过。
