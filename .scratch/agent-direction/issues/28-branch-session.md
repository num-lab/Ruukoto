# 28 — 为 ruukoto-code 增加 `/branch`，从当前会话建立新会话

**What to build:** 在 Coding Agent 的 TUI 中提供 `/branch [名称]`，从当前普通开发会话的已落盘历史建立一个独立会话，继承适用的上下文状态和会话默认设置，成功后自动切换，等待拥有者输入。

**Blocked by:** 无。2026-10-09 通过两轮 grilling 确认 Q1—Q13，拥有者两次答复“全部按照推荐”，授权登记工单。本单的实现与验证结果见末尾。

依据：[领域术语](../../../CONTEXT.md)、[ADR 0001：完整历史](../../../.agents/notes/implemented/architecture/2026-09-19-preserve-session-history.md)、[ADR 0016：上下文压缩](../../../.agents/notes/implemented/architecture/2026-09-26-lossy-context-compaction.md)、[ADR 0017：两个产品与工作区](../../../.agents/notes/implemented/architecture/2026-10-02-two-agent-products.md)、[ADR 0018：资料身份与组织归属](../../../.agents/notes/implemented/architecture/2026-10-03-legacy-workspace-org-attribution.md)。

## 目标与范围

拥有者可在已有对话的基础上尝试另一条思路，两个会话各自保留后续历史。执行 `/branch` 不产生模型请求，不提交任务，也不重放复制历史里的工具调用。

父子使用同一工作目录，文件改动继续共享；会话分支不创建 Git 分支或 worktree，不保存或恢复文件快照，同目录任务继续按现有目录占用规则串行。本单不提供选择旧消息作为分支点的界面、跨工作区分支、历史合并、自动结果回传、CLI 或 IM 命令。

分支会话仍是普通开发会话，可继续按相同规则建立分支。来源关系用于追溯及核实资料引用，不构成 SubAgent 身份或新的任务执行权限。

## 已确认行为

### 命令、命名与切换

- `/branch [名称]` 要求当前已选择 Coding Agent 的普通开发会话。SubAgent、main、已退役归档会话及其他不可写来源明确拒绝；不能只靠 TUI 隐藏入口保护身份。
- 支持普通工作区会话和已映射到工作区的旧会话。尚未映射到工作区的旧会话提示先完成已有映射流程；目录失效、被替换或不再符合执行范围时拒绝，不静默改用其他目录。
- 名称是新会话的持久展示字段，支持中文及名称内空格。显式同名允许，以会话 ID 区分；不会覆盖已有会话。省略时后台生成“父标题 · 分支 N”，同一来源下并发创建的自动编号不同。同一个创建请求重试沿用原名称与编号。
- 创建后及首次提交后，分支名称均能在现有会话列表中显示。父标题为空时使用现有未命名会话的展示规则，不要求父会话已有任务标题。
- 成功后自动切换到新会话，显示来源会话和实际分支点，拥有者仍可从原列表切回父会话。新会话编辑器从空输入开始，等待拥有者提交；不复制父会话草稿、滚动位置等客户端状态。
- 失败时保留父会话选择和草稿，显示具体原因；不切到半成品会话。命令回显及结果沿现有命令历史机制留在发起会话，不作为模型消息复制到新会话。

### 历史快照与活动任务

后台处理命令时固定一次来源历史快照及其边界，复制分支点之前的完整消息历史；不使用当前模型上下文、滚动摘要、TUI 已加载页或任务结果摘要替代原历史。后续来源追加不进入新会话，父子后续各自写入独立 JSONL。

一致点按消息和工具批次确定，不能仅依据 `task.status`：

- 纳入完整写入 JSONL 的用户、assistant 和工具结果消息。已完整落盘的用户消息可以成为末条，不要求等到 assistant 回答。
- 来源正在运行、等待审批或存在排队任务时也允许分支。末尾尚在执行且未配对完成的工具批次整体回退到之前的安全边界；活动任务中较早已闭合的批次可保留。批次配对要区分任务及调用轮次，不能用整个文件的工具调用 ID 集合判断，因为跨任务可能复用 ID。
- 较早中断、取消或失败任务中的缺配对记录作为历史事实保留，模型视图沿用已有孤儿工具记录清理。这是完整历史原则的必要边界，不能因一次旧中断丢弃其后所有正常对话。
- 排队输入仅存在于任务行、尚未落盘的输入和流式输出片段不纳入。首次模型响应前若尚无可复制的落盘消息，拒绝并提示等待落盘或使用 `/new`；不能把空历史误报为完整分支。
- 严格解析完整 JSONL 行，损坏完整行明确报错；未换行的部分尾记录排除。回退或排除尾部时，结果说明实际分支点与未纳入内容；无法验证安全边界时拒绝。

复制保持消息内容、顺序、条目 ID 和来源关联可追溯，新会话有独立的 Ruukoto ID、pi ID、header 和历史文件。分支操作自身不修改、补换行或修复源文件；来源正在执行时允许其正常追加，但不能把它的正常写入算作分支操作写入。

不复制源任务行、任务队列或暂停状态、工具操作账本、审批及单次批准、目录占用、运行中 SDK、工作委托、SubAgent 身份和待投递通知。原任务、审批、锁及 SubAgent 工作继续归原会话；新会话在用户提交后建立自己的任务。

### 会话设置与共享配置

- 继承来源 `projectId`、`workspaceProjectId`、工作目录及其核实后的目录身份。已映射旧会话不得仿照 `/new` 改用展示目标作为资料身份，否则会改变指令、记忆、MCP、凭据与资料授权范围。
- 独立复制会话默认模型、思考档位、默认运行模式及 `confirmTools`，包括来源已选择的 plan、auto-review 或 full_access；条件更新版本属于新会话，不能把来源版本直接当作新会话已发生的修改。TUI 自动切换不得用不完整投影或其他会话设置覆盖后台已继承的值。
- 项目指令、Web Search、MCP、Jev、记忆、资料授权及凭据继续由同一个项目配置来源管理，后续变更共同生效，不为分支另建配置副本。来源单次审批、任务级 `grantedPaths` 和临时授权不继承。
- 读取资料与新任务执行继续核实当前有效范围；已撤销、过期或失效的授权不会通过来源关系恢复。分支不得扩大资料身份、工具能力或系统权限。
- 分支时不复制模型选择记录、prompt 调用记录和累计用量；新会话累计 token 用量从零开始，后续只统计自己实际发出的模型调用。

### 压缩点与工作清单

继承与所复制历史相符的 active 压缩点，建立独立记录与新 ID，保留生成来源。覆盖范围或指纹不匹配、已失效的压缩点不继承，分支后续按现有上下文机制重新处理。父会话后续替换或作废压缩点不影响分支，分支的压缩也不影响父会话；完整历史始终保留可查。

工作清单取所复制历史中最近一次成功 `todo_write` 的完整参数，父子后续各自更新；不取分支点之后的来源清单。新会话的模型上下文和 `/todo` 展示须一致，不能因为没有复制原 `tool_ops` 而丢失清单。`in_progress` 保留为步骤状态，不启动原任务；没有清单时沿用现有空清单行为。

### 原任务、产物与 SubAgent 结果引用

保留原任务、会话、产物及工作 ID 作为来源事实。来源任务可以被查阅，但不得投影为新会话自己的活动任务、队列、累计统计或操作入口。

- 快照里已有的产物引用按原资料身份只读查询，保持原归属及读取边界；附件集合不得从用户或模型正文里的任意 ID 自动授予资格。正在追加的 partial 产物如果进入来源读取范围，必须固定快照字节上限和当时状态，不能借读取把分支后的输出引入快照。
- 已包含的图片引用继续指向原不可变产物。历史图片进入新会话模型上下文时，应允许宿主核实的来源引用，重新校验归属、当前资料范围、MIME、大小及哈希；不能仅因引用的 `sessionId` 属于来源而报错，也不能放宽为任意其他会话的图片可读。来源缺失或图片损坏明确报错，不静默删图或发送缺图请求；不新增 TUI 图片上传能力。
- 分支点已有的已完成 SubAgent 结果可按原工作 ID 只读查阅，结果范围由宿主固定到快照内已有的结果任务和产物。只记录 work ID 不够：原工作后来继续执行或 Agent 被复用后，新任务及结果不能自动进入分支的来源结果集合。
- 来源只读资格仅用于资料及已完成结果查询，不用于原工作的继续委派、Agent 复用、消息、取消、关闭或改动汇总。新会话可按现有规则委派自己的新工作。拥有者原有控制面权限继续按原 ID 核实，不因建立分支而失效。
- A → B → C 的连续分支须保留快照内已核实的祖先来源资格及原引用边界，不能只允许直接父会话导致 C 中仍指向 A 的资料无法读取；也不能以祖先关系开放其全部资料或分支之后的新结果。

现有项目内普通资料读取范围继续按原规则管理；本单限制的是分支自动继承的历史、附件和来源结果集合，不把共享项目的资料授权改造成新的全量时间快照。

## 已核实实现基础与涉及范围

实施前 `/new` 通过创建空会话再切换，没有复制历史、来源关系或独立展示名称。消息权威副本是 pi JSONL，压缩点保存在 SQLite；清单在历史里，但当前 TUI 主要经工具操作记录恢复参数。

实现优先复用仓内严格历史解析、目录与身份校验、资料授权、压缩指纹、命令表和会话切换能力；不新增依赖，不建设通用分支图界面或第二套配置系统。预计涉及以下路径，具体落点由实现时阅读调用方确定：

- `packages/tui/src/tui/` 的 `commands.ts`、`app.ts`、`state.ts`、会话摘要/列表及清单展示：注册、补全、帮助、请求、完整元数据安装、切换、名称、来源和历史读取。`/artifact` 也要能定位已有来源引用，不能仅查新会话任务列表。
- `packages/control/src/` 的 `ops.ts`、`server.ts`、`protocol.ts` 与 `packages/runtime/src/runtime.ts`：增加薄的已认证分支操作，后台确定身份、快照、设置及创建结果，统一处理重启和失败。
- `packages/core/src/` 的 `types.ts`、`db.ts`、`store.ts`、`history.ts`、`history-index.ts` 与 `packages/agent/src/session-factory.ts`：持久名称、来源会话/分支点/资料边界、独立历史、清单参数恢复和创建幂等；按实际数据形状补迁移及相关 fixtures。
- `packages/agent/src/` 的 `context-assembly.ts`、`compaction.ts`、`inbound-images.ts`、`subagent-tools.ts`，以及 `packages/runtime/src/subagents.ts`、资料读取接线：压缩点继承、来源图片校验、固定结果范围和只读来源核实；原工作管理入口继续使用原会话归属校验。
- 会话创建应答、实时事件、重连快照与相关配置界面/演示数据：新字段及默认设置一致投影。旧会话迁移后名称与来源为空，继续使用原展示和读取规则；检查既有实例导入的字段清单与回退账本，避免丢失新增来源事实或绕过来源校验，不新增跨实例分支入口。

安装的 pi 0.85.1 提供 `forkFrom` 和 `createBranchedSession`，但不能直接认定满足仓库语义：前者可能静默跳过损坏行并给源文件补换行，后者会修改所持 manager 的会话 ID 和文件。源 Driver 及源历史保护、严格解析和宿主元数据边界须先核实，再选择最小可用实现。

## 创建一致性与失败恢复

创建请求使用持久幂等键。同键同参返回同一分支及原快照，同键异参明确冲突；明确再次执行命令产生新键、新会话。应答丢失时按原键核实，不生成新键盲目重建，也不把结果未知直接报告为未创建。

JSONL 与 SQLite 没有跨文件事务，不能宣称两者原子提交。实现须安排文件准备、元数据登记、应答及启动恢复，使复制失败、数据库失败或进程崩溃不会留下可选但缺历史的会话；遗留准备文件或未完成登记须可清理或核实恢复。禁止为回滚删除来源资料，成功分支的来源信息不能依赖 TUI 客户端文件保存。

创建应答、持久事件和快照必须一致展示新名称、来源、工作区归属、模型/模式及各自版本。另一已连接客户端和退出重进的客户端看到相同状态；只有发起客户端执行自动切换，其他客户端不被事件强制切换。

### 1. 固定 JSONL 的安全分支点

- 在 `packages/core/src/history.ts` 复用严格解析，增加只读快照选取：打开源文件并固定本次长度，只读该字节前缀；保留完整行，识别 header、条目链、宿主任务标记和工具批次。源文件身份或前缀不再可核实时拒绝，不补换行、不修文件。core 仍不写消息历史。
- 用 `TASK_START_MARKER`、`TASK_END_MARKER` 与当次任务状态区分历史终态和活动尾部；按任务及 assistant 调用轮次配对，不能全文件按 toolCallId 去重。活动尾部批次整体回退，早先终态缺配对保留；末条完整用户消息有效，排队输入和未落盘流式片段不纳入。元数据不足以证明尾部安全时明确失败。
- 产出固定的源身份、字节上限/指纹、末条 ID、消息数量和尾部排除说明。保留消息内容、条目 ID、顺序及来源标记；新 header 与 pi ID 由 agent 的历史文件准备函数生成，不能对源 Driver 持有的 SessionManager 调用分支 API。
- 用真实格式夹具测试空历史、完整用户尾、部分尾行、损坏完整行、活动未闭合批次、跨任务重复调用 ID、旧中断后正常对话及读取期间追加。除允许的来源正常追加外，逐字节确认源文件未被分支修改。

交付条件：只读快照结果可重复核对，安全点的回退理由明确；尚不创建可选会话。

### 2. 幂等创建、schema 与崩溃恢复

- `packages/runtime/src/branch-session.ts` 作为本功能编排入口，经 Runtime 调用；只接收来源会话 ID、可选名称、请求幂等键。由产品能力声明允许范围，后台核实普通开发身份、工作区映射、目录 dev/ino 和保护根。客户端不得提交目标文件路径、来源清单或继承授权。
- `packages/core/src/db.ts`、`types.ts`、`store.ts` 增加持久展示名、来源边界及分支请求记录。请求记录保存参数指纹、目标宿主/pi ID、自动编号、固定设置/压缩点/来源清单和文件准备状态；未发布的请求不进入 sessions 列表。自动编号在事务内按直接来源分配，同键读取原记录，同键异参报 `request_conflict`。
- 顺序固定为：验证并取得快照 → 事务保存不可变准备记录 → 在目标历史目录写独占准备文件并刷盘、安装最终文件 → 事务创建会话、来源记录、有效压缩点、完成回执与事件 → 提交后应答/广播。JSONL 与 SQLite 无跨文件原子性；每个崩溃点用准备记录恢复，绝不重新选取较新的源历史充当同一请求。
- 恢复时只处理属于该请求的目标文件；已有文件须核对 header、ID 和内容摘要。原前缀无法再读或不符则保留明确失败回执，不删除源资料、不发布缺历史会话。后台对分支文件缺失要拒绝打开，不能落入 `openPiSessionManager` 当前的“文件不存在则新建”兜底。
- 继承 `projectId` 与 `workspaceProjectId`，为模型选择、思考档位、默认模式和 `confirmTools` 初始化新会话自己的版本；不复制源任务、队列、占用、批准、选择记录和用量。新增 schema 与控制协议按实施时版本单调升级（本轮基线分别为 32、16），同步受影响 fixtures 与迁移测试。

交付条件：并发同键只发布一个会话，自动名称不撞号；文件写入/rename/数据库提交失败和真实后台退出窗口均无可选半成品；同键重试保留原快照，创建不调用模型。

### 3. 固定来源资料与结果的只读范围

- 在创建快照时从宿主任务、工具账本、入站媒体记录和已送达结果中核实引用，保存限定来源清单；正文里的任意 ID 不产生资格。保留原任务/会话/产物 ID，partial 文本产物固定当次字节上限和状态，已完成图片固定 MIME、大小与哈希。
- 将同一来源核实用于历史/产物读取、TUI `/artifact`、`inbound-images.ts` 的引用视图及模型请求前恢复；每次读取继续核实当前资料权限和文件内容。缺失、损坏、撤销或伪造引用明确报错，模型请求数为零，不能静默去掉图片。
- `SubAgentManager` 的结果读取允许命中固定的已完成任务/产物集合；work ID 本身不能开放后续结果。管理操作仍沿原父会话身份校验，分支不得继续、复用、发消息、取消、关闭或汇总源工作，自己的新工作照常创建。
- 连续分支继承已核实祖先条目及其原上限，与本次复制范围取交集；不能只保存直接父 ID，也不能查询祖先当前全部资料来补齐。来源任务仅是查询对象，不进入新会话活动任务、队列、用量或操作按钮。

交付条件：A → B → C 的图片/产物/已完成结果引用可用，源后续追加及复用结果不进入继承集合；无关会话和管理操作被拒绝。验证实际模拟模型 payload 与拒绝时的零请求。

### 4. 压缩点、清单与导入兼容

- 用 `compaction.ts` 的 `checkpointFingerprint` 核对复制消息，复制匹配的 active 压缩点内容并分配新 ID，保留生成来源；范围越界、失效或指纹不符时不继承。后续父子各自压缩，不复制选择/prompt 记录。
- 从复制范围内最后一次成功 `todo_write` 的配对调用参数恢复清单；通过后台派生视图供 `/todo` 使用，后续本会话成功写入覆盖该视图。模型上下文与 TUI 采用同一历史事实，不伪造源 `tool_ops`，也不依赖 TUI 已加载页是否包含原参数。无清单沿用空状态。
- 核对 `apps/ruukoto-code/src/legacy-import.ts`、`packages/channels/src/personal-import.ts` 和 `packages/core/src/import-support.ts` 的字段/表策略与回退账本：保留适用的名称和来源事实；缺少来源对象或新格式不能核实时明确拒绝/标明不可用，不丢弃来源字段后扩大权限。旧会话的名称和来源为空，原行为不变，不增加跨实例分支入口。

交付条件：分支后的第一次模型请求、`/todo`、重连以及再分支一致；原压缩点/清单继续变化不影响已有分支，导入与迁移保留原资料标识。

### 5. 控制面、TUI 与完整验收

- 在 control 的 `ops.ts`、协议分派和 Runtime 接线增加已认证 `branch_session`，扩展按请求键核实创建结果的能力；应答丢失后保留原请求键并核实，不恢复成“未创建”或生成新键重建。明确再次执行命令才分配新键。
- 创建应答、`session.created`、会话查询与重连快照下发一致完整元数据。当前 TUI 的创建事件会填默认 confirm/空字段，须修复投影；分支切换先安装后台结果，走保留目标设置的切换路径，避免 `switchSession` 的跨会话设置传播发出错误 CAS。只发起客户端自动切换，其他客户端仅更新列表。
- 在 `commands.ts` 注册 `/branch [名称]`、补全和帮助；复用命令历史绑定发起会话，失败保留父选择与草稿，成功让新编辑器为空并显示实际来源/分支点。会话列表优先使用持久名称，首个任务不得覆盖，普通未命名会话继续沿原摘要规则。
- 更新 README 命令表、usage 的共享工作目录说明、受影响模块文档与图解；在 CONTEXT 中补“会话分支”的已实现定义，明确与 Git 分支、worktree 和 SubAgent 的区别。提案随代码转 implemented，入口加笔记锚点。

交付条件：两客户端、断线重连和退出重进都看到同一名称/设置/来源；运行中、等待审批和有队列的源会话均可在安全点分支，新会话首次提交按现有目录占用等待，不重放源任务。
