# 双产品方向：已发布工单与拆分记录

状态：拥有者已确认“按草案发布”，24 张正式工单已发布。本文保留获批拆分，实施状态以各独立工单为准。

依据：[已确认规格](spec.md) 与 [ADR 0017](../../docs/adr/0017-two-agent-products.md)。24 张首期工单已按依赖顺序逐票发布，初始状态均为 ready-for-agent；有阻塞边的工单须等全部前置达到 resolved 后领取。下文保留批准时的交付与验收内容，原规格和既有父任务状态不变。

## 拆分原则与执行顺序

先兼容扩展新产品、工作区和通用 Agent 身份，各使用路径逐步迁移，最后收缩旧角色和写入口。旧标识只要仍用于历史、来源或权限校验就保留，不要求一次性替换全部存储字段；已有工具策略、审批、历史、上下文压缩、outbox 和 Linux 执行机制直接复用。

阻塞边只表达缺少前置就无法完成本票的交付。macOS 执行验证只阻塞对应执行接入，不阻塞工作区、SubAgent 或 IM 审批；同级通信不阻塞 worktree 并行；旧数据迁移不阻塞新实例能力。多个工单修改相同代码区域时需协调集成，这不单独构成产品依赖。

发布时可开始的前沿：01、03、05、08、11、20。建议先关注 03 的技术可行性，并按“本地编码 → IM 管理 → 长任务协作”安排里程碑验收；这一优先顺序不作为额外阻塞边。

后续阶段继续包括跨端共享记忆、正式 QQ 群聊外挂、邮件和 GitHub comment 对话。协议及剩余产品细节按既有规格在对应阶段确定，本稿仅为首期及必要的旧系统退役拟定可实施工单。

## 各工单共同的交付要求

- 每张工单完成从用户入口或现有可信入口到结果可查的路径，涉及的持久化、权限、交互和验证随本票完成，不另拆成数据库/API/UI 水平分层工单。
- 范围以当前可独立演示的行为为准，采用已有能力，不另建预期未来需要的通用平台。
- 完成相关端到端检查、类型检查及仓库要求的验证；同步本次行为涉及的运行说明和图解，验证记录区分模拟结果与真实环境结果。
- 每票保留失败与恢复边界，不把未知外部效果视为可以安全重试；不隐式扩大资料授权。

## 已批准的工单内容快照

### 01 — 两个产品独立安装和启动

**交付：** 以两个产品入口启动独立实例，配置、数据、凭据和停止操作互不影响；在迁移期兼容现有角色与旧数据。

**Blocked by:** 无，可立即开始

- [ ] 两个产品可以分别构建、安装和升级；升级或停止一端不要求另一端同时升级或停止。
- [ ] Coding Agent 不启动消息平台连接或个人调度；Personal Agent 可独立进入原有拥有者主会话。
- [ ] 同机并存时配置、数据锁和控制面不会串用；新产品不会误用开发本项目的隔离实例。
- [ ] 采用兼容扩展接入产品类型，保留旧记录的可读性，不在本单全局重命名角色或存储字段。
- [ ] 完成相关端到端检查、类型检查及仓库要求的验证；同步本次行为涉及的运行说明和图解，验证记录区分模拟结果与真实环境结果。

### 02 — 打开 TUI 时启动后台，退出后继续任务

**交付：** 拥有者直接启动 Coding Agent 即可进入任务界面，后台按需启动；关闭、重连和显式停止都有明确行为。

**Blocked by:** 01 — 两个产品独立安装和启动

- [ ] 后台不存在时按需拉起；同时打开两个终端只形成一个对应实例的后台。
- [ ] 关闭 TUI 不取消任务，再次打开能看到同一任务和结果，不重复提交。
- [ ] 显式停止只作用于指定产品实例；后台不可用、启动失败和不兼容版本给出明确状态。
- [ ] 沿用后台异常中断后的记录恢复与人工继续规则，不把连接丢失当作重新执行授权。
- [ ] 完成相关端到端检查、类型检查及仓库要求的验证；同步本次行为涉及的运行说明和图解，验证记录区分模拟结果与真实环境结果。

### 03 — 验证开发机执行权限的技术边界

**交付：** 用可复跑的最小原型验证 macOS 可用的受限执行方式，并复核 Linux 现有路径，为产品接入提供实际证据。

**Blocked by:** 无，可立即开始

- [ ] 实际演示授权工作目录内读取、修改和运行检查，同时拒绝未授权文件、网络与控制面授权材料访问。
- [ ] 验证子进程不能绕过边界；停止操作能回收实际执行进程，不能只终止界面。
- [ ] 明确受限模式与完全访问模式各自的系统身份、控制面保护和前置条件；完全访问不能伪造拥有者身份。
- [ ] 记录验证环境、可行方式、限制和复跑步骤；没有可行方式时如实记录阻塞，不能把 local 无隔离路径当作验证通过。
- [ ] 复用现有 Linux 后端开展检查，避免重复建设已经交付的容器和执行账户机制。
- [ ] 完成相关端到端检查、类型检查及仓库要求的验证；同步本次行为涉及的运行说明和图解，验证记录区分模拟结果与真实环境结果。

### 04 — 在开发机完成受限和完全访问任务

**交付：** 把已验证的执行方式接入实际开发任务，macOS/Linux 均可完成一次代码修改和检查，并由拥有者明确选择权限模式。

**Blocked by:** 03 — 验证开发机执行权限的技术边界

- [ ] 真实工具执行使用已验证的系统边界，能完成授权目录内的代码修改与检查。
- [ ] 越界操作遵循审批规则，子进程与实际文件、网络访问也受约束，不能仅检查工具参数。
- [ ] 完全访问由拥有者显式选择，使用已定义的执行身份，不获得控制面授权材料。
- [ ] 受限后端缺失或失效时在执行前拒绝，不静默回退到普通账户执行；停止和异常中断沿用未知效果规则。
- [ ] 完成相关端到端检查、类型检查及仓库要求的验证；同步本次行为涉及的运行说明和图解，验证记录区分模拟结果与真实环境结果。

### 05 — 按工作区创建和切换开发会话

**交付：** 拥有者打开目录后使用工作区与会话组织开发工作，一个根目录可以包含多个仓库，新入口兼容现有资料归属。

**Blocked by:** 无，可立即开始

- [ ] 通过可信入口打开目录，创建或复用工作区并新建会话，TUI 可列出、切换和恢复各工作区的会话。
- [ ] 按真实目录身份判定工作区，同名目录不会合并，别名不会意外重复创建。
- [ ] 一个根目录可以包含多个仓库；普通工作区列表不混入角色、群聊或内部 SubAgent 会话。
- [ ] 新增工作区归属时保留旧项目兼容关系，新会话从创建、执行到历史查看形成完整路径。
- [ ] 旧 API 和现有实例仍可读取，不要求一次性替换全部 Project 字段。
- [ ] 完成相关端到端检查、类型检查及仓库要求的验证；同步本次行为涉及的运行说明和图解，验证记录区分模拟结果与真实环境结果。

### 06 — 在工作区管理配置与资料授权

**交付：** 拥有者按工作区查看和修改指令、工具配置及资料授权，新任务使用这些配置，旧项目入口在迁移期继续兼容。

**Blocked by:** 05 — 按工作区创建和切换开发会话

- [ ] 从工作区界面或可信管理入口查看、修改指令及已支持的工具配置，新任务读取正确版本。
- [ ] 按工作区创建、查看和撤销资料授权，实际历史、产物、记忆查询及上下文注入执行对应边界。
- [ ] 多工作区并存时修改只作用于目标，符号链接和旧项目映射不导致改错归属。
- [ ] 保留旧配置的读取及兼容写入，先迁移真实调用方再删除旧入口，不另建一套与旧配置并行漂移的状态。
- [ ] 完成相关端到端检查、类型检查及仓库要求的验证；同步本次行为涉及的运行说明和图解，验证记录区分模拟结果与真实环境结果。

### 07 — 把旧开发会话和资料映射到工作区

**交付：** 升级旧开发数据后，拥有者能按工作区找到原会话、历史和产物，记忆及资料权限保持原有边界。

**Blocked by:** 05 — 按工作区创建和切换开发会话

- [ ] 同一旧项目包含不同目录时可形成可核查的工作区映射；目录失效或归属有歧义时明确列出，不静默猜测。
- [ ] 历史、产物、记忆来源、指令及工具配置仍可定位，保留旧标识作为必要的兼容来源。
- [ ] 跨项目资料授权映射不隐式扩大；撤销授权后的查询与上下文注入仍按来源校验。
- [ ] 迁移重复执行不重复创建，失败可恢复；源记录保留，不要求删除旧存储字段。
- [ ] 完成相关端到端检查、类型检查及仓库要求的验证；同步本次行为涉及的运行说明和图解，验证记录区分模拟结果与真实环境结果。

### 08 — 在绑定拥有者的 IM 私聊完成审批

**交付：** QQ 和 Telegram 中触发已有受控操作时，拥有者能查看审批详情、批准或拒绝，并继续收到任务结果。

**Blocked by:** 无，可立即开始

- [ ] 分别通过 QQ、Telegram 演示已有需审批操作的申请、详情、批准或拒绝、任务继续及原入口回复。
- [ ] 核实绑定拥有者、平台目标和配置版本；其他身份、旧绑定、失效或已消费的审批均不能执行。
- [ ] 审批响应直接进入审批处理路径，不排在正在等待审批的普通任务后面造成死锁。
- [ ] 批准绑定具体操作及范围并单次消费；平台身份不会变成任意控制面访问权。
- [ ] 处理重复消息、重新绑定和后台重启，不重复执行已获批操作；两平台分别验证入站失效边界。
- [ ] 完成相关端到端检查、类型检查及仓库要求的验证；同步本次行为涉及的运行说明和图解，验证记录区分模拟结果与真实环境结果。

### 09 — 通过 IM 检查并管理 Linux 服务

**交付：** Personal Agent 用专用账户检查指定测试服务，经 IM 批准实际执行需要授权的管理操作，并向原入口汇报。

**Blocked by:** 08 — 在绑定拥有者的 IM 私聊完成审批

- [ ] 完成服务状态或日志检查、提出指定管理操作、IM 审批、真实执行和结果返回的完整链路。
- [ ] 提供真实可验证的主机执行及必要提权边界，不能仅向 main 开放 bash 就宣称具备服务器管理能力。
- [ ] 授权固定操作和目标，控制面、后台凭据和其他任务权限仍受保护，越界及权限不足明确失败。
- [ ] 开发机器离线不影响此服务器侧流程；执行中断或结果未知不自动重发管理操作。
- [ ] Linux 验证使用可控测试服务，保留可复跑证据；模拟平台测试与真实服务操作验证分别说明。
- [ ] 完成相关端到端检查、类型检查及仓库要求的验证；同步本次行为涉及的运行说明和图解，验证记录区分模拟结果与真实环境结果。

### 10 — 保存、使用和撤销限定的长期授权

**交付：** 拥有者为具体操作和目标授予持续权限，后续任务可在有效范围内执行，撤销后恢复审批。

**Blocked by:** 09 — 通过 IM 检查并管理 Linux 服务

- [ ] 拥有者可以创建、查看和撤销一条明确的操作与目标授权，例如重启指定测试服务。
- [ ] 新任务命中有效范围可执行，换目标或操作必须重新审批；撤销后下一次执行不再放行。
- [ ] 执行前重新核实授权版本与范围，模型、子任务消息和普通平台文本不能自行创建或扩大授权。
- [ ] 单次批准不因长期授权机制而跨任务复用；不默认开放任意 root 操作，不放宽既有特殊审批规则。
- [ ] 完成相关端到端检查、类型检查及仓库要求的验证；同步本次行为涉及的运行说明和图解，验证记录区分模拟结果与真实环境结果。

### 11 — 主 Agent 委派通用 SubAgent 并收到结果

**交付：** 在已有开发会话和 main 中走通通用委派：登记工作委托，创建独立 SubAgent，执行有界任务、返回结果并保持空闲。

**Blocked by:** 无，可立即开始

- [ ] 主 Agent 可创建 SubAgent 并执行一个受控读取或分析任务，拥有者可查工作委托、子任务状态和结果。
- [ ] SubAgent 完成后保留身份与上下文、进入空闲，不自动关闭；主会话在等待结果期间仍能处理新消息。
- [ ] 工作委托与一次执行任务明确区分，跨主 Agent 对话轮次仍能关联原工作；重复委派不会重复创建同一次执行。
- [ ] 工具和资料由宿主限定；SubAgent 不能再创建下级、直接向拥有者发送或取得拥有者控制面身份。
- [ ] 新增通用身份与旧固定角色兼容共存，复用已有任务、历史、结果和幂等机制；本单不删除旧 coding 调用路径。
- [ ] 现有 main 的分析委派接入通用只读路径，保留旧修改委派兼容，避免最后清理时才补分析职责迁移。
- [ ] 完成相关端到端检查、类型检查及仓库要求的验证；同步本次行为涉及的运行说明和图解，验证记录区分模拟结果与真实环境结果。

### 12 — 继续委派、跨工作复用并显式关闭 SubAgent

**交付：** 同一个 SubAgent 可以继续原工作或接手新工作，保留上下文；主 Agent 和拥有者都能显式关闭它。

**Blocked by:** 11 — 主 Agent 委派通用 SubAgent 并收到结果

- [ ] 同一主 Agent、同一用户会话内，先补充原工作，再复用同一 SubAgent 承接另一工作，各次执行保留独立记录。
- [ ] 复用时重新确定当前工作、有效工具、资料、工作目录与权限，前次批准不延续。
- [ ] 任务终态、TUI 退出及空闲超时均不自动关闭；空闲不要求继续调用模型或运行工具进程。
- [ ] 主 Agent 和拥有者可查看并显式关闭，关闭后拒绝新委派；历史、产物及未汇总改动保持可查。
- [ ] 关闭与新委派发生竞争时结果明确，不能出现显示已关闭却继续接收任务的状态。
- [ ] 完成相关端到端检查、类型检查及仓库要求的验证；同步本次行为涉及的运行说明和图解，验证记录区分模拟结果与真实环境结果。

### 13 — 让同项工作的 SubAgent 相互通信

**交付：** 同项工作中的多个 SubAgent 交换有来源的消息并协作，复用到新工作后旧协作者失去通信资格。

**Blocked by:** 12 — 继续委派、跨工作复用并显式关闭 SubAgent
