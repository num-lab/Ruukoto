# 文件检索、后台进程与结构化提问

## 确认范围

2026-10-21 拥有者要求为文件检索、后台进程和提问制定方案，并确认：两端规划，先 Coding Agent；后台进程跨消息保留，直到显式停止或会话关闭；首版先停后台再修改同目录代码，保留现有占用规则。原方案轮只交付方案；拥有者随后授权接手 Coding 文件检索，其余切片仍仅为规划。方案与实施按[开发流程](../../.agents/skills/development-workflow/SKILL.md)推进。

先交付三个 Coding 完整切片，再接个人 durable；统一模型工具语义，不共用业务存储、Task 或审批记录。实现入口依次为[文件检索](issues/01-coding-file-search.md)、[提问](issues/02-coding-owner-questions.md)、[后台进程](issues/03-coding-background-processes.md)、[个人接入](issues/04-personal-adapters.md)。各切片可独立审查，不以只注册工具或只做客户端样例视为完成。

## 1. 文件检索

### 工具与结果

| 工具 | 参数 | 行为 |
| --- | --- | --- |
| `list_files` | `path?`、`glob?`、`limit?` | 递归列出匹配的普通文件；默认当前工作目录，`limit` 默认100、范围1–200 |
| `search_files` | `query`、`path?`、`glob?`、`ignore_case?`、`limit?` | 对文件内容作字面匹配；`query` 非空且最多4096字符，不接受换行；默认区分大小写，预览上限同上 |

`path` 必须是现有目录，按当前产品的文件读取范围解析；`glob` 为一个最多512字符的文件路径匹配式，不是 Shell 参数。首版不提供正则、语义搜索、索引、文件修改或自定义 rg 参数。无glob时遵循根内ignore并跳过隐藏文件；显式glob沿rg原生语义，可以覆盖ignore/隐藏过滤，但不能扩大资料授权。二进制文件、符号链接仍跳过且不跟随链接；排除父目录及用户全局ignore配置。模型参数描述与结果必须说明实际过滤语义，不承诺传glob后仍跳过全部隐藏/ignored文件。

结果提供检索根、相对文件路径；内容匹配另给1起行号和有界行片段。顶层区分 `scanComplete`（扫描是否完成）、`previewTruncated`（预览是否裁剪）与 `partial`（原始证据是否不完整），附已捕获条目数及可读产物引用；扫描未完成时不得把计数称为全部命中。预览每行最多2048字符、整体最多64 KiB，超出须标记。原流捕获最多8 MiB、单次最多10秒，达到预算即停止并保留 partial；没有分页游标或快照保证，较大搜索应收窄 `path`/`glob`。只因模型预览上限裁剪时继续捕获，完整证据由 `read_artifact` 读取。

### 执行与资格

共享参数、argv和结果解析放 agent，实际读取发生在执行边界内。使用宿主预先解析的已安装 `rg`，参数数组调用，不拼 Shell；固定 `--no-config --no-ignore-parent --no-ignore-global`，列文件使用 `--files --null`，内容使用 `--json --fixed-strings`，查询通过 `-e` 传入。不得在工具调用中自动下载 rg/fd；缺前提报 `file_search_unavailable`，不静默退到宿主扫描或任意 Shell。非UTF-8路径无法无损表示时明确返回不支持及部分结果，不生成替换字符路径。

Coding 的普通开发会话、Plan、只读/写入 SubAgent 和符合原规则的工作流步骤可用；宿主固定只读评审可用，后者仍无写资格。装配、发送前与调用门使用同一清单。权限来源是当前任务的工作区、readRoots、已授予路径与角色保护，不能借检索发现未开放资料；完全访问保留现有模式含义，不把工具过滤宣称为 OS 隔离。

个人端沿 `tools.json.workspace`、有效资料授权和原工作来源接纳，不能改用 `command.json` 的独立目录。目录身份、配置和授权版本在实际执行前复核；受限读取在只读原生边界内执行，完全访问沿现有文件工具权限，保护目录及子会话资料资格仍由对应入口核实。首版越界目录需先通过已有路径授予/资料管理入口开放，不新增递归扫描审批协议。

rg退出0为完成且有结果，退出1为完成且无结果；其他退出、权限错误或目录变化返回具名失败和已捕获部分。取消属于无写入效果，但执行未停止时仍保留原执行占用。搜索结果只是观察，后续 `read`/`read_file` 必须重新核实当前对象。

设计取舍见[受控文件检索笔记](../../.agents/notes/implemented/feature/2026-10-21-controlled-file-search.md)。

## 2. 结构化提问

### 工具与交互

`ask_user({questions: [{question, options?}]})` 一次接受1–3题；题目非空、每题最多2000字符；有选项时为2–5个互异非空单选项，每项最多200字符。每题始终可以自由输入，答案每题最多4096字符。首版不做多选、任意表单 schema、默认答案自动提交或模型指定通知目标。

工具提交持久问题后立即返回 `status: pending` 和“结束本轮，回答将作为后续拥有者输入”的指引。每会话最多一个待答批次；同一宿主工具操作重复只返回原结果，另一次创建返回 `question_pending`，不得覆盖旧问题。创建后的当前轮收窄业务工具，允许输出说明和宿主状态查询，不再据未获得的答案继续业务操作；装配、发送前与调用门共同执行，不能只依赖提示词。待答不增加 Task 状态、不占目录、不阻塞主聊天，其他拥有者输入仍按原队列处理。

普通开发和个人主会话的真实拥有者来源可提问，Coding Plan 可用。SubAgent、定时、GitHub、工作流步骤及内部汇总不开放：子 Agent 向上级报告缺少的信息；工作流沿原 `ask` 机制。完全访问不自动填写业务答案，也不因回答而绕过操作审批。

TUI/Desktop 显示题目卡片并逐题选择或输入，客户端管理问题引用、版本和稳定请求键；个人 CLI 及 QQ/Telegram 用列表和原宿主菜单回复，始终有返回、取消、状态与下一步。普通聊天不自动解释为答案，IM仅回复已送达原菜单可提交；不得要求人复制内部ID或输入JSON。

### 回答、来源与恢复

记录原工具操作、会话、实际拥有者输入、完整题目、入口代次、权限快照、问题版本与状态；回答记录原文、选择、实际回答者来源、稳定请求键、消费事实和续接引用。状态为 `pending → answered/canceled/stale`，终态不可覆盖；取消不产生答案或续接，入口失效使未答问题 stale。普通新消息、客户端断开和会话存档不自动取消问题；显式取消所属工作使其待答问题失效。创建任务自然结束或后台重启不删除已接纳问题。

回答必须逐题完整校验，不选中的选项不能被默认补齐；同键同参返回原回执，同键异参拒绝，两个客户端只有一个能消费。问题属于哪个原入口就沿该入口回答，个人另一IM平台不因共享main取得答题资格；可信本机入口可查状态和取消旧问题。续接按实际回答时的真实拥有者输入和当前权限接纳，不继承旧批准或通过参数指定权限。

Coding 在 `Runtime.submit` 的同一事务内核实并消费问题、保存答案、插入唯一排队 Task 及事件；提交后才应答与广播。个人在同一 durable commit 保存 answer-admission 和唯一续接后台 Task，Task以固定键向main admission，恢复只接回原 Submission。个人必须扩展 `personal-source.ts` 对新来源的校验，不伪装旧IM原文、不走默认来源兜底。应答丢失先查原回执；不换键新建续接，不重发未知IM通知。

模型续接输入包含原题目与实际答案，并持久绑定对应来源；原用户回答、规范化模型输入和实际请求证据都可重建。JSONL与SQLite不宣称原子，Coding沿原入队及历史恢复规则处理其间窗口。待答卡片、原答复和已消费状态须能从快照及事件恢复，禁止只存在客户端内存。

设计取舍见[持久提问笔记](../../.agents/notes/proposed/feature/2026-10-21-persistent-owner-questions.md)。

## 3. 后台进程

### 工具与范围

首版仅向完全访问的真实拥有者主会话开放启动；Plan、受限模式、SubAgent、定时、工作流与汇总不开放。保留 `bash`/`run_command` 原有前台语义，新增显式接口，不把 `nohup` 或 `&` 解释成持久执行声明。

| 工具 | 参数 | 结果 |
| --- | --- | --- |
| `process_start` | `command`，非空、最多16384字符 | 单次启动并返回唯一 `process_id` 与实际状态；不承诺服务已健康 |
| `process_status` | `process_id?`、`offset?` | 无ID时按创建时间倒序分页列本会话记录，offset默认0、每页最多20项，返回totalCount/nextOffset；指定ID时不得带offset，给状态、启动来源、退出观察、停止核实及日志大小 |
| `process_output` | `process_id`、`stream`（stdout/stderr）、`offset?` | 按原字节位置读取，默认0、每页最多32 KiB；返回实际片段、nextOffset与完整性，文本展示不得破坏原字节 |
| `process_stop` | `process_id` | 持久登记停止意图并立即返回；通过status核实停止完成，不把接纳当已停止 |

目录、环境、平台执行身份、模式和来源由宿主固定，不提供模型可选cwd/env/信号/端口或自由PID。首版无stdin、PTY、自动重启、启动脚本库、外部进程接管或后台重启后继续运行。每会话最多一个未停止核实的执行；stdout/stderr合计最多16 MiB，达到上限保留partial、登记停止并核实，避免日志无限增长。原始日志有私有、可校验的证据归属，进入模型的每个片段进历史/请求证据。

### 归属、占用与跨轮

后台执行归会话，保存启动Task/op、权限与入口快照及目录身份；独立执行单元不属于当前Driver的临时worker。先保存starting意图，原Task仍保留目录占用；在串行工具边界核实当前临时worker及后代停止，并准备可恢复的参考快照。随后同一事务重核活动Task、权限、目录与会话停止屏障，将原Task占用无空窗地转给独立执行，保存参考快照/来源和当前Task的观测阶段，再收窄当前轮工具门；完成后才允许一次实际launch，不能直接第二次申请同目录占用或先释放再抢回。

实际launch前持久认领一次，启动和交接成功提交后才返回；同一原操作恢复只查原执行、停止或核实，绝不重放命令。临时worker停止失败时保留原Task占用且不launch。转交后可信证明尚未启动且无残留时，才可释放独立预留；原Task仍活动时须重新核实全部资源条件才能转回原Task。launch是否发生或停止无法核实时保留独立占用和stop_unverified，不能转回后继续写入。交接前取消/失败须停止；交接后原Task自然结束、取消或失败不级联停止独立后台，需显式后台停止或关闭动作。

后台持有独立的目录写占用；同会话也不能绕过。启动当前轮在交接事务即进入内部对话，后续拥有者轮从独立执行的已核实参考快照与阶段接纳；必须扩展Runtime的conversationAdmitted/initialPhase及参考提供者，不能要求该会话曾调用agent_wait。显式开放本会话状态/日志/停止、提问和完全访问浏览器；不读取工作目录、不启动普通worker/MCP。新会话第一次启动也必须能在第二轮查停，停止核实后重新取得占用才恢复业务工具。

浏览器在该阶段的开放是本提案对当前执行阶段限定的明确扩展，仅限同一真实完全访问来源，仍逐调用核实权限和网页未知效果。需同时调整Driver发送前的browser/resourcePhase判断、实际工具装配和调用门，不只改白名单；来源不符时只允许无外部效果查询与可信停止。参考快照及观测阶段的实际模型输入均持久记录，资料已撤销则停止依赖该资料的模型请求，不借观测阶段重新读取目录。

修改文件、运行普通命令或同目录委派前须先停止后台，再重新获取目录。`agent_wait`只回收和让出当前Task的临时执行，不释放会话后台占用；依赖同目录的后台工作须返回明确冲突和停止指引，不无限等自己持有的目录。工作目录父子及dev/ino冲突沿现行规则判断。其他会话不得使用或停止此句柄；拥有者可从已认证的会话后台列表选择并停止。

### 停止、关闭与恢复

状态区分 `starting/running/stop_requested/stopped/stop_unverified`，命令的exitCode/signal单独记录；主进程退出不能单独推出stopped。主动停止、日志预算耗尽、原入口/实际授权撤销、目录身份失效、应用后台关闭均先持久记录，再停止并核实整个执行单元及管道；停止失败保留占用和现场。仅改变会话默认模式不追溯撤销原授权，但新受限任务不能操作或继承原完全访问能力。

当前产品只有存档，没有持久会话关闭协议。首版在会话菜单新增“结束本会话后台”，承担拥有者确认的关闭行为：先登记该会话停止屏障，阻止此前已接纳但尚未交接的启动，停止全部既有执行，核实后报告；保留会话和历史。关闭窗口、退出TUI、切换会话和存档不执行该动作。以后的新拥有者请求可显式启动新执行，不新增通用会话终态或自动恢复服务。

应用重启先恢复原记录并停止/核实遗留执行，不恢复运行、不重新执行命令。Linux复用原机器/boot/scope/invocation/cgroup身份；macOS扩展现有监督器的进程唯一身份、后代归属和持久停止回执，达不到真实核实条件就保持stop_unverified。任何平台都不得从裸PID/PGID恢复后直接发信号。平台支持和恢复验收未通过的切片不得以降级启动器交付。

进程停止不证明命令的外部写入回滚。结果未知沿原操作事实保留，退出码和日志仅作为观察；不能把进程已退出当作业务成功或可重试证明。日志/状态查询跨轮仅取得原记录可见性，不能扩大原资料或凭据范围。

### 预览与个人接入

开发服务由命令明确绑定本机地址；日志中的URL仅是候选，模型用已有浏览器真实访问核实，不扫描或自动开放端口。首版验收为启动服务→工具返回→后续浏览器访问→下一拥有者轮查询→显式停止→普通写工具重新取得目录；不承诺服务存活时热更新源码。

个人端使用独立durable记录和工具Task，复用低层执行与停止原语，不接旧Store、ApprovalGate或ArtifactStore。启动只接受主会话真实完全访问拥有者来源，并要求已有 `command.json` 固定目录；这是显式新增的主会话工具，不向子工作/定时传播自由Shell或长期授权。原工作、入口和权限按durable逐次核实。

个人端必须新增共享durable目录claim，而不是只在后台启动时查询一次：后台starting预留、普通run_command的prepare/start、文件write_file的批准消费都在各自commit中双向核实并取得同一认领，覆盖现有父子路径和dev/ino冲突规则。普通命令持有至停止核实，文件写持有至写入/关闭观察完成；效果或停止未核实按原操作保留。这样既阻止后台之前已在途的写入，也阻止后台之后的新写入；即使完全访问、子工作或定时命令也不能跳过本结构化入口的认领。恢复核对claim与原操作/来源反链，不能由Task意外终态清除。接入前升级扩展并拒绝旧未决状态，旧程序缺扩展须拒绝，不能忽略新后台或继续走旧无claim写入口。

## 4. 持久化与交付约束

Coding新增问题与后台执行持久记录、对应事件和快照；后台目录占用需能区分Task与独立执行持有者，`endTask`不得清除后者。运行态、状态事件及停止/回答消费须在各自Store事务提交后应答广播。core仍不写会话JSONL，文件日志发布与数据库提交不声称跨存储原子。新schema和控制面协议在各切片实施时从实际版本递增，不在本方案预约固定数字。

保留当前精确版本拒绝策略，不默默迁移旧库、填默认授权或清空已有档案；实施前告知新档案/对应旧版本查阅要求，跨实例导入需显式支持新增记录或在有记录时明确拒绝。个人扩展同样先核实旧未决工作及格式，不用假恢复材料自动启用。

新增工具schema、结果、错误、收窄阶段和续接输入必须取实际请求快照验收；记录toolSchemas/systemPrompt估算前后数字。后台身份、内部路径、客户端请求键不进入面向人的操作步骤。跨层失败使用带code类型；失败结果必须说明影响、保留事实和当前可行下一步。

## 5. 验收总则

每个切片完成工程审查与适用产品验收后才交付。定向离线检查证明业务契约；macOS/Linux真实执行证明文件范围、进程身份和停止；真实模型证明工具选择、待答结束和续接；TUI/Desktop/个人IM分别验收可读交互。缺外部前提就保留未验证，不能以模拟通过替代。各工单列出最小检查集合，不默认跑全仓检查。
