# Agent 工作流实施计划

要求以[规格 A1–A12](spec.md)为准，理由与备选见[决定草案](../../.agents/notes/proposed/feature/2026-10-12-agent-workflows.md)。本计划已通过独立方案审查，拥有者于 2026-10-13 确认完整计划及 Git 范围；产品代码尚未实施。代码基点为 `d1b1b543c3ad6063331bbe1bf6328396392f38e4`。

## 一、执行归属与数据

工作流定义是可复用的脚本；工作流运行是一次固定脚本版本、参数与来源授权的后台工作。步骤是脚本按稳定键登记的工作，尝试是步骤的一次实际 Agent 执行。已有工作委托、SubAgent 身份、任务与工具操作继续分别记录；这些概念不互相替代。实现时按领域规范补充 CONTEXT.md，当前不把计划写成现行产品行为。

core 保存定义版本、运行、步骤、尝试绑定和人工问题。运行至少记录来源产品/项目/用户会话/发起任务、可选调度运行、资料引用、权限模式与版本、有效能力和资源范围、脚本与参数摘要、资源限额、结果回报目标及其配置代次。脚本文本、完整入参、步骤输入输出和控制结果都必须可重建；大正文沿用产物存储，小状态与事件在同一 SQLite 事务内提交。文件先落盘、核实内容摘要后才登记引用；不宣称 SQLite、产物和会话 JSONL 跨文件原子。

步骤绑定既有 Task、SubAgent 与工作副本，增加由宿主识别的工作流归属。运行协调者是宿主代码，不占用一个长期等待的模型任务，也不伪装为 main 或 scheduled 会话。普通父任务结束不使已登记运行消失；运行自身的授权与取消状态决定其后续步骤资格。

工作副本准备、补丁提取、汇总及原生命令检查使用运行派生的短期宿主操作任务，明确标为宿主执行而不创建模型 SDK 会话；这些任务真实持有 worker、工具操作账本和源/目标目录占用。任务权限从运行绑定解析，不借用已经结束的发起任务。将 `Runtime.executeWorkCopy` 目前依赖活动父任务及 Driver 的执行登记接到具名执行归属：普通任务继续由 Driver 持有，宿主操作任务由其执行器登记、停止和核实；二者共用 launcher 与收尾规则，不能删除活动执行检查。此类任务不计 Agent 尝试数，但实际运行时间计入预算；取消、崩溃和停止未核实都沿该真实任务保留占用及操作效果。

所有创建与控制操作有稳定请求键；先查重，再检查容量或执行预检。同键异参明确报冲突。取消、答复、资源调整与新步骤登记通过运行版本和同步事务仲裁，不能靠脚本内变量决定宿主状态。

## 二、受限脚本与步骤结果

优先验证[QuickJS/WASM 独立进程候选](script-runtime-research.md)。脚本进程只具有解释器及有界宿主消息通道，不得到模型凭据、控制令牌、Runtime 对象、Node 对象或直接文件/网络能力；步骤自身仍按现有访问模式执行。脚本隔离适用于来源为 full-access 的运行，因为编排程序与实际工具是不同的执行入口。

脚本只需 Agent 调用、人工问题、受控成果汇总和进度输出四类宿主原语；串行、分支、循环用 JavaScript，批处理助手在同一受控上下文中实现，不另造配置语言。每个产生持久状态的调用必须给出本运行内唯一的稳定步骤键，宿主记录调用类别、完整参数摘要、依赖与结果；无效参数和引用不存在的步骤在执行前拒绝。

Agent 步骤显式声明 `dependsOn`，宿主要求依赖已登记，并在失败、取消或跳过时阻止依赖步骤实际执行。生成脚本的说明必须要求完整声明结果依赖；宿主只保证声明过的依赖，不能从任意 JavaScript 语义推导全部数据依赖。分支可以读取成功值或失败信息，预期步骤失败返回具名结果；脚本语法、越权宿主调用与协议损坏属于运行错误，不与业务失败混淆。

步骤默认使用独立上下文；验证步骤新建验证者，读取实际副本及验证标准，不以修改者的自述代替验收。首版模型选择固定到运行，不新增逐步模型路由。结果支持文本或 JSON；JSON 使用已有 typebox 校验依赖及有界 schema 预检，在产物与步骤结果中保留原始输出和失败事实。格式不符不等于操作未执行，也不自动重跑整个 Agent。

脚本与参数在运行开始时固定，恢复不重读已修改定义。禁止宿主时钟、随机数、外部模块、直接 I/O 和未管理定时器；需要这些输入时由固定参数或已记录步骤结果提供。脚本执行时间、解释器内存与栈、消息和结果大小、待处理宿主请求与日志均有宿主硬限制；解释器堆上限不冒充整个进程 RSS 保证。具体数值随隔离实验确定，必须写入运行器测试与诊断。

## 三、步骤权限与资料范围

新增工作流步骤身份绑定或等价的具名绑定，由 core 的身份解析统一读取。模型与脚本不能提交 main 身份、审批来源、凭据或宿主内部字段。步骤的有效能力是运行开始保存的来源能力、当前仍有效的资料与配置、步骤主动收窄三者的交集；来源既有的受控编码委派能力也可通过工作流使用，不能把 main 没有直接 edit 工具误解为不允许其已获准的修改委派。

工具检查同时覆盖装配、模型请求前与实际调用门。不能仅修改 SubAgent 白名单；须接入 `executionProfile`、Driver 的个人绑定核实、host-data Accessor、SourceResolver、MCP、应用数据、scheduler、service 和资料/产物读取。个人业务数据的归属保持来源主身份，执行者仍是工作流步骤；步骤只获得显式传入或在来源范围内核实的资料，不复制主会话完整历史或所有凭据。

允许读取本次运行明确依赖步骤的结果与产物，并在每次送入模型前复核资料引用；拒绝跨运行、未授权项目及 prompt 快照。所有新增模型输入在子会话历史、选择记录或原文快照中可重建。原项目的资料撤销和入口配置换代不能因旧结果已缓存而失效。

访问模式在运行开始固定，会话以后选择新默认值不反向改写运行。显式停止/撤销运行或来源资格失效会阻止后续调用；停止后重新授权另走可信拥有者入口。单次批准与限定长期操作授权不作为工作流可自行复制的能力。计划模式不发起可执行工作流，普通 SubAgent 与步骤不能创建嵌套工作流；这些入口资格由宿主校验。

## 四、并发、资源与等待

按来源会话统一计数普通 SubAgent 和工作流 Agent，默认上限三；多个工作流共享名额，满额排队，不因单次扇出报容量错误。队列的领取、取消、恢复与实际任务登记必须一致；普通消息与已在途子任务继续遵守既有并发约束。运行协调器和等待中的人工问题不占 Agent 名额。

一百次限额计每次实际开始的 Agent 尝试，包含安全重试和验证者，缓存结果与纯脚本处理不计。计数在启动前预留/核实，不能由三个并发启动同时穿透上限；自动重试单步骤最多两次，仍受整项预算约束。预算调整只从拥有者控制面或认证 IM 入口接受，脚本和模型工具参数只能申请更小的限额。

一小时按运行状态下的累计墙钟时间计算，不把并行步骤耗时相加。仅在没有可执行或活动工作、整项运行等待人工时停计；仍有其他分支运行时继续计时。暂停区间单独持久化；重启无法准确确认最后一段计时或停止状态时，先暂停等待核实，不能把消耗清零或自动补足预算。到限先持久化暂停意图，禁止新步骤并停止在途执行，按操作账本处理被中断的副作用；已有成果保留。

人工问题是业务步骤，不是审批请求。保存问题、选项/回答约束、运行与步骤 ID、来源入口、版本和回答；只有匹配拥有者的可信答复能原子地消费一次。取消、问题失效、代次变化和迟到答复不能恢复执行。工具审批沿既有机制执行，业务回答不能消费工具批准；两类等待都不占住主聊天。

## 五、恢复、失败与取消

运行区分排队、运行、等待人工、暂停及终态；终态区分成功、部分失败、失败和取消。暂停持有具体原因，如限额、效果未知、来源失效或停止未核实。脚本正常返回后仍由宿主核对所有登记工作，不允许丢弃失败项后宣称全量成功；尚有任务、未决问题或未核实执行时不能记成功终态。

恢复从固定脚本与参数重建控制过程，按步骤键和完整输入摘要复用已完成结果，按已记录的结果交付顺序重放宿主 Promise；避免 `Promise.race` 在重启后改变已作出的分支决定。步骤键重复异参、调用次序无法与既有控制记录对应或缺少必需结果时拒绝恢复并保留现场，不猜测另一项工作。编辑脚本或入参创建新运行，不偷偷替换旧运行的程序。

尚未实际执行的已登记步骤在运行授权有效、未取消且无未知效果或未核实占用时恢复排队。已开始的步骤先核实已有任务、操作账本与执行单元退出；已完成结果直接复用。只读或可证明未执行的失败可在预算内重试；任一已开始写操作效果未知则整项运行暂停，绝不只根据步骤声明为只读就重跑。已知写入生效但最终结果缺失也不得自动重跑，拥有者需核实后决定续接或另起工作。

只对可证明安全重复的步骤做自动重试，不建立通用副作用补偿或 exactly-once 承诺。普通失败结束受影响分支，其他独立分支继续；依赖它的步骤标为跳过并记录原因，最终报告明确覆盖范围。

取消先提交意图和事件，再停止脚本与名下全部排队、运行、等待审批/人工的任务；阻止新登记、迟到结果驱动、回答和批准恢复执行。停止未核实保留占用和现场，界面显示尚有执行待核实；已修改文件、已发送消息与其他外部效果不撤销。单独取消一个工作流不取消同来源的其他工作。

## 六、工作副本与结果送达

修改步骤复用现有独立 Git worktree 与单一写入者机制。首版批量代码修改限定为 Git 工作区，非 Git 分析和其他业务工具仍可用；拥有者已在 Q12 确认这项范围。非 Git 批量修改在产生写入前明确拒绝，不降级为并行原地写；需要该能力时另行设计独立副本与受控回写。

完成修改并核实写执行已停止后，在副本占用保护下由宿主提取相对基线的完整补丁，固定其字节、内容摘要、基线与工作/运行/步骤身份，作为不可变的待验证成果。验证者拥有独立上下文，只读的是这份被审成果；需要落盘的检查在按相同基线和补丁重建的独立验证副本/临时区执行，不能写回待汇入成果。验证记录绑定该成果摘要、基线、验证任务和真实结果，脚本传入“通过”文本不能替代记录。

受控汇总只接受本运行中通过相应独立验证的不可变成果。取得副本与目标占用后，再核实修改工作的当前成果摘要仍匹配；验证后发生改动或续派形成新成果时旧验证失效，需重新提取和验证。实际套用使用已冻结的补丁，不能重新生成另一份差异套用。复用 work-copy 的预检、套用与事件账本，目标占用持续到串行整体检查收尾，宿主操作任务持有这段真实执行。每个副本冲突零套用，先前已成功汇入的其他副本仍保留；不承诺多份副本整批原子回滚。主聊天可继续，涉及同一目标目录的写任务按占用规则排队。

子步骤结果交给工作流协调器，关闭该路径原有的逐个父模型唤醒；普通 SubAgent 送达不变。最终结果先提交，再以运行 ID 和终态版本的稳定键进入现有内部队列与回报通道。dev 增加可信的最终结果唤醒，排在当前用户任务之后；main 沿原拥有者入口汇报。结果生成、父级汇总与对外发送分别去重；取消仅报告已取消及未停止事实，不发送成功汇报。

由定时任务发起的工作流属于该调度运行：调度关闭须等待整个工作流，取消计划级联取消运行，最终只由调度运行已有回报路径发送一次，避免工作流和调度各发一份。入口配置失效保留成果与未送达原因，不自动改发其他目标。

## 七、定义与交互入口

定义库放在各实例已有 agentDir 下的 workflows 目录，名称映射到脚本文本；保存和加载时形成内容版本。已被运行引用的版本不可变；手动编辑当前文件只影响之后的新运行，历史版本与运行保留。路径、名称、UTF-8、体积、语法与符号链接的范围检查在登记前完成，不能让保存入口任意覆盖宿主文件。

模型得到少量宿主工具用于发起、查询、取消、保存已有脚本及读取编写说明；工具携带可信任务上下文，不允许填写授权或提高预算。命名定义通过现有命令入口带参数运行，临时脚本也经过相同加载、版本与权限核实；不强求兼容 Claude Code 文件格式。

控制面提供统一的列表、详情、定义管理和运行控制。TUI 展示阶段、步骤结果、等待原因、用量与状态，支持答复、暂停、恢复和取消；CLI 提供同等可脚本化入口。个人 IM 使用绑定拥有者的明确命令处理答复与控制，优先解析原始文本，避免把引用、外部正文或模型生成的文本当作控制操作。格式错误或定位歧义明确拒绝，不交给模型猜测要批准哪个问题。

## 九、验收与检查

最小端到端样例使用六个有明确预期的输入，其中一项故意失败：独立处理、独立验证、汇总覆盖清单。编码样例验证独立副本和目标工作区的实际字节；个人样例包含联网工具替身、应用数据以及绑定 IM 的等待与最终回报。先离线证明编排，再以真实模型和真实平台独立验收，不把替身结果记为产品体验通过。

关键故障包括：登记后未启动崩溃、写操作已生效但结果未登记、结果落盘后未回报、父任务已结束后仍创建/汇总副本、宿主操作任务取消且 worker 停止未核实、脚本取消后迟到 IPC、预算抢位、人工回答与取消竞争、资料撤销、IM 代次变更、工作副本替换、验证后改字节/续派、验证命令试图写被审成果、多个运行争同一目录，以及恢复时 Promise 返回顺序改变。每项断言状态、事件和真实外部效果，不能只检查捕获了异常。

各单运行 `npm run check:static` 与直接相关测试；具体文件见工单。增加解释器依赖和 worker 打包时跑 `npm run build`、lint/typecheck，并同步 README、docs/development.md 与 pre-push-checks 的相关入口。总体实现跨 core、agent、runtime、control、channels 和 tui，07 属于确实跨全仓的改动面，应执行一次完整 `npm run check`，先前失败或相关修改才复跑。

当前计划资料只运行 notes 与文档检查；不因写计划运行应用测试。四格脚本实验、真实 worker、真实模型与 IM 尚未执行。任何环境前提缺失都保留未验收及恢复条件，不标为通过。
