1. 核实既有 SubAgent、结果送达、权限、恢复和产品入口；源码核实与用户目标讨论并行，事实问题不交给拥有者猜测。

3. 将已确认的目标、非目标、关键契约和验收标准收敛到规格；技术取舍及既有决定的冲突另写 proposed 决策笔记。未回答的推荐项不记为已确认。
4. 形成按依赖排序的实施步骤、源码与文档影响范围、最小验证集合，提交独立方案审查。先修正可由事实解决的问题；涉及拥有者取舍的意见集中回到讨论。
5. 所有设计分支收敛后，请拥有者核对最终共同理解；确认范围清楚且方案审查无阻断，才交实施。

## 源码核实与设计约束

只读探索者 `workflow_feasibility` 于 2026-10-12 在上述基点核实，以下为静态源码事实，不是行为实测。

| 已有事实 | 影响后续计划的原因 |
| --- | --- |
| [SubAgentManager.assertSource 与 delegate](../../../packages/runtime/src/subagents.ts) 要求普通委派的父任务仍处于活动状态，并复核模式与权限版本。 | 主 Agent 先结束、后台编排继续发起步骤，需要明确持久执行归属与授权来源。 |
| 同一父会话最多三个活动 SubAgent 执行任务，超额报错；[常规子代理工具](../../../packages/agent/src/tool-availability.ts) 只读能力为 read/read_artifact，修改能力另含 edit/write/bash。 | 大规模扇出需要排队；联网调研和个人事务步骤是否扩大工具能力，必须结合 Q1、Q2 决定。 |
| [编排器](../../../packages/runtime/src/orchestrator.ts) 已登记子任务终态与结果；[父级送达](../../../packages/runtime/src/parent-delivery.ts) 默认把结果交给父模型。 | 工作流程序消费结果与最终送达需要独立明确，避免每一步都唤醒父模型并重复汇报。 |
| [运行时恢复](../../../packages/runtime/src/runtime.ts) 保留中断、效果未知与未核实占用；开放调度运行的未执行队列有恢复例外。 | 必须分别处理从未执行、已知完成与效果未知，不能将重启统一解释为重跑。 |
| [模型目录](../../../packages/agent/src/model-selection.ts) 已有选择校验；现有委派入口取默认模型，没有每步模型参数，未找到模型最终输出的 JSON Schema 契约。 | 每步模型选择和结构化结果需要单列范围，不能视为现成能力。 |
| [WorkerLauncher](../../../packages/agent/src/execution/launchers.ts) 已有独立进程与 OS 执行边界；当前依赖及源码没有现成 JS 编排解释器。 | 已确认采用受限 JavaScript；宿主调用协议、执行中止和资源隔离须先验证，尚未选定解释器依赖。 |
