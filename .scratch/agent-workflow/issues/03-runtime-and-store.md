# 持久工作流运行与协调器

Status: resolved

## 目标与边界

落实[规格 A3、A4、A7、A8、A9](../spec.md)的执行基础，按[实施计划](../implementation-plan.md)一、二、四、五节建立宿主持有的运行、步骤与尝试；先使用假 Agent，不绕过[04](04-step-capabilities.md)的权限接线直接放开业务工具。

## 实施与交付

1. 在 core 定义运行、步骤、尝试、问题和不可变定义版本，状态与事件同事务；保留任务/工作/Agent/操作的现有归属，schema 与协议版本单调升级。
2. 在 runtime 新增协调器，接入 02 的脚本进程和队列；固定来源、脚本、参数与模型，发起任务结束后依靠运行自身授权继续工作。
3. 按稳定步骤键与输入摘要幂等登记，记录宿主结果交付顺序；复用已完成结果，恢复未执行工作，检测脚本重放分歧与缺失资料。
4. 实现来源会话共享并发、尝试数和时限计费、显式暂停/恢复/取消。通过真实事务竞争验证抢位、取消与启动、预算调整与排队的顺序。
5. 贯通已有任务和工具操作效果分类；已执行写操作结果缺失、格式失败或停止未核实不得变成自动重试。普通任务/普通委派的恢复行为单独回归。
6. 实现运行派生的短期宿主操作任务和具名执行登记，真实持有工作副本操作的 worker、账本与占用；改造 executeWorkCopy 的依赖入口以支持它，保留普通 Driver 路径，不伪造仍活动的原发起任务或删除停止核实。宿主任务不创建模型会话，不计 Agent 尝试，执行时限仍计费。

主要落点为 packages/core/src 的 schema/store/types/session-identity、packages/runtime/src 的新协调模块、runtime、subagents、orchestrator；涉及控制面共享类型但不提前实现完整 UI。

## 实施结果

core 的 `workflow.ts` 与六张工作流表保存不可变定义、完整运行来源/参数/模型、步骤、真实执行、问题和控制回执；状态和事件同事务，schema 升至 36、协议升至 20。协调器通过 02 的固定入口重放调用与结果交付，绑定既有工作、SubAgent、Session、Task 和 Runtime 的同一工具操作账本；普通出队、结果注入、唤醒和工作控制排除工作流绑定，普通委派保持原行为。

同来源共享三个实际 Agent 名额，启动事务预留尝试和预算；默认 100 次尝试、一小时累计墙钟，安全重试最多两次，整项人工等待才停计。版本与稳定控制键仲裁取消、暂停、资源调整和回答；冷启动独立保留停止/计时核实。写入效果未知、已生效但缺输出、格式失败后的写入以及缺失/损坏结果都阻止重跑，原始超限输出保存到产物并核实摘要。

`workflowHostOperation` 和 `HostExecutionManager` 以运行派生任务持有真实 worker、账本、实际单元和目录占用。`executeWorkCopy` 支持具名宿主执行，原任务结束后可真实创建与汇总 Git 副本；不创建模型会话、不消耗 Agent 尝试。已登记未执行操作和完整宿主缓存按原稳定键恢复，停止未核实保留占用。跨实例导入明确拒绝含执行绑定的源，不能丢弃绑定后将步骤当普通 Agent 继续。

领域术语、模块地图、core/runtime/execution/workflows 说明、导入边界、开发测试导航与最小检查入口已同步。[实施决定](../../../.agents/notes/implemented/architecture/2026-10-13-workflow-runtime-and-store.md)记录理由、备选和旧笔记审计。
