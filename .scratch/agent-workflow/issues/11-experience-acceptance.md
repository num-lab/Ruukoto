## 目标与边界

逐项验收[改进规格 E1–E10](../experience-spec.md)。依赖 [08](08-workflow-sidebar.md)、[09](09-internal-report-visibility.md)、[10](10-agent-wait.md)实现和文档完成；[12](12-im-progressive-controls.md)不在本次交付内。原 [07](07-acceptance.md) 的有效证据与未验项目保留，本单只对新内容作结论。

## 方案

1. 汇总实际 diff、各单最窄用例和文档，独立实现审查者从需求与源码核对，不以工单“已完成”代替证据；每个缺陷退回所属工单。
2. 组合场景：从侧栏启动至少两个可区分运行，其中一个产生失败与待答问题；主 Agent 等待期间继续聊天、回答、暂停/恢复、再等结果，检查状态、资源占用、隐藏提示及唯一最终报告。
3. 编码产品跑真实修改/验证/汇总及非 Git 子任务等待；个人产品核实新输入打断与固定来源结果送达。故障注入覆盖断线、客户端重启、后台重启、重复点击、版本变化、来源失效、停止/效果未知与消费竞争。
4. 按实际跨模块范围运行检查；若符合总计划预计的全链路改动，执行一次完整 `npm run check`。macOS/Linux 验证原生停止/恢复，Linux 用 `ssh tx`；真实模型以 `RUN_MODEL_CHECK=1` 显式运行，真实 IM 需原绑定入口。
5. 拥有者验收常驻侧栏可读性、焦点/返回/窄屏操作，以及是否能判断“仍在工作、需我介入、已经结束”。分别记录工程和产品结果；必要外部环境缺失保留恢复条件。
