# Agent 工作流规格

本规格记录已确认的产品要求；实施入口见[工单](issues/01-workflow-design.md)，具体实现与验证见[实施计划](implementation-plan.md)，外部机制见[Claude Code 调研](claude-code-research.md)。方案已通过独立审查，拥有者已于 2026-10-13 确认最终共同理解。

## 已确认目标

拥有者于 2026-10-12 分别对三轮 Q1–Q2、Q3–Q6、Q7–Q11 回复「全部按推荐」，于 2026-10-13 对 Q12 的完整计划与 Git 范围核对回复「接受」。以下要求已确认，不构成代码已实施或已验收。

| 编号 | 要求 | 验收方向 |
| --- | --- | --- |
| A1 | 第一条验收场景为批量任务：并发分析或修改、独立验证、最终汇总；这个场景不排除其他用途。 | 选择一组可核对的输入，逐项对应处理结果与独立验证结论，最终汇报明确失败及未完成项。 |
| A2 | ruukoto 与 ruukoto-code 都支持工作流，共用编排能力，各自沿用已有工具、权限和交互入口。 | 两产品分别从其适用入口完成同类编排，核实能力与结果归属没有跨产品混用。 |
| A3 | 采用模型生成、宿主执行的受限 JavaScript，支持串行、并发、分支和有停止条件的循环。脚本负责调度 Agent 与处理结果，具体操作通过步骤内的工具完成。 | 脚本驱动各类控制流；直接文件、命令和联网操作不能绕过步骤工具与其权限检查。 |
| A4 | 工作流独立在后台运行，主会话可以继续响应；进度可查询，结束后统一回报，工作流有自己的执行记录和授权来源。 | 发起任务结束后仍可按工作流的有效授权执行后续步骤；新用户消息不被整项编排占住。 |
| A5 | 步骤可以使用来源授权范围内的工具，覆盖编码、联网调研和个人事务；单步可以收窄，不扩大来源权限，不继承单次批准。 | 分别验证适用工具可用、来源没有的工具或权限不可得、收窄有效及单次批准不能复用。 |
| A6 | 拥有者可明确要求工作流；模型也可在当前任务授权内选择使用，并受宿主资源上限约束。外部资料中的指令不能成为新的启动授权。 | 显式与自主发起均进入相同的来源和资源核实；外部输入不能伪造拥有者选择或扩大工作范围。 |
| A7 | 独立分支在其他步骤失败时继续，依赖失败结果的步骤停止；复用已完成结果，恢复尚未执行的步骤。只对可证明安全重复的操作有限重试；写入效果未知时暂停并请拥有者核实。 | 故障注入证明无关分支可完成、失败依赖不运行、恢复不重复已完成步骤、效果未知不重发，最终报告与实际执行记录一致。 |
| A8 | 同一来源会话共用三个 SubAgent 并发名额，满额排队；每次最多一百次 Agent 执行尝试与一小时运行时限，人工等待不计。拥有者可调整，模型不能通过编排接口自行提高；超限暂停并保留成果。 | 普通委派与工作流共享计数，重试计入尝试数，缓存复用不计；并发抢位不超额；人工等待、超限暂停、调整后恢复均可核对。 |
| A9 | 首版支持命名保存、查看和参数化运行；每次运行固定脚本版本与参数，修改形成新版本，先通过文件与现有交互入口管理。 | 原运行及其恢复继续使用原脚本与参数；修改后的定义用于新运行；定义不可读或校验失败明确拒绝，不静默换版本。 |
| A10 | 支持持久化的显式人工等待步骤；回答绑定具体运行与步骤，等待期间日常聊天及其他工作继续可用。 | 重启后问题与已有回答仍可查；重复、过期、跨运行或错误来源的回答不能被错用；业务回答不构成工具批准。 |
| A11 | 修改步骤在独立工作副本中工作，经独立验证后，在原任务授权内汇总到目标工作区并运行汇总后检查。冲突保留双方成果并报告；提交、推送和发布沿用明确授权。 | 验证者有独立上下文，结论绑定实际汇入的成果版本；失败成果不自动汇入，单份副本冲突不套用该份改动；此前已汇入的成果保留，汇总后检查失败可见，不声称已回滚或已交付。 |
| A12 | 首版批量代码修改限定为 Git 工作区，复用现有独立工作副本与受控汇总；非 Git 分析及其他业务工具仍然支持。 | 非 Git 批量修改在准备副本或产生写入前明确拒绝；非 Git 分析与已授权业务工具不因这项限制被拒绝。 |

范围取舍与备选理由见[工作流决定草案](../../.agents/notes/proposed/feature/2026-10-12-agent-workflows.md)。

## 完成与取消

正常返回脚本结果不直接代表所有工作成功；宿主必须核对本次运行登记的步骤、尝试、问题、工具操作和停止状态。失败、跳过与未完成项始终进入最终报告，取消后保留历史与成果。涉及具体运行状态、幂等键、通知时序和取消核实的实现细节由实施计划持有，并交独立审查。

## 范围之外

首版不建设可视化流程编辑器、插件市场、分布式执行集群、跨产品实例编排或嵌套工作流；不承诺外部副作用恰好执行一次或取消后自动回滚。普通 SubAgent 的既有身份与工具范围保持独立，新增能力通过明确的工作流步骤归属启用。

步骤首版沿用运行开始固定的模型选择，复用现有模型目录；逐步骤选择不同模型不作为本次新增能力。执行结果提供文本与经校验的 JSON，足以支撑分支与汇总；不增加模型供应商专用的结构化生成接口。

非 Git 批量代码修改不属于首版，已确认范围见 A12；需要该能力时另行设计独立副本与受控回写，不降级为并行原地写。
