# 2026-10-11：macOS 已归属后代夹具的 CI 失败修复

来源为 [98a46ed 的 CI](https://github.com/num-lab/Ruukoto/actions/runs/38129294407)。两个 Ubuntu 矩阵均通过；macOS / Node 22.19.0 与 24.15.0 各只有一项失败，均为 `test/101-native-macos-helper.test.ts` 的控制通道关闭回收用例。

两个矩阵都在调用 stop 之前的 `停止前心跳确实增长` 断言失败。上一轮修复的未知孤儿用例在两个矩阵均通过，生产监督器未改变。

## 反馈与修复

旧用例有限 shell 循环每 20ms 写心跳，宿主只固定等待 100ms 判断增长；既没有等待新写入事件，也没有保持夹具生命期。停止后固定等 80ms 断言冻结也不能证明进程退出。

在本机 Node 22.19.0 下，把旧 shell 的心跳间隔改为 500ms、循环上限改为 20 以保持异常夹具有界，即可确定性复现相同的停止前心跳断言失败（2840ms）。真实 C 监督器与宿主等待期限没有改动。

最终夹具用同样 500ms 心跳的 detached Node 代替短命 sleep 循环。后代先安装 TERM handler 再报告父 PID；停止前等待新心跳，后代写出的 TERM 标记证明它确实收到并忽略 TERM。回执仍严格要求 `reaped: true`。

后代仅继承 stdout，并且字面程序从不自行关闭该 FD；因此监督器自己的主 PID 退出不能让共享管道提前产生 EOF。停止回执后，宿主在既有 5 秒等待期限内等整个 pipe 关闭，再断言心跳未继续增长，独立核实后代已退出。20 秒自然上限使异常夹具有界，`release` 只在 `finally` 写入；成功还须 TERM 标记、true 回执、EOF 和心跳冻结全部成立。退出证据不单独判定退出原因。没有新增生产接口，没有放宽退出证据或信号身份规则。

独立退出证据另有故障注入负例：仅在 `/tmp` 编译监督器副本，让它漏发 KILL 且谎报 `reaped: true`。新夹具通过回执与 TERM 标记检查后，在共享管道关闭等待处失败（11180ms 含清理），因此不能靠主 PID 退出或谎报 true 掩盖仍活着的后代。负例期间未替换正式二进制或生产源码；临时测试、副本源码与二进制已删除。

决定与备选方案见[异步测试阶段核实](../../.agents/notes/implemented/testing/2026-10-11-await-observed-async-phases.md)。
