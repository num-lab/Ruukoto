# 原子发布 macOS 受限启动标记

Status: ready-for-human

当前环境验收范围沿[06](06-node24-ci-budget.md)的 Node24 双平台和 90 分钟 job 预算；本工单已有 Node22 反例保留为历史证据。

## 目标与边界

测试精简的固定工作区全量发现普通 reviewer 子任务未到 completed，原现场不足以直接确定原因。静态检查另发现 macOS 可信 bootstrap 直接写 native-started，读端每十毫秒看到文件存在但未写完就立即拒绝启动并缓存停止未核实。本工单依据 Node22/24 的受控红绿修复这个确定竞态，不把机制复现冒称历史失败的直接取证。

保持 Seatbelt 权限、五秒启动期限、十二秒停止期限、严格标记内容、机器错误原因和停止身份。Linux 路径、持久身份格式、执行预算及工作进程协议不变。

## 方案

在每单元已有私有临时目录写完 native-started.tmp，再 rename 到 native-started，成功发布后才 import worker。读取端仍只接受 started，缺失继续在原预算内等待，坏值或不可读仍按原失败路径保留执行占用；写入或发布失败不得导入 worker，不捕获并伪造成功。沿用完整标记和监督器 started 两份证据的原启动判定。

只扩展现有 test/101-native-macos-helper.test.ts 的真实 Seatbelt bootstrap 用例：在可信 Node 的创建/截断与写入之间建立受控停点，原版确定拒绝、修复后标记尚未发布且正常放行后启动成功；真实停止后核实已回收，继续保留宿主 FD 不继承、缺标记失败及错误携带停止身份。补验坏值和写入/发布失败不加载 worker。探针与清理只处理自有进程和目录。

## 审查与验证

独立方案审查核对所有调用方、可信加载次序、同目录 rename 权限、严格读取和停止未核实语义。局部红绿、helper 整文件与真实 reviewer/快照组合通过后，再按主工单运行固定工作区完整检查；不增加重试、skip 或放宽期限。文档同步 docs/modules/execution.md，理由写独立 bug-fix 笔记并与原生执行决定互链。主工单继续持有远端四格验收。
