# 提高 CI 时限并结束 Node 22 支持

Status: ready-for-human

## 目标与授权

拥有者在测试精简后的 CI 仍超时后明确要求“直接提高 timeout-minutes，同时为简化维护，删除对 node22 的兼容”。本轮基点为 `947bba81`，工作区干净；该指示取代 02 的四格矩阵与四十五分钟上限，不重新征求已有授权。保留 macOS/Linux、文件并发二、现有独占清单、离线开关与失败透传；不增加自动重试或放宽单个测试/产品期限。

## 已知事实

[CI 40079786517](https://github.com/num-lab/Ruukoto/actions/runs/40079786517) 检查 `5cd1ec5a`：Linux/Node24.15 在约三十一分钟成功；Linux/Node22.19、macOS/Node22.19 和 macOS/Node24.15 的 annotation 均明确超过四十五分钟。提高 job 预算不代表已证明 macOS 的全部失败原因或保证下一轮通过。

## 方案与范围

- 将 job 的 timeout-minutes 从 45 提高到 90；移除 node 矩阵轴，setup-node 固定 24.15.0，仅保留两个操作系统任务。
- 根、七个共享包、两个产品、Desktop 与独立 foundation 的 engines 统一为 >=24.15，两个 lockfile 只同步对应本仓包元数据，不更新依赖解析。setup、桌面登录/受管环境及部署示例按同一最低版本拒绝旧 Node。
- 工作流 worker 和 MyGo sidecar 的构建 target 升到 node24.15。移除两处为 Node22 保留的 SQLite 编号参数具名绑定适配，改用 Node24.15 已实测支持的位置绑定；SQL、schema 和查询语义不变。去掉同步查询注释中过期版本限定。
- 同步 README、AGENTS、开发/使用/桌面/产品/部署说明及提交前检查；新笔记部分取代旧策略并互链，旧历史结果和归档不改。02 当前验收改为由本工单持有的 Node24 双平台与九十分钟预算，已有真实覆盖和未完成远端验证继续保留。

## 验证与交付

独立方案审查无阻断，按[决定](../../../.agents/notes/implemented/testing/2026-10-24-node24-ci-budget.md)实施。扩充原 setup 与桌面环境用例，核实 Node22、24.14 拒绝，24.15 及更新版本通过；桌面旧版本沿原 node_unavailable，不改认证或环境采用规则。SQLite 沿真实账本及聊天结果回归，确认重复编号参数的各条查询仍正确。执行静态检查、相关定向测试、工作流构建与 MyGo sidecar 构建验证；本轮不机械重跑全量，原始 CI 与新配置远端验收分开记录。独立实现审查亲自执行版本拒绝/最低版本通过的最窄检查。

产品体验验收不适用；Node22 不再受支持属于拥有者明确选择。CI 新两组结果仍需后续推送才能取得，本轮不自动推送或部署。
