# Coding Agent 侧聊规格

## 目标与确认依据

让拥有者在 Coding Agent 主任务继续执行时，通过 `/side` 打开可连续追问的独立侧聊，讨论当前上下文而不把侧聊内容带回主 Agent。本文持有产品要求；理由与技术取舍见[决策记录](../../.agents/notes/implemented/feature/2026-10-29-coding-side-chat.md)，实施与验证见[工单](issues/01-side-chat.md)。

拥有者于 2026-10-29 在本聊天的三轮 grill-me 访谈中，分别以「全部按照建议」确认 Q1–Q4、Q5–Q8、Q9–Q12。下表是这些确认的合并记录。

## 已确认的行为

| 编号 | 约定 |
| --- | --- |
| R1 | 首版只在 TUI 的普通 Code 会话提供 `/side`；它打开侧聊输入，不切换当前主会话，不进入主会话消息队列或引导路由。 |
| R2 | 每个主会话关联一个持久侧聊。首次打开固定主会话已落盘历史的安全快照，随后只延续侧聊自己的历史；再次打开不刷新来源快照。 |
| R3 | 快照复用会话分支的完整行与工具批次规则，可能排除正在生成的文字和活动尾部未闭合工具批次。空主会话可以从空快照开始；无法核实的历史不得静默降级为空白侧聊。 |
| R4 | 主任务运行、等待审批或等待后台结果时均可打开并使用侧聊；不停止、引导或恢复主任务，不改变主队列暂停状态、审批或目录占用。 |
| R5 | 侧聊只做无工具问答，不装配文件、命令、搜索、MCP、记忆写入、提问工具、SubAgent 或工作流工具。资料不足时说明缺口，由拥有者补充文本或回主对话处理。 |
| R6 | 侧聊不自动写入主会话历史、工作结果送达或共享记忆。所有普通 Agent 的历史、产物及记忆来源接口默认排除侧聊，包括指定会话、任务、条目或产物 ID 的直接读取。 |
| R7 | 首版没有专用回传入口；拥有者可自行复制侧聊内容到主输入框，随后沿普通消息或显式引导处理。复制前后不建立后台自动回传关系。 |
| R8 | 侧聊显示为主输入框上方的悬浮层，有独立滚动与输入焦点，保留部分主对话和主任务状态可见；窄终端沿用悬浮层，不增加左右分屏。 |
| R9 | Esc 只收起侧聊，保留本次 TUI 内的草稿、历史、滚动位置及正在生成的回答；侧聊内 `/interrupt` 只中断侧聊当前回答。Ctrl+C 先清侧聊草稿，草稿为空时退出客户端，后台两边的任务继续。 |
| R10 | 切换主会话时收起侧聊；回到原主会话后 `/side` 重开原侧聊。已接纳的消息与历史跨 TUI 退出、断线和后台重启保留；草稿不新增跨进程持久化保证。 |
| R11 | 侧聊回答期间可编辑下一条草稿，本轮结束后才能发送；首版不提供侧聊消息排队、重排或引导。 |
| R12 | 每次发送侧聊消息时沿用父会话当时选择的模型和推理档位，固定到本次任务；没有独立模型、推理档位或权限模式配置。 |

## 交互与上下文边界

裸 `/side` 创建或重开当前主会话的侧聊，本身不发送模型请求；首版不增加行内提问参数、侧聊列表、重置、嵌套、转普通会话或从侧聊分支的入口。侧聊输入不复用主会话的全套 slash 命令分发，`/interrupt` 绑定当前侧聊任务，不能携带其他会话任务 ID；其余主会话管理命令不在侧聊中执行。

固定快照指主会话的安全历史前缀，不等于打开瞬间主 Agent 最近一次实际模型请求，也不包含工作目录的文件快照。项目指令、长期记忆和技能目录原本不属于会话历史，首版不另行复制或动态加载这些参考块；历史里已经记录的技能正文与工具结果仍可阅读。主会话后来新增的消息、工作清单、后台观察、SubAgent 或工作流结果不能自动注入侧聊。侧聊使用说明其问答职责与无工具限制的简短系统提示；不借用主 Agent 的执行任务或待办语义。自动上下文压缩沿已有机制在侧聊内独立进行，不更新父会话压缩点。

侧聊的来源消息只用于模型理解，不复制来源任务、审批、临时授权、工作管理关系或累计用量；侧聊的消息与用量归自己的任务。复制历史中的旧工具调用仍是历史，不获得当前可调用能力。历史图片与附件沿原有来源核实、模型输入能力和资料授权检查处理，不因为侧聊无工具就省略已有信任边界校验；首版侧聊新输入只接收文本。

侧聊的消息、系统提示、快照来源及压缩结果必须通过既有 JSONL、持久字段、选择记录与 prompt 快照重建，不引入只存在于客户端或模型内存中的隐藏输入。拥有者仍能通过侧聊入口查看自己的记录；侧聊从普通会话列表和普通会话搜索中排除。

R6 是应用资料接口的默认隔离，不是完全访问模式下的 OS 保密承诺。主 Agent 若经文件工具读取后台数据，继续受已有保护根与执行规则约束；本功能不另建 OS 沙箱。并行调用仍可能遭遇 provider 限流，不承诺外部服务容量或零延迟。

## 中断、失败与恢复

收起、退出客户端与主任务终态都不取消侧聊。后台重启将侧聊的 queued、running 和 awaiting_confirmation 任务全部标为 interrupted，保留已接纳输入与已有输出，不自动重发模型请求。queued 包括已经接纳但尚未启动的崩溃窗口，不能沿普通会话「保留 queued 并暂停队列」处理；侧聊恢复后可接受新的追问，无需 `/resume-queue` 或 `/continue`，不改变父队列状态。

一次侧聊调用失败只结束该侧聊任务。上下文超限或发送前校验失败不套用普通执行队列的暂停流程，拥有者可编辑并再次提交；每次仍重新核实预算、历史、图片、授权与模型配置，损坏或资料不可用时继续明确拒绝，不自动重放旧输入、不跳过校验。若出现不应存在的侧聊执行占用，按异常报错，不能用自动恢复释放它。

创建或提交应答丢失时，客户端保留原请求键并向后台核实；未确认接收前不换键重发或恢复成可重复提交的普通草稿。多个客户端同时打开只发布一个侧聊；同时发送最多接纳一个未终结任务，另一端保留草稿并刷新侧聊实际状态。忙碌判断由后台事务保证，不能只靠输入框禁用。

来源历史损坏、已发布侧聊 JSONL 缺失、身份绑定异常、模型配置更新中、模型能力不匹配或发送失败都给出受影响操作和可执行下一步；跨层错误使用类型与 code。侧聊失败不改父任务、审批或目录占用，不能静默新建空历史或回退为普通 Code 会话。

## 产品验收

真实 TUI 中由拥有者确认：主任务工作时可侧聊多轮且主状态继续更新；能看清当前输入归属；长回答独立滚动且输入框始终可达；窄终端、中文输入、字母 q、粘贴和已有快捷键正常；主草稿不被覆盖；Esc、`/interrupt`、Ctrl+C 和切换主会话的作用范围符合 R9–R10。重新进入 TUI 后能找到原侧聊，并能辨认它仍基于首次快照。

真实模型验证无工具问答、沿父模型选择及主侧并行。以上在实施后验收，本次方案不声称任何真实客户端或模型验证已通过。
