# 配置更新与迁移规格

本规格由拥有者在 2026-10-25 的对话要求产生：解除已审计的不必要停机、无关条件、展示字段阻塞和配置永久不可变限制；保留单一写入者、实际权限、旧操作身份、未知效果核实与历史证据。当前授权为制定方案，尚未实施。执行入口为[工单](issues/01-remove-global-restrictions.md)，理由与旧决定审计见[决策提案](../../.agents/notes/proposed/architecture/2026-10-25-operation-scoped-configuration.md)。

## 目标与范围

| R2 | PA Skills 保存、导入、启停统一停存启 | 原后台在线写入；后续请求采用新选择，原请求和历史正文不改 |

不引入通用配置平台、第二套任务状态机、新依赖或自动业务重试。不新增 PA 桌面 Web Search/IM/命令/服务页面；这些配置继续由已有 CLI 提供，引入的独立操作只是拆开原来捆绑的保存。浏览器配置的全面热更新、秘密上传或环境变量管理、跨机器接管旧进程、整个档案迁机、历史/托管包物理回收不在本期。

## 共同契约

### 单一入口与单一写入者

个人配置的解析、档案身份、条件修订和保存由 personal-settings.ts 持有；CLI、桌面 remote 和本机控制面共用它，不在 renderer 或 CLI 复制保存判断。在线使用已持锁后台及既有 Harness，不再另开 Storage 写活跃档案；离线执行者必须取得同一档案锁，使用同一声明式保存逻辑，不创建 Harness、不执行模型或外部工具。

在线不可达或应答丢失不代表后台已停止；取锁失败保持拒绝。离线保存与“启动服务”是独立操作，不检查原模型 key 或 systemd 启停权限。线上缺凭据、无效新端点等不相干故障不阻止保存其他目标。生产与开发实例都允许该实例自身在线保存，开发器仍拥有进程生命周期。真实模型测试只能由显式动作使用实际后台环境执行，离线结果为未验证。

保留期望修订与实际修订比较。MCP 编辑以服务 ID 为生效范围，expectedRevision 与 savedRevision 仍是整个 mcp.json 的文件修订，整文件请求明确表示替换全部服务；过期修订不自动合并。配置写入可以按档案短暂串行，运行中工作不因此等待其他模块的长操作；等待某目标生效不得占住全局写入互斥。

共享一个文件的多个对象区分“文件保存未核实”与“已证明保存、等待对象生效”：前者暂时阻止该文件的后续保存，其他文件可继续；后者只阻止同一对象的另一笔修改。MCP B 后续保存基于已经提交的完整候选文件，保留 A 的已保存候选，但只发布 B 的运行选择，不顺带发布 A；A 的恢复沿不可变保存记录证明原修订到当前修订的完整链，不仅比较当前文件是否等于 A 的候选哈希。缺链或当前文件不符最后保存事实时，重新进入该文件待核实。整文件替换与任一服务待生效操作冲突，必须先完成或显式取代它。

### 保存、生效与请求回执

一次配置操作只替换一个配置文件或托管清单。复用现有原子文件替换和 durable 存储；以 session-scoped 的设置操作 family（按稳定操作键）与配置版本 family（按目标及版本）保存候选和阶段事实，每次阶段追加事实，既有事实/版本不可覆盖。已有模块配置 entries 在根会话存在后继续追加；不再新增另一份文件账本。候选包含的凭据仍为原有引用；不记录解析出的 key 或认证头，不把私有端点和候选正文放进公开回执。

在线通过 Harness.commit，离线持锁后通过 SDK 公共 createSession(storage).commit 执行相同设置事务；不启动 Harness、不调用私有根会话创建方法，也不直接编写 durable 底层 SQL。首次配置尚无根会话时，同事务创建 PersonalFormatDoc 和设置初始化证明，配置 family 使用 session scope，不向不存在的 ROOT_CONVERSATION_ID appendEntry。启动识别“仅完成配置初始化、尚无根会话”的明确合法状态，由 Harness.root 正常创建根；已有历史库缺根或缺初始化证明仍拒绝，不能借此放宽坏库检查。

回执区分“未保存”“已保存、等待相关操作结束”“已保存、生效失败”“已生效”“结果待核实”；至少返回操作键、目标、savedRevision、effectiveRevision 和结构化原因。程序管理键和版本，用户只见操作、影响对象与可执行下一步。保存成功不等于连接测试通过，生效表示运行时已选择该修订，凭据/网络健康单独报告。

持久写意图及候选版本 → 单文件原子替换 → 提交保存事实和模块配置选择 → 发布对应运行对象 → 登记实际生效。配置文件与 SQLite 不宣称原子；写意图/回执由个人档案持有，remote 只保存或投影它自己的接纳关联，不能成为第二份生效权威。离线读取同一回执，不需要启动 Harness。

| 失败窗口 | 结果与恢复 |
| --- | --- |
| 写意图前的解析、授权或修订冲突 | 明确未保存，原配置继续可用 |
| 已有意图，文件仍为原修订 | 核实后记未保存；不自动再次执行保存 |
| 文件已为候选修订，保存事实/运行对象尚未发布 | 已保存未生效；只暂停受影响目标的新接纳，旧操作仍用原版本 |
| 运行对象已发布，生效回执未完成 | 核实当前对象/持久选择的修订，补全原回执；不再次写配置或发送业务操作 |
| 文件既非原修订也非候选修订，且没有完整后继保存链证明，或无法核实来源 | 保留待核实并报告文件内受影响目标，不猜测成功、回滚或另建请求重试 |
| 共享 SQLite I/O 或 commit 采纳失败，SDK Session/Harness 已失败 | 实例停止新接纳，按原关闭/锁规则保留并恢复档案；不能吞掉错误继续调用失败的 Harness |

目标级隔离适用于共享存储仍可信的对象发布失败、连接失败或应答丢失。SDK 会因 Storage 错误关闭 Session，配置更新不改变这一故障归属；共享存储失效可以影响整个实例，不能以“无关操作继续”为由降级必要保护。

同键同摘要返回原结果；同键异参拒绝。断线和客户端关闭不取消已接纳的配置操作。关闭后台时等待已进入提交段的配置操作落到可恢复阶段后才关库、放锁。相同目标等待生效或结果未知时保留一笔原操作；其他目标可以继续管理。候选未生效前不通过自动覆盖旧文件回滚，恢复只完成可证明幂等的配置发布，不重放旧模型、MCP、IM 发送或服务操作。

等待生效的已知候选可显式“撤回待生效更改”：按当前 savedRevision 新建一次受条件保护的配置操作，引用仍在生效的旧版本作为新候选，并记录取代关系；不删除原回执、不把原保存改成未保存。原结果未知时必须先核实，不能撤回一个尚不知是否发布的操作。普通保存不提供自动重试或自动回滚。

### 新旧操作、收窄权限与定时范围

本次实际模型请求、工具接纳、后台进程和发送操作记录所选配置版本；它们的旧结果/恢复始终使用原选择，不能从同名模型、服务或当前目录重新路由。新配置只影响后续接纳。Skills 从下一次模型请求刷新；Code 原有任务钉版语义保持。

权限收窄另在实际发送/执行前核实当前资格。停用技能/服务/IM 后，尚未开始的相关调用不得凭旧快照取得新的执行权；已经开始的调用保留原目标、原凭据引用和结果未知事实，停用不声称取消或远端停止。旧响应中的工具调用必须能定位生成它的请求选择；更新期间无法保持身份的调用明确拒绝，不悄悄改用新配置。

定时计划继续保留创建时的范围，不因新增服务、允许工具、资料授权或新环境自动取得能力。纯展示名不应取消计划；已经因实质变化失效的计划，即使配置改回，也不能自动恢复资格。新旧版本和原请求证据只追加，不改写旧 entry 或计划快照。

## 各模块的应用方式

### 只读、Code 模型和诊断

CLI 在选择“查看”前通过 executePersonalSettings / personalControl 查询，不先抢离线锁。Skills/MCP 复用既有查询；服务和命令补固定配置摘要查询，不开放任意文件读取。只读不检查模型凭据、不枚举无关未决业务。离线只读仍持锁。

Code 在 RuntimeModels.saveCatalog 的差异判断中排除 provider.name、已有模型.name、按唯一 ID 调整列表顺序，以及真正新增的模型 ID；仍走原修订、目录校验、完整模型栈准备/发布/回滚、停止等待。新增 ID 必须与 SDK 实际模型目录核对，不能把覆盖 SDK 内置模型误当新增。重复 ID 拒绝；协议、地址、认证、headers、已有模型参数/能力、未知高级字段和删除继续使用受影响 provider 的占用与引用检查。

rg 每次实际调用复用 resolveFileSearchExecutable，不增加轮询或缓存；诊断区分“现有 PATH 内尚未安装”和“后台环境未包含安装目录”。

### Skills 与模型

Skills 复用现有 ManagedSkillsStore、原包发布和下一请求 prepare；在线修改由宿主串行管理清单。重构发送前 verify，使已固定请求的正文与引用仍可核实；不能拿当前清单变化直接否定全部旧请求，也不能使新调用复活已停用项。

模型由 Harness 持有当前选择和仍被旧操作引用的 provider。每个配置版本使用不可复用的内部 provider ID，按 personal-<配置版本> 登记；同一 modelId 更换 endpoint/API/key 引用也不能覆盖旧 provider ID。SDK 的 generation checkpoint 只保存 provider/modelId，后续 request/poll/abort 会重新查 MutableModels，因此必须先注册新 provider，再更新后续请求的 AgentDoc；冷启动先按持久版本恢复旧 provider，再 resume 原 generation。用户仍看到普通模型名，内部 ID 不成为设置输入。

复用 SDK 已有 MutableModels / registry 更新能力。主会话、子会话、新委派、定时会话、自动审查和图片能力判断均取得本次选择，不继续捕获初始 options。正在发送的请求用旧对象结束，新请求用新选择；缺少新凭据时可保存并显示不可调用，不回退到其他模型或借旧 key。provider 释放必须晚于所有活跃 generation、poll/abort、自动审查及恢复引用结束，不能仅依据主聊天已返回。

### MCP、电脑与 Web Search

MCP 模块内部维护当前服务选择，每次接纳保存具体服务、工具定义和凭据引用；更新 A 不改变 B 的已开始调用。原调用的恢复不再要求当前整份 MCP 配置完全相同。保存不再检查未修改服务的凭据；启用、改变认证、新增服务仍校验本次引用。撤销文件不降级匿名。停用/删除先阻止该服务的新接纳，保留旧记录与原配置版本供核实。

电脑正常暂停/继续/恢复沿既有入口。修改电脑目标或允许工具，只等待该电脑连接与操作达到可证明的边界；保留原观察/停止证据，不能重用旧截图接受新绑定。普通 HTTP 服务和聊天不因此停止。

MCP 改显示名仍保留完整配置修订和历史，但不重建无变化的连接、不撤销原批准或使定时计划失效。由每次成功保存的配置版本链证明原 generation 到当前之间连续仅修改 services[].label 与宿主生成的 generation；兼容判断由 MCP 模块持有，调用/计划消费者不各写一份。新链记录离线保存的中间版本，不能只看启动时才追加的旧 MCP entries；迁移前没有完整保存链的两代不能猜测兼容。

兼容关系作为内存派生索引，从已核实配置版本链重建，只有对应持久提交成功后才更新；不再增加一份持久索引作为权威。查询绑定索引构造时的当前修订，迟到索引不得用于新修订。引用损坏必须报错。端点、凭据、服务集合/ID、启停、工具定义/允许范围、CUA 或格式版本任一步变化都截断兼容关系，改回也不恢复旧资格。工具 description/title 会进入模型定义，不按纯展示字段放行。

PA Web Search 从 tools.json 中捆绑的资料目录和 HTTP 凭据配置拆出独立更新操作及运行选择；沿用现有 CLI 的启停/凭据引用交互，不要求为了搜索创建资料目录。旧 search 字段按兼容规则读取为初始版本，新操作不切换无关 HTTP/文件操作的配置身份和批准。先停用阻止新搜索，在途搜索保留原参数与证据；每工作次数上限和资料授权规则保持。已有定时计划不会因重新启用搜索而扩大创建时工具范围。

### IM 在线启停与换绑

Telegram、QQ 各自持有当前配置、连接和停止信号。候选账号/拥有者/凭据通过现有配对流程核实，CLI 不用自己的 shell 环境替后台证明凭据；本期不新增秘密存储入口。

切换只关闭该平台的新接纳并停止旧 poll，不等待整轮模型结束。将“核实代次 → 提交主会话输入 → 保存 submissionId”和“核实来源 → 保存 sending → 固定发送句柄”分别纳入该平台的短临界区。已经开始的发送沿原目标结束，结果未知不重发；提交新代次后，旧待发回复与审批失效，不改发给新绑定者。

提问、普通回复、委派汇报和定时通知都按原来源代次取得固定发送句柄，不能继续捕获启动时的 QQ API。候选失败尽量保留旧入口；Telegram 接管水位已经改变等外部事实单独持久记录，不假装能回滚。新配置提交后连接失败显示“已保存，入口未连通”，按原操作恢复连接。停用/换绑不删除历史、工作或旧回执，不影响另一个平台。

### 命令目录与服务路径迁移

首版采用同机、本能力安全边界切换，不建立多套并行命令/服务执行运行时。保存新候选后，列出真正依赖旧目录或 helper 的待执行、活动工作、后台进程、未决停止与未知效果；不自动取消这些操作，也不等待无关聊天/技能/其他能力。相关旧工作结束后发布候选；用户可保留当前配置或按原管理入口处理阻塞。

保存不可变配置版本及切换记录，新操作引用版本；旧记录缺版本时以迁移时核实的原配置和明确历史边界解释，不重写旧 entry。命令恢复沿原 prepared.spec/input、执行身份、指纹；后台进程沿已保存 config；服务操作补原 helper/策略/sudo 路径的版本引用，原机器、策略修订和 hostOpId 不变。

删除“所有历史必须与当前配置指纹/目录相等”的要求，改为与历史绑定版本比较。已终结且无需再次接触执行环境的历史可在旧目录消失后读取；尚需读原输出文件或停止原进程时仍核实实际旧路径/机器，缺失只报告该项不可用，不假造结果，也不阻止新配置下的无关工作。

新目录仍核实 realpath/dev/ino、保护根、machineId、TMPDIR；新 helper 仍核实固定协议、账户、提权与部署。迁移不把旧长期授权或定时范围授予新部署。旧环境未核实结束时不能通过新 helper 的“找不到操作”解除占用。同机切换不要求新建档案；本期不提供跨机活跃执行迁移。

## 协议、格式与升级

settings 新写请求使用 v2，固定公共字段为 id、profile、expectedRevision、op；op 的判别联合限定 model、skills、mcp、web-search、telegram、qq、commands、services 各自已定义操作，电脑继续归 MCP 服务，不接受自由目标名、命令或任意文件写入。查询原操作只需 v2 和 id；新协议读写字段归 apps/ruukoto 的设置类型及 apps/desktop/src/shared/personal-settings.ts，跨客户端共用的纯 wire 类型按需放 packages/view/src/personal-protocol.ts，不为了搬类型改聊天帧。

v2 回执固定包含 id、profile、target、scope、requestDigest、status、savedRevision、effectiveRevision、code 和有界 relatedOperations。scope 由操作决定（例如 MCP 的 serviceId 或全部服务），不由客户端随意选择；savedRevision 表示文件提交身份，effectiveRevision 表示该 scope 的已发布配置版本，不能拿它代表整个文件。设置读取返回文件修订及各 scope 的生效事实，允许 A 待生效而 B 已生效。

status 限 rejected、saved、waiting、active、failed、unknown、superseded，不存在的修订明确为 null，不用 started 推断已生效。superseded 仍保留原 savedRevision，并指向取代它的新操作；状态与追加事实在同一事务更新。候选正文和秘密引用的完整值不在普通回执中，仍经已有认证设置读取。DesktopHost、renderer、Electron/MyGo 共用桥、远程白名单和结构化错误映射一并更新。v1 查询保持兼容，v1 新写请求明确要求客户端升级；不支持 v2 的旧后台显示升级要求，不能默默回退成停存启。

新操作通过已有 maintenance 接纳/查询通道投影设置回执；停止/启动只是显式服务管理操作。旧 maintenance.json 的 stopping/stopped/saving/saved/starting 回执保留旧解释和恢复/人工核实入口，未决旧维护先处理，不按新逻辑重放。新配置操作的暂时阻塞仅归其目标，不沿用全局唯一 pending 把所有页面锁死。

首次需要新配置版本/回执时，在同一档案写入者内由程序迁移，增加明确的 PERSONAL_FORMAT 能力标记。新程序对旧格式、迁移中标记、已完成新格式采用封闭的解析分支，不放宽任意未知版本。写序固定如下：

1. 持锁核实原 profile.json、durable 格式、已有引用与原配置，准备原格式、配置摘要、目标格式和稳定迁移 ID；此时不落新格式记录。
2. 先原子替换 profile.json 为带来源/目标格式、配置摘要和迁移 ID 的迁移中标记，并确认文件与父目录持久化。旧程序的完整格式比较此时必须拒绝，才能开始写新 records。
3. 在线用现有 Harness、离线用 createSession，在一次 durable 事务中保存原配置版本、旧引用的明确适用边界、新格式和迁移完成事实；无根初始库还包含设置初始化证明。旧会话和 entries 不移动、不覆盖。
4. 最后将 profile.json 原子替换为已完成新格式。新程序遇迁移中标记，只接受可核实的“数据库仍为原格式”或“数据库已提交同一迁移 ID”两种状态，分别继续事务或完成标记；摘要/引用不符则拒绝，不当空白初始化。

旧快照/计划不用新默认补写权限。profile.json 临时文件及确有必要的新文件列入 personal-profile 私有布局白名单，版本化解析和普通文件/权限/链接检查保持；不修改共享 core 的 SCHEMA_VERSION 来表示个人配置迁移。代码升级可正常重启一次，新格式完成后的配置保存不需要进程重启。
