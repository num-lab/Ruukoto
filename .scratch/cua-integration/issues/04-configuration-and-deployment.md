# 04 交付 Cua 配置与人工恢复入口

Status: ready-for-human

## 目标与边界

实现[规格R7](../spec.md#r7-管理与部署)，沿现有 MCP 设置与管理入口完成双端启用、暂停、恢复；不新造桌面视频界面或沙箱管理平台。

## 方案

1. Code的MCP设置增加“本机Cua Driver”，Personal增加“Linux桌面沙箱”。从已安装程序和既有沙箱选择，显示权限/连接检查结果；内部命令与代次由程序生成，不让用户编辑JSON或填请求键。
2. 沿03的配置/控制接口接 TUI/CLI、Desktop code-mcp 与 Personal settings/controls。保存前核未决动作及配置版本，停用立即拒绝新调用；关闭设置窗不代表停止后台动作。
3. 恢复入口逐步显示原未知动作、执行停止核实、人工检查、开始只读恢复、新截图接受。Linux需要整沙箱停止时明确告知未保存应用状态会丢失并由拥有者选择；不伪造“一键重试旧动作”。
4. docs/usage.md给官方安装链接与固定版本、Mac direct宿主权限、Linux本地运行前提、正常关闭/故障处理；不要求额外一台Mac，不安装TLS网关。工具与命令有变才同步README、development和pre-push-checks。
5. 按真实改动同步desktop、tui/control与personal-durable模块。无Cua环境时普通设置/聊天仍可使用。

## 进展与交接

- 当前角色与阶段：双端管理实现、主工作区验证和独立工程审查完成，无未解决工程阻断；真实安装、桌面及拥有者体验待验收。
- 下一角色与动作：拥有者从正常设置完成两端配置和暂停／继续；05复用本单证据补正式桌面、模型与一次丢答恢复，不重复离线矩阵。
- 当前内容：Code桌面与配置TUI选择本机固定Driver，CLI的mcp cua复用配置向导；Personal菜单和桌面PA设置选择既有Linux沙箱。路径、版本、哈希、容器及观察身份由程序管理。Code用固定制品静态工具清单与同direct宿主的OS只读授权预检；Linux固定--embedded且只接本机Docker，不连接共享daemon或新建网关。正常暂停拒绝新调用，停止未核实时仍保留待处理状态。
- 恢复结果：两端实际呈现受保护的新图；桌面完整读取、校验并成功加载全部图片后才可接受，CLI交系统图片查看器再由本人确认。接受绑定原观察，重观察前失效旧图，配置停用或换修订后的Code旧接受也拒绝。Code逐服务暂停带原service_id，不能停止另一来源的绑定；Personal恢复后保留原暂停，显式继续才开放。
- 界面精简：按拥有者反馈删除常驻提醒、重复说明与原始证据正文，用当前阶段、截图和操作顺序表达恢复流程；实际错误与Linux停止丢失未保存状态的确认保留。当前截图：[Code](../evidence/04-code-cleanup-browser.png)、[Personal](../evidence/04-personal-cleanup-browser.png)。
- 证据与限制：[本单工程证据](../evidence/04-offline.md)与离线浏览器截图；无真实Cua桌面／模型／远端部署验收。缺安装或权限时普通聊天与HTTP设置保留；授权位、合成图片和离线成功不能代替实际捕获或人工体验。

界面精简后另跑两端设置49项回归、check:static与两桌面壳构建，全部通过；独立审查10项窄回归与失败消息反例通过。浏览器离线夹具核实截图在确认按钮之前、图片加载后才可确认、失败重观察显示错误并清除旧图，Personal接受仍发送原观察。
