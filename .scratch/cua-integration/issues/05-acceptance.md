# 05 验收双端最小可用流程

Status: planning

## 目标与边界

按[规格R8](../spec.md#r8-验收与结束标准)验收正式Code/Mac与Personal/Linux入口。依赖02–04，不重新开展旧01探针矩阵，不把模拟、真实执行、真实模型和人工体验混称通过。

## 方案

1. 复用[归档](../archive.md)已核实的制品与隔离环境。核新入口的程序/身份/权限前提，仅记录变化；不自动启动旧探针或恢复其输入。
2. 每端用一个测试应用：模型读取新画面随机内容，填写/点击一次，再根据新截图确认；应用独立计数、实际模型请求、图片产物和历史导出共同证明。入口必须是正式产品，不能用独立脚本代替。
3. 每端在新调用链做一次真实写后丢答，证明旧动作不重发；复用同一停止机制的历史证据核实际受管执行身份，完成本人检查、开始只读恢复、新图接受和一次新工作。旧unknown不改判。Linux整沙箱停止必须按R6明确选择。
4. 权限/来源/目标越界、消息超限、冷恢复与普通HTTP兼容由02/03离线回归提供；不再为它们每项安排真实GUI与双Node重演。修复后只补受影响项，不追加无需求来源的门槛。
5. 独立审查按明确疑点和证据缺口复核，拥有者确认配置、批准节奏、暂停/恢复提示是否清楚。结果写精确未验项；失败不覆盖原记录。

## 进展与交接

- 当前角色与阶段：方案独审已通过；02图片与03接线的离线工程实现和独审完成，正式验收等待04的正常管理与截图查看。
- 下一角色与动作：02–04完成后由验收者运行上述有限流程；不提前要求用户重做Mac/Linux环境实验。
- 当前内容：规划快照见[review.md](../review.md)；03的接口、主工作区检查和Linux停止原语见[工程证据](../evidence/03-offline.md)，不能用这些离线证据替代本单正式流程。
- 阻塞与恢复条件：缺模型、隔离桌面或实际产品入口则保持待验收；列所缺前提，不用探针替代。

## 验收与证据

工程待验证：双端各一次成功流程、一次丢答恢复流程及相关离线回归。产品待验收：正常设置入口、批准节奏和人工恢复引导。新证据仍放仓库外受保护目录，仓库只记来源、版本、哈希和结果索引。全部通过即结束首版验收；跨产品桌面独占明确不在验收范围。
