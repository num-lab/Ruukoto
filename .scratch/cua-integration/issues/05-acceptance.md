# 05 验收 Cua 双产品完整流程

Status: planning

## 目标与边界

按[规格 R1–R8](../spec.md#共同契约)验证完整交付，依赖 01–04。工程与产品分别验收，Code 或 Personal 单端通过不能关闭整项工作。验收用隔离桌面和随机测试内容，不需要真实账号、支付或公开发送。

## 方案

1. 核对最终源码、版本/镜像摘要、两端配置和原有回归；汇总后重新判断检查范围。补齐各单遗漏的调用方和人类文档，再进行独立实现审查。旧结论只覆盖原快照。
2. 经正式 `ruukoto-code` 与 `ruukoto` 入口，在 Mac Driver 和 Linux 沙箱分别完成读取随机画面、点击计数器、输入随机文本、再截图验证及完整导出；检查原图片哈希、模型实际请求、Code JSONL/prompt、Personal 原生记录/请求快照之间的对应。
3. 注入“应用已执行、响应未收到”，覆盖网关断线/502/503/自造 JSON-RPC 错误、响应超限/截断、后台退出/冷恢复、取消和模型轮结束；实际提交数保持一次，目标不可被新任务/其他会话抢占。只读原结果查询完成前，人工效果说明不解除远端结束待核实。独立审查者亲验此反例。
4. 经真实管理器验证两个消费者争用同一目标/别名、越界沙箱、批准后撤权、计划/子/定时来源拒绝、人工暂停交还与恢复后重新观察。用截图里的恶意指令证明其不能改变绑定或权限。
5. 真实模型检查使用显式 `RUN_MODEL_CHECK=1` 和已有配置方式，外部 smoke 入口按仓库约定建立并文档化；离线默认不调用模型、不要求桌面。模拟 provider 证据和真实模型证据分别记录，失败保留复现命令。
6. 拥有者从正常界面验收配置、批准节奏、手动登录/接管、继续、截图取回和故障提示；记录通过或具体缺口。完成后更新本单状态及提案生命周期，保留原证据；提交、推送、生产部署权限另按会话授权。

## 验收与证据

| 要求 | 工程证据 | 产品证据 |
| --- | --- | --- |
| R1–R3 配置、目标、权限 | 越界/撤权/旧批准/来源负例，两端正式入口 | 拥有者能理解当前目标和批准范围 |
| R4 独占与跨轮 | 双客户端/别名竞争，重连引用与暂停恢复 | 登录、人工接管、继续符合预期 |
| R5 图片 | 混合/错误结果、预算、原图哈希、实际 provider 与历史 | 两端能看图继续并完整取回 |
| R6 恢复 | 执行后丢答且动作次数为一，原结果查询与未知保留 | 待核实时有可执行且不误导的指引 |
| R7 部署与管理 | Mac 系统授权、Linux 桌面、TLS/凭据、退出归属 | 正常入口可完成配置和解除 |
| R8 双端交付 | 真实 Cua + 真实模型分别成功；独立实现审查 | 拥有者明确接受上述体验 |

工程验收待验证，产品验收待验收，独立实现审查待执行。`evidence/05-acceptance.md` 汇总命令、版本、实际环境、快照指纹、作者/审查者归属及未覆盖项；证据文件在实际执行后创建，不提前填通过。方案审查见[review.md](../review.md)。
