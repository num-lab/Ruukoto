# Cua 双产品接入规格

本轮只制定方案和创建工单，不安装 Cua、不操作真实桌面、不修改运行代码。功能属于新执行能力、权限与持久化契约，按[开发流程](../../.agents/skills/development-workflow/SKILL.md)走重流程。决策理由见[接入提案](../../.agents/notes/proposed/architecture/2026-10-22-cua-integration.md)，源码与上游依据见[调查](research.md)。

## 目标与已确认范围

拥有者先要求了解本项目接入 trycua 的方式，明确「两端都支持」，随后要求「为 cua 的接入制定方案并创建工单」。2026-10-22 的范围确认选择「先做本机 Mac + Linux 沙箱」及「沿用现有 MCP 权限」。这授权本轮规划，不代表已经授权安装、生产部署或真实账号操作。

| 产品 | 首版目标 | 权限 |
| --- | --- | --- |
| Coding Agent（ruukoto-code） | 开发机本机 macOS 的 Cua Driver | 沿现有 MCP 的本地副作用分类、审批与完全访问规则 |
| 个人 Agent（ruukoto） | 独立 Linux 桌面沙箱 | 沿个人 durable MCP 的来源、逐次批准与完全访问规则 |

完成后，两个产品的主对话都能读取桌面或窗口、操作测试应用、取得截图并根据画面继续；截图可从原会话记录重建并完整取回。模型循环、会话历史、权限和任务事实继续由各产品持有，Cua 提供电脑操作。

首版采用主对话绑定目标的交付切片：Code 普通拥有者会话、Personal 拥有者 main 可绑定；SubAgent、定时任务、工作流步骤及 GitHub 评审不自动继承该电脑目标。该限制只针对登记为 Cua 电脑目标的服务，普通 MCP 的现有资格不变。后续扩展独立桌面委派需要另行规格。

不包括 Personal 远控 Mac、Windows、云账号与计费接入、自动创建或删除沙箱、远程桌面视频 UI、密码库、IM 截图外发、通用 stdio 插件平台或更换 Agent 框架。现有 agent-browser 继续使用，不与 Cua 自动互相接管。人类先在本机窗口或沙箱既有桌面入口完成登录，模型不收集密码。

## 接入结构

优先采用「各产品 MCP 宿主 → Streamable HTTP → 固定执行端桥接 → Cua stdio」路线；Code 的执行端连接本机 Driver，Personal 的执行端连接预先准备好的 Linux 桌面沙箱。桥接候选为固定正式版本的 Supergateway，尚未选择可交付版本。它只解决协议转换，不能假定提供目标独占、持久回执或远端停止证明。

[01 选型与探针](issues/01-transport-and-lifecycle-probe.md)是路线放行前置：核实桥接的认证、Cua session 与窗口引用、原结果恢复及目标认领，产出实际协议和版本快照。现成组合满足契约则直接复用；缺少目标认领或查询原操作的能力时，先记录缺口，提出基于现有 MCP SDK 的最窄执行端适配并独立复审，不能默默自写网关、降级为任意 shell 或放宽恢复保证。02 的图片能力可独立交付；03–05 以 01 的通过结果为前置。

共享 `packages/agent/src/mcp/` 只持有传输、远端数据校验与无状态转换。Coding 的配置、审批、操作与图片仍走 core/Runtime/ToolRouter；Personal 的相同责任仍走 `personal-mcp`、durable 与 `personal-media`。传输层不持有两端任务，不用旧 Task Store 模拟 Personal 的运行状态。

## 共同契约

### R1 配置与认证

Cua 服务需由可信管理入口显式标记为电脑目标；不能根据名称前缀或远端描述猜测，也不能让模型把普通 MCP 升级成电脑服务。配置引用固定服务、产品档案、目标身份及内容修订，使用具名目标类型。Code 按工作区配置来源管理，Personal 按档案管理并沿停机持锁保存。已有普通 MCP 配置与历史保持原语义；持久结构变更须有明确版本、迁入和新版本拒绝规则。

首版产品端仍使用 HTTPS、固定源和 Bearer 凭据；本机执行端也须给出可验证的 TLS 部署路径。loopback HTTP 只用于现有模拟探针，不因便于部署直接转成生产能力；若 01 证明本机 HTTPS 不可交付，回方案者提交端点策略变更及理由再复审。执行端凭据由拥有者配置，模型不能指定程序、shell、端口、凭据、沙箱创建/删除或任意目标地址。

### R2 目标固定与最小工具集

一个绑定只对应一台固定电脑或一个固定沙箱。沙箱名称的默认值不构成隔离：若 Cua 工具允许参数覆盖目标，可信适配必须在发出前拒绝异目标；不能只靠说明要求模型不填写。Driver 的 lifecycle session、路径和程序身份由宿主管理，窗口/元素引用仍使用 Cua 返回值。普通文本、截图、远端描述不能扩大目标或授权。

允许列表只收完成截图、窗口查询、点击、输入、按键、滚动及必要生命周期操作的实际工具。按发现结果和 schema 选择，不预写不存在的工具名；shell、任意文件操作、剪贴板、批量脚本、权限提升和沙箱管理不在默认列表。必须使用复合工具时，明确它所有可能动作的副作用类别，不能把带写分支的工具整体标成只读。

### R3 来源与操作授权

电脑目标采用上述主对话切片；工具装配、发送前检查、实际调用和恢复均核对同一来源资格。Code 的读工具仍以本地明确分类为依据；写/unknown 在 confirm/auto-review 逐次批准，full_access 沿原免操作审批规则。Personal 的 MCP 在 confirm/auto-review 对每次调用批准，不能因服务端 readOnly 标注而免审。计划模式沿原来源限制，不因电脑操作得到写能力；Cua 的系统权限和沙箱隔离不能代替 Ruukoto 授权。

批准绑定原目标、工具定义、参数、配置修订和任务；等待期间换模式、停用服务、撤销凭据或改目标后，旧批准失效且不发请求。自动审查仍沿现有 MCP 规则，不新增“看起来安全就批准点击”的规则。

### R4 独占与跨调用状态

主会话显式选择目标后持续持有绑定，跨正常对话轮保留桌面状态，直到拥有者暂停交还/解除或后台停止。一次工具调用串行不等于整个桌面操作串行：从观察到动作再到验证期间，不允许另一 Ruukoto 会话或另一个产品取得同一目标。目标认领必须在实际控制该桌面的执行端核实稳定身份，URL 别名、另一个配置来源、凭据轮换与重连不能绕过占用。

01 必须确定认领、查询、释放与重连的具体请求字段、认证归属和持久性，再进入 03。通用网关的 HTTP session 或 Cua 的隐式 session 本身不作为整台电脑的独占证明。Personal 当前逐次连接/关闭 MCP，必须验证窗口/元素引用不会在下一次调用失效或属于另一 transport lease；若需要保留连接，保留在 Cua 绑定层并纳入暂停、取消、重启及证据恢复，不全局改变普通 MCP 连接寿命。

人工登录时先暂停自动化并核实在途操作，拥有者通过现有本机/沙箱桌面操作，再显式继续并重新观察。自动化只能保证受管入口的独占，不能声称阻止用户或其他系统程序移动窗口。跨轮保留页面不等于跨 Cua/沙箱重启恢复页面；重启后重新观察，不重放旧动作。

### R5 图片进入模型与记录

支持 MCP 内联 `image` 内容的 JPEG/PNG/WebP；远端资源 URL、audio 与 resource_link 保持既有不自动下载行为。校验 base64、实际 MIME、图片数量、单图和响应总字节预算，边界值与完整读取的上限在 02 钉定；图像字节不得经过文本的 32 KiB 预览或 1 MiB 截断路径。预算须在聚合响应和解码前生效，超限保留有限诊断，不吞入无限 base64。

Code 复用 ArtifactStore、操作产物登记、图片视觉块及原 JSONL/prompt；Personal 复用私有产物、`PersonalImageRegistrar` 与最终 provider 前的来源/哈希核实。先保存图片及引用，再向模型提供视觉块，文件与数据库不宣称原子。按原内容顺序保存文本、结构化结果和图片的位置及出现次数；重读只读取已保存内容，不再调用 Cua。不能用一页 JSON/base64 代表模型看过图片。

支持纯图片、文本混图、多图和 `isError` 带图。模型不支持视觉、格式不符、落盘失败或历史图片损坏时，明确说明受影响结果；图片失败不能把已经执行的点击改记“未执行”，更不能提示重试点击。完整原终结应答、远端 `isError`、图片展示失败、业务效果未知分别记录。原 JSON-RPC 证据保留或转为可重建的不可变产物，不修改旧证据格式和旧历史。

### R6 失败、停止与恢复

| 情况 | 归属与保留事实 | 可执行的下一步 |
| --- | --- | --- |
| 配置/权限/schema/目标/认领不符，尚未发送 | 宿主拒绝；已知未执行 | 查询配置或让拥有者处理原占用 |
| 可核实对应原下游操作的完整终结应答（含 isError） | 原请求结束；实际业务结果按应答解释 | 检查结果；显示图像失败不改变应答事实 |
| 已发送后未取得原下游终结证据，包括超时、断线、取消、进程崩溃、网关 HTTP 错误及响应超限/截断/解析失败 | 持有者保存原操作及 effect_unknown/结束待核实，阻止后续动作 | 查询原请求或拥有者核实；不自动重发 |
| 只读观察被取消 | 无写入效果；仍须核实远端调用是否结束 | 查询或停止原观察，不能提前释放目标 |
| 用户说明业务已生效/未生效 | 仅补充业务事实 | 继续取得原请求结束/停止证据 |
| 图片处理失败 | 保留已取得的执行应答与图片错误 | 读取已保存证据或报告；不重做业务动作 |

HTTP close/DELETE、桥接进程退出、SSH 断开与 MCP cancellation 都不自动证明 Cua daemon 或沙箱中的动作结束。具备原 SSE 游标时只读取原流，缺游标/事件保留或执行端原操作查询时继续待核实。恢复不得 initialize 后再发旧 tools/call 来“查询”。Cua session 结束是否能证明动作停止必须由 01 实测，不能靠名称推断。

效果分类依据“是否已发送”和“是否取得对应原下游操作的终结证据”，不能只枚举现有 McpError.code。网关自行生成的 HTTP 4xx/5xx 或 JSON-RPC error 不等于 Cua 的业务应答；有可靠的发送前拒绝证据才记未执行。响应预算中断可能发生在点击已经完成之后，不能将结果读取失败提示为可重试的点击失败。

变更面分两处：02 新增的“响应未完整读取”分类适用于所有 MCP 的 write/unknown，已发送且无完整终结证据就保留未知；03 对登记为电脑目标的桥接服务进一步核实下游终结来源。其他普通 MCP 的既有 HTTP/JSON-RPC 错误类别不在本轮整体改写，原历史不追溯重分类。该扩展与旧[MCP 写工具结果定性](../../.agents/notes/implemented/feature/2026-09-23-mcp-write-tools-approval.md#结果定性)的关系由提案记录，权限和批准规则继续复用。

冷恢复先读取原绑定和未决操作；有未知时保留目标占用，禁止换端点、会话、凭据或新沙箱掩盖旧执行。02/03 必须区分“工具 Task 结束”“业务效果”“远端动作结束”和“目标认领可释放”。Code 不能只沿现有 MCP 的一次 effect_unknown 标记便放开下一任务；Personal 继续沿原来源暂停与原请求结束规则。已绑定历史及截图不删除。

### R7 管理和部署

复用现有 MCP 设置与 CLI/个人管理入口，增加电脑目标的选择、绑定状态、暂停交还、继续、解除及未决操作入口；内部标识、版本和请求键由程序管理。拥有者能从正常入口看到“不可用/占用/待批准/操作中/暂停/待核实”，得到当前可执行动作。关闭设置窗或客户端不取消后台工作；显式停用立即阻止新调用，但不会伪造在途动作结束。

Driver、网关和沙箱是预先配置的外部执行能力，模型任务不自动安装、提权或创建服务。macOS 使用官方应用持有系统授权，Linux 使用专用桌面及账户，外部程序版本和镜像摘要固定。后台只关闭自己持有且身份核实的连接/运行单元；不退出用户应用、不删除沙箱/登录资料。服务缺失只使 Cua 不可用，不阻断普通聊天和无关工具。

### R8 验收与交付

离线用例、真实 Cua/网关/桌面与真实模型分开记证据；外部验收显式启用，缺凭据、桌面、权限或 Linux 环境时保持待验收。macOS Code 和 Linux Personal 都经正式入口完成“读图中的随机内容 → 操作计数器/输入框 → 再读截图核实”；测试应用同时记录实际提交数，断线及冷恢复后计数仍为一次。

覆盖双会话争用、目标别名、越界沙箱、计划/子/定时来源、批准后撤权、Cua/网关/后台各自退出、执行后网关 502/503 或响应超限、原响应查询、恶意/超大图片、纯文本模型及历史图片被改写。截图应与实际模型请求和会话记录对应并完整导出。产品验收另由拥有者检查双端配置、人工接管/继续、批准节奏和故障提示，不能用模型成功替代体验验收。
