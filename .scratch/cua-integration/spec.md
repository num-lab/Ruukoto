# Cua 双产品接入规格

本方案以 `14ee3d007bac3bb99cf104ad55c8aeccb7aa50a4` 为代码基线，取代旧桥接、全局目标认领及自建执行服务方案。2026-10-23 拥有者要求去掉跨产品独占同一桌面的保证，先在仓库外保存实验材料，再回滚到 `e8479aa1` 之前。归档与回滚见[备份索引](archive.md)，选型依据见[官方资料与源码核对](research.md)，理由见[新决策](../../.agents/notes/implemented/architecture/2026-10-23-cua-official-mcp.md)。规划轮只交付规格与工单；实际实现、剩余管理入口和正式验收分别由各工单记录。

## 目标与已确认范围

| 产品 | 首版环境 | 操作权限 |
| --- | --- | --- |
| ruukoto-code | 当前开发机的本机 Mac | 沿现有 MCP 分类、审批与完全访问规则 |
| ruukoto 个人 Agent | 个人 Agent 所在 Linux 主机上的独立桌面沙箱 | 沿个人 MCP 来源、逐次批准与完全访问规则 |

双端均完成“观察画面→操作应用→重新截图确认”，模型看到的图片能从会话历史重建。主对话可用；SubAgent、定时、工作流和 GitHub 评审不自动取得电脑入口。已有普通 MCP 的来源资格不变。个人 Agent 远控 Mac、Windows、自动创建/删除沙箱、云计费、视频 UI、任意 shell/文件工具不在首版。

拥有者已接受人工恢复：丢答后先核实该执行进程停止，再由拥有者检查桌面、明确恢复并重新截图；历史原结果仍未知，旧动作绝不重发。这条要求继续有效；不再承诺跨产品、跨实例、跨配置别名独占同一桌面。

## 接入结构

采用官方 MCP stdio，复用已安装 `@modelcontextprotocol/client@2.0.0` 的 `StdioClientTransport`，不手写 JSON-RPC，不新建 HTTPS 服务、Supergateway 或执行端 SQLite 回执库。

- Code：后台启动已配置的官方 `cua-driver mcp --direct`。direct 的实际执行 runtime 属于该进程，macOS 权限按实际启动账户与宿主归属配置；不借用另一个用户的图形会话。
- Personal：后台启动已配置的官方 `cua --embedded mcp --sandbox <固定沙箱> --permissions <固定最小集合>`。固定 CLI 0.7.0 的普通入口会优先连接已运行的 daemon，宿主显式选择 embedded，确保当前 CLI 持有输入源。CLI 连接已存在的专用 Linux 桌面；不用共享 `cua daemon mcp`，不逐调用启动 CLI。
- 两端仍用自己的模型循环、审批、操作记录与图片存储。共享 MCP 层只承担协议、schema 校验、消息限额及请求/应答记录钩子。持久绑定、停止核实和恢复由产品持有。

这是仅针对两种 Cua 配置的本地进程入口，不是任意 stdio 插件平台。原 HTTPS MCP 配置、认证和连接语义保持不变。SDK 原生接口可用于理解生命周期；首版不并行维护另一套 SDK 业务工具。

## 共同契约

### R1 配置与执行入口

拥有者从管理入口选择本机 Driver 或本地 Linux 沙箱，程序生成固定命令与参数。可信配置保存程序绝对路径、核实的制品版本/哈希、产品来源与修订；Linux 再保存既有沙箱的稳定身份。模型不能提交 executable、shell、环境变量、任意参数或新的控制地址。环境按官方必要项显式构造，不把产品凭据整包交给子进程。

配置使用具名的 Cua 分支，不能伪造 HTTPS endpoint 承载本地命令。Code 的 MCP 配置/存储/控制与 Personal 配置解析/版本/恢复一并调整；原 HTTPS 数据原样读。新增格式明确版本并拒绝旧程序误读，旧历史不自动重写。缺程序或权限只令电脑入口不可用，不阻断普通聊天。

### R2 固定目标与工具

Linux 的 `--sandbox` 只是默认值。宿主保存真实工具原 schema，向模型暴露受限 schema，实际发送前拒绝异沙箱覆盖并注入固定目标。身份由宿主管理；窗口、元素与坐标来自最新 Cua 观察。有效模型 schema 和实际发送参数都进入原记录。

允许截图、必要窗口/应用查询、点击、输入、按键、滚动等实际发现的最小工具。官方 CLI 权限先收窄，Ruukoto 再用允许列表和本地副作用分类约束。生命周期管理只供宿主；shell、文件、剪贴板、脚本/批量执行、沙箱创建删除不向模型开放。复合工具按所有分支的能力审核，不能把可写工具整体当只读。

### R3 沿用 MCP 权限

Code 对本地明确分类的读工具沿原规则；write/unknown 在 confirm/auto-review 逐次批准，full_access 免操作审批。Personal 沿现有 MCP 对 confirm/auto-review 每次调用批准。远端 readOnly 提示不是授权，计划模式不获得电脑写权限。

批准绑定来源、目标、实际工具/参数及配置修订。发送前再次核实资格并单次消费；停用、改目标或撤权后旧批准失效。stdio 的发送钩子必须在实际 tools/call 写入管道前落盘原请求和批准消费；不能用“换了传输”绕过原闸门。

### R4 连接寿命与有限并发

每个产品实例的 Cua 管理器仅有一个活动电脑绑定；由一个符合资格的主会话使用，顺序派发，不自动排队给另一会话。正常对话轮之间保留同一 MCP 进程/连接，Personal 的普通 HTTPS 逐调用连接逻辑不改变。暂停时先结束或核实在途调用，再交还；继续前重新观察。后台退出或子进程丢失后，旧快照、坐标缩放和元素引用失效。

本地绑定只避免本实例会话互相打断。没有全局桌面锁、root 注册表、跨产品 claim、端点别名归一或第二状态目录防绕过协议；其他产品、独立实例及人类仍可能操作同一桌面。首版的 Mac 与 Linux 沙箱彼此独立，使用者需避免其他控制器同时介入。不能把 session label 当作桌面锁。

### R5 图片进入模型与历史

复用 Code 的 ArtifactStore/图片视觉块和 Personal 的 registerImage/provider 核实。MCP 内联 JPEG/PNG/WebP 经过 base64、真实 MIME 和大小校验，先保存产物和引用，再给模型图片块。保存内容顺序、原工具归属与哈希；重读历史只读产物，不重新截图。纯图片、混图和 isError 附图均有明确结果；不下载任意资源 URL。

Cua stdio 每条消息上限 48 MiB，使用 SDK 的 maxBufferSize 在聚合/JSON 解析前限流；每图最多 8 MiB、每次最多 4 张，解码前先核长度。此预算足以容纳四张上限图片的 base64 与普通 JSON 开销，额外正文超总量仍拒绝；不是任意大小响应的保证。文本继续走现有预览/产物限额，图片不经过文本截断。02 负责图像校验，03 负责 stdio 消息预算与发送后中断分类；不要求先实现所有 HTTP/SSE 预算分支。

取得完整原应答后，图片校验、保存或模型展示失败不改变原动作事实，也不能提示重试点击。没有视觉能力的模型在动作前报告能力不符。任何模型可见定义、图片和宿主追加提示都可从记录重建。

### R6 失败、持久记录与人工恢复

复用 Code 操作账本与 Personal durable 原操作，不另建执行服务或第二套任务库。保存原请求、取得的应答、执行进程身份与恢复控制事实。没有原回执时保持未知，不再以“必须跨进程找回原回执”作为接入前置。

| 情形 | 记录与下一步 |
| --- | --- |
| 权限/配置/目标/schema 拒绝，可靠确认尚未发送 | 已知未执行；修正前提后才可发起新操作 |
| 对应原请求的完整终结应答 | 保存真实应答；返回不等于应用完成，按画面核实 |
| 写/unknown 已发送而无完整应答，包括超时、断流、消息超限或崩溃 | 记录 effect_unknown，冻结本产品的电脑绑定，禁止自动重发 |
| 只读观察中断 | 无写入效果；连接状态丢失时仍暂停并重建观察 |
| 用户确认业务效果 | 追加说明，不伪造原应答或把 remoteEnded 改为 true |

恢复顺序固定为：冻结新输入 → 核实原执行单元停止 → 拥有者检查结果并选择开始恢复 → 新连接仅观察并保存新截图 → 拥有者接受该观察 → 开放新工作。历史 unknown 永远保留，旧任务/工具不能因恢复重新派发。重启、换配置或重开同一产品会话都不能绕过该档案的待核实记录；不把这扩成跨档案/跨产品目标锁。

Mac 对 direct 进程复用项目已有原生进程身份及停止核实能力；不以代理退出、PID 消失或连接关闭代替实际 runtime 停止。Linux 的 CLI 退出不代表 guest 停止；先关闭受管 CLI 输入源，再核实原沙箱运行代停止。需要停止整个沙箱时，由拥有者明确选择并说明内存/未保存应用状态会丢失，保留磁盘；无法核实时继续冻结。不自动停止用户应用或删除沙箱。重启沙箱只能发生在拥有者选择开始恢复后。

Personal 必须显式增加仅对 Cua 生效的恢复结算事实：核实停止、owner 选择、最新观察接受与旧执行身份相关联。原 remoteEnded 仍只由完整原应答决定。mcpUnresolved、配置阻塞、来源/工作等待、汇总和 UI 都使用该事实判断能否结束旧等待并开始新工作；不能仅改一个显示字段，也不为普通 HTTP MCP 增加人工强制解锁。Code 对应冻结和解冻同样落盘，冷启动先恢复冻结再开放工具。

### R7 管理与部署

在现有 MCP 设置/CLI/个人管理入口增加 Cua 类型选择、程序检查、固定沙箱选择、启停、暂停、继续及待核实恢复引导。用户不填写内部请求键、进程代次或数据库字段。配置与权限由拥有者管理，模型不安装程序、授予 macOS 权限或调整沙箱运行策略。

安装说明采用官方命令并固定制品；Code 明确 direct 宿主的 Accessibility/Screen Recording 归属，Personal 明确本地 Docker/沙箱前提。更换启动宿主后重新核实权限，不能沿用另一终端的授权结论。Cua stdout 仅承载 MCP，stderr 有界并去除凭据。无需为本机入口配置 TLS/Bearer 网关。

### R8 验收与结束标准

01 只交付官方依据、已有证据映射和明确剩余项，不再运行探针。02/03 用实际产品接口加离线窄回归。05 在两种正式产品入口各完成一次“随机画面→输入/点击→新截图核实”，应用独立计数验证结果；新版正式调用链各做一次丢答与人工恢复验收。复用旧环境、固定制品与相同停止机制的有效证据，只补调用链差异，不复刻所有旧故障组合。

必须覆盖目标越界、审批撤销、断线不重发、消息上限、历史图片和未知冷恢复。Node22.19/24.15 的 stdio 连接成功/取消/退出用离线子进程夹具验证；真实桌面无需按 Node 版本重复。模型、真实执行、人工体验分开记结果。失败先用最窄夹具定位，仅重跑受影响项；新增验收要求须先说明对应哪条已确认契约。独立审查复核具体缺口，不机械重演全部 GUI。
