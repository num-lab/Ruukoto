# 新闻推送

## 目标

在提醒和 outbox 稳定后，由 main 管理固定关键词和来源，定时生成带 URL 的新闻摘要。

## 实现范围

- 复用现有 Web Search/Tavily 工具，不新增搜索服务。
- main 可以提议关键词、来源和推送时间；新增来源需要 owner 确认。
- 搜索结果保存必要的 URL、标题、时间和摘要来源，不自动写入长期记忆。
- 同一时间窗口和 URL 去重；失败、限流和结果未知进入任务/通知状态。
- 新闻摘要通过 outbox 推送，低优先级事件可批量合并。

## 验证

- 推送内容包含可访问来源 URL；
- 重复搜索不会在同一摘要中重复同一来源；
- Tavily 不可用时不会伪造新闻事实；
- 新闻任务不会读取未授权项目资料或个人私密历史。

### 2026-09-25：实现新闻计划与持久采集

main 通过已有 `schedule_create` 的 `action=news` 提议固定关键词、来源域名、
时间窗口和推送时间。统一审批新增 `notification.mode=news`，TUI 明确展示
动态新闻授权；新增来源、修改关键词或时间均取消后重建并重新确认，
`full_access` 同样需要 owner 确认。目标与配置版本仍由宿主固定。

抽出结构化 `searchTavily` 供原 Web Search 工具与新闻采集共用，不新增搜索服务
或依赖。宿主按已批准参数直接采集，不创建模型任务，不读取会话、项目资料、
应用数据或记忆，也不自动写入长期记忆。每次最多 5 个关键词、每次搜索最多
5 条结果，批准域名（含子域）和原定时间窗口在宿主再次过滤；缺少有效发布时间
的结果不进入摘要。URL 去重忽略片段和常见跟踪参数，多关键词合并为一条通知。

schema v18 保留旧计划、调度运行与发送账本，仅扩展计划动作并增加
`schedule_runs.news_result`。有界快照保存 URL、标题、发布时间、查询时间、
服务请求 ID 和 Tavily 摘要来源，与固定正文及 outbox 操作同事务提交。
重复扫描、重启与漏过周期沿用原运行键，不重复搜索已完成窗口。
采集失败或限流登记 `news_*` 失败通知；重启遗留 `searching` 标记为 `unknown`，
不自动重搜。实际外发结果未知仍使用 `effect_unknown`，不换键重发。

已补充 ADR 0015、领域术语和运行说明。首版使用搜索摘要原文，不做模型改写或
逐条网页抓取；来源页面后续可能失效。延迟采集仍受搜索服务相对查询时间的限制，
无法保证补齐漏过的旧新闻，不推断或补造缺失事实。

验证：`npm run typecheck` 通过；最终 `npm test` 共 479 项，478 通过、0 失败、
1 项真实模型连通性测试按默认配置跳过。新增迁移测试覆盖旧 CHECK、全部旧数据、
索引、外键和失败回滚，`integrity_check` / `foreign_key_check` 通过；新闻集成
测试覆盖 main 审批、来源与目标变更、URL 去重、隐私隔离、部分搜索失败、限流、
超时、重启、取消及项目禁用。原 Web Search 与调度器回归均通过，TUI 演示数据
已同步新增事件。所有搜索和发送使用本地模拟服务，未进行真实 Tavily 或
Telegram/QQ 收发验收。
