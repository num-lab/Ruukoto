# QQ 群聊与 chat agent 衔接

## 目标

把已有 NapCat 群聊规划接入新的角色和事件编排层，不让 QQ 群成员获得 main 的个人资料和控制权限。

## 实现范围

- 复用 `.scratch/personal-agent/issues/07-qq.md` 的指定群、明确 @、同群 FIFO、5 分钟过期和撤回处理规则；
- 每个“登录账号 + 群”绑定独立 chat Project/Session/工作目录；
- chat 仅接收本群触发交互，默认不注册 Shell、文件、MCP 或通用 HTTP 工具；
- 群资料与 main 个人数据、开发历史、个人共享记忆和项目指令隔离；
- 群聊摘要只有经 main 明确接收的结构化结果才能进入 outbox；
- 普通群回复不改变 owner 权限，不批准开发任务，不开启完全访问。

## 验证

- 群成员无法读取 main 数据、开发历史或凭据；
- 机器人自身消息和重复事件不形成回声任务；
- 撤回消息不进入后续上下文，未发送回复被取消；
- 跨群会话、队列和资料完全隔离；
- 真实群收发仍需拥有者单独授权，模拟测试不代表部署通过。

## Comments

### 2026-09-24：实施方案

复用 `qq_sessions` 的每群项目、会话与目录，保留 `qq_group` 类别和空工具集合。群消息登记为 `qq_group` 入站事件，编排器沿用收件原请求键和原正文派发 chat 任务；旧任务先核实并关联，不换键重跑。配置、撤回与五分钟有效期在派发及启动前复核。

“main 明确接收”采用两个 main 专属宿主工具：`chat_result_list` 只列来源元数据，`chat_result_accept` 保存有界摘要快照、来源与接收记录，不自动唤醒 main 或外发。通知通过单独的 `chat_result` 来源引用已接收快照，继续使用现有拥有者审批；原始群资料与 coding 委派边界不放宽。此窄例外及撤回语义记录于 ADR 0014，补充 ADR 0012。

schema v17 增加接收账本，以及收件的配置版本、引用关联与撤回时间。验证使用本地模拟 OneBot、模型及通知渠道；真实收发与 Linux 部署另行验收。

### 2026-09-24：实现与验证完成

- 群入站现在先持久化，再由编排器派发为每群独立的 chat 任务；保留旧项目、会话、目录、原请求键与历史。旧收件的未建任务、已建未关联、已完成未登记发送三类窗口均可恢复，不重复执行模型或发送。
- 同毫秒消息按持久登记顺序执行；保留指定群、结构化 @、自身回声过滤、同群 FIFO、五分钟过期与空工具集合。撤回同时排除引用交互，旧版无引用 ID 的交互保守处理。
- main 的群结果列表只公开元数据；明确接收后保存固定摘要及来源与审计记录。通知引用仍经拥有者审批，并在批准提交与发送前复核撤回；原始群历史、产物、记忆及 coding 资料边界继续拒绝。
- 群回复按任务读取最终文本，重复终态监听与恢复沿用已有发送事实。在途发送被撤回或停用时记 unknown；迟到回执不改写该状态，也不重发。启动补发不阻塞入站撤回处理。
- CONTEXT、ADR 0014、运行文档与 TUI 演示事件已同步。独立审查发现的启动终态遗漏、同毫秒乱序和恢复补发阻塞撤回均已修正并覆盖回归。

最终验证（macOS，Node v24.15.0，本地模拟）：`npm run typecheck` 通过；`npm test` **471 项，470 通过、0 失败、1 跳过**（默认关闭的真实模型检查）；`git diff --check` 通过。新增 `test/47-qq-group-bridge.test.ts`、`48-chat-results.test.ts`、`49-chat-result-flow.test.ts`，扩展原群聊测试；schema v16 → v17 两次打开迁移保持身份、任务、群映射与发送事实，外键检查与 SQLite 完整性检查通过。

未向真实 QQ 账号或群发送消息，未执行真实 NapCat 兼容性与 Linux 部署验收。真实验收仍按原群聊工单要求由拥有者另行授权。
