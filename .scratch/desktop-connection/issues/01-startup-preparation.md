# 桌面启动环境预热与轻量探测

Status: resolved

## 目标与边界

拥有者在 2026-10-17 确认优化「启动应用时连接本地 Code 后台」，并授权「先做环境预热和轻量探测」。本轮只提前准备环境、取消探测阶段的重复快照；保留登录 shell、Node 版本校验、路径与令牌来源、严格协议版本、正式连接快照、锁竞争和失败不重复拉起规则。不优化后台冷启动、快照 SQL、分页，不改 UI 与配置，不停止日常后台；拥有者随后授权提交，未授权推送。

验收：环境在 DesktopHost 创建时开始，订阅复用同一次结果；环境失败由首次连接可见地报告，重新连接可重试；退出取消尚未完成的读取，退出后不采用环境或创建连接。已有后台的探测仅 auth + ping，正式连接仍 auth + connect；停止中的后台与异常响应不能当成就绪，也不能拉起第二个实例。版本与认证明确拒绝、传输中断后重新判断 socket、并发实例锁和冷启动继续有效。

## 方案

1. 共用 DesktopHost 构造时调用既有 selectEnvironment，缓存当前应用生命周期的 promise；预热本身不创建后台或 SSH。缓存失败保留到连接消费并报告，再允许显式重连重试；预热拒绝有已附着的处理器，避免未处理拒绝。getEnvironment 在消费时采用环境。给环境读取传入 AbortSignal，close 取消并等待读取结束，关闭期间不发布失败或启动连接。
2. ensureBackend 的 probeWithReason 在认证后调用现有 ping 并使用探测超时；要求 pong=true 且 stopping=false，不请求快照或订阅。停止中使用具名错误码和停止指引，异常响应保留安全失败；socket 可达时均不重复启动。正式 ControlConnection 不变。
3. 修改调用方相关测试：Host 预热、失败重试、关闭取消、环境进程取消；控制面探测不取快照、正式快照一次、停止/异常响应、ping 阶段版本拒绝/超时/中断。开发启动器的已有实例门控使用共用 socket 可连性检查，避免停止中的实例重复拉起；启动就绪等待继续认证 ping。同步 desktop/control/tui 模块文档与新决策笔记。
4. 执行静态检查及相关测试，构建 MyGo 与 Electron 共用宿主；用隔离 Code 数据与真实 MyGo 窗口验证启动链路并记录测量范围。独立审查方案、实现与证据。
