# 文件树目录读取性能

Status: ready-for-human

## 目标与边界

拥有者于 2026-10-17 确认按讨论方案实施：合并目录保护检查的重复扫描，目录列表只检查目录身份，保留读取前后独立复核，再测 MyGo 的完整点击链路。HEAD 为 632db30，起始工作区干净。本次不改 UI、协议、持久化、文件预览规则或通用工具保护；不增加监听缓存、预读、树组件或线程。验收完成后拥有者追加「提交」，授权本地提交，仍不推送或重启日常实例。

## 方案

在 agent 的 approved-ops 增加仅供目录读取使用的批量保护核实：同阶段收集工作区根和目标目录的祖先身份，保护树按目录遍历一次，以 Dirent 排除普通文件及符号链接；入口实际核实两目标为目录，每个保护目录枚举前后以 BigIntStats 比较 dev／ino／mode／mtimeNs／ctimeNs，分类快照发生变化时拒绝；继续核实保护根位于工作区内的反向关系，保护根本身是文件时同样拒绝祖先授权。每个阶段使用独立的身份集合和遍历，不跨读取前后或跨请求缓存。原通用 assertGrantNotProtected、assertNotProtected、isProtectedPath 与文件预览继续原行为。Runtime 的 listWorkspaceFiles 前后调用新入口，保持原身份、路径、枚举上限、失败转换和清理。

先补会在旧实现失败的 FS 调用次数回归，固定保护目录结构后增加普通文件，断言不逐文件 lstat 且每目录仅在前后各扫描一次；补物理目录别名、保护根文件、符号链接、读中替换／新保护关系和扫描失败的拒绝回归。Linux 真实 bind mount 用 ssh tx 隔离临时目录验证；前提不足明确保留缺口。通用硬链接与文件预览回归证明未放宽安全语义。

沿用真实 listWorkspaceFiles 基准，对相同返回结果测优化前后，注明进程启动和 OS 缓存。隔离 MyGo 配合真实 Runtime／ControlServer，对根目录、首次子目录、重复展开分别测后台、桥接往返及可见行；仅添加隔离验收脚本，不在产品埋点。同步 desktop／execution 模块说明及决策笔记，运行 check:static、相关测试、必要后台构建与 MyGo 验收，不跑无关全仓检查。理由见[目录保护优化](../../../.agents/notes/implemented/bug-fix/2026-10-17-directory-protection-cost.md)。
