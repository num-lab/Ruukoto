# Code 提交与控制验收

实施基点 `4d03a32`，macOS arm64、Node v24.15.0、Electron 44.7.2。范围见[工单](../issues/05-code-submit-and-controls.md)；前置 04 已 resolved。本轮没有提交、推送或发布。

## 实现与影响范围

主进程为 Code 目标在应用数据目录中按控制目录摘要隔离 PendingRequestStore，submit 与 continue 共用 SubmissionGuard，保存完整参数后发送，同会话提交／同来源继续复用原待核实记录。每次快照安装与在线应答丢失触发串行核实，合并追加触发；跨异步请求仍核对原连接和实例，守护请求沿控制器脱敏。渲染进程按请求键显示结果，恢复输入先只读交付、合入原会话草稿与继续来源，再确认严格清理；重复确认、迟到拒绝与宽容清理失败都不会重复合并。

PendingRequestStore 新增 read/remove，仅 ENOENT 表示不存在，损坏记录单列，权限和 IO 失败向调用方传出；clear/list 及 TUI 的宽容策略保留。SubmissionGuard 的连接参数收窄为实际消费的结构接口，协议、后台任务语义与存储格式不变。

界面增加输入框、按会话保存模型与四种默认模式、中断／取消／继续、暂停队列横幅及补模型确认。模型目录分页并保留档位与可用性；设置和任务控制不自动重放，按 outcome 读回实际状态或等待同实例快照，较新的队列事件不会被旧应答回滚。普通草稿按实例和会话保存在渲染进程内存，重载后丢失；尚未交付的待恢复原文继续保存在持久记录中。

同步了 desktop、control、usage 与既有桌面提案。未增加依赖、preload 入口或控制面协议。

## 独立实现审查

不同执行上下文直接核对工单、规格、实现、调用方、文档及回归；亲自执行最终主进程 26/26、定向 ESLint 与 desktop/control typecheck，Vite 开发转换及完整 renderer 的浏览器打包零警告。发现并关闭守护绕过令牌脱敏、跨实例迟到失败丢失输入、模式冲突码遗漏、队列状态与提示回滚、浏览器引入 Node 模块，以及拒绝后残留记录导致重复恢复的问题。各项有对应回归；重同步测试先等待快照自行触发查询，再施加额外并发触发，能捕获遗漏 onSnapshot 接线的回归。

结论：独立实现审查通过，无未解决阻断。共享恢复基线不能替代桌面接线检查，GUI 证据单独列在下节。

## 真实 Electron 外部验收

真实打包应用、真实 Runtime 与 ControlServer 使用临时 Code 档案；模型为本地 MockModelServer，TUI 为真实 TuiApp 加 FakeTerminal。所有 GUI 动作经 CUA 操作，观察使用实际窗口截图与可访问性树；后台状态经另一条已认证控制面连接读取。结果与任务身份保存在[结构化证据](05-electron/verification.json)。

| 外部清单 | 实际结果 |
| --- | --- |
| 提交与流式输出 | 输入框发送后观察到运行中和增长的回答，发送后草稿清空；默认模式由 Ask for approval 切到 Plan |
| 模型与模式同步 | GUI 从 mock 切到 second/alt-model，下一任务固定 second/alt-model、planMode=true；同时运行的 TuiApp 收到相同模型和 Plan 默认模式 |
| 中断、继续、取消 | GUI 中断到 interrupted；继续产生一个 resumesTaskId 指向原中断任务的新任务并完成；另一任务经取消按钮到 canceled |
| 重启暂停与补模型 | 实际停止并用原档案重启后台；停机期间将一个旧排队任务的模型置空作为遗留夹具。GUI 显示暂停横幅，恢复时显示 1 个任务与具体模型；取消确认仍暂停，再确认后模型补齐且任务完成，横幅消失 |
| 提交恰逢后台重启 | 临时 Unix socket 代理在后台返回真实成功应答后截断应答并断开，GUI 显示结果未知与发送禁用；代理经控制面停止后台。再以原档案重启后台，恢复代理后核实原键，没有重复任务 |
| 待核实输入下重开应用 | 上一行的待核实记录仍在磁盘时实际退出应用；用同一应用数据目录重开，首个快照后显示“已关联原任务，输入没有重复提交。”；请求仅匹配原 task_1d9cfcb534f312f64ba3113b，记录数归零 |

重启与丢答通过代理和临时后台生命周期确定触发，没有断开机器网络，没有访问日常档案。受管验收实例由探针重启后台，重新打开应用等价于重新连接已有后台；没有声称本轮重新验证日常应用自动拉起或旧版本恢复，这些沿用既有证据。最终窄修复不改变本轮已操作的正常 GUI 流程；丢答重开在最终打包产物上完成。
