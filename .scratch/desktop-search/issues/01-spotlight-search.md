# Desktop 应用内 Spotlight 搜索

Status: ready-for-human

## 目标与边界

拥有者于 2026-10-21 要求为 desktop GUI 制定类似 Spotlight 的全局搜索方案，并在本轮对话确认「应用内 Spotlight：⌘K 搜索全部工作区的会话、聊天内容，并快速跳转」。原轮交付方案；拥有者于本轮要求接手工单，实施者据此开始产品实现。

拥有者随后明确「接受，将工单转为ready for agent并提交」，确认下述 P1—P5、完整交互方案与性能验收标准；原轮完成实施交接并提交方案材料；本轮按接手请求完成实现，尚未提交代码。

本工单采用[重流程](../../../.agents/skills/development-workflow/SKILL.md)，当前角色为实施者；理由是新增交互、扩展控制面契约，并涉及历史分页与消息定位。设计取舍见[决策提案](../../../.agents/notes/implemented/feature/2026-10-21-desktop-spotlight-search.md)。本需求取代[旧桌面首版 R10](../../desktop-gui/spec.md)中暂缓 Spotlight 的部分，其他暂缓能力继续按各自工单处理。

| 编号 | 确认决定 |
| --- | --- |
| P1 | 全部工作区指当前连接的 Code 数据实例；在 PA 页面也可搜索 Code；名称结果显示工作区归属，正文结果按最新要求省略工作区名。新 Personal durable、其他数据实例与外部应用另案处理。 |
| P2 | 搜索普通开发会话，包含已存档会话；按工作区组织归属显示。SubAgent、调度、工作流执行与已退役角色会话不混入结果。打开已存档结果保留存档标记，不自动取消存档。 |
| P3 | 聊天内容包含已完整落盘的用户文字和 Agent 正文，包括执行记录中收起的中间回复；不包含思考、工具参数与结果、internal_report、文件内容和附件二进制。 |
| P4 | 中文连续字面匹配，英文 ASCII 字母不区分大小写；按整个输入查子串，支持单字。首版不提供拼音、模糊纠错、分词、正则或语义检索。 |
| P5 | 搜索只查询并导航，不调用模型，不执行命令或修改会话设置。名称与正文结果均直接打开对应普通会话，保留正常输入，不新增查看历史模式。首版先证明现有位置索引的检索路线满足性能验收，不预先引入全文引擎。 |

上述范围、下述交互方案与性能验收标准已由拥有者接受；随后截图反馈明确取代历史模式与精确消息定位：所有结果直接打开对应会话，删除「查看历史」栏和只读输入提示。技术实现可在同一产品范围内调整；如果性能验证要求改变索引架构，应先更新决策提案并复审。

## 交互方案

顶栏在侧栏开关左侧放置搜索图标，悬停显示 ⌘K；收起侧栏后两个按钮一起保留，避开原生窗口控制区，首个标签为两按钮让位。⌘K 切换搜索开关，组合输入和按键重复不切换。空查询按 summaries 的 lastActiveAt 显示最近活动的普通会话，最多 8 项；不持久化搜索词或新增最近使用数据库。

弹窗复用现有 Dialog、Input、Button 与 Lucide，从上向下进入，桌面中央偏上、宽度约 640px，小窗口留 16px 外边距；明暗沿用应用主题灰色背景。搜索框保持输入焦点，下方分「会话」和「聊天内容」两组。会话项显示名称与工作区，最多 8 项；正文项按拥有者最新参考图，上行显示会话名及存档标记，不再显示工作区名，下行显示高亮 snippet，能放下的短消息完整显示，超宽时按实际像素宽度让匹配词尽量位于中间，缩放时重新计算，右侧显示相对时间；悬停时间可看完整日期。长名称单行末尾省略，正文预览保持单行，超出显示范围的部分裁切，名称结果的工作区、存档标记与右侧时间独立保留。结果使用滚动区域，两组之间显示分隔线；滚动条只在滚动中及停止后 700ms 内显示，固定宽度，不再叠加详情弹窗。

标题匹配立即在后台已筛好普通会话资格的完整 summaries 上执行，快照只补名称和存档等展示字段；摘要尚未准备好时显示加载，不能以快照的 `kind` 代替资格判定。聊天查询在输入停止 180ms、且输入法组合结束后开始。每页最多 20 条正文命中，每条历史消息一个结果；一条消息多次命中先展示首个片段。会话结果按完整匹配、前缀、子串分层，同层按最近活动排序；正文使用稳定扫描顺序并渐进追加，不声称已按全库相关性或时间排序。切换输入后清除旧正文结果，避免把旧结果当作新查询答案。

↑／↓移动选中项，Enter 打开，Esc 或再次 ⌘K 关闭并恢复原焦点；组合输入期间 Enter 只确认输入法。使用 combobox／listbox 语义、可见选中态和状态播报。⌘K 在输入框中也可用；首次连接遮罩未退出、其他模态窗口已打开时不抢焦点。Ctrl+K 只在非终端区域作为替代，终端 Ctrl 组合键仍交给 shell。

按拥有者最新反馈，搜索弹窗省略常驻检索说明、逐来源覆盖提示和「重新搜索」按钮；加载使用输入框内图标，查询状态保留读屏播报，实际读取失败与离线可见，已有命中可滚动续载。只有所有可读范围扫描结束且没有遗漏时才播报「没有找到」；未完成时可播报「暂未找到，继续搜索中」。自动串行续页到得到 20 条或扫描完成；已有 20 条后滚动接近列表末尾自动续查，移除「加载更多」按钮，不设置累计结果总上限。无命中的续页也必须推进，且给输入、关闭和后台其他工作让出执行时间。

点击会话项或正文项均关闭弹窗，复用现有 openSession 和标签管理，直接打开对应普通会话。结果片段帮助辨认会话，不单独定位原消息；正常消息范围、实时输出、向上加载更早历史、草稿与附件及输入能力沿用既有行为。选择后焦点交给会话输入框，Esc 取消仍恢复原焦点。

## 实施步骤与影响范围

### 1. 先验证并修好已有检索

1. 增加最窄回归：两个以上会话、单页一个命中、无命中页、预算恰在会话切换、中文和长行；证明固定历史数据下遍历会终止、不重不漏。跨会话按稳定会话身份排序；返回最后实际扫描条目的会话和偏移；失效游标明确要求重搜，不能静默从头开始。
2. 沿用 `search_history`，补齐 `ops.ts` 中已有 server 支持的 cursor、scan_limit、context_chars、since、until 类型，并保留请求 snake_case 与响应 camelCase 的显式转换。新增可选 `scope: "workspace_chats"`，省略时保持已有调用的搜索范围与提取语义；该 scope 固定采用 P2—P4。普通会话资格由宿主身份判定，不能只以 `kind === "dev"` 识别。内部正文提取复用历史展示规则，避免正文命中无法展示的内容。
3. 搜索候选集合来自后台全部普通会话，包含存档；工作区展示使用 sessionDisplayAttribution。为既有 `list_session_summaries` 增加相同可选 `scope: "workspace_chats"`，由后台与正文搜索复用资格判定，省略 scope 保持旧调用不变。GUI 使用这一完整列表作名称候选，不能从缺少调度绑定信息的快照自行推断资格，也不能把已打开标签、最新任务快照或侧栏可见项当全局数据源。GUI 必须如实处理 complete、cursor、unindexedSessionIds 与历史尚未落盘的区别；创建／归属更新和重连后重取候选，旧代次不安装。
4. 首先在临时合成历史上测冷索引、热查询、零命中、最后会话才命中与大单条消息，并并发读取后台状态。根据结果只改本功能必要的检索路径：增量索引用固定字节批次，索引登记和进度在同一短事务内；按索引分批取行并按条目与字节计预算，避免整文件分配和每会话 `.all()`；拥有者 GUI 路径在批次间让出事件循环。已有同步 Agent 工具调用保持其既有接口。
5. 每个搜索控制器最多一个在途正文请求，输入变化只记录最后查询；旧页结束后不再续扫旧查询。索引准备也要计入预算、能从进度继续，不能只给匹配循环加 scan_limit。关闭、断线与换快照淘汰旧结果；请求结束后不再继续旧轮次。若单条 JSON 解析仍阻塞心跳，先退回方案评审，选择隔离读取执行或派生全文索引，不能用客户端超时掩盖后台阻塞。

GUI 续页游标必须能表示「准备索引」和「扫描正文」两阶段，并关联当前会话、源文件身份、索引进度和最后实际扫描位置。首条候选尚未读到就耗尽预算时，返回 `hits=[]`、`complete=false`、非空续页游标和本批进度，客户端继续同一查询；不能因没有命中或扫描条数为零停止。存量无阶段游标按原扫描语义处理，新增阶段仅用于 GUI scope。每个不完整页必须推进索引字节或扫描位置；不能推进时返回明确错误，禁止无限返回相同游标。替换或截断来源使对应游标失效，要求重搜，不拿旧偏移读新文件。

GUI scope 增加按会话返回的带 code 来源问题列表，区分尚未首次落盘、已登记历史丢失、权限失败和损坏；判定依赖历史索引状态与已提交输出引用，不仅看路径存在与否。可核实的其他会话继续搜索，失败来源在响应与搜索状态中明确列为未覆盖，GUI 不逐项展示；`complete` 只表示扫描遍历到末尾，不代表来源全部可读。只有 `complete=true` 且没有待落盘来源或来源问题时才可宣称全范围零命中。旧 scope 保留既有失败语义。

涉及 `history-index.ts`、runtime 的拥有者搜索与会话摘要、core Store 的既有摘要查询、control server／ops／协议版本与接口夹具；共享扫描修复同时核对 `packages/agent/src/host-tools.ts`、TUI commands、CLI 搜索调用和旧 summary 消费方。首版不改核心 schema、不复制历史正文、不增加依赖；如这一前提不能满足性能标准，先修订架构方案。

### 2. 直接打开普通会话

拥有者最新截图反馈取代独立历史定位方案，理由与取舍见[直接会话导航决定](../../../.agents/notes/implemented/simplification/2026-10-21-desktop-search-session-navigation.md)。正文项与名称项统一走既有 openSession，不再创建独立 EventFlow 或禁止输入；删除窗口控制器、专属栏、定位高亮和返回最新操作，以及只服务这条路径的方法与过期测试。

实现后更新 `docs/modules/desktop.md`、`docs/modules/control.md`、`docs/modules/core.md`、`docs/modules/view.md` 中实际受影响的行为，以及 `docs/usage.md` 的入口与故障恢复；若修改 runtime 独立契约，同步 `docs/modules/runtime.md`。将提案转 implemented，给承载决定的入口加 Note 锚点；旧存档决定只补充搜索打开的展示例外。只有新增或修改命令时才同步 README、development 与 pre-push-checks 的对应命令，不提前将拟议行为写成现状。

### 已确认的性能验收标准
