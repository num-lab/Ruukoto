# Desktop 应用内 Spotlight 搜索

Status: ready-for-agent

## 目标与边界

拥有者于 2026-10-21 要求为 desktop GUI 制定类似 Spotlight 的全局搜索方案，并在本轮对话确认「应用内 Spotlight：⌘K 搜索全部工作区的会话、聊天内容，并快速跳转」。本轮交付方案，不实施产品代码。

拥有者随后明确「接受，将工单转为ready for agent并提交」，确认下述 P1—P5、完整交互方案与性能验收标准；本次完成实施交接并提交方案材料。

本工单采用[重流程](../../../.agents/skills/development-workflow/SKILL.md)，角色为方案者；理由是新增交互、扩展控制面契约，并涉及历史分页与消息定位。设计取舍见[决策提案](../../../.agents/notes/proposed/feature/2026-10-21-desktop-spotlight-search.md)。本需求取代[旧桌面首版 R10](../../desktop-gui/spec.md)中暂缓 Spotlight 的部分，其他暂缓能力继续按各自工单处理。

| R1 | 使用应用内 ⌘K 打开类似 Spotlight 的搜索界面。 | 拥有者选择 |
| R2 | 覆盖全部工作区的会话与聊天内容。 | 拥有者选择 |

### 已确认的产品范围

| 编号 | 确认决定 |
| --- | --- |
| P1 | 全部工作区指当前连接的 Code 数据实例；在 PA 页面也可搜索 Code，结果明确显示工作区归属。新 Personal durable、其他数据实例与外部应用另案处理。 |
| P2 | 搜索普通开发会话，包含已存档会话；按工作区组织归属显示。SubAgent、调度、工作流执行与已退役角色会话不混入结果。打开已存档结果保留存档标记，不自动取消存档。 |
| P3 | 聊天内容包含已完整落盘的用户文字和 Agent 正文，包括执行记录中收起的中间回复；不包含思考、工具参数与结果、internal_report、文件内容和附件二进制。 |
| P4 | 中文连续字面匹配，英文 ASCII 字母不区分大小写；按整个输入查子串，支持单字。首版不提供拼音、模糊纠错、分词、正则或语义检索。 |
| P5 | 搜索只查询并导航，不调用模型，不执行命令或修改会话设置。查看命中附近历史时暂不接受提交，返回最新后恢复输入。首版先证明现有位置索引的检索路线满足性能验收，不预先引入全文引擎。 |

上述范围、下述交互方案与性能验收标准已由拥有者接受。技术实现可在同一产品范围内调整；如果性能验证要求改变索引架构，应先更新决策提案并复审。

| 位置 | 当前事实 | 本功能所需 |
| --- | --- | --- |

| `packages/core/src/history-index.ts` | 派生索引不存正文；当前跨会话 cursor 会重扫更早会话，预算恰在会话切换处用错偏移。索引和搜索使用同步整块读取。 | 修复跨会话续页，并对索引、扫描与单条读取分别设预算。 |

| `packages/view/src/event-flow.ts`、`state.ts` | 最新投影初始保留 300 条；孤立旧条目可能被裁掉；完整任务事件可能补入窗口之外的消息。 | 历史定位使用独立的连续窗口，实时投影继续接收事件。 |
| `apps/desktop/src/main/ipc.ts` | 未放行历史搜索；Electron、MyGo 共用 Host 和 renderer。 | 只向 Code 放行本功能所需只读能力，复用现有桥接。 |

上述缺陷由本次源码调查发现，不代表已经修复。跨会话分页复现与性能调查记入验收证据；现有 CLI、TUI、Agent 的搜索调用也是回归范围。

[调查与审查证据](../evidence/investigation.md)保存了可运行的临时合成档案探针和结果：10 万条消息首次索引加 2000 条扫描约 4.41s，热路径约 51.76ms；两会话单条命中续页会 a／b 重复，预算跨会话时会漏下一会话首条。它们是现状缺陷证据，不是产品验收通过记录。

## 交互方案

侧栏展开时在 New chat 附近增加「搜索」行，显示放大镜与 ⌘K。收起侧栏时沿用现有图标轨道约定，仍可用快捷键打开。空查询按 summaries 的 lastActiveAt 显示最近活动的普通会话，最多 8 项；不持久化搜索词或新增最近使用数据库。

弹窗复用现有 Dialog、Input、Button 与 Lucide，桌面中央偏上、宽度约 640px，小窗口留 16px 外边距；明暗沿用应用主题。搜索框保持输入焦点，下方分「会话」和「聊天内容」两组。会话项显示名称与工作区，最多 8 项；正文项显示关键词片段、会话、工作区与时间，按需标注已存档。结果使用滚动区域，不再叠加详情弹窗。

标题匹配立即在后台已筛好普通会话资格的完整 summaries 上执行，快照只补名称和存档等展示字段；摘要尚未准备好时显示加载，不能以快照的 `kind` 代替资格判定。聊天查询在输入停止 180ms、且输入法组合结束后开始。每页最多 20 条正文命中，每条历史消息一个结果；一条消息多次命中先展示首个片段。会话结果按完整匹配、前缀、子串分层，同层按最近活动排序；正文使用稳定扫描顺序并渐进追加，不声称已按全库相关性或时间排序。切换输入后清除旧正文结果，避免把旧结果当作新查询答案。

↑／↓移动选中项，Enter 打开，Esc 关闭并恢复原焦点；组合输入期间 Enter 只确认输入法。使用 combobox／listbox 语义、可见选中态和状态播报。⌘K 在输入框中也可用；首次连接遮罩未退出、其他模态窗口已打开时不抢焦点。Ctrl+K 只在非终端区域作为替代，终端 Ctrl 组合键仍交给 shell。

搜索中、继续扫描、零命中、部分历史不可读、读取失败与离线分别呈现。只有所有可读范围扫描结束且没有遗漏时才显示「没有找到」；未完成时可显示「暂未找到，继续搜索中」。自动串行续页到得到 20 条或扫描完成；已有 20 条后以列表末尾「加载更多」续查，不设置累计结果总上限。无命中的续页也必须推进，且给输入、关闭和后台其他工作让出执行时间。

点击会话项复用现有 openSession 和标签管理。点击正文项后关闭弹窗，在该会话进入命中附近的历史窗口，展开所属执行记录，滚动并短暂高亮目标消息及关键词。搜索定位成功后将焦点交给目标消息区域；加载失败时保留原视图，显示可重试原因，不把停留在会话最新处称为定位成功。

历史窗口显示「查看历史」与「返回最新」。向上／向下滚动分别加载连续的更旧／更新页；实时新输出只更新后台事实和正常会话投影，不跳走旧历史，也不自动滚到底部。返回最新后恢复正常对话流与输入；历史窗口中的输入区暂不接受提交，避免把历史位置误认为分支或继续来源。切换会话后退出历史窗口。

## 实施步骤与影响范围

### 1. 先验证并修好已有检索

1. 增加最窄回归：两个以上会话、单页一个命中、无命中页、预算恰在会话切换、中文和长行；证明固定历史数据下遍历会终止、不重不漏。跨会话按稳定会话身份排序；返回最后实际扫描条目的会话和偏移；失效游标明确要求重搜，不能静默从头开始。
2. 沿用 `search_history`，补齐 `ops.ts` 中已有 server 支持的 cursor、scan_limit、context_chars、since、until 类型，并保留请求 snake_case 与响应 camelCase 的显式转换。新增可选 `scope: "workspace_chats"`，省略时保持已有调用的搜索范围与提取语义；该 scope 固定采用 P2—P4。普通会话资格由宿主身份判定，不能只以 `kind === "dev"` 识别。内部正文提取复用历史展示规则，避免正文命中无法展示的内容。
3. 搜索候选集合来自后台全部普通会话，包含存档；工作区展示使用 sessionDisplayAttribution。为既有 `list_session_summaries` 增加相同可选 `scope: "workspace_chats"`，由后台与正文搜索复用资格判定，省略 scope 保持旧调用不变。GUI 使用这一完整列表作名称候选，不能从缺少调度绑定信息的快照自行推断资格，也不能把已打开标签、最新任务快照或侧栏可见项当全局数据源。GUI 必须如实处理 complete、cursor、unindexedSessionIds 与历史尚未落盘的区别；创建／归属更新和重连后重取候选，旧代次不安装。
4. 首先在临时合成历史上测冷索引、热查询、零命中、最后会话才命中与大单条消息，并并发读取后台状态。根据结果只改本功能必要的检索路径：增量索引用固定字节批次，索引登记和进度在同一短事务内；按索引分批取行并按条目与字节计预算，避免整文件分配和每会话 `.all()`；拥有者 GUI 路径在批次间让出事件循环。已有同步 Agent 工具调用保持其既有接口。
5. 每个搜索控制器最多一个在途正文请求，输入变化只记录最后查询；旧页结束后不再续扫旧查询。索引准备也要计入预算、能从进度继续，不能只给匹配循环加 scan_limit。关闭、断线与换快照淘汰旧结果；请求结束后不再继续旧轮次。若单条 JSON 解析仍阻塞心跳，先退回方案评审，选择隔离读取执行或派生全文索引，不能用客户端超时掩盖后台阻塞。

GUI 续页游标必须能表示「准备索引」和「扫描正文」两阶段，并关联当前会话、源文件身份、索引进度和最后实际扫描位置。首条候选尚未读到就耗尽预算时，返回 `hits=[]`、`complete=false`、非空续页游标和本批进度，客户端继续同一查询；不能因没有命中或扫描条数为零停止。存量无阶段游标按原扫描语义处理，新增阶段仅用于 GUI scope。每个不完整页必须推进索引字节或扫描位置；不能推进时返回明确错误，禁止无限返回相同游标。替换或截断来源使对应游标失效，要求重搜，不拿旧偏移读新文件。

GUI scope 增加按会话返回的带 code 来源问题列表，区分尚未首次落盘、已登记历史丢失、权限失败和损坏；判定依赖历史索引状态与已提交输出引用，不仅看路径存在与否。可核实的其他会话继续搜索，失败来源明确列为未覆盖；`complete` 只表示扫描遍历到末尾，不代表来源全部可读。只有 `complete=true` 且没有待落盘来源或来源问题时才可宣称全范围零命中。旧 scope 保留既有失败语义。

涉及 `history-index.ts`、runtime 的拥有者搜索与会话摘要、core Store 的既有摘要查询、control server／ops／协议版本与接口夹具；共享扫描修复同时核对 `packages/agent/src/host-tools.ts`、TUI commands、CLI 搜索调用和旧 summary 消费方。首版不改核心 schema、不复制历史正文、不增加依赖；如这一前提不能满足性能标准，先修订架构方案。

### 2. 补齐精确历史定位

1. 扩展 `read_history`：`before`、`after`、`around` 三者互斥，around 为命中 entryId；返回包含目标且前后连续的窗口，以及更旧／更新两个游标。旧 before 和最新页调用语义保持；新增响应字段由同仓协议版本统一管理。
2. around 默认读取目标前后合计最多 50 条，正文预算沿用现有页预算。必须保证目标入页，附近条目允许因预算减少；长目标正文按既有 UTF-8 分片补读后再判定位成功。around 和前后续页优先复用位置索引，不为远古命中从最新一页逐页追溯，也不每页整文件解析。缺目标、来源损坏、文件身份变化分别报类型化错误。
3. CodeState 持有本次搜索定位窗口和导航序号；复用 EventFlow 的正文与任务分组投影，保持独立于最新 SessionView。只恢复窗口内条目及其所需任务状态，不把整个任务的全部输出重放进窗口。为窗口内历史补读、任务状态和工具详情保留同实例／代次检查；连续性不能证明时停止安装该页。
4. Conversation 为真实 entryId 建立可检索的 DOM 关联，允许一个 entry 对应多个流式段；先展开 ExecutionTrace，再用现有 MessageScroller 定位 section，并校准到目标消息。高亮只改展示，不把带标记的文本写回历史。返回最新、切会话、同实例重连与换实例分别清理或重建窗口，迟到响应不覆盖新导航。

涉及 core history、runtime readHistory、control ops／server、view 的历史窗口或现有 EventFlow 最小扩展、CodeState、Conversation、activity／tool-activity。需要单独核对 TUI 与 Inspector 的旧分页调用。不得通过 appendEntryView 向最新列表塞入孤立旧消息来代替连续窗口。

### 3. 接入弹窗、文档与体验验收

增加 `search-dialog.tsx` 与必要的搜索状态持有代码，在 App 接入快捷键和入口；状态归 Code 当前实例，不混用 Personal。IPC 仅向 Code 放行 search_history；read_history 使用原桥接并校验扩展参数。Electron 和 MyGo 共用 renderer／Host，不新增原生搜索桥接或系统级快捷键。

实现后更新 `docs/modules/desktop.md`、`docs/modules/control.md`、`docs/modules/core.md`、`docs/modules/view.md` 中实际受影响的行为，以及 `docs/usage.md` 的入口与故障恢复；若修改 runtime 独立契约，同步 `docs/modules/runtime.md`。将提案转 implemented，给承载决定的入口加 Note 锚点；旧存档决定只补充搜索打开的展示例外。只有新增或修改命令时才同步 README、development 与 pre-push-checks 的对应命令，不提前将拟议行为写成现状。

### 已确认的性能验收标准

界面打开和标题结果 p95 ≤ 100ms；热索引在常用规模下，输入稳定后首批正文结果或明确扫描进度 p95 ≤ 500ms（含 180ms debounce），无命中完整扫描 ≤ 3s；增长规模允许渐进返回，但每批必须推进，停止输入或关闭后不得继续发起旧轮次查询。并发 `ping`／状态读取 p95 ≤ 100ms、单次 ≤ 250ms，用于发现同步检索阻塞后台；同时报告首批命中、全部扫完与内存峰值，不以仅显示 spinner 达成全文性能要求。若未达到，修订检索实现并独立复审，不降低标准宣布通过。
