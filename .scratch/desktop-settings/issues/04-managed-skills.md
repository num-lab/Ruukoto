# 04 Skills 托管导入、启停与安全移除后端

Status: ready-for-agent

## 目标与边界

补齐[Skills 管理边界](../spec.md#skills-管理边界)和 R7。前置：无。共享的仅为技能文件扫描与托管操作，Code 与 Personal 的任务、锁和证据仍各自持有。旧外部技能不迁移、不改写。

## 方案

1. 扩展 `packages/agent/src/skills.ts`，保留原扫描结果与排序语义，显式接收外部来源及托管清单选中的包；Code 的托管根在 agentDir，Personal 的在其档案，不能在外部技能库建管理目录。返回来源、宿主内的稳定身份、内容修订和只读状态。正文详情有界读取，使用稳定身份而非名称定位；模型目录仍只含名称、描述和原版本规则。
2. 托管根内固定为 `state.json`、原子写临时文件 `state.json.tmp`、`packages/<id>/<原包名>/` 与导入暂存区 `.staging/<id>/<原包名>/`，不向 Personal 档案顶层散放临时目录。单包导入采用普通文件复制、总量限制、复用原解析检查、拒绝源链接/硬链接和冲突，保留原包目录名以稳定缺省技能名称，校验完成后发布不可变内容至固定 packages 路径；再条件原子提交 state.json，以清单提交作为可见点。发布内容后清单写失败的孤立包不可见，保留供诊断，不扫描它当已安装。文件失败保留源库和原托管库，返回带 code 错误；预览与最终发布再次核对同一内容。
3. 托管状态清单有格式版本、内容修订、包身份及 enabled/disabled/removed 状态；校验和提交在串行变更段核对修订，未知版本拒绝使用。启停/移除只改元数据，固定内容路径不移动；移除从可用清单消失但保留字节，不新增物理 GC。新任务按当前清单选入技能，旧任务正文/引用及原恢复快照继续可读；导入重新命名或启用冲突不覆盖外部赢家。
4. `packages/runtime/src/runtime.ts`、`control/src/server.ts` / `ops.ts` 增最窄列表、详情、导入预览/提交、启停和移除入口；沿既有 list_skills 保留 TUI 读取兼容，不公开任意文件读取或删除接口。
5. 核对 `latestAgentReferenceSnapshot`（包括 ended agent_wait）、内部对话及恢复入口；后续新任务从旧参考装配时按当前托管状态过滤并保存新的选择记录，不能复活停用/移除技能或改写旧证据。共享托管布局检查保留普通目录/文件、当前所有者、无符号链接、文件 nlink=1 与私有权限要求，目录 0700、文件 0600；只允许已定义的管理节点，包内名称仍按技能内容规则处理。未完成 .staging、部分 state.json.tmp 与合法孤立 packages 可安全重开，但不能当作已提交清单或技能；不自动删除它们。Personal 在 06 将根目录纳入档案校验与权限分类，并于持锁后、读取/启动前复用内部布局检查；不引入旧 Runtime 依赖。
6. 新模型可见目录/内容仍通过 Code 选择记录与 Personal 请求快照重建；修改了模型可见文字时再按 agent-facing-text 审查。同步 `docs/modules/agent-context.md`、`control.md`，补实现决定与安全边界锚点。
