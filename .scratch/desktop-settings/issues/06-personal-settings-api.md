# 06 Personal durable 配置查询与停机管理入口

Status: ready-for-agent

## 目标与边界

提供新 Personal 的模型、Skills、MCP 设置操作，遵守[Personal 生效规则](../spec.md#personal-接入与生效)及 R2–R4、R6–R7。前置：[04](04-managed-skills.md)。不迁移个人聊天或引入旧 Db/Runtime，不在线改写持锁配置。

## 方案

1. 在 `apps/ruukoto/src/personal-control.ts` 增认证只读配置/版本/忙状态接口，返回模型元数据、技能来源/诊断、MCP 服务/工具/凭据引用与未决阻塞；由持有档案的后台读取，不暴露密钥、任意 SQL、文件或完整证据。另增仅由用户主动触发的模型连接测试，使用所选配置及实际后台凭据环境，有限超时与最小输出，不运行工具或提交主会话工作；返回脱敏测试结果，保存成功不代替测试。
2. 增受限的机器管理入口，可由 CLI 与远端固定程序调用；输入/输出是版本化且有界的 JSON，操作仅含查询、配置预检/保存、显式模型测试、托管技能、MCP 发现与支持的生命周期查询。非交互入口使用结构化错误，不复用向导文字解析。离线操作必须 `lockPersonalProfile`，无锁不直读存储；模型测试无法取得实际服务环境时明确返回尚不可验证，不拿 SSH shell 的凭据证明 systemd 可用。
3. 复用 `parse/savePersonalConfig`、`savePersonalSkills`、`savePersonalMcp`，修订比较和配置写入在同一锁内。所有保存再次检查未决输入/工作、配置身份和未知外部占用；模型凭据只保存环境变量名，MCP 凭据按原私有文件及摘要规则核实，失效不转匿名。
4. 先修改 `apps/ruukoto/src/personal-profile.ts`：将精确的 `managed-skills` 名称纳入顶层私有目录分类，布局检查与锁后 chmod 复用同一分类，不能只加入普通文件 allowed 或放宽任意目录。托管根缺失仍允许旧档案持锁，`profile.json` / `PERSONAL_FORMAT` 不因该可选目录改版；存在时先用 lstat 核实普通目录、无符号链接、当前 uid 和无 group/other 权限，再沿原规则保持 0700，禁止按文件改成 0600。取得 EXCLUSIVE 锁后、配置读取与 Harness 启动前，调用 04 的托管内部布局检查；对清单读取和导入提交沿用相同检查，不以 chmod 修复错误所有者、链接或公开目录。顶层未知目录仍拒绝。
5. 集成 04 的扫描、state.json 与包操作，托管根固定在个人档案，外部配置目录只读；state.json.tmp、.staging 及合法孤立 packages 只能位于托管根内，私有普通类型通过校验后允许再次持锁，不解析未提交临时 JSON、不扫描暂存或孤立包，也不自动删除。包文件继续核实所有者、无符号链接、nlink=1 和 0600，目录保持 0700，未知管理节点/清单版本拒绝。保证 `personal-skills.ts` 每次实际请求的目录、正文及引用仍落入 durable 请求证据，外部库路径与托管路径不得误混成本机 GUI 路径。
6. 为 Personal MCP 补持久单服务启停的配置版本和显式迁入，保存时生成新代次，发现只请求原定义并供拥有者选择；停用保留端点与允许列表、不允许新调用，不能修改已有操作/请求快照。核对恢复标记，旧程序拒绝未知版本。单独修改与验证相关原决定笔记，不把元数据当第二套执行状态。
7. 提供有界远端目录选择/技能预览所需操作，限拥有者明确选择的配置来源与导入过程，不扩展成通用远端文件浏览器。所有机器命令与参数的新增同步 README、`docs/development.md`、pre-push-checks 和 `docs/usage.md`；模块事实同步 `personal-durable.md` 的档案布局及安全约束，并同步基础档案保护的决定与锚点。

## 待处理审查意见

**P1：把托管技能纳入 Personal 档案布局与权限校验。** `lockPersonalProfile` 对档案顶层目录采用白名单，并在取得锁后按另一份目录名单修正权限；当前两处均不包含拟新增的 `managed-skills`。复审在隔离临时档案创建该目录后，再次取得锁即报 `profile_unrecognized`。若仅实现第 4 步的扫描与导入，首次导入后后续管理和后台重启都会被档案校验阻止。源码依据：[档案锁与布局校验](../../../apps/ruukoto/src/personal-profile.ts)。

方案者须将 `personal-profile.ts` 的目录白名单、权限修正和安全校验明确纳入本单：托管目录保持私有普通目录，保留所有者、符号链接和权限检查，并核对 04 的清单与临时发布布局可被重新持锁接受。不能只放宽任意目录或遗漏权限名单，导致托管目录被按普通文件设为 `0600`。此项接线方案须复审，登记意见不等于问题已解决。

处理方案：上文步骤 4/5 与 04 已补齐根目录的统一分类、持锁后的内部校验和临时发布恢复；安全拒绝与旧档案可缺省并行保留。独立方案复审已通过，P1 方案阻断解除，尚无产品实现证据。
