## 产品范围

### 设置结构

保留左下设置入口与左分类、右内容浮窗。类别为「外观」「模型」「Skills」「MCP」「PA 远程连接」「已存档会话」。外观和存档沿用现有功能；本轮的「等」涵盖配置所需的凭据和连接状态，不扩展到 IM、调度、权限、工作流或全部后台管理功能。

模型、Skills、MCP 顶部使用 shadcn/ui Tabs，仅显示「Code」「PA」两个选项，不加标题、说明或重复的范围提示；分别对应本地 Code 与远程 Personal，默认当前目标，切换不改变聊天目标。MCP 在 Code 下还须选择工作区，初值可来自当前普通会话；没有工作区时引导先添加。同一工作区可能组织多个旧项目会话，不能从工作区唯一推断配置 `project_id`；多来源时提供按名称选择的「配置来源」，默认当前会话原来源，无当前会话时默认工作区自身来源。后台有界列出候选与服务归属，程序管理内部标识。Personal 无工作区或来源选择。

设置应可在没有打开会话时使用。类别切换、关闭、切换目标或工作区遇到未保存编辑时提供保存、放弃、继续编辑选择；正在提交或待核实时不得把另一目标结果装入当前表单。沿用现有 shadcn 组件、视觉与焦点行为，不增加页面框架或第二套窗口。

### 功能与范围矩阵

| 类别 | Code | Personal |
| --- | --- | --- |
| 模型 | 实例级提供方及模型增改删；API Key 状态、替换与清除；后台默认模型与 Effort；摘要模型；显式连接测试 | 档案级当前模型、API 类型、地址、上下文与输出上限、图片能力、凭据环境变量引用；显式连接测试；不伪造提供方目录或独立摘要模型 |
| Skills | 实例级列表、名称检索、诊断、正文预览；本地单个技能目录导入；托管技能启用、停用、移除 | 档案技能库目录配置、远端技能列表、诊断及正文预览；从远端已有单个技能目录导入托管副本；托管技能启用、停用、移除 |
| MCP | 所选工作区的服务增改删、启停、连接及工具发现检查；凭据绑定；工具允许列表与 `read/write/unknown` 声明 | 档案级服务增改删、启停、发现与工具允许列表；远端私有凭据文件引用或显式匿名；保留逐次审批与配置代次 |
| 连接与凭据 | 模型密钥和 MCP 所需凭据在相关表单管理，只读显示配置状态 | SSH 主机、新 durable 档案目录、程序定位与生命周期方式由连接向导选择；模型环境引用与 MCP 私有文件引用在远端校验 |

Code 密钥允许在明确提交期间经过 IPC，到后台后沿已有存储保护；读取只返回元数据，输入保存后清空，不回显已有值，不写日志或浏览器存储。MCP 新凭据第一次写入就限定原配置来源与 `mcp` 操作，不能等服务配置成功才收窄；当前通用凭据创建接口缺此参数，须补最窄专用写入口或受校验的来源参数，失败/取消也不能遗留通用 HTTP 可用的秘密。模型目录中的高级字段采用可选展开表单；修改时保留未展示字段和后端脱敏占位符，不通过重建简化对象丢掉已有 headers 或兼容设置。

Code 模型凭据按已配置位置展示，配置存在和实际认证可用分别报告；既有 `credentials.configured` 只指存储条目。存储条目、目录 apiKey/具体 header 的替换或清除须明确选定来源，不影响其余来源，环境由后台启动环境管理；移除存储条目后不能保证提供方不可用。设置读取不解析动态凭据、不执行命令、刷新 OAuth 或联网，无法安全证明的环境/SDK 有效性保持未验证；连接测试仍由用户主动触发。[02](issues/02-code-models.md)承担脱敏元数据、操作范围与 TUI 在线/离线同步。

Code 的模型地址沿已有后端校验；MCP 继续沿已有 HTTPS 远程传输约束，不加入 stdio、OAuth 或仓库自动发现。连接测试由用户主动触发，并说明会联网；模型测试可能产生费用。保存配置不等于连接测试通过。MCP 工具发现不执行任何业务工具，远端只读标注不自动成为本地授权。

### Skills 管理边界

保留既有 `<agentDir>/skills`、Personal 配置的外部技能库和已有符号链接的读取行为，作为「外部维护」来源展示；管理操作不改写或删除这些源目录。用户选择导入后，由所属后台把单个根含 `SKILL.md` 的技能包复制到宿主私有托管区；源目录不修改。Code 使用本机目录选择，Personal 使用远端目录选择，不能将 Mac 路径提交给远端冒充存在。本期不包含跨机上传。

托管区以程序生成的身份定位技能，不按可重复的技能名称删除。复用已有扫描、frontmatter、正文与引用规则，导入前预览名称、描述、诊断和冲突；冲突时拒绝覆盖。复制拒绝符号链接、硬链接、设备和越界路径，限制总文件数与字节数；临时复制校验完成后再发布，失败不能暴露半个技能或清理源目录。

托管相对布局为 `managed-skills/packages/<程序身份>/<原包目录名>/`，发布后内容与路径不改；Code 位于自身 agentDir，Personal 位于自身档案，绝不建在配置的外部技能库内。宿主私有、版本化状态清单只保存托管包身份、内容修订及启用/停用/移除状态，采用条件修订与原子写；扫描显式接收外部来源和清单选中的托管包，不扫描全部 packages，不在旧外部技能树新增状态。保留原包目录名，以免依赖目录名的缺省技能名称改变。

托管根内固定为 state.json、state.json.tmp、packages 与 .staging 四类管理节点，临时发布均留在此根内。[04](issues/04-managed-skills.md)提供私有普通目录/文件、所有者、无链接及清单布局检查；[06](issues/06-personal-settings-api.md)将 managed-skills 同时纳入 Personal 档案布局与权限分类，持锁后在读配置/启动前复用内部检查，目录保持 0700、文件 0600。托管根不存在的有效旧档案仍可开启；安全的半成暂存、未提交临时清单或孤立包允许再次持锁，但不成为已安装技能、不自动删除；未知管理节点、版本和不安全对象继续拒绝。

启停与移除只改清单，不能移动旧 `PinnedSkill.dir`。停用/移除从后续新任务选择起生效，既不选入自动目录，也不接受新的显式调用；已钉版任务及原恢复引用继续可读，历史已有正文不被撤回。新的任务即使复用 `latestAgentReferenceSnapshot` 进入内部对话阶段，也须按本次托管状态重新选择技能并记录新的选择事实，不能复活停用项或覆盖旧快照。frontmatter 的「仅显式调用」是独立状态。导入、重新启用均检查重名冲突；Personal 状态清单变更仍沿原停机锁与未决检查，不因此新增在线配置。首版移除是逻辑移除，页面明确说明保留包字节供旧引用读取，不提供物理回收；不删除既有会话、技能历史快照或引用证据。

### Personal 接入与生效

本功能只增加新 Personal 的设置管理连接，不承诺同步迁移聊天、审批流和旧 Personal view 投影。旧连接与新 durable 管理连接必须有明确来源标记；未提供新协议或程序时说明需要升级，不能回退到旧后台显示成功。新管理连接失败不使 Code 设置失效。

复用 OpenSSH 的同账户认证与共用 Node 宿主。在线状态及只读查询复用 `personal-control.ts` 的认证 HTTP over Unix socket；后台停机时由远端固定程序的受限机器入口读写配置，JSON 经 stdin/stdout 传递，不拼接为远端 shell 命令。机器入口只允许本功能明确操作，禁止任意路径读写或任意命令执行；离线读取也须持锁，在线读取经后台，不能绕过锁直读活跃 SQLite。协议版本、档案身份、路径与请求版本由程序核实。

保存需停机的设置时，界面先展示影响并由拥有者选择「停止、保存并启动」。支持现有 CLI 脱离后台，以及仓库部署的 systemd 服务两种生命周期；向导识别或让拥有者选择受支持的既有服务，不接受自由命令模板。受管开发后台只读，拒绝由设置页接管生命周期。systemd 必须停止原服务并等待锁可取得，不能只发 HTTP stop 后与监督者抢锁。当前服务 helper 不允许管理后台自身，也不提供 start/stop；部署必须另给精确固定的系统服务 start/stop 授权，且配置优雅停止超时不自动 SIGKILL。无该前提只读并给出管理员部署步骤，GUI 不安装提权规则。任何方式都先检查未决输入、工作和未知外部占用，忙则保留配置并返回可处理事项，不取消工作、不强杀、不清除占用。

远端配置入口在停机持锁后再次核对原档案、修订与未决事实，调用现有 `savePersonalConfig`、`savePersonalSkills`、`savePersonalMcp` 的规则；一项表单一次写入，不承诺跨多个配置文件原子提交。Personal MCP 当前没有持久的单服务停用状态，实现须显式增加版本化的配置表达和旧配置迁入规则，保留服务信息而从新调用中排除停用项，核对 durable 原配置与历史证据，不能简单删服务冒充可恢复停用。

成功提交后按原生命周期启动并重新读状态与实际配置，区分「已保存且已生效」「已保存但启动失败」「未保存」「结果待核实」。启动失败保留已保存事实，给出恢复启动或重新配置选择；不自动回滚或重发。后续由用户显式发起恢复动作。在线预检/测试由实际后台核实凭据引用是否可用，启动后再次核实；离线时无法取得实际服务环境就显示未验证，不读取或复制 systemd EnvironmentFile。CLI 脱离后台只有在原凭据启动环境已核实时提供自动恢复，否则只读并说明需先配置受支持的启动方式；SSH shell 中存在不代表原 CLI 或 systemd 服务环境可用。

## 共同契约与失败处理

| 编号 | 契约与可验证结果 |
| --- | --- |
| R1 | 作用范围始终可见；无会话可管理；工作区映射只影响展示归属，写入原配置来源；切目标、换实例、断线和关闭后迟到结果不覆盖其他表单 |

| R4 | 凭据只写入所属后端；列表、事件、错误、日志与截图材料不含秘密；状态与移除按来源，存储条目消失不等于无认证来源，列表读取无动态凭据执行；取消秘密编辑或目标切换后清理输入；引用无效不降级匿名 |

| R6 | Code MCP 保留工作区、配置版本、允许列表和批准消费规则；Personal 保留停机锁、代次、未决检查与远端结束核实；禁用不等于撤销原调用副作用 |
| R7 | Skills 源内容不受写管理影响；仅显式调用和停用分开；版本冲突/复制失败不改库；停用影响新任务选择，旧正文/引用与历史快照可读；逻辑移除不自动回收字节；Personal 忙则拒绝配置变更，托管根与安全暂存可重新持锁/启动，布局和权限拒绝不放宽 |
| R8 | 每页有加载、空、失败、离线、只读、保存中、冲突和待核实状态；错误提供下一动作，字段错误定位字段；键盘可操作、状态有文字、窄窗滚动且遵守减少动态效果 |
| R9 | Electron 与 MyGo 通过相同宿主取得真实配置；离线桩和 SSR 不冒充真实远程、模型或 MCP 验收 |

## 验收与交接
