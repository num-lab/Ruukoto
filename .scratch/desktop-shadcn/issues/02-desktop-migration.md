# Desktop 按定稿 demo 迁移

Status: ready-for-human

## 目标与依据

拥有者于 2026-10-16 明确认可当前 demo，并要求「严格按照现在这个 demo 修改 desktop 的 GUI，保持布局、样式和交互一致，不要自行添加内容」；后台已有但 UI 未体现的能力先列清单、暂不实现。该指示取代旧规格要求的额外诊断卡、固定检查器页面与参数展开门槛。[冻结副本](../approved-demo/)与[逐文件哈希](../approved-demo-manifest.json)是本轮视觉与交互基准，原 demo 不再修改。[后台 UI 清单](../backend-ui-backlog.md)记录推迟范围。

## 方案与范围

1. 将定稿的官方 shadcn 组件、Lucide、主题 token、布局 CSS、侧栏宽度与焦点交互移植 `apps/desktop/src/renderer/`，依赖归根 workspace 锁文件。Electron 客户区填满原生窗口，保留系统标题栏按钮与拖动区；不在真实窗口内再画浏览器 demo 的外层桌面与仿真红绿灯。内部三栏、48px 标签头、间距、颜色、排版与交互保持一致。
2. `App` 接现有 `CodeState` 的工作区、会话与标签。设置窗口只保留外观与运行目标，Personal 使用已有配置读取／保存与连接占位。名称筛选仅过滤已加载的工作区与会话，不增加全文检索。没有会话时沿用 demo 空态；连接失败沿用 demo 重连空态。错误沿用 demo 提示外观，不新增诊断面板。
3. 消息流保持现有历史与实时投影，使用真实 Markdown、轻量工具组与独立 SubAgent 行。Edit / Write 摘要按不同文件计数；详情保留文件与紧邻增删数，Read 不显示行范围。识别到实际工具目标的内联路径可打开对应调用的 diff；同文件多次修改按调用身份区分。历史从顶部滚动加载，保留滚动锚点，不新增旧式「加载更早」行。HTML 与本地图片仍禁止通过 Markdown 执行或读取。
4. 审批卡进入当前会话流，自动读取真实参数，不再要求手动展开。审批仍按原实例与 permissionVersion 应答；权威成功或事件确认后卡片消失。结果未知时保持防重与状态查询，不把超时当作批准或拒绝。
5. 输入区按定稿组织模式、模型与提交；真实提交与待核实状态保留并锁住原文，确认接收后清空，失败留原文。保留 SubmissionGuard 的原 requestId、实例隔离与不自动重复提交。运行且无草稿时提交按钮改为停止；有草稿时继续支持排队。停止后的继续来源只跟随后台权威状态；保留 demo 的继续条、队列暂停条与恢复确认弹窗，不恢复已删除的状态卡。模型目录和 thinkingLevel 用已有真实值，不能硬编码 demo 模型。
6. 右栏改为按会话保存的 diff / Agent 独立标签与新标签选择页。保留工具结果读取的调用身份、失败分类与快照竞态保护；差异无卡片、固定行号与标记、空写入显示普通空内容。右侧标签头保留 1px 分隔线，图标灰色，整体侧栏折叠与宽度调节沿用定稿。

主要影响：renderer 的 app、conversation、composer、approval-cards、inspector-panel、style 与新增复用组件；code-writes、approvals、inspector 的最小状态调整；desktop package 与根 lock；相关 desktop 测试、模块说明、使用说明、决策笔记与验收证据。后台能力不顺便扩大 desktop allowlist。

拥有者明确选择补齐两处最小后台支撑。附件由系统选择器只读用户选定快照，按 192 KiB 块上传，submit／continue 携带稳定安全元数据；任务、不可变产物及 task.attachments 事件同事务绑定，图片复用视觉引用，普通文件沿 read_artifact 读取。原文与引用按请求键恢复，纯附件可提交；暂存不自动清理。分页增加可选 field／offset 与 content:BoundedText|null，旧预览兼容，renderer 严格核对偏移及总长。两份独立方案与实现复核均通过；合并后统一提升协议至 v27，禁止旧后台静默忽略附件。

## 验收

- 基准文件哈希保持不变；正式组件与样式可追溯到冻结副本，外层原生窗口适配与模拟场景的排除有明确依据。
- 定向测试覆盖原文留存至权威接收、核实事件先于 IPC 响应、拒绝与断连、会话与实例隔离、防重复恢复；审批成功移除及未知结果查询；动态右栏标签、同文件多调用、过期请求丢弃与差异行号。
- 现有 desktop main、Personal、build、recovery、creation、stream、inspector 测试通过；`npm run check:static`、desktop 生产构建及签名验证通过。后台分页／附件如获授权，补相应最窄契约测试。
- 实际 Electron 检查明暗、宽窄窗口、工作区树与会话、模式／模型菜单、审批、消息与差异、Agent、设置、侧栏动画与拖动；真实模型或 SSH 前提缺失明确记为未验证。测试 fixture 仅用于生成实际协议状态，不带入产品。
- 实施前独立方案审查、完成后独立实现审查，无未解决阻断。demo 产品选择已获拥有者认可；正式 GUI 的主观一致性保留最终产品验收。
