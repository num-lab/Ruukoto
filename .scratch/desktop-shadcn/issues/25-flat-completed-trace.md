# 平铺工具调用与完成后的 Trace 收起

Status: ready-for-human

## 目标与边界

拥有者于2026-10-18要求删除 Read 预览的“Read 时捕获的版本”说明，限制思考正文显示行数、超出滚动，取消工具调用分组，任务完成时动画折叠最终回复之前的 trace。同步可变 Demo 与 Desktop；不改冻结稿、后端协议、会话记录或真实 reasoning 内容，不提交、不推送、不重启日常应用。

## 方案

删除 Read 快照的常驻说明，文件直接预览；确实部分捕获或展示截断时只保留紧凑的状态说明。思考正文最多显示6行，保留原文、换行、选择、键盘滚动。ToolActivity 移除工具摘要折叠层，按原顺序直接显示 Thought、Read、Edit／Write、Bash 和 SubAgent；保留 Read 路径跳右栏、单条调用详情、失败标红、参数／结果分页、Thinking 及已完成／进行中工具（拥有者追加要求去掉 Working 标题）。

Conversation 用稳定任务身份承载执行记录，完成且最终 assistant 正文已经到达时默认收起此前记录，最终回复始终位于折叠区外。执行中的容器保持同一实例并展开，完成时仅改变 open，复用 TraceCollapsible 的 Radix Presence、180ms 开合与减弱动画；可以重新打开。失败、取消、审批、暂停、缺少最终回复或归属不明时不自动藏起记录。用户输入、审批卡不进入折叠区；中间 assistant 进度正文与对应执行记录同收起，不跨任务或用户消息。最终正文只认同任务最后语义条目为有 entryId、非 streaming 的非空 assistant，且任务 completed；同 entryId 的全部片段留在外面。按时间顺序连续分段，不按 taskId 重排；排队用户消息作为硬边界，活动 wrapper 键从任务与前置边界生成，避免阶段切换重挂载。

Demo 使用相同展示规则及明确的演示完成状态，不以静态样例证明真实任务生命周期。生产投影与生命周期测试使用实际 EventFlow、Conversation；不新增依赖或测高／滚动控制器。文档同步 desktop 模块与决定笔记，旧分组决定部分取代并互链。
