# 登记工作目录不再按设备号失效

Status: resolved

## 目标与边界

拥有者在同一真实路径、同一 inode 而设备号变化的报错后明确要求「删掉对设备号的检测」。会话与工作区的共享目录复核只比较真实路径和 inode；设备号变化不阻止文件树、Git 读取及普通任务工具执行。目录消失、变成非目录、真实路径或 inode 变化仍拒绝。

保留数据库字段、挂载别名识别、物理保护范围与同次执行的 dev/ino 复核；本轮不改变已冻结的工作流来源、工作副本快照、审批对象和旧实例导入的独立身份契约，不扩大文件访问范围。

## 方案

1. core 的同步、异步复核返回本次解析身份，比较中移除 dev，错误只报告实际判据。
2. Runtime 普通任务启动及等待后重取资源使用本次设备号登记占用；保持取得占用后的复核。ToolRouter 为启动工作区核实路径/inode，再将本次设备号传给 worker，避免旧记录继续触发 native/init 拒绝。
3. 增加共享复核正反例、旧 dev 工作区文件/Git 读取及旧 dev 会话真实工具执行回归；保留原生启动身份拒绝用例。更新 core、execution 文档与决策笔记。
