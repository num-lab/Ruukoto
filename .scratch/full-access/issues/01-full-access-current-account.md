# 01 — 完全访问使用启动账户并统一免审批

规格：[完全访问实施规格](../spec.md)。决策依据：[完全访问使用启动账户且不请求审批](../../../.agents/notes/proposed/feature/2026-10-12-full-access-current-account.md)。本单持有实施顺序、进度及验证证据，决策理由由提案持有。

## 问题与完成条件

当前完全访问在 native/container 后端下要求 systemd 专用执行账户入口，多个工具仍走人工审批，SubAgent、IM 和调度等宿主任务又固定为 confirm。仅修改 launcher 不能交付统一的完全访问体验。

完成时，两个产品均能直接以启动账户使用完全访问；所有已开放工具免操作审批；任务和计划按规格取得并保存授权；专用账户配置要求及误导性说明清理完毕。请求确认、自动审查、Plan、操作账本、停止核实和入口认证通过回归；macOS 与 Linux 均有实际执行证据。

## 与通用定时任务单的分工

[通用定时任务工单 01](../../generic-scheduler/issues/01-generic-scheduled-tasks.md)负责删除 news／定时 notify、计划模式与通知目标落盘、每次独立执行、审批来源、整项运行及最终回报。本单负责共享执行账户、工具免审批和普通任务／委派权限传播，并参加调度联验；不再修新闻 approvalId，也不先做通知计划兼容。

本单公共授权与免审批接线优先落地；通用定时单的删除、存储和独立运行准备可先做，最后联验模式来源与全部工具行为。两单不互相等待整单 resolved，调度字段和执行机制只在其归属工单实现一次。

## 实施计划

按以下顺序推进，每步随行为变化补最窄回归。阶段完成不等于整单交付；全部验收结束才标记 resolved。

### 1. 统一授权记录与任务模式来源

- 梳理 Task、工作内消息、父级送达和普通通知授权的字段与写入事务。复用任务有效模式和 permissionVersion，为延迟投递保存最少授权信息；Schedule 的模式与通知绑定由通用定时单实现，不引入第二套权限引擎。
- 在委派、消息和结果登记时明确钉定来源任务与当时模式，向通用定时单提供同一来源规则。新建任务、登记触发来源及关联事件应在各自现有事务中一致提交；异步准备后复核任务活动状态与权限版本，不能按后来变化的会话默认值补授权。
- 为完全访问操作表达真实授权来源，使工具账本和计划能够核实执行资格，不冒充拥有者逐次批准、自动审查批准或长期操作授权。受限模式继续使用原有批准消费规则。
- 同步受影响的类型、存储读写、控制面响应、调用方和夹具。需要改变 schema／协议时更新当前版本并保留较新库拒绝规则，不提供旧格式适配、回填或静默默认值。

交付检查：授权落盘后可重读并跨后台重启使用；完全访问、人工批准及长期授权来源可区分；事务失败没有半条任务、计划或事件。

### 2. 完全访问直接使用启动账户

- 在共享 launcher 选择处一次性修正 full_access 路由，使用当前账户启动 worker，复用已有 worker 协议与进程登记。清理专用执行 UID、受保护启停脚本及 systemd 执行账户启动器依赖；其他模式仍使用原受限后端。
- 继承用户环境并剔除内部控制通信变量，保留工作目录与 worktree 固定 Git 环境。不传出环境值作为诊断，不额外要求用户配置代理或 SSH agent。
- 核对 ToolRouter → LaunchSpec → ToolWorkerHost → worker 的所有权限分支，避免移除 OS 沙箱后仍留下与完全访问冲突的文件／网络限制。接口的工具白名单、资料归属和输入校验仍按既定职责执行。
- 沿用 starting 登记、启动失败时的执行单元交接、停止结论缓存、Driver 收尾与目录占用。平台监督方式不增加必填启动配置；普通结束、取消和模式切换不能把未知停止结果改成成功。主动脱离管理与外部服务按已确认限制报告。

交付检查：缺少旧执行账户环境变量时也能启动；worker UID 与后台一致，外部目录、网络及用户工具环境可用；受限模式缺隔离能力仍拒绝执行。

### 3. 所有完全访问工具免操作审批

- 在现有审批／执行共享入口落实完全访问授权，逐一接通结构化文件、HTTP、应用数据、一次外发及服务工具，并核对 MCP 已有分支。通用定时运行使用同一机制，工具调用不产生审批等待状态、审批通知或自动审查调用。
- 保留操作前的活动任务、模式版本、目标身份、配置修订及凭据绑定核实。失败返回已知未执行或实际已知结果；已经开始却无法核实的写操作仍记效果未知，不自动重发。
- 调整仍保留工具对 approvalId 的返回与展示依赖，记录真实完全访问授权来源。普通通知登记继续与授权／操作状态在同一事务提交，不能靠伪造人工批准满足外键或运行条件；新闻和定时固定通知的专用批准关联由通用定时单直接删除。
- 服务 helper 保留固定目标、OS 授权、修订复核和操作 ID 单次认领。完全访问不经过长期授权候选失败后的人工回退；缺 helper 或 OS 权限明确失败。

交付检查：每类工具至少有完全访问成功执行、执行前拒绝和取消／效果未知回归；confirm 与 auto-review 仍保持原审批行为。

### 4. 接通委派、IM、调度与工作副本

- SubAgent 新建、继续、复用及协作加入采用本次发起任务的模式；工作内消息和结果唤醒使用登记时的来源授权，覆盖忙碌排队、延迟投递和重启恢复。模型输入不能提供权限升级来源，复用身份不沿用另一项工作的授权。
- worktree 创建与改动汇总的临时执行采用实际发起任务的有效模式，保留目录身份、写入目标、占用、成果和冲突处理。完全访问不因固定 confirm 的临时 worker 被要求安装沙箱。
- 将已绑定拥有者的 QQ／Telegram 私聊与其他外部事件分开确定模式：私聊取主会话默认值，GitHub 等入口使用明确的现有约束。平台身份核实、幂等接收和原目标回复规则保持有效。
- 联验通用定时单保存的创建模式进入独立运行及其派生任务，确认共用完全访问或受限执行路径；会话改模式或后台重启都不能重算计划权限。独立上下文、固定汇报目标及 news／notify 删除由该单交付，本单不保留旧 wake_main 共享会话分派作为兼容路径。
- 保持会话默认、指定任务模式和已有计划三者的作用范围。测试新模式继续旧工作与旧任务迟到结果交错，证明既有任务不被改写，旧单次批准与长期授权不随模式继承。

交付检查：从拥有者私聊或开发会话发起完全访问工作，经过委派、工作副本、结果汇总后不会意外回到 confirm；外部事件不会获得会话完全访问权限。

### 5. 清理部署要求并同步可见说明

- 删除执行账户专用启停脚本、相关环境配置与引用，调整两个产品及开发入口的配置校验。更新 systemd 模板和说明，使当前运行账户可以部署，不要求三账户和工作区 ACL 初始化。
- 单独整理服务 helper 的调用账户、只读检查身份及 sudoers。保留服务管理必要的 OS 授权和策略，不把删除执行账户误做成删除服务能力，也不对真实机器执行账号清理或部署变更。
- 同步系统提示、工具说明、SubAgent 委派正文、TUI 模式描述与计划授权展示，使文字准确反映任务实际模式。自然语言澄清缺失信息仍可进行；不能再以旧权限说明要求完全访问任务重复审批。
- 实现时更新 `CONTEXT.md`、`docs/modules/execution.md`、`agent-tools.md`、`runtime.md`、`scheduler.md`、`deploy.md` 等实际受影响文档，以及使用说明和图解。旧决定的取代关系集中依照提案审计处理，不在规划阶段继续向旧 notes 批量追加提案提示。

交付检查：全仓搜索旧执行入口变量、专用账户说明及“完全访问仍审批／子任务固定 confirm”，清理当前代码和使用文档中的失效引用；历史证据按历史事实保留，不改造成新实现验收记录。

- 本机 macOS 与 `ssh tx` Linux 使用独立临时数据和虚拟凭据验证完全访问。记录 UID、环境继承、工作区外读写、联网、普通进程及后代停止；未核实停止和主动脱离的限制单列。

## 验收标准

- [ ] 两个产品在没有专用账户和旧执行入口配置时可用完全访问，使用实际启动账户权限及用户环境。
- [ ] 所有已开放工具完全访问下零审批等待、零自动审查；授权来源、执行校验、事务和操作账本准确。
- [ ] SubAgent、消息、结果唤醒及 worktree 临时执行按正确来源传播模式，覆盖继续、复用、迟到和恢复。
- [ ] 拥有者私聊跟随主会话默认；定时计划保存创建模式；其他外部事件不被提升。
- [ ] 会话默认变化不改写已有任务或计划，指定任务切换不级联；旧批准和长期授权不继承。
- [ ] 停止、取消、失败和模式切换均保留无法核实结果与目录占用，不承诺收回外部服务或主动脱离进程。
- [ ] 请求确认、自动审查和 Plan 的隔离及审批回归通过；缺隔离能力不降级。
- [ ] 专用身份、启停入口及误导性说明清理完成，无旧配置兼容、数据回填或过渡双路径。
- [ ] macOS／Linux 实测及定向测试结果有记录；文档、提案状态与代码一致。
