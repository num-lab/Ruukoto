# 完全访问方案实施规格

决策依据：[完全访问使用启动账户且不请求审批](../../.agents/notes/implemented/feature/2026-10-12-full-access-current-account.md)。实现与验证由关联工单记录；理由、备选方案及已接受的风险统一保存在该笔记。

实施工单：[01 — 完全访问使用启动账户并统一免审批](issues/01-full-access-current-account.md)。

调度范围与[通用定时任务规格](../generic-scheduler/spec.md)共同实施：后者删除 news／定时 notify，负责独立运行、计划字段、审批来源和最终回报；本规格负责其使用的任务模式与共享免审批行为，不再适配新闻审批。

实施状态：已完成并与关联工单联合验收，详见[验收报告](validation.md)；旧配置、旧 schema 与退役计划不做转换或授权回填。

## 目标

ruukoto 与 ruukoto-code 的 full-access 使用启动应用后台的系统账户，不施加任务沙箱，不请求操作审批，不要求专用执行账户、专用后台账户或执行账户启停入口。

## 已确认的交付范围

- 完全访问继承后台启动时的用户环境，包括 PATH、HOME、代理、SSH agent 和工具凭据；清除内部控制通信变量。后台进程、控制面认证、IM 拥有者身份核实和工具能力分工保留，完全访问不自动取得额外 OS 权限。
- 所有已开放工具统一免操作审批，包括结构化文件与 HTTP、MCP 写工具、破坏性应用数据变更、通用调度任务中的工具操作、一次外发和服务操作。执行前校验、幂等认领、操作记录、事务与效果未知不重放仍然成立。
- 委派、工作内消息、结果唤醒和工作副本临时执行沿实际发起任务传播授权。继续旧工作或复用 SubAgent 以本次发起任务为准，不永久绑定第一次授权，也不继承单次批准或长期操作授权。
- 绑定拥有者的 QQ／Telegram 私聊按创建任务时的主会话默认模式执行；定时计划保存创建时模式，触发时按保存值执行；GitHub 等其他外部事件保持原入口的明确约束。
- 修改会话默认模式只影响后续新任务，不改写已有任务和定时计划；显式任务模式切换仅影响指定任务。立即收紧工作需停止整项工作后按新模式重新委派。
- 完全访问无需另配进程管理入口即可运行。停止时回收归属明确的进程，残留或无法核实停止时报告并保留目录占用；不承诺收回主动脱离管理的进程、另行提权的进程或外部服务。
- 快速迭代期直接替换旧设计：清理旧身份要求、专用执行入口及配置，不做配置兼容、协议适配、旧任务或旧计划字段回填和过渡双路径。

## 边界

请求确认、自动审查和 Plan 的受限执行、审批规则与工具约束保持有效。系统服务管理仍需其独立的 OS 授权，缺权限直接失败，不转应用审批或密码交互。

同账户完全访问可触及该账户有权限的后台数据、凭据及控制面令牌；资料 API 和入口认证不能被描述为对完全访问进程的隔离。模式切换不撤销已经发生的外部效果。

本工单不增加工具族，不删除已有的独立实例导入能力，也不授权清空真实数据、删除实际系统账户或修改真实部署。实现落地时同步人类文档和决策笔记；规划阶段只记录范围、顺序和验收。
