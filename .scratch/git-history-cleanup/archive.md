# 原始证据的归档与找回

## 仓库里保留什么

工单、规格、验收结论、复现源码、必要输入和冻结稿继续随 Git 保存。原始日志、截图、压缩包等按已审核清单移出当前树及历史；用途尚未消歧的文件保留，本次不宣称已经清空所有原始产物。

指向本页的链接用 `path` 查询参数保留原仓库相对路径；工单中的内联路径和代码块也保留原文。这些路径记录的是过去那次运行的原件，不代表当前 clone 中仍有对应文件。需要原件时按原路径查拥有者的本地归档，不把重跑结果当作过去的证据。

## 找回原件

拥有者保存了迁移前完整 Git 对象、引用、工作区差量、精确清理清单、新旧提交映射及恢复回执。具体本机位置由本次交付提供，不把私人目录或原始资料上传到公开仓库。

1. 从链接的 `path` 参数或原工单取仓库相对路径，并选对应旧提交；只有新提交号时先查新旧提交映射。
2. 在与旧工作区隔离的恢复目录读取旧 Git 对象，按旧提交与路径导出原件；不要直接在原样 `.git` 备份上 checkout、worktree 或 push，因为其中仍保留旧远端及工作区指针。
3. 对照备份校验记录核实字节。备份中的未提交变更、删除与冲突状态按恢复说明另行恢复，不能用 Git 历史代替工作区差量。

被忽略的本机文件、空未跟踪目录和符号链接指向的外部内容不在差量备份内，仍保留在旧副本。已经不存在的 worktree 只能找回保存的 Git 状态。本次不删除旧副本，也不承诺恢复从未被保存的内容。

## 后续提交

原始运行产物默认放仓库外；`.gitignore` 防止普通误加，相关回归检查为 `npx tsx --test test/scratch-retention.test.ts`。Git 忽略规则不阻止 `git add -f`，也不限制已跟踪文件增长；确需增加必要输入时先核实用途并放入受维护的测试目录，特殊例外由拥有者审查。不要为了交证据强制添加原始产物。

旧克隆另行迁移独有改动，不能将旧历史合并回清理后的分支。正式远端切换仍需独立确认；当前阶段和核实结果见[工单](issues/01-clean-history.md)。
