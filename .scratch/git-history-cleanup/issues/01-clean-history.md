## 目标与边界

执行[已确认规格](../spec.md)。拥有者最终收窄为仅交付清理后的本地仓库，GitHub 重建与平台记录归档由其自行完成。本次交付两个本地分支、无远端配置的独立完整检出；不含远端推送、保护规则变更或旧工作区清理。

## 方案

1. 沿历史路径盘点原始产物，生成精确路径清单及保护例外；核实测试、脚本、冻结稿的传递依赖，不能把历史测试输入当作原始输出删掉。不确定用途保留并报告。精确清单与保护例外完成独立审核、固定摘要后，才执行第 3 步。
2. 完整备份 Git 公共目录（对象、refs、reflog、stash、各 worktree 索引）及各工作树相对 HEAD 的变更和未忽略未跟踪文件。记录删除与冲突状态，校验源前后稳定，抽验恢复；被忽略的本机文件留在旧副本，不声称已备份。任何并发变化停止本轮演练。
3. 在仅含远端 `main`、`develop` 的隔离仓库，用标准 `git-filter-repo` 按精确清单移除历史路径，保留变空提交及合并拓扑，保存提交映射。逐提交比较删除范围之外的树条目，核实受保护文件字节不变。
4. 在两个清理后分支头分别应用入库规则、引用说明和必要检查；不搬动无需迁移的冻结稿或已有复现脚本。更新 `.gitignore`、任务约定、开发说明、相关 skill 和新旧决策互链。用默认忽略拦普通误加，配真实 Git 暂存正反例；显式强制添加须审用途，不引入历史子树基线或证据服务。
5. 对现行 Markdown 引用按删除清单核对，覆盖未纳入现有链接门禁的 `.scratch` 工单。移出的证据统一指向归档说明并保留原路径用于找回；不为每个文件创建占位文件，不改封印归档。引用说明只说明原件外存，不能宣称新 clone 已携带证据。
6. 在无残留文件的干净检出运行 `npm run check:static`、构建和受影响测试；将清理前已存在的问题与清理新增问题分开，不把未执行记成通过。以同条件新 clone 的对象库大小比较收益。
7. 独立审查后交付清理后的本地仓库、清单、映射、恢复方法和检查结果。拥有者自行重建 GitHub；本任务不再准备线上临时仓库或执行远端切换。

后续迁移由拥有者避免旧历史回流；旧工作区及独有工作原地保留。本地交付不代表 GitHub 平台记录已备份或远端已经切换。
