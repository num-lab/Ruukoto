# Git 历史瘦身

## 已确认的要求

拥有者于 2026-10-30 在六轮 grilling 及最终汇总中确认以下范围，并授权方案落盘、备份与隔离演练；远端切换仍需另行确认。

- 缩小全新 clone 的体积并给远端仓库瘦身，阻止原始运行产物再次默认入库；不以清空当前目录代替历史瘦身。
- 定向重写 `main`、`develop`，保留代码演进与新旧提交映射，接受提交哈希变化；不压成单个初始提交。
- 工单、规格、结论、源码、复现脚本、测试输入和冻结稿继续入库。仅供留档的日志、截图、录屏、会话或请求记录、归档包与数据库快照按实际用途移出历史；不按整个目录盲删，不为达到某个比例删有用内容。
- 迁移前历史和未完成工作备份到仓库外的本地受限目录，长期保留、人工恢复，不上传、不自动删除。原始证据不能以重新运行冒充原件。
- 先准备远端清理结果与新副本；旧工作区、分支和 stash 不删除，其独有改动另行迁移，不能把旧历史 merge 回来。本地独有提交不随本次远端改写发布。
- 两个新分支头不得因清理引入构建、相关测试或现行记录引用回归；不逐个修复历史提交的证据链接，不承诺每个旧版本仍能原样复跑。清理范围之外的历史内容必须保持不变。

实施入口为[工单](issues/01-clean-history.md)，取舍依据为[决策笔记](../../.agents/notes/proposed/process/2026-10-30-git-history-evidence-retention.md)。清理清单、原始备份、恢复回执、命令日志与提交映射留在仓库外；工单只保存核实结论与定位方式，不再次提交大体积证据。

## 新发现的服务端限制

只读复核发现 GitHub 另有30个 PR head 引用，其中13个已知提交的树仍含删除清单中的路径，最多一棵树含2340项。这些只读引用不随 `main`、`develop` 改写；[GitHub 说明](https://docs.github.com/en/authentication/keeping-your-account-and-data-secure/removing-sensitive-data-from-a-repository)明确 PR 引用只读，支持不会为非敏感数据清理这些引用。

因此本次隔离演练只能证明普通完整 clone 的下载收益，不能证明原 GitHub 仓库后台空间会随 GC 回收。远端瘦身目标未完成；正式切换前由拥有者决定是否接受只先交付 clone 收益并保留现有 GitHub 元数据，或另议仓库级迁移。没有删除、重建仓库或修改 PR 引用的授权，不以统计延迟掩盖这项缺口。
