# ruukoto-code 手动上下文压缩

拥有者需要在继续对话前主动整理模型上下文，并用可选指引调整摘要重点。入口为 TUI 的 `/compact [prompt]`。2026-10-11 经三轮 grilling 与最终复述确认；实施与验收见[工单 01](issues/01-compact-command.md)，技术取舍见[决策笔记](../../.agents/notes/implemented/feature/2026-10-11-manual-context-compaction.md)。

## 入口与参数

- 仅向 ruukoto-code 的当前普通开发会话开放，包含普通分支会话。后台通过产品能力声明与会话身份核实资格；未选择会话、main、SubAgent、已退役归档及其他不可写会话明确拒绝。
- `/compact` 使用固定摘要规则；`/compact 保留数据库迁移细节` 在固定规则后补充本次指引。省略参数与全空白参数等价；去掉命令及参数首尾空白，保留参数内部空格与换行，不解析 shell 引号或选项。
- prompt 不成为普通拥有者消息、长期记忆或后续压缩偏好，也不替换摘要的基本规则。命令及结果沿现有 TUI 命令历史保存，不写入会话 JSONL；为核实同一次请求保存的参数不属于会话偏好。
- 不提交普通任务、不创建工作委托、不启动工具 worker、不调用主模型；仅在需要摘要时调用摘要模型。成功后留在原会话，等待拥有者继续输入。

## 压缩范围

手动命令跳过自动压缩的高水位、低水位目标、最小收益与失败冷却门槛。有可压缩内容时直接生成滚动摘要，不以“只清理工具结果”代替成功。自动压缩保留原有触发、尾部保护、清理与失败降级规则。

保留最近一个完整 assistant 回复批次及其后的原文尾部；一个批次包含 assistant 消息及其配对工具结果，不能拆开工具调用与结果。较早的已完成内容进入摘要，包含单个长任务的中间过程。最近请求、较早清单批次不额外永久保留原文；摘要必须交代拥有者要求、已确认决定和未完成工作，保持内容来源区别。现有项目指令、技能、记忆等参考块照常由上下文组装提供。

历史中的旧中断、取消或失败任务仍是历史事实，沿用模型视图的孤儿工具记录处理；不能因旧孤儿记录截掉其后的正常对话。完整行损坏、会话文件身份不符或存在无法核实的部分尾记录时明确失败，不修复或补写历史。没有可保留的完整回复批次时提示暂无可压缩内容。

摘要沿用“上一版有效摘要＋新增覆盖段的原消息”。新压缩点的覆盖边界不回退；只有成功生成摘要并提交压缩点后，后续模型调用才使用它。已压缩部分不会因新 prompt 从全部历史重建。

| 输入情况 | 结果 |
| --- | --- |
| 空会话，或没有较早可摘要内容且没有旧摘要 | 提示没有可压缩内容，不调用模型、不替换压缩点 |
| 覆盖范围可以推进 | 用旧摘要与新增覆盖原文生成摘要，附本次 prompt（如有） |
| 覆盖范围不推进，有旧摘要且提供 prompt | 按新指引改写旧摘要，覆盖范围保持不变 |
| 覆盖范围不推进，未提供 prompt | 提示没有新的可压缩内容，不调用模型、不替换压缩点 |

同一个已接收请求的重试返回原结果；拥有者明确再次执行命令是新请求，并按上表判断。新 prompt 只能利用旧摘要里仍存在的信息，不能恢复已经遗漏的细节。跳过收益门槛意味着摘要成功不承诺估算一定下降，结果如实报告前后估算。

## 模型与摘要规则

- 使用现有摘要模型配置；未配置时用本次接收时的会话当前模型，沿用现有模型选择解析。配置了摘要模型但不可用时明确失败，不静默改用其他模型。
- 沿用中文结构化摘要、保留路径/命令/函数名/错误原文、区分拥有者要求与工具/文件/网页内容、约 4,000 字目标。prompt 只是补充重点，摘要不是拥有者新指令或授权依据。
- 单次尝试，沿用 180 秒超时、输出上限与无思考参数的调用方式。输入预算包含本次指引、固定摘要指令、旧摘要和新增原文；预算不足明确失败，本期不做分块滚动或全历史重建。
- 接收时固定本次使用的模型与参数，运行中的摘要 provider 纳入配置修改的使用中检查。后续会话设置变更不改写本次调用。

## 占用、取消与持久结果

当前会话有执行中、等待审批、排队、正在启动的任务，或已有手动压缩时，拒绝新 `/compact` 并提示等待或先停止原操作。检查必须在后台落实，覆盖任务启动的异步窗口，不能只判断 TUI 状态或 `Driver.busy`。

手动压缩占住当前会话后，拒绝该会话的新提交、继续任务及队列启动；拒绝不丢弃用户输入。其他会话照常使用，不因手动摘要取得工作目录执行锁。查看历史、切换会话与断开终端不取消压缩；结果始终归发起会话。

`/interrupt` 取消当前会话的在途手动压缩，原有任务中断行为保留。取消与成功提交由后台确定唯一终态：取消先成立则不替换压缩点；成功已提交则返回已完成，不声称撤销成功。后台停止中止并收尾本次操作后再关闭存储；异常退出后，把未完成请求登记为中断，不自动重新调用模型。

控制面快速返回已接收结果，通过同一请求 ID 查询进度与结果。请求参数按同键同参复用、同键异参冲突处理；应答丢失和重连先核实原请求，不自动换键重发。成功时在一个 SQLite 事务里切换压缩点、保存请求终态并写完成事件，提交后才应答与广播；已成功但应答丢失的请求重连后仍可确认成功。

摘要报错、超时、空输出、输出触顶、输入超限、取消或提交失败时，原有效压缩点不被替换，不应用只清理的部分结果；未有压缩点时保持无压缩点。旧点原本已经失效时不能恢复它或声称它仍有效，应报告无法使用。历史文件始终只读，不承诺 SQLite 与 JSONL 之间存在事务。

## TUI 反馈

命令加入现有派发、补全、帮助和操作手册命令表。显示已接收/正在压缩及最终成功、无需压缩、失败、取消或中断结果；成功包含摘要覆盖条数、前后上下文估算与实际摘要模型，失败包含错误码、可读原因和安全下一步。输入和模型请求正文不进入通用错误文本。

切换会话不串回显；另一客户端、断线重连及退出重进可通过后台状态核实本次操作。结果不只依赖一个仍在等待的客户端请求，也不能让后台已完成操作永久显示“正在压缩”。

`/context` 保持查询最近一次主模型调用及其选择记录的行为，不新增当前压缩点展示。手动成功之后、下一次调用之前，它仍可能显示旧压缩点；命令结果说明这个区别。历史选择记录和 prompt 快照不改写，也不伪造一次主模型调用用于刷新展示。

## 兼容与范围外

压缩点保留真实生成来源，自动压缩关联任务与调用序号，手动压缩关联独立请求，不能填造假的任务 ID。分支复制自己的有效压缩点并保留来源，不复制在途操作、取消权限或请求回执。旧实例导入继续保留适用压缩点，操作回执仅属于原实例。

本期不增加个人 Agent、SubAgent、独立 CLI 或 IM 入口，不改变自动压缩策略，不提供 prompt 持久偏好、摘要编辑器、全历史重建、分块摘要、压缩前写记忆或通用后台任务框架。
