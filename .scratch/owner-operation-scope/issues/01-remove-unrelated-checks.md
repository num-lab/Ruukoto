# 移除 Git、个人工具与工作区登记的无关检查

Status: resolved

## 目标与边界

拥有者于 2026-10-24 要求「先处理前三项」，对应已提交浏览修复后的审查结果：Git 的全树元数据限制；个人网络与完全访问工具无条件检查资料目录；工作区与会话登记无条件采用 Agent 保护规则。本轮实现这三项，文件硬链接预览、技能重复读取、受限挂载批处理、目录分页和 Git 入口预取不在范围内。已确认的取舍不再请求批准。

保留拥有者认证、实际目标和目录身份、配置及权限修订、审批与未知效果记录、只读 Git 命令约束、分页一致性和输出预算。受限执行仍拒绝保护范围；不添加权限开关，不修改模型授权、持久化格式或控制协议。工作树已有 CI／测试策略修改不纳入。

## 方案

1. Git：删除 `workspace-git.ts` 的 `scanMetadata` 及两次调用，允许普通本地克隆、共享对象库、配置 include 与元数据链接。指针文件按最终打开的普通文件句柄有界读取并核实稳定性，发现 Git/common 目录后保留真实身份检查。保留 HEAD、全部 refs、remote、shallow、grafts 的前后摘要，并加入链接形式 HEAD 的 readlink 文本，不枚举无关对象；固定日志 UTF-8 编码，固定 argv/env 继续禁止 hook、pager、签名命令、fsmonitor、自动维护与 lazy fetch。用真实小仓库核对正常 clone、shared clone、include、元数据链接及翻页变化；无关 `.git` 文件不应被枚举。
2. 个人工具：通用 `active()` 不再检查无关资料目录；受限文件操作与文件检索按原模式核实资料目录，完全访问检索仅核实实际 cwd/目标身份，完全访问绝对文件读写只核实实际目标。HTTP/Web Search 保留配置、来源、权限、凭据、目标与未决效果检查，不依赖资料目录存在。使用现有 `PersonalServiceMode` 传递执行模式，不新增布尔选项。
3. 个人命令与后台：`verifyPersonalCommandConfig` 按执行模式决定是否核对保护范围，保留 Linux、格式、cwd-dev/ino、machineId 与 TMPDIR 检查；命令接纳、准备、开始意图和后台 500ms 监督传已固定的来源模式。`readPersonalCommands`、`savePersonalCommands` 与 `personalCommandEnvironment` 保持共享配置的原启用规则；只支持完全访问的后台专属装配按该模式核实。
4. 工作区：`resolveUsableDir` 只解析目录身份，覆盖打开工作区、新会话、分支及恢复；组织迁移两处登记同步移除保护参数与扫描，保留身份、包含关系、修订和事务。native 已在启动前核实范围；Runtime 的 local 受限启动补一次既有批量保护核对 workspace/grants/readRoots，完全访问沿原启动器；不把 local 测试后端宣称为 OS 沙箱。
5. 调用方和测试同步；新笔记解释检查的归属，与原浏览、Git、工作区、个人工具及命令决定互链。文档更新 desktop、runtime、execution、personal-durable 和受影响 usage 内容。
