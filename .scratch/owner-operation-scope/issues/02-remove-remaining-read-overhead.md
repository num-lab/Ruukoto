## 方案与验收

1. 文件预览：删除 `readWorkspaceFile` 对 nlink 等于 1 的三处要求，普通文件判断和其他一致性检查保留；更新对应错误描述。替换旧拒绝断言，增加硬链接完整分页读取、从另一名字修改后旧修订拒绝及控制 socket 成功读取。回归需在旧实现失败；现有父链替换、原位变更、缺失与协议用例仍通过。
2. 技能：`readManagedState` 在单次同步核实中复用已遍历包的内容修订，`ManagedSkillsStore.entries` 复用已加载条目计算启用项冲突诊断，删除第二轮状态和技能读取。Personal 每次 `prepare` 完整加载并保存本次请求快照；两个发送边界只核实已保存快照、技能配置及目录身份和当前托管清单选择，不重读包正文。外部正文变动、新增技能在下一次 `prepare` 生效，本次继续用已保存内容；配置变化、托管停用／移除、清单损坏仍阻止本次发送。清单级核对复用私有文件稳定读取和既有解析，完整包核对仍在加载、管理与重开执行。SDK 不返回原始字节，因此保留 SDK 解析和宿主正文钉版读取，不重写扫描器。回归覆盖读取次数、真实请求双记录与旧快照一致、后续刷新、配置／目录身份变化和托管停用／损坏清单拒绝。
3. 原生挂载：`prepareNativeLaunch` 将逐 mount 的 `assertGrantNotProtected` 合为既有 `assertGrantsNotProtected` 一次调用，删除无用 import。运行依赖根按保护根计算的只读例外保持独立。新增多挂载只枚举保护树一次的回归，沿现有反例验证硬链接／bind 别名、保护祖先、目录及候选变化和读取失败仍在启动前拒绝。
4. 文档同步 desktop／runtime、技能所属模块和 execution；决策按原归属及翻转范围维护。代码汇总后运行静态检查及实际受影响测试。原生范围在 macOS 与 Linux 隔离验证，真实模型及原生 Desktop UI 不属于本轮必要验收。
