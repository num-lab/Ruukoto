# 文件树续页与按需 Git 查询

Status: resolved

## 目标与边界

拥有者于 2026-10-24 要求先提交第 4–6 项，再处理第 7、8 项：「给文件树加上续页，右侧栏始终显示git graph入口，点击后读取，若没有git仓库直接显示简要提示」。前轮提交为 `18c6e8ab`。本轮修改正式 Desktop 和控制面目录查询，不改变文件内容读取、Agent 权限或 Git 历史分页；不重启日常服务。已有 CI／测试策略改动不纳入。

## 方案

1. 目录请求增加可选 `cursor`，响应以 `nextCursor: string | null` 取代 `truncated`，每页最多 200 项并保留字节预算。异步扫描目标单层，保留游标之后最小的 201 个候选，用二分插入限制内存；顺序为目录优先、名称按字符串严格比较，不依赖本机 locale。无总项上限、不保留目录句柄或跨请求缓存。
2. 游标绑定工作区、相对目录、根及父链身份、目标目录修改修订和最后返回项。扫描前后核实身份和目录修订；变化拒绝旧页，不拼接不同目录状态。参数错误与读取失败保留类型化错误，特殊文件和符号链接仍不进入文件树。Runtime 和所有控制调用方同步异步返回，协议从 38 升至 39。
3. 每层目录末尾提供「加载更多」，追加失败保留已读条目并可重试；游标失效提示刷新目录。自动／手动刷新重读已加载页段，成功后一次替换，不退回首 200 项或因首屏缺项删除后页缓存。刷新、续页、重试与断线继续按状态对象和代次丢弃失效响应；折叠后已发出的单次只读应答可进入缓存，切换、卸载或折叠停止后续页及后续层请求，按原展开意图处理。
4. 删除 snapshot、新标签页选择和 panel effect 中对空页／新页的 Git 预取。Code 右栏新标签页始终提供 Git graph，有工作区即可点击；点击直接打开 Git 标签并查询。非仓库只显示「此工作区没有 Git 仓库。」及刷新，查询失败保留错误和重试；空仓库与非仓库分开。已打开 Git 标签的显式选择、恢复与刷新沿原缓存和分页规则。
5. 更新调用方测试及实际组件的可执行 fixture，不改冻结 Demo 或旧验证日志。同步 desktop／runtime／control 文档、usage 及新旧决定；原正式协议升级说明沿既有启动与不兼容提示。

## 验收

- 后端：超过 400 个目录项跨页完整、无重复、跨页严格排序；大于 200 的子目录同样可续；篡改／跨目录／跨工作区游标、读取中变化和页间变化拒绝，响应有界且字节截页仍前进。真实控制 socket 覆盖新增参数和协议响应；一万项首／后页记录耗时并确认事件循环可推进。
- 前端：追加、失败重试、重复点击、刷新保留页段、断线／折叠／切换时迟到响应、删除失效和读取取消回归。新标签页、打开右栏和快照不发 Git 请求；点击后仅请求目标工作区，非仓库／空仓库／真实仓库均正确展示。
- 产品：使用正式组件、真实隔离 Runtime/control socket 和临时目录，在浏览器验收根及子目录续页、自动刷新、始终可见的入口与非仓库提示，检查明暗及窄栏。使用 Playwright 操作并保存截图与查询计数；不以静态渲染代替交互。
- 工程：`npm run check:static`、影响面的定向测试与双壳前端构建；独立实现审查无阻断。无需真实模型或 IM。
