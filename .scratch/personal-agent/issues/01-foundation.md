# 验证 pi 复用与 Linux 权限基础

## 目标

为[项目规划](../spec.md)确定可用的依赖版本、扩展入口与 Linux 执行边界，产出最小示例和选型记录。当前仓库没有应用代码，不预先构建完整框架。

## 实施范围

- 核实 pi 实际发布包与版本，优先验证 coding-agent SDK；关闭自动压缩、阻止非预期摘要、读取完整历史、调整每轮模型输入、注册自定义工具、从后台驱动多个会话并读取事件。若公开接口不足，记录具体阻碍后评估 AgentHarness 或 agent-core。
- 确认哪些基础工具和持久化能力可直接复用，避免重复存储同一份权威历史。选择匹配上游的运行时、TUI 库、本机通信方式及持久化后端，固定依赖版本。
- 在 Linux 验证受限执行方案的文件、子进程、网络、凭据和后台控制接口隔离；授权控制面须与两种模式的项目命令分别保护，完全访问任务也不能冒充拥有者给其他任务授权。覆盖宿主实际支持情况；容器、沙箱或系统身份等只选满足已知要求的方案，不做多后端抽象。
- 列出上下文、记忆、工具和入口所需扩展点；明确哪些生命周期、权限和存储不变量由宿主维护。编写可信自用插件的最小接入示例，不建设平台。

## 交付与验证

提交可运行的最小示例、固定版本和简短选型记录，说明 Linux 环境前提。使用模拟消息和临时目录验证历史未被上下文筛选修改、多会话状态不串用，以及子进程不能越过权限边界；真实模型只需少量连通性检查。不以生成代码的成功率设置产品门槛。

如果缺少 Linux 测试环境或模型凭据，应准确记录未验证项，不将本机其他操作系统测试写成 Linux 已通过。
