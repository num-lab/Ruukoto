# 后台任务与持久化

## 目标

任务生命周期独立于 TUI，支持不同会话并行和同一会话排队，基础行为见 [ADR 0002](../../../docs/adr/0002-detach-terminal-from-task-runtime.md)。

## 实施范围

- 使用 01 确定的依赖与持久化方案，实现项目、会话、任务和后台事件接口；保留完整历史及任务状态，提供本机启动、连接与停止入口。
- 覆盖排队、运行、等待确认、已中断、完成、失败与取消。新消息默认排队，提供显式中断；取消会传播给模型调用和所管理的工具进程。
- 同一工作目录限制为一个可写任务；按实际路径识别目录，不能通过路径别名绕过。不同目录可并行，已有独立 worktree 可分别运行。
- TUI 断开不取消任务；重连读取最新状态及后续事件，不因重发输入而重复创建任务。等待确认只阻塞对应任务。
- 后台重启将未完成执行标为中断；工具是否产生外部效果无法确定时保留该事实，由拥有者决定下一步，不自动重放。

## 实施计划

计划日期：2026-09-19。沿用 [issue 01 的验证结论](../foundation-findings.md)；下面的 SQLite 元数据存储、控制面协议和恢复规则属于本工单拟实施的方案。issue 01 尚待维护者复核，目标 Linux 服务器的隔离前提也尚未验证。

1. **固定运行时边界与持久化职责**
   - 使用 `@earendil-works/pi-coding-agent` `0.85.1` 的 SDK 驱动会话；单个后台进程负责调度、状态和事件，每个会话使用独立 SDK 实例。应用放在根目录的 `src/`，固定依赖并提供运行脚本；`verification/foundation` 继续保留为验证工程。
   - pi JSONL 是消息历史的唯一权威副本。宿主另存项目、会话、任务、确认请求、目录占用、幂等键和持久事件；尚未送入 SDK 的输入按任务请求保存，写入历史后关联对应条目，历史查询仍读取 JSONL。
   - 元数据拟使用 Node.js 24 的 `node:sqlite`；本机 24.15.0 已检查基础事务可用，实施时补验文件数据库和异常恢复。在事务中一起提交任务状态、目录占用与对应事件，提交成功后才应答和广播。SQLite 与 pi JSONL 没有跨文件事务，不能声称两者原子提交。
   - 先补做首次响应前崩溃的验证：固定版本的 `SessionManager._persist()` 会推迟新会话的首次文件写入，`message_end` 订阅回调也早于 SDK 写历史。优先通过公开接口建立可持久化的会话并验证落盘时序；验证不足时先保留已接收请求和中断事实，不宣布消息已持久化或任务已完成，不靠调用私有方法绕过。
   - 将任务 ID 与历史条目关联；任务完成前核对最终历史已写入。恢复时若发现状态和历史不一致，保留原始文件、记录缺失或不确定部分并要求人工处理；损坏的 JSONL 不得被静默忽略或覆盖，已捕获的不完整输出也不得伪造成完整回复。

2. **实现项目、会话和任务模型**
   - 项目用于组织会话；会话绑定已有工作目录和稳定的 pi session id，同一项目可以绑定不同 worktree 的会话。任务开始前用 `realpath` 和目录的设备号、inode 核对目录身份，拒绝排队期间被替换或失效的目录；规范化路径和目录身份都参与占用检查，覆盖符号链接及同一目录的挂载别名。
   - 每个会话只允许一个活动任务，新消息持久化后按 FIFO 排队，调度不使用 SDK 的易失 follow-up 队列。运行和等待确认期间均持有会话及目录占用；其他目录可以并行。互斥保证只覆盖该后台管理的任务，不能阻止外部编辑器写入。
   - 状态采用 `queued → running → awaiting_confirmation → running`，执行结束进入 `completed`、`failed` 或 `canceled`，故障或显式中断进入 `interrupted`；排队任务可直接取消。中断原因、取消意图和外部效果是否确定分别记录，不以新增状态排列所有组合。
   - 提交请求携带由客户端保存的 `request_id`，唯一范围为会话。同键同参数返回原任务，同键不同输入或权限参数返回冲突；只有数据库提交成功才确认接收，客户端可安全重试丢失应答的提交。

3. **实现后台调度与生命周期控制**
   - 启动时先取得数据目录的独占实例锁，禁止两个后台写同一会话；识别遗留实例和执行进程，不能只凭 PID 文件或 socket 不存在就删除锁。
   - 恢复后把原先 `running`、`awaiting_confirmation` 的任务标为 `interrupted` 并追加原因；尚未执行的 `queued` 请求保留顺序，暂停自动调度，等待拥有者显式恢复队列。已中断任务不再次转换，不自动重放模型调用、确认结果或工具操作。
   - 目录占用仅在确认旧执行已经停止后释放。Linux 启停使用 systemd 服务管理后台与其子进程，覆盖异常退出后的残留回收；无法确认执行已退出时保留占用并报错，不能让新任务与旧进程同时写目录。
   - 显式 `interrupt` 结束当前运行或等待确认的任务并记录为 `interrupted`；`cancel` 可取消排队或活动任务。活动任务先提交停止意图，再调用 `AgentSession.abort()`，取消模型请求及确认等待，向受管理的工具进程组发送终止信号，超时升级强制终止；确认 SDK 停止且进程退出后再提交最终状态、释放占用。
   - 取消与自然完成竞争时，通过条件更新确定唯一终态，重复取消无额外效果。拒绝确认只阻止对应操作，允许模型根据拒绝结果继续；重复批准、参数不匹配或失效批准均不得再执行。权限判定和真实授权执行由 issue 03 接入，TUI 展示由 issue 04 实现。
   - 工具开始前保存操作 ID 与执行意图，结束后记录已知结果；执行意图存在而结果缺失时标记 `effect_unknown`，保存已有输出。停止或重启不代表外部效果撤销，拥有者继续时必须先看到这些事实。

4. **提供最小本机控制面**
   - 用 Node 标准库实现 Unix socket、换行分帧 JSON 请求及最小 CLI，覆盖启动、连接、创建项目/会话、提交、查询、事件订阅、中断、取消、继续、恢复队列、响应确认与停止。校验协议版本、请求参数、帧大小、对象归属和允许的状态跳转。
   - 数据目录和 socket 设置访问权限。ADR 0003 要求可信拥有者入口与项目命令分开；同 UID 的 socket 权限无法区分拥有者终端与完全访问命令。issue 02 仅开放可信客户端和模拟工具，真实工具上线前由 issue 03 完成并验证客户端授权凭据、控制面身份与执行账户的隔离，不能仅因使用 Unix socket 就宣称满足权限保证。
   - 持久事件带单调序号、任务 ID 和足够的恢复信息；完整消息引用已写入的 JSONL 条目，运行中片段暂存为未完成输出，落盘后转为条目引用，避免建立第二套权威消息历史。首版不裁剪持久事件。
   - `connect` 返回一致的快照与序号 `N`，随后无缝补发 `seq > N` 的事件并订阅新事件；已有快照的客户端也可从上次确认的游标补发。客户端按序号去重，非法游标要求重新取快照；慢客户端断开后用游标恢复，不阻塞执行或无限积压内存。
   - 客户端断开只移除订阅。`continue` 创建带 `resumes_task_id` 的新任务，保留旧中断记录并展示已知进度和结果不明的操作；恢复模型上下文时不得补造成功工具结果或原样重发旧输入，结果不明的操作须先由拥有者核实或明确决定再次执行。
   - `stop` 先拒绝新任务并暂停调度，再中断活动任务、回收工具进程、落盘并关闭服务；排队输入保留。进程信号使用同一关闭路径，不能把停止后台等同于断开客户端。

5. **通过 SDK 接入模拟模型与工具**
   - 沿用 issue 01 的本地 mock provider 和临时目录方式，通过实际 SDK 跑完整路径；仅加载显式登记的模拟工具和可信扩展，关闭内置编码工具及项目自动发现的可执行资源，显式指定模型配置和凭据路径。
   - 禁用自动压缩、非预期摘要和自动重试；模拟 provider 返回上下文超限时，任务记录 `interrupted` 和 `context_overflow` 原因、暂停该会话队列并提示调整上下文，不自动摘要或反复调用。上下文选择策略由 issue 05 完成。
   - 工具覆盖可控延迟、等待确认、进程树、拒绝正常终止及写入一次外部标记。模拟验证通过后由 issue 03 沿用同一执行路径接入真实编码工具，避免在权限边界完成前开放宿主 Shell。

6. **用一组集成验证覆盖关键不变量**
   - 使用现有 `node:test`、本地 mock 服务和临时目录编写少量集成场景，以进程退出、持久记录和副作用计数为断言，不照搬状态机分支逐项写测试。
   - 并发场景验证同会话 FIFO、等待确认时保留占用、不同目录并行、符号链接和挂载别名互斥、独立 worktree 并行以及重复后台启动被拒。
   - 重连场景在提交已落盘但应答丢失时断开；重试必须返回原任务，同键异参失败。重连握手期间继续产出事件，验证快照和事件无缺口、片段和完整历史可恢复。
   - 停止场景验证模型取消、确认等待解除、进程树强制回收及锁释放顺序；无法清理时其他同目录任务不得启动，取消与完成竞争只能产生一个终态。
   - 崩溃场景覆盖接收后尚未启动、首次 assistant 消息前、工具已产生标记但未记录结果、JSONL 已写而任务状态未提交。重启后请求仍在，排队不自动启动，活动任务显示中断，未知操作的标记计数不增加，历史原文保持完整。
   - 补验上下文超限不摘要、不循环重试，以及数据库写入失败时不应答成功、不启动外部操作；运行相关集成测试和 typecheck。模型凭据可用时可做一次短连通检查，缺失时记录跳过。
   - 提供运行命令、数据布局、恢复步骤和 Linux systemd 配置说明；本机 macOS 检查与 Linux VM 检查分别记录，目标服务器验证未完成时明确列出，不能据此声称已完成部署验证。

## 交付与验证

先用可控的模拟工具验证断开重连、并行与目录互斥、中断及重启恢复，再接入真实编码工具。检查已记录历史未被覆盖，无法证明成功的外部操作没有被自动执行第二遍。无需为每个状态编写重复的单元测试。

## Comments

### 2026-09-19：实现完成

应用代码在根目录 `src/`（agent / control / core / runtime 四层），运行命令、数据布局、恢复步骤与 systemd 配置见 [docs/runtime.md](../../../docs/runtime.md)。全部离线集成验证 16 项通过（typecheck 通过）；真实模型经完整运行时路径连通（deepseek/deepseek-flash 一次短往返）。

要点：

- 持久化按计划 1 落地：pi JSONL 为唯一权威历史，`node:sqlite` 存元数据；任务状态、目录占用与事件同事务提交后才应答与广播。`SessionManager._persist()` 对新会话推迟首次落盘的行为已实测确认（首次 assistant 消息前崩溃 → 无会话文件），宿主以任务记录保存输入、恢复时不伪造历史，未调用私有方法。
- 任务模型按计划 2/3：`queued → running → awaiting_confirmation`，终态条件更新仲裁取消/完成竞争；目录身份用 realpath + dev/ino，占用以 dev+ino 为主碰撞键；中断原因、取消意图、effect_unknown 分字段记录，重启恢复不自动重放。遗留占用保留并暂停会话，由拥有者 `resume_queue` 核实后释放。
- 控制面按计划 4：Unix socket + 换行分帧 JSON + 最小 CLI，connect 快照与订阅在同一步完成保证无缺口，游标补发、按 seq 去重、非法游标拒绝。ADR 0003 的身份隔离未实施（如实声明，归 issue 03）。
- SDK 接入按计划 5：封闭配置（显式 models/auth 路径、关压缩/重试、`session_before_compact` 一律 cancel、`noExtensions/noSkills/noPromptTemplates/noThemes/noContextFiles` 关闭项目自动发现、工具白名单仅模拟工具）。超限经 `isContextOverflow` 检测 → interrupted + context_overflow + 暂停队列，无摘要无重试（已测）。
- 集成验证按计划 6 以场景组织：并发/互斥（含符号链接别名）、幂等与断线补发、中断/取消/确认/进程组回收、两段真实 SIGKILL 崩溃恢复、超限、DB 写入失败。挂载别名与独立 worktree 场景未单独实测（机制与已测路径相同，见 docs/runtime.md 诚实清单）；无法确认进程退出时保留占用的路径在 POSIX 上无法用测试强制（SIGKILL 不可抗拒），实现保留并报错。

实现过程中修正的两个关键时序问题，供 03/04 复用：`message_end` 订阅回调早于 SDK 落盘（扩展事件 → 订阅者 → 同步持久化），条目引用只在读文件核实后发出；tsx 以子进程运行 CLI 时是包装器 + 内层 node 两级进程，测试/守护脚本按进程组终止。

术语备注：本工单与代码沿用「确认请求」，CONTEXT.md 现有术语为「审批请求」，两者指向同一概念，宜由 domain-modeling 统一收录。
