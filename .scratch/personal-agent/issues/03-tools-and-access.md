# 编码工具与两种权限模式

## 目标

接入文件读取、修改和命令执行等编码能力，落实[权限 ADR](../../../docs/adr/0003-enforce-explicit-access-modes.md)中的请求确认和完全访问。自动审批不在本工单范围。

## 实施范围

- 优先复用上游工具，通过统一执行边界覆盖文件、Shell 及其子进程；请求确认模式为默认，模式绑定任务且由可信的拥有者入口选择。
- 在授权工作区内自主修改和验证；越界文件访问、未授权网络、凭据访问及外部写操作先形成具体审批请求。真实约束由 01 验证的执行环境实施，不能依赖命令黑名单。
- 审批展示任务、操作、参数与权限范围。批准只能消费到对应操作，不放开整个后台进程；参数变化或扩大范围重新确认。拒绝不执行，无在线 TUI 时等待。
- 完全访问显式启用后不做逐次确认，使用运行账户已有权限；模型和工具不能提升模式。切换不追溯撤销既有操作，也不放行其他任务。
- 两种模式的项目命令均不能修改宿主授权状态或冒充拥有者；完全访问只解除该任务的执行限制。后台授权控制通道、模式配置和服务凭据必须独立保护，不能只对受限项目命令隐藏；具体采用不同系统身份或等效隔离由 01 验证。完全访问任务可读取执行账户可访问的数据，这一模式不提供该账户内部的文件隔离保证。
- 编码结果包含改动与检查结果；工具输出的模型视图可以限长，但应保留可查询的已捕获正文，避免先在工具中丢弃内容再声称全量留存。

## 实施计划

计划日期：2026-09-20。沿用 [01 的验证结论](../foundation-findings.md)与 [02 已实现的运行时](../../../docs/runtime.md)。本计划以当前代码为依据；容器工具路由、拥有者认证、单次授权执行及目标 Linux 服务器部署均需在本工单中验证，不能把基础探针通过视为这些能力已经完成。

### 1. 先验证身份隔离与完整工具路由

现有 `src/agent/driver.ts` 根据会话的 `confirmTools` 决定是否等待，批准后直接返回工具执行；`src/control/server.ts` 依靠数据目录和 socket 的文件权限，没有独立的拥有者认证。两者可以复用生命周期与事件机制，但不能直接作为真实工具的权限边界。

- 采用三个不同身份：拥有者使用可信 CLI/TUI；后台身份持有授权数据库、模型凭据与控制接口；专用执行账户运行完全访问任务。请求确认任务仍进入 01 选定的 Linux 容器。执行账户不属于拥有者或后台的授权组，也不能读取其认证材料、修改服务代码和配置，或通过 sudo、容器管理接口取得这些权限。
- 这修正了 01 findings 中“完全访问任务以拥有者账户运行”的拟议部署方式：如果该账户也能读取 CLI 的授权材料，它就能冒充拥有者。改用专用执行账户符合 ADR 0003；完全访问提供的是这个账户已有的系统权限，工作区访问按部署配置授予，不承诺读取拥有者账户的全部文件。
- 后台通过受保护的 Linux 启动入口，以固定执行 UID 启动工具进程。先验证由 systemd 管理执行单元、固定身份和 cgroup 的路径；所需提权入口只允许后台调用，执行账户不能调用它或修改其配置。容器管理权限也只留给可信后台。不要以 root 运行项目命令，或向项目暴露通用的特权启动接口。
- 固定使用已安装的 pi `0.85.1`。先用 `read`、`edit`、`write`、`bash` 做一次真实工具路由验证。包内 `read` 在调用自定义 `ReadOperations` 前，仍经 `resolveReadPathAsync()` 调用宿主 `fs.access`；因此本计划将上游工具定义的完整执行放进工具工作进程，SDK、模型调用和会话持久化留在后台。工作进程只接受工具调用并返回数据，不获得审批、模式切换或控制面凭据。
- 工作进程与后台使用最小的有界消息协议，复用 Node 标准库和上游工具定义；参数通过结构化消息传递，不能拼入启动器的 Shell 命令。只注册这四种编码工具及后文所需的审批操作、输出查询工具，关闭项目自动发现的可执行扩展。镜像、工作进程代码与依赖固定并由可信身份维护。
- 这一验证须证明：文件操作、路径解析、Shell 及其子进程确实在执行边界内；完全访问命令不能读取拥有者认证材料、调用控制接口、修改授权文件或服务代码。缺少环境时记录未验证项；真实工具不得在检查失败后回退到后台账户执行。

### 2. 将模式与权限范围绑定到任务

在 `src/core/types.ts`、`db.ts`、`store.ts` 和 `src/runtime/runtime.ts` 扩展现有任务与审批记录，不另建一套任务状态机。

- 任务保存 `accessMode`、权限版本和已授权工作区范围；默认请求确认。完全访问只能由已认证的拥有者通过 `submit`、`continue` 或显式切换接口选择。`continue` 创建的新任务默认请求确认，旧批准不继承；拥有者可在提交时重新明确选择完全访问。
- 模式与初始权限参数进入提交幂等比较。同一 `request_id`、相同参数返回原任务；修改模式或权限范围后复用该键必须冲突。工具工厂读取当前任务的权限，不能将首次创建 SDK 会话时的模式缓存给后续任务。
- 模式切换只在没有执行中工具的边界生效。执行中的调用继续使用开始时的范围；拥有者如需立即停止，使用已有中断入口。切换前停止并核实旧执行单元及其后代进程已退出，再建立对应模式的执行环境；无法核实时切换失败。等待中的审批在切换时失效，后续执行重新判定；记录模式变化事件及权限版本，不能因切到完全访问而自动执行旧待批准操作。
- 审批保存宿主生成的操作 ID、任务 ID、工具名、不可变参数、工作目录身份、权限范围与权限版本。范围至少区分文件读写、网络目标和方法、凭据引用；参数和请求正文可完整查阅，凭据值不进入审批展示。权限变化或操作内容变化需要新请求。
- 操作 ID 不直接信任模型生成的 `toolCallId`：为宿主操作分配唯一 ID，另存 SDK 调用 ID 供关联，避免不同任务复用调用 ID 时冲突或串用批准。
- 为现有 SQLite v1 数据提供事务迁移，旧任务默认请求确认，旧未决审批失效；保留历史、任务与事件。`confirmTools` 仅保留给模拟测试，不再决定生产权限。

### 3. 接入受限执行与完全访问执行

新增集中处理工具启动、停止和结果捕获的执行模块，通过现有 `toolFactory` 与 Driver 接入。宿主统一完成参数校验、任务归属、权限判定和操作记录；上游工具负责文件编辑与命令结果格式化。

- 请求确认模式使用固定 Linux 容器配置：只挂载拥有者授权的工作区，非 root、移除 capabilities、禁止新增权限、只读基础文件系统，临时目录单独可写；默认无网络，不传宿主凭据、SSH agent、代理配置、控制 socket 或容器管理 socket。基础镜像提供明确的工具链，工作区内命令可自主修改和验证代码。
- 容器按任务建立并在任务结束后回收；审批需要额外能力时不修改该常驻容器的权限。相较 01 拟议的按会话复用容器，这样可以避免后续任务继承临时挂载、环境与残留进程；工作区文件仍按现有项目模型保留。
- 启动前沿用目录身份检查，确认真实路径、设备号和 inode；拒绝将后台数据、服务代码、认证材料或其父目录作为授权工作区。检查嵌套挂载、符号链接、硬链接和特殊文件带来的暴露，不能只做路径字符串前缀判断。容器内的系统工具与临时文件属于基础执行环境，不应被描述成“只能访问工作区内任何字节”。
- 对 Git worktree 检查 `.git` 指向的 common Git directory。需要访问工作区外 Git 元数据时，由拥有者在可信入口将具体路径及读写范围明确配置为该任务的基础权限，并展示共享 Git 元数据的影响；不能因为它是 worktree 就自动挂载主仓库或整个父目录。单次文件操作的批准不能转为后续命令可复用的挂载。
- 完全访问工具在容器外使用专用执行账户的权限，不逐次审批；后台仍校验任务归属并记录执行结果。它不获得控制面身份，也不提供执行账户内部的文件隔离保证。
- 模型请求由后台发送并使用后台模型凭据，项目 Shell 不继承该网络通路和凭据。项目内自带的秘密本来就属于已挂载内容，不能宣称容器会自动识别并隐藏它们；授权工作区时需明确这一范围。
- 超时、中断、取消、模式切换和后台重启都复用现有生命周期入口。扩展 `managed-processes.ts` 的登记内容，记录可恢复的容器或 systemd 单元身份；停止整个容器/cgroup 并核实已空后才释放目录占用。仅杀 Docker CLI 或等待 Shell 主 PID 消失不足以证明子进程退出；后台崩溃后也不能假定容器随父进程自动销毁。

### 4. 实现具体操作的审批与单次消费

自由 Shell 不做命令语义识别。范围内命令直接执行；被执行环境阻止的访问向模型返回明确错误，模型可提出一个新的、具体的审批操作。不得自动在更高权限下重试整个脚本，因为失败前可能已产生工作区修改或其他副作用。

- 首期提供结构化的越界文件操作与单次 HTTP 请求，覆盖外部文件读取/修改、网络访问、凭据使用和外部写入。审批中列出目标文件及修改内容，或 HTTP 方法、完整目标、头部和请求正文，以及所需凭据的名称与用途。这提供可验证的最小外部执行通路；GitHub 专用操作留给 06 接入同一机制。
- 批准后的文件操作由固定执行身份完成，只操作已批准的对象和内容；采用受限解析或固定文件描述符访问，覆盖符号链接与等待期间目标替换。写入绑定待写内容及必要的原文版本；对象、内容或范围变化时失败并重新申请。额外文件不会因此永久挂载给项目 Shell。
- HTTP 请求由可信的单次请求执行器发送，固定方法、目标与正文，默认不自动跟随重定向或重试；凭据按拥有者预配置的目标绑定注入，不能由模型任意选择秘密文件或将凭据转发到其他地址。解析结果和实际连接范围必须校验，控制接口等保留目标即使被请求也不向项目开放。凭据原值不会交给项目进程；明确请求读取普通凭据文件时，走相应文件审批，控制面认证材料始终排除。
- 批准一个 HTTP 请求不会给脚本开放整个主机的网络。只有目标域名或端口限制，无法保证同一服务上的其他写操作没有发生；因此首期不通过给任意 Shell 临时联网或注入通用凭据来实现单操作授权。暂不能表达为结构化操作的需求明确返回限制，由拥有者选择适当工具或显式完全访问模式。
- 后台从保存的不可变请求构造执行参数。批准决策、事件与消费资格通过 SQLite 条件更新提交；真正启动前再次校验任务仍活动、权限版本匹配、操作未消费，并原子记录消费与执行开始。工作进程只能收到这次执行载荷，不能提交一个批准 ID 后自行替换参数。
- 将“已提出但尚未执行”与“已开始但结果未知”分别记录。拒绝、失效和取消等待的操作已知未执行；批准与取消竞争时只有一个结果可启动执行。批准后崩溃、启动应答丢失或外部结果未落盘时不重放；无法证明未执行的操作沿用 `effect_unknown`，由拥有者核实后决定。
- 没有在线 CLI/TUI 时保持 `awaiting_confirmation`，保留目录占用；其他目录任务继续运行。拒绝只阻止该操作并返回可理解的结果，允许模型继续处理任务。

### 5. 保留工具正文并补齐拥有者入口

- 在上游工具截断之前捕获 Shell 输出与文件读取正文：利用工作进程中的 `BashOperations.onData` 和文件 Operations 包装器把原始数据传回后台，先存入受保护的任务产物文件，再生成限长模型视图。文件读取保留本次已捕获版本，不能用日后重读已变化的工作区文件代替原文。
- 工具产物由后台分配 ID，记录任务归属、字节数、完成或部分捕获状态，并在 pi 工具结果中保存引用；SQLite 只记录元数据，不复制整份会话历史。上游 `OutputAccumulator` 的临时文件不能直接当作跨重启可查询的最终存储。
- 提供按产物 ID、偏移和长度读取的工具与控制接口。宿主依据当前任务和项目权限查找产物，不接受模型传入任意宿主路径，不跨项目返回正文。首期只完成工具正文查询，通用历史索引与上下文预算仍由 05 实现。
- 流式传输设置背压和单帧上限，区分命令输出与工作进程协议。磁盘写入失败时停止执行并保留已捕获的部分及失败原因，不能继续丢弃输出后报告完整成功；中断或异常退出同样保留已有数据。外部效果与产物落盘不具备原子性，结果记录必须反映这一事实。
- `src/control/client.ts`、`server.ts`、`protocol.ts` 与 `src/cli.ts` 增加拥有者认证、提交模式、切换模式和正文查询。最小认证采用仅拥有者客户端与后台可读的随机令牌；认证成功前不返回快照或执行请求，令牌不放在命令行、工具环境或日志中。socket 单独放在可供拥有者连接的受控目录，后台数据库目录仍只对后台开放。
- CLI 的任务查询、连接快照和事件持续提供当前模式、权限版本、待审批操作及正文引用，供 04 的 TUI 直接复用；本工单用 CLI 完成所有授权流程验证。

### 6. 用集成场景验证并交付

沿用现有 `node:test`、mock provider、临时目录和本地模拟服务，新增少量按场景组织的测试。纯协议与状态测试可在本机运行；实际权限测试必须运行在具有不同系统身份及容器能力的 Linux 环境，不能用 mock 执行器替代后宣称边界通过。

先修正基础探针的判定入口：现有 `run-probes.sh` 不会因汇总结果不一致而以非零状态退出，也未校验预期探针是否齐全。补上服务就绪、执行成功与探针集合完整性检查，区分真正的权限拒绝和容器未启动等基础故障；缺项或不一致必须使命令失败。以真实存在的工作区外秘密文件和可访问的对照服务验证拒绝原因，避免把目标不存在或服务未启动计为隔离成功。

1. 在临时 Git 仓库通过实际 SDK 和四种真实工具完成“读取—修改—检查失败—修复—检查通过”，断开客户端后任务继续，重新连接可查看改动与检查结果；模型输出由 mock provider 控制，不依赖真实模型成功率。补验 Git worktree 的外部元数据未授权时不可达、显式授予任务范围后可执行检查，单次批准不会留下额外挂载。
2. 在请求确认模式下，验证直接与脚本间接的网络访问、越界文件读写、符号链接/路径替换、隐藏凭据、后台接口和容器管理接口均被阻止；子进程不能绕过。再用本地模拟服务验证批准前计数为零、批准后仅对应请求执行一次，其他 URL、方法、正文、任务及重定向不能复用批准。
3. 验证重复批准、批准后取消、等待期间参数或文件变化、权限切换、任务结束后迟到批准，以及不同任务复用 SDK 调用 ID；拒绝和未执行取消不标成外部效果未知。无客户端时一直等待，重连后的状态和操作内容完整。
4. 拥有者显式启用完全访问后，执行账户能进行其权限内的文件与网络操作且不逐次等待；默认和后续任务仍使用请求确认。让完全访问命令尝试读取拥有者令牌、修改服务代码/授权数据库、伪造审批及提升其他任务，均应失败。
5. 让 Shell 主进程退出但子进程继续、子进程调用 `setsid`、忽略终止信号，再分别取消任务和强杀后台；确认容器/cgroup 清理后才释放占用。无法确认清理时保留占用并报错。缺少权限后端、镜像或身份配置时明确失败，不回退完全访问。
6. 在批准已消费但启动结果未确认、模拟服务已产生副作用但结果未落盘两处注入故障；恢复后不重放，保留不确定事实。补验超长 stdout/stderr、跨分块 UTF-8、已读取文件随后被修改、查询越权与存储失败，正文引用能重连及跨后台重启读取。

运行 `npm run typecheck`、包含新增场景的 `npm test`，并在实际 Linux 执行环境运行权限集成测试及 `verification/foundation` 的 `npm run linux:probes`。扩展探针时同时保留原有基础用例。模型凭据可用时可做一次短编码连通检查，缺失时记录跳过。

交付包括上述代码、SQLite 迁移、固定工具镜像与启动配置、测试命令和 `docs/runtime.md` 中的部署/恢复说明；验证记录分别标注 macOS、Linux VM 与目标服务器的结果。目标服务器尚未验证时明确列出前提，不声明已满足部署保证。实施确认身份和容器生命周期方案后，再按领域文档约定补充架构决策记录。

## 交付与验证

本轮修复的实现缺陷（前一轮留下的或实现中发现的）：
