# TUI 与断开重连

## 目标

提供类似 pi agent 的终端交互，使用后台任务接口而不在 TUI 内持有执行循环。

## 实施范围

- 复用 01 确定的 TUI 能力，提供项目与会话切换、输入、流式结果、工具输出、排队状态、明确中断和中断任务的继续操作。
- 显示审批请求及其参数，允许拥有者批准或拒绝；展示当前权限模式，完全访问必须通过明确的拥有者操作开启。
- 退出与断开只关闭客户端，提供重新连接现有任务的入口；后台不可用时准确显示连接状态，避免悄悄另起同一任务。
- 提供历史查看及展开完整工具输出的入口，和 Agent 的历史读取能力使用同一资料来源。

## 实施计划

计划日期：2026-09-20。基于 [01 的选型结论](../foundation-findings.md)、[02/03 已实现的运行时](../../../docs/runtime.md)与 [ADR 0002](../../../.agents/notes/implemented/architecture/2026-09-19-detach-terminal-from-task-runtime.md)。03 的容器与 systemd 部署仍有未验证项，详见 [03 工单](03-tools-and-access.md)；TUI 接通协议不代表这些执行边界已经通过部署验证。

### 1. 建立最小 TUI 入口与布局

- 在现有 CLI 增加 `tui [--session <id>]` 入口，只连接已运行的后台；默认进入项目与会话选择，没有项目时可调用已有接口创建项目、填写工作目录并创建会话。不存在的指定会话明确报错，不自动新建或提交任务。
- 固定直接依赖 `@earendil-works/pi-tui` `0.85.1`。本机已核实它作为 coding-agent 的嵌套依赖安装，公开导出 `ProcessTerminal`、`TuiAltScreen`、`VStack`、`ScrollView`、`Editor`、`Markdown` 和 `SelectList`；应用直接导入时应在根 `package.json` 声明依赖，不引用嵌套安装路径或上游测试文件。
- 采用单个全屏页面：顶部显示项目、会话、工作目录、连接状态和任务权限；中间滚动查看消息与工具记录；底部保留多行输入和当前任务/队列状态。项目与会话切换、历史和审批详情用已有选择列表或覆盖层打开，窄终端也保留这条纵向结构。
- 代码先集中在 `src/tui/` 的入口、连接与视图状态、组件几个文件，复用 `src/control/client.ts`。从 CLI 提取可共同使用的连接配置与拥有者令牌读取逻辑，避免导入会自动运行 `main()` 的 `cli.ts`。TUI 不创建 SDK 会话、不加载模型凭据、不直接打开后台数据库或 JSONL。
- 输入使用上游 Editor，支持中文、多行和 bracketed paste；`Enter` 提交，`Alt+Enter` 换行，帮助中列明终端相关限制。大段粘贴的折叠标记只用于展示，草稿与提交必须保留展开后的原文。项目路径补全不能扫描拥有者本地文件后假装是后台工作区；首版只做固定操作的补全。

### 2. 补齐独立客户端所需的读取与事件接口

当前控制面已提供认证、`connect`、任务提交/继续/中断/取消、审批应答、模式切换、`get_task` 和 `read_artifact`。但 `task.output_entry` 只带 JSONL 条目引用，没有历史正文 RPC；快照不包含运行中的输出，`task.output_fragment` 也没有消息标识。现有重连测试直接读取后台 JSONL，不能作为 TUI 历史查看的实现。

- 在后台增加按会话、消息条目 ID 和游标分页读取历史的接口，提供最近一页、向前翻页及指定条目的读取。复用 pi JSONL 与现有任务条目关联，返回角色、内容、工具关联和稳定条目 ID；不建立第二份权威历史。文件路径由后台按归属查找，客户端不能传任意宿主路径。
- 把 JSONL 读取放到一个可供控制面及 05 历史工具共用的后台读取模块；04 只交付显示所需的原文读取与分页，搜索、上下文选择、长期记忆由 [05](05-context-and-memory.md) 完成。保留来源和项目范围校验，不能因是 TUI 接口就绕过共享读取边界。
- 历史分页固定本次读取的末端位置，后续追加通过事件获取，避免翻页时重复或跳过消息；超大单条消息提供有界分段读取。完整记录解析失败时返回明确错误；文件尚未首次落盘或尾部正在写入时与历史损坏区分，不将部分记录伪装成完整消息。
- 为运行中的 assistant 输出增加后台分配的消息标识和最终条目关联。当前 `task.output_fragment.text` 是某条消息截至当时的累计文本，TUI 应替换对应预览，不能不断追加导致重复。最终正文确认落盘后用条目替换预览；多轮模型回复与工具调用保持各自顺序。
- 新连接取得当前任务的最新预览及其对应序号，不能只等待下一次模型事件。优先从已有持久片段和当前 Driver 状态重建；尚未完成的文本明确标为“生成中”或“中断前已捕获部分”，不进入完整历史。缺失片段时如实显示，不能补造内容。
- 工具完成后通过 `get_task` 取得操作、错误和产物引用；展开正文复用 `read_artifact`。运行中的工具先显示名称、参数与执行状态，只有产物已经可查询时才刷新已捕获内容；不为界面新增另一条工具执行路径。现有产物读取会先读完整文件再切片，实施本步时改为按偏移读取，避免每翻一页都加载整个大日志。
- 对握手、任务详情、实时事件、replay 和历史/产物读取按序列化后的字节数设限，计入 JSON 与 base64 开销；现有 1 MiB 帧限制不能承载 1 MiB 原始产物的 base64。累计输出片段及携带完整参数的工具/审批事件改为有界预览与可查询引用，不能只限制查询应答却让推送超限。快照只保留状态摘要、活动任务和有界的近期任务，已结束任务按会话分页查询；大审批参数和消息正文按 ID 分段读取，不能为缩短快照而丢失可查看的正文。必要协议变更同步更新共享类型与版本，不兼容时给出明确提示。

### 3. 保证连接恢复与输入提交不重复

- 连接过程依次为建立 socket、拥有者认证、同步快照、进入在线状态。复用 03 的令牌来源，不把令牌放入输入历史、日志或待提交记录；补齐可指定拥有者令牌文件路径的共享配置，以支持拥有者与后台使用不同 UID 的部署。
- 扩展 `ControlClient` 的断线通知：当前 socket 关闭只拒绝正在等待的请求，空闲 TUI 无法立即知道连接断开。断线时标记连接不可用、通知订阅者并停止发送；客户端和服务端同时补验未换行帧、超长帧、非法协议及响应超时，异常不能留下假在线状态。
- 握手前注册并缓冲实时事件，取得序号 `N` 的快照后先安装快照，再处理 `seq > N` 的事件。补发中不晚于 `N` 的事件只用于补齐显示记录，不能把最新任务状态回滚到旧状态。修正现有 `handshake()` 在返回前直接把 replay 推给监听者的时序，避免快照与实时推送互相覆盖。
- 游标只在事件已经应用后前进，按全局序号去重并检查缺口，不能先按当前会话过滤再维护全局游标。`invalid_cursor`、`cursor_too_old` 或发现缺口时重新同步快照、历史和最新预览；不会重新执行任务。冷启动也从后台重建内容，不依赖上次 TUI 的内存。
- 暂时断网或后台不可达时显示最后同步时间，保留输入草稿并以有上限的退避间隔重连；认证失败、协议不兼容和配置错误停止自动重试，显示修复入口。重新连接只恢复观察，不发送 `resume_queue`、批准、继续任务或启动后台。
- 输入发送前生成 `request_id`，把操作类型（submit/continue）及完整请求参数原子保存到拥有者私有目录，再发送原封不动的请求；参数包括会话、原文、权限模式、授予范围，以及 continue 所需的原 `task_id`。确认后台已接收并获得任务 ID 后清除待确认记录。应答丢失时显示“接收结果待核实”，不能生成新键悄悄启动第二个任务。
- 增加按 `session_id + request_id` 精确查询任务的只读接口，供重连核实已接收请求，包括已离开近期快照的完成任务。查到后关联原任务；明确未接收时才以原键和参数重试，查询失败时保留待核实状态。原任务可能已切换权限模式，不能仅凭当前模式与原请求不同就当成另一任务；发生 `request_conflict` 时重新核对并展示冲突，不通过换新键消除错误。
- 待确认记录绑定后台数据实例的稳定标识；由后台在数据库元数据中持久化并在握手返回该标识。后台重启保留标识，新数据库分配新标识；此时保留待核实输入并要求拥有者处理，不能重发到一个空后台。记录仅保存尚未确认接收的请求，不作为会话历史副本。
- 会话切换保留各自草稿、滚动位置和待确认输入，异步查询结果按会话与连接批次匹配后更新，防止旧页面请求覆盖新页面。断线期间允许编辑，但不自动发送新草稿；状态恢复后由拥有者正常提交。

### 4. 完成任务、审批与权限交互

- 普通输入调用 `submit`；已有活动任务时仍按后台规则排队，显示当前任务、队列顺序与暂停原因。明确提供“中断当前任务”“取消排队任务”“继续已中断任务”和“恢复暂停队列”，均绑定选中的任务/会话 ID；不能用一个含糊的停止按钮同时承担退出客户端和停止后台。
- “继续”先展示旧任务的中断原因、已完成操作及 `effectUnknown`，让拥有者填写继续指令，再调用 `continue` 创建新任务。若会话队列仍暂停，明确显示新任务正在排队和单独的恢复队列操作，不能宣称已经开始执行。后台重启造成的中断和单纯的客户端断开分别显示；不能把未知外部效果显示成失败后可安全重试。
- 顶部持续显示后台实际 `accessMode`；有 `pendingAccessMode` 时另写明“待切换”，只有模式生效事件或刷新后的任务记录才能更新实际模式。切换失败展示后台原因，不乐观宣称已获得或收回权限。握手补充执行环境说明，开发用无隔离 `local` 后端需显式标记，不能仅凭“请求确认”字样暗示隔离已生效。
- 新任务默认请求确认。完全访问通过明确的模式操作选择，展示目标任务及“使用专用执行账户已有权限”的范围；其选择不自动扩散到下一个任务或其他会话。工作区外授予路径以路径、读写范围和用途展示，共享 Git 元数据沿用后台提供的影响说明。
- 审批详情显示任务、工作目录、操作、参数、权限范围与当前状态；HTTP 请求展示方法、目标、正文和凭据名称/用途，文件写入提供待写内容查看。正文可以分页，批准时必须绑定原请求 ID 与权限版本；页面不改写请求内容，也不提供“永久允许此工具”的捷径。
- 新审批到达时显示提示和待处理数量，不抢走输入焦点。拥有者主动打开详情后才有批准/拒绝操作；普通输入的 Enter 或粘贴内容不能触发批准。关闭详情不等同于拒绝，切换会话后仍能发现其他会话的待审批请求。
- 批准不等同于执行成功。发送应答后等待后台状态；遇到已失效审批、其他客户端已处理、任务结束或权限版本变化时刷新详情，禁止继续提交旧选择。审批或模式切换应答丢失时先查询实际状态，不像幂等的任务提交那样盲目重放。

### 5. 处理长输出、终端安全与退出

- 用上游滚动区和 Markdown 渲染完整消息，工具结果默认折叠为操作与结果摘要；滚动到历史时新输出不会把视口拉回底部，提供返回最新位置的入口。只渲染已加载的有界历史窗口，向前翻页仍能找回原文，不因限制界面内存而删除后台历史。
- 产物按字节分页，连续读取使用流式 UTF-8 解码，避免中文跨分块变成乱码；跳到任意偏移时明确边界处理。`partial` 产物与 `complete` 产物分别标识，二进制内容显示类型和字节数，不直接作为终端控制文本输出；内联图片不是首期必需能力。
- 渲染消息、工具日志、文件名和审批参数前处理不可信终端控制序列，复用 pi-tui 的 `stripTerminalSequences` 并验证其覆盖范围，阻止擦屏、光标控制、OSC 52 剪贴板写入及伪造界面；对影响参数辨识的不可见控制字符显示转义形式。只改变展示，历史与审批执行参数保持原值。链接不自动打开，状态不只靠颜色表达。
- 限制刷新频率并合并同一消息的预览更新，保持键盘输入响应；调整终端大小、中文输入法、组合字符、宽字符和长行均使用上游宽度/光标机制，不自行计算字符串长度替代显示列宽。
- `/quit` 与 `Ctrl+C` 统一退出客户端；显式任务中断使用独立操作。正常退出、SIGTERM、SIGHUP 和可处理的异常都关闭 socket、停止 TUI 并恢复 raw mode、光标和终端屏幕，不发送 `stop` 或取消任务。退出前保留尚未确认接收的请求；重新打开后可核实。进程被强杀时无法保证执行清理回调，文档给出终端恢复方法。
- 非 TTY 环境不启动交互页面，提示使用已有 CLI 命令；TUI 错误和后台日志不能直接混入正在绘制的页面。仅连接本机 Unix socket，远程使用沿用登录服务器后启动 TUI 的方式，不新增远程协议。

### 6. 按真实交互路径验证并交付

复用现有 `node:test`、mock provider 和临时后台，通过控制协议验证状态，以真实终端或 PTY 验证输入与退出；不为每个组件编写重复快照测试。

1. 创建/切换项目与会话，提交多行中文和大段粘贴，运行可控的多轮流式回复与工具调用；断言累计片段没有重复、最终消息只出现一次、排队状态与后台一致，切换会话不会串入旧查询结果。
2. 在首次回复前、工具运行中和等待审批时关闭 TUI，重新连接后应看见仍在运行的任务或其真实终态、最新片段/历史和审批；再覆盖握手期间收到实时事件、重复事件、序号缺口、超过 5000 条补发范围和后台重启。全程不自动新建任务或恢复暂停队列。
3. 在后台已提交任务但应答未送达时断开，退出并重开 TUI，验证同一输入只对应一个任务；重复 Enter 不重复发送，应答超时保留待核实状态，同键异参被拒绝，换后台数据实例不会自动重发。待确认记录写入失败时不得先发送请求。
4. 验证跨会话审批提示、参数正文查看、批准/拒绝、两个客户端同时处理、审批失效和应答丢失；验证新任务默认请求确认、完全访问显式选择、待切换与已生效的区分，以及切换失败的展示。普通编辑和粘贴不能触发审批。
5. 使用超过单帧上限的历史、工具日志和审批正文，验证分页能访问完整内容、编码边界正确、部分产物如实显示；TUI 账户没有后台历史文件读取权限时仍能通过认证接口查看。加入恶意 ANSI/OSC 内容、损坏记录和正文不可用场景，确认界面不被控制且错误不会被包装成正常内容。
6. 在真实终端检查 80×24 及缩放后的布局、中文输入法、多行粘贴、滚动后持续输出、详情关闭后的焦点、Ctrl+C 与重新进入；在 PTY 验证退出后终端状态恢复且后台任务继续。优先用 Python 标准库 `pty` 或现有终端设施，不仅为测试引入新的 TUI 框架。

运行 `npm run typecheck` 与包含新增场景的 `npm test`；有 Linux 环境时用 03 的真实工具后端完成一次“提交编码任务—查看输出—退出—重连—查看改动与检查结果”。真实终端检查记录终端类型、操作和结果；macOS/mock 检查、PTY 检查与 Linux 实际执行分别记录，缺少某项环境时明确列出未验证部分。

交付为 `src/tui/`、必要的共享控制面/历史读取改动、测试与 `docs/runtime.md` 中的启动方式、快捷键、重连和恢复说明。保持 02/03 的任务与权限语义，04 不重建后台执行循环；05 可直接复用本工单新增的历史读取接口。

## 交付与验证

在真实终端检查流式输出、审批、会话切换、退出和重连。后台执行一个持续任务时关闭 TUI，再连接后应看到持续执行的状态；输入重发不能重复启动任务。避免只用组件快照声称整个交互已验证。
