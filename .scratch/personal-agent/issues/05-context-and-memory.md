# 上下文、历史检索与长期记忆

## 目标

实现[完整历史与独立上下文](../../../docs/adr/0001-preserve-session-history.md)，使拥有者可以修改选择规则和记忆策略。

## 实施范围

- 按模型预算组装系统与项目指令、当前任务要求、最近完整交互，预留模型回答与工具结果空间。保持工具调用和结果配对，不能原地修改历史。
- 必须保留的内容自身超出预算时，明确暂停并给出原因；不能偷偷引入摘要。超长工具结果采用有原文引用的有限视图，完整正文继续可查。
- 提供按消息标识或范围读取原文及基础搜索；先使用现有存储和简单索引，不把向量数据库列为依赖。以项目范围过滤读取，跨项目必须显式开放，QQ 使用独立范围。
- 长期记忆保存个人偏好、项目约定、确认后的决策和经验，关联来源及修改记录，支持修改与撤销；临时进度保留在会话中。记忆不能改变执行身份、权限模式或审批规则。
- 记录每轮选入和排除的消息标识及原因，供调试和后续 Jev 对比；更换选择策略不改写历史。不自动删除原始历史。

## 实施计划

计划日期：2026-09-20。沿用 [ADR 0001](../../../docs/adr/0001-preserve-session-history.md)、[01 的固定版本验证](../foundation-findings.md)和 [04 已实现的历史读取](04-tui.md)。当前 `src/core/history.ts` 已提供 JSONL 分页/分段读取，03 已保存工具正文产物；应用尚未接入逐轮上下文选择、Agent 历史搜索或长期记忆。下面方案基于本地 pi `0.85.1` 代码，不把基础扩展点验证当作预算与权限行为已经完成。

### 1. 统一历史、产物与记忆的数据访问范围

- 在后台增加一个共用的资料访问判定入口。拥有者身份来自已认证控制连接；Agent 的身份、当前任务、会话和项目由宿主注入，不能从工具参数里的 `project_id`、角色或文件路径取得权限。当前 `Runtime.withSessionHistory()` 只检查会话存在，不能原样开放给模型。
- Agent 默认读取当前项目的会话历史、工具产物和生效记忆。跨项目读取由拥有者在可信入口明确设置来源项目、目标项目及资料类别，支持查看与撤销；授权关系存于后台 SQLite，模型只能请求读取已有范围，不能自行创建授权。`grantedPaths` 和完全访问模式均不隐含扩大历史或记忆 API 的范围。
- 列表、搜索、结果计数、摘要、分页游标、原文读取和来源跳转都先执行范围校验；产物按其真实任务/会话归属检查。将目前 `read_artifact` 仅允许当前任务的逻辑接到同一判定，使同项目旧任务的正文引用可用，同时阻止跨项目猜测 ID 读取。拥有者可以在 TUI 显式切换项目查看资料，不把拥有者控制连接的全局权限传给模型工具。
- QQ 尚未接入，本工单不增加群管理平台；未识别的入口或资料范围默认拒绝。未来 QQ 必须拥有独立范围，不能因共用后台而默认读取开发项目或个人共享记忆。完全访问任务仍可能通过执行账户可访问的普通文件取得资料，这是 ADR 0003 的既有边界，不将 API 过滤宣传为该账户内部的文件隔离。
- 授权撤销从后续查询和上下文注入起生效；跨项目结果与派生记忆保留来源范围标记，缓存命中时也重新校验。不能承诺撤回已经发送给模型的内容、已生成的派生文本或已经发生的外部效果，也不通过删除原始历史实现撤销。

### 2. 在既有历史模块上增加原文检索

- 保留 `read_history`、`read_history_entry` 的 TUI 展示视图，并增加结构化消息的读取表示。当前 `HistoryEntryView` 会合并 text 块，只保留工具调用的 ID/名称，图片等内容仅标记存在；它不能用于重建包含工具参数、结果和内容块的原始模型消息。原文读取以 JSONL 中的条目为依据，保留 `parentId` 和完整消息结构；图片或大字段可按来源引用分段读取，不把它们悄悄省略后称为完整原文。
- pi JSONL 继续作为消息历史的唯一权威副本。在现有 SQLite 中增加可重建的条目位置索引，只记录项目、会话、条目 ID、父条目、角色、文件身份与字节位置等元数据，不复制全部消息正文。按已完整落盘的换行记录增量更新；尾部部分记录不入索引，完整记录损坏明确报错。
- 索引记录文件身份与已处理位置；追加写入继续增量处理，文件替换、截断或索引缺失时重建派生索引，不能覆盖源文件。恢复时校验索引与源条目一致；未完成同步的会话明确标记，不把尚未扫描到的资料当作“没有结果”。首次落盘前当前任务输入来自已接收任务记录，仍标明尚未成为完整历史条目。
- 首版搜索支持字面关键词、会话/任务、角色和时间范围，按固定顺序分页返回命中片段及可读取的来源 ID；中文直接按原文匹配。先在授权范围内依据索引定位原文并扫描，不引入向量库、嵌入模型或额外全文引擎。查询限制结果数、返回字节数和单次扫描量，支持取消及继续游标；未扫描完时明确返回“搜索未完成”，不能只搜索最近消息却声称覆盖全部历史。
- 使用 SDK 当前分支消息作为上下文候选，不能直接把 JSONL 中全部分支按文件顺序拼进模型输入。历史查询可以访问保留的旧分支，但返回分支/父条目信息；查询结果作为带来源的工具结果进入当前交互，不伪装成当前会话中新的拥有者指令。
- 通过现有宿主工具注册方式提供 `history_search` 和 `history_read`，参数只接受资料 ID、过滤条件和有界范围。文件路径、索引和后台读取由宿主处理，不向工作进程开放数据目录或控制令牌。读取工具的结果也受下文的工具结果预算约束，不能用一次搜索重新填满上下文。

### 3. 实现可替换且有预算约束的上下文选择

- 在 `src/agent/` 增加独立的上下文选择函数：输入为当前任务、SDK 当前分支消息、来源标识、项目指令、可用记忆及预算；输出为本轮消息视图、来源引用和选择理由。默认只实现一个确定性策略，使用已有宿主扩展注册；不建立策略插件平台。为 [08 的 Jev 实验](08-jev.md)保留替换此函数的入口，合法性、权限和最终预算检查始终由宿主执行。后续实验失败可按 08 回退到已验证的基础策略，再通过同一检查；不能回退到未筛选的全量输入。
- 必留项为宿主系统指令、已加载的项目指令、当前任务原文及拥有者在当前任务中的明确补充。项目指令通过显式配置的工作区内文件读取，复用 03 的受限文件访问路径，保存本次读取版本与来源；不因需要项目指令就开启 `noExtensions` 等已关闭的自动执行资源。项目文本和记忆不能变更控制面身份、审批规则或权限模式。
- 当前项目指令按任务开始时的内容固定，拥有者要求刷新时才建立新版本；文件缺失、不可读或超大分别说明，不偷偷取未授权的祖先目录文件。宿主指令、项目指令和任务输入各自只注入一次，避免 SDK 组装和自定义选择同时重复添加。任务实际使用的文件内容须可追溯到捕获产物，而非日后可能变化的工作区路径。
- 选择以完整交互为单位：较早的用户轮次连同其 assistant 和工具交互整体保留或移出；当前任务输入固定保留，其工具循环可按已完成批次取最近部分。一次 assistant 中的全部 `toolCall` 与对应 `toolResult` 构成不可拆分的一组，包含失败结果；最新刚完成的工具批次须保留，工具调用参数不截成不合法 JSON。尚未取得真实结果的调用不能补造成功结果，恢复时沿用原有不确定性处理。
- 先装入必留内容及当前必须处理的工具批次，再按从近到远的顺序放入其余完整交互；少量长期记忆在单独上限内按当前项目优先、更新时间与 ID 稳定排序选入，不挤掉当前任务要求。超长工具结果可在模型视图中换成有界原文片段、错误/完成状态和可读取引用，历史消息与产物本身保持原样。无法保留最小合法交互时暂停，不退化为随意删掉配对消息。
- 预算以实际模型的 `contextWindow` 为总量，同时计入 system prompt、工具 schema、消息、图片等内容；为回答及思考输出、下一批工具结果和估算误差分别预留空间。首版使用显式、可校验的预算配置，拒绝负数、超出模型上限或缺少可靠窗口配置的情况，不能把缺失值当作无限容量。
- 可复用 pi 导出的 `estimateTokens(message)`，但该版本以字符数除以 4 等规则估算，对中文不是保守上界。逐次重新估算实际选中的内容，补足系统提示、工具定义和多模态开销，并用安全余量及可配置校准系数控制误差；不把 SDK 基于旧 usage 的 `getContextUsage()` 当成本轮精确计数。记录估算与实际 provider usage 的差异，明确这是预算估计而非精确 token 保证。
- 每个工具结果和每批工具结果设置返回预算；多个工具同时产生大结果时，合计也不能超过预留空间。分段历史读取与 `read_artifact` 返回原文片段和继续读取位置；大字段已有 JSONL/产物来源时直接引用，不再复制一份正文。必留输入或图片仍超限时明确暂停，不摘要、不静默删除。

### 4. 在模型请求前落实硬性检查与暂停

- 通过 `session-factory.ts` 的宿主 `context` 扩展，在每次模型调用前返回新消息视图。pi `0.85.1` 会对上下文消息做深拷贝，但选择器仍需保持输入不可变；现有 foundation 测试中的 `slice(-2)` 仅证明扩展点可用，不能直接作为完整交互策略。
- 先做小型 SDK 验证：该版本会捕获 `context` 和 `before_provider_request` handler 的异常后继续运行，因此不能仅在扩展里抛错阻止发送。保留并包装公开的 `sdk.agent.streamFunction`，在委托原发送函数前核对最终 `systemPrompt/messages/tools`、权限范围、配对和预算；策略失败或资料读取失败由宿主保存阻断原因，最终检查发现该原因时拒绝发送，不退回未筛选的全量历史。
- 同一请求的输出配置与预算一致，计入 provider 对思考预算及 `maxTokens` 的处理；上游自动压低输出上限并不保证输入超限时会停止。保留原 stream function 的取消信号、provider 选项和事件语义，不重写模型循环或依赖私有方法。`before_provider_request` 可用于核对实际请求表示，不承担阻断职责。
- 预算不足映射为已有 `interrupted` 状态及明确原因（如 `context_budget_exceeded`），暂停该会话队列，并按现有停止路径清理执行单元和占用。Agent 可能把发送前异常转换成 `stopReason: error`，Driver 必须依据宿主原因识别，不能只等待 `sdk.prompt()` reject 或按普通失败结束。
- 不在上下文钩子内等待 `sdk.abort()`，避免钩子等待本轮执行结束造成死锁。保留已有 provider `context_overflow` 兜底、关闭自动压缩和重试；估算漏报时也只中断并展示原因，不自动摘要、缩短输入后重试或重复执行工具。
- 拥有者可以查看超限组成并调整预算、项目指令或策略，再通过现有“继续”和“恢复队列”入口启动新任务。继续时应保留原任务目标的来源关联，不能只发送一句“继续”就丢失被中断任务的要求；原任务记录和结果不明的操作保持不变。

### 5. 保存有来源、可修订和撤销的长期记忆

- 复用 SQLite 保存记忆当前版本与追加的修订记录，字段包括稳定 ID、适用项目/个人共享范围、类别、正文、来源引用、版本、状态、作者、任务及修改原因。类别限于个人偏好、项目约定、已确认决策和经验；每个版本保留其实际来源，不把全部历史或临时任务进度自动转换为记忆。
- Agent 通过 `memory_list/read/save/revoke` 等少量宿主工具维护当前项目记忆，拥有者通过控制面和 CLI/TUI 查看、编辑、撤销及恢复旧版本。来源可引用已持久化的会话条目、已捕获的工具产物及其范围；拥有者直接输入的记忆以本次可信操作记录作为来源。引用必须存在且可访问；自动生成内容标明 Agent 作者，不能伪称拥有者已经确认。
- 默认新记忆留在当前项目。个人偏好需要在多个项目复用时，由拥有者明确设为个人共享；共享范围不自动包括 QQ。跨项目读取授权不赋予对来源项目记忆的写权限，也不允许 Agent 把借来的资料转存成无来源的共享记忆。引用受限来源的派生记忆后续读取时仍检查来源范围，除非拥有者明确开放新的适用范围。
- 修改使用预期版本号进行条件更新；两个会话并发修改同一记忆时返回冲突并保留两边输入，不能静默覆盖。修订、当前版本和对应事件同事务提交；Agent 写入关联宿主操作 ID，使执行结果查询能够确认是否已经提交，不因响应丢失重复生成修订。
- 撤销将当前状态标为停用，恢复旧版本创建一条新的修订，不删除旧版本或回退审计记录。所有变更提供前后内容和来源查看；原始会话与产物不随记忆撤销删除，也不从一次撤销推断需要回滚其他记忆。
- 每轮组装上下文时重新读取生效版本，作为带来源和版本的参考内容注入，不冒充新的用户消息或宿主权限配置。已撤销/旧版本不再自动注入；与当前拥有者要求冲突时以当前要求为准，冲突的记忆需明确标注或修改，不能悄悄拼成一致。已经出现于原始历史的旧事实仍是历史事实，界面说明其版本已停用，不承诺模型从此无法在原文中读到它。
- 首版不做独立的自动总结任务或后台记忆清理，Agent 在正常任务中按需维护少量记忆。提供总注入预算、单条大小和查询返回上限；未选入的记忆仍可查询，并记录未注入原因。记忆策略允许拥有者替换，但写入权限、来源记录和修订规则由宿主维持。

### 6. 提供可检查的选择记录并验证

- 每次模型调用保存任务/会话、调用序号、策略及配置版本、模型、指令来源版本、选入/排除的消息 ID、记忆 ID/版本、工具正文片段范围、各项估算与理由。请求发出前保存选择记录，返回后补记实际用量；记录无法落盘时停止并报错。尚未落盘的消息使用宿主临时标识，落盘后关联真实条目；不能假造 JSONL ID。只记录可访问候选的标识，不用排除日志泄漏其他项目的标题或片段。
- 选择记录与消息历史分开，SQLite 保存选择元数据与引用；指令等当次输入已有捕获产物时复用引用。界面提供“本轮上下文”查看、预算组成、排除原因及原文跳转。CLI/TUI 同时增加基础历史搜索和记忆版本管理入口，复用 04 的有界响应与分页，不实现精确重放整个外部环境。
- 选择器、记忆策略及预算配置从拥有者控制的宿主配置加载，校验后在明确的任务/模型调用边界生效并记录版本；项目命令和记忆正文不能改写这些配置。为新增授权、索引、记忆与选择记录提供从现有 SQLite v2 的事务迁移，迁移失败保留原数据并报错。

沿用 `node:test`、mock provider、临时 JSONL 与本地工具，按下列场景验证；同时检查选择函数输出和模型服务实际收到的请求，不能仅凭 provider 没报错判断配对正确。

1. 构造多轮长会话及一次 assistant 调用多个工具的回路，使早期消息退出上下文；验证当前要求、最新工具批次和错误结果仍合法配对，搜索能找回早期暗号及大工具结果尾部，读取原文后模型可引用确切来源。比较已存在历史条目的内容/哈希和产物字节，证明选择与检索没有修改它们。
2. 让必留指令、当前输入、工具参数或图片占满预算，断言 provider 请求数为零、任务中断且会话队列暂停；再注入选择器异常、读取错误与实际 provider overflow，验证没有绕过最终检查、自动摘要、反复请求或重放工具。恢复后的新任务仍能看到原任务要求。
3. 覆盖中文、代码、长工具 schema、多结果合计和思考预算，检查实际请求的系统提示、工具定义与输出配置均已计入；选取记录能解释每条消息的去留。固定输入与配置重复选择应得到相同结果，切换策略不改动权威历史。
4. 在项目 A、B 与同项目不同会话间测试历史搜索、原文、产物、记忆和来源跳转；无授权时连结果计数与片段都不可见，拥有者开放后可读，撤销后后续读取/注入被拒。伪造项目 ID、个人共享范围、完全访问模式或未知 QQ 入口不能扩大资料 API 权限；Agent 不能跨项目写记忆。
5. 创建、修订、并发修改、撤销和恢复记忆，验证来源可追溯、冲突不覆盖、旧版本可查、停用版本不再自动注入。重启与事务故障后当前版本、修订和事件一致；同一操作结果丢失后可核实，不重复写入。不存在或无权访问的来源被拒绝，任务状态更新不会自动产生长期记忆；工具说明明确排除临时进度，不把语义分类宣传成可完全自动保证的校验。
6. 覆盖追加中的 JSONL、未完成尾行、完整行损坏、文件替换/截断、索引重建、旧分支和超大字段；分页和搜索游标不丢失或重复结果，扫描上限触发时如实返回未完成。重建只修改索引；无权限来源不因索引或缓存存在而泄漏。

运行 `npm run typecheck` 和包含新增场景的 `npm test`，复用 04 的历史/重连测试和既有 overflow 测试。模型凭据与 Linux 执行环境可用时，用真实开发任务观察超长会话检索和记忆复用，记录实际 token 用量与估算偏差；缺少环境时明确列出未验证项，不设置模型成功率门槛。

交付为共享资料访问与历史索引、上下文选择和请求检查、记忆修订存储、必要的工具/CLI/TUI 入口、迁移与测试，以及 `docs/runtime.md` 中的数据布局、预算配置、授权和撤销说明。Jev 服务接入、向量检索、记忆自动清理和历史保留期限均留在各自后续范围。
