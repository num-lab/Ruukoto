# GitHub 项目维护

## 目标

由拥有者明确触发 CI 分析或 PR review，在现有任务、历史与权限机制中完成。

## 实施范围

- 接入配置的 GitHub 仓库，读取 GitHub Actions 运行状态、失败步骤及日志，读取 PR 元数据、变更和检查结果。集成时核实官方 API 或现有 CLI 的实际能力，复用适合的入口。
- 记录所分析的提交、运行或 PR 修订，报告提供来源。信息缺失、日志过期或 PR 已变化时明确说明，不能把旧版本分析标为新版本结果。
- 默认交付分析或 review 草稿。拥有者要求发布时，在请求确认模式生成绑定目标与正文的审批；完全访问任务按其显式授权执行。审批期间目标修订发生影响分析的变化时重新核对。
- GitHub 写凭据留在受控执行路径，受限项目命令不能直接取得。自动监听、自动修复、自动合并另行讨论。

## 交付与验证

用记录样例或模拟 API 检查日志归因、差异定位、修订变化和审批；配置实际仓库后完成只读连通性验证。真实评论发布仅在拥有者明确要求且符合当前任务模式时进行。
