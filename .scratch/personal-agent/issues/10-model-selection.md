# 提供方、模型与思考强度切换

## 目标

允许拥有者在 TUI 中切换提供方、模型和思考强度，无需重启后台；界面明确显示当前选择、实际生效配置及生效时机。

## 当前情况

2026-09-21 当前工作区：

- [CLI](../../../src/cli.ts) 仅在启动后台时通过 `--model provider/model` 选择模型，并将 `thinkingLevel` 固定为 `off`。
- [Runtime](../../../src/runtime/runtime.ts) 持有全局模型配置，并在创建会话 Driver 时传入模型和思考强度；Driver 会按会话复用。切换需要同步实际 SDK 会话，不能只更新展示字段。
- [控制协议](../../../src/control/protocol.ts) 和 [TUI](../../../src/tui/app.ts) 已提供这些信息的只读展示，尚无切换入口。
- `package.json` 与本地安装包锁定 pi `0.85.1`。该版本已提供 `ModelRuntime.getModel/checkAuth`、`getSupportedThinkingLevels` 和 `AgentSession.setModel/setThinkingLevel`；思考档位类型包含 `low`、`max`，本项目重复声明的联合类型尚未包含这两项。SDK 会钳制不支持的档位，需要在宿主校验并核对生效结果。

## 实施范围

- 在 TUI 提供可发现的选择入口，列出后台已配置的提供方及其模型，标明当前选择；复用现有命令补全与选择组件。首期按切换已有配置理解，新增提供方配置或录入凭据是否纳入，留待评估。
- 根据所选模型和实际使用的 SDK 能力提供思考强度选项。不支持思考或不支持某一档位时明确提示，不能假设所有模型支持相同档位，也不能静默忽略用户选择。
- 通过已有的拥有者认证控制接口读取选项、提交选择并返回生效结果。后台校验提供方、模型、凭据可用性与思考强度；无效组合拒绝整次变更并保留原配置，调用失败时明确报错，不静默改用其他模型。
- 明确配置作用域、保存方式及生效时机，处理运行中任务、排队任务和继续中断任务的行为。不同会话并行执行时不得串用配置；配置切换不能改变任务权限或触发工具重放。
- 切换后使用实际模型的上下文窗口、输出限制与思考预算组装模型上下文，并验证跨提供方历史消息和工具调用记录的兼容性。沿用 [ADR 0001](../../../docs/adr/0001-preserve-session-history.md)，保留完整会话历史；上下文不足时明确提示，不自动摘要或删除原文。
- TUI 在后台确认后更新显示，区分运行中任务使用的配置与后续任务的选择；重连后从后台恢复真实状态。模型凭据保留在后台，不传入 TUI 或写入日志。

## 工程建议（待评估）

本计划采用以下工程默认方案。它们用于安排实现，尚未实施，也不表示用户已经逐项确认；工单保留 `needs-triage`，便于整体评估。

- 按会话保存选择，新会话继承后台启动默认值；后台重启恢复已保存的选择，配置失效时显示错误并提示重新选择。
- 客户端发送前记录完整选择，后台接收新任务时固定该值。后续切换影响之后新发起的提交，运行中和已排队任务保留原配置；断线前已经准备好的请求仍使用原选择。
- 继续中断任务沿用现有“创建新任务”语义，使用本次提交的选择并明确展示；旧任务、权限模式和审批规则沿用原有语义。
- 首期切换后台启动时已经加载的配置；候选来自显式 `agentDir` 下的提供方配置、凭据和启动参数。新增提供方配置、凭据录入及配置热加载另行评估。

## 实施计划

### 1. 统一模型选择类型和后台目录

在 [领域类型](../../../src/core/types.ts) 增加 `ModelSelection`，只保存 `provider`、`modelId`、`thinkingLevel`。思考档位复用已安装 SDK 导出的类型，替换 Runtime、Driver、会话工厂中的重复联合类型。数据库与客户端均不保存完整 SDK Model、API Key、headers 或 endpoint 配置。

在 `src/agent/model-selection.ts` 放置目录过滤、组合校验和模型解析所需的小函数，复用现有 `ModelRuntime`，由启动默认值、设置接口、任务提交和 Driver 共用。此处无需增加注册框架或另一套配置存储。

- 模型目录以后台加载的 `models.json`、该 `agentDir` 的凭据提供方及显式启动模型为范围，取 SDK 已解析的模型资料。不能直接将内置 `getModels()` 全表当作用户配置，也不能把 `getRegisteredProviderIds()` 当作全部配置提供方；后者仅覆盖扩展注册。
- 候选只输出标识、名称、上下文窗口、输出上限、支持的思考档位及可用状态。凭据检查使用 SDK 的 `checkAuth` 等现有接口；本项目使用 `refreshOnCreate: false`，不能依赖尚未刷新的 `getAvailableSnapshot()` 判定所有模型不可用。
- 用 `getSupportedThinkingLevels(model)` 生成选项并校验完整组合；不支持思考的模型只接受 `off`。切换到不支持原档位的模型时，要求在选择框内选定合法档位后一次提交，不能由后台静默降档。
- 缺少配置、认证材料或模型能力不匹配时返回可辨认的错误码及安全说明；认证材料可用不代表提供方网络、额度或远程权限已验证。目录读取和切换操作不发送计费模型请求。

### 2. 持久化会话选择和任务配置

修改 [数据库](../../../src/core/db.ts) 与 [Store](../../../src/core/store.ts)，沿用 `sessions`、`tasks` 表。会话增加可空的 `model_selection` 和递增的 `model_selection_version`；任务增加可空的 `model_selection`，旧记录以 `null` 表示未记录，新任务必须写入完整值。为新任务保存规范化原始提交参数的不可变摘要，供幂等比较使用；无需再复制一份输入原文。旧任务无法还原的原权限参数不伪造回填，客户端通过 `find_task` 核实并关联。

数据库当前为 v4，迁移到 v5。建新库、v1/v2/v3/v4 升级都要经过补列路径，迁移与版本号同事务提交；保留既有历史、事件和恢复规则。不要只在 v4 路径补列，现有 v1 迁移分支也需要覆盖。

明确旧数据的处理：

- 旧会话在 Runtime 解析启动默认值之后，一次性保存该默认选择及初始版本；已有选择不被启动参数覆盖。
- 旧终态任务保持 `null`，界面显示“模型配置未记录”，不能将升级时的默认值写成历史事实。
- 旧排队任务保持 `null` 并维持暂停。拥有者恢复队列前，界面展示待补配置的任务数和当前选择；`resume_queue` 接受显式确认的完整选择，在同一事务内仅为这些旧任务补齐配置并恢复队列。已有配置的排队任务不改写。无确认参数时返回明确错误，CLI 也展示此要求。配置先经过组合与凭据校验，事务中继续执行原有占用检查；任一步失败不补配置、不恢复队列。补齐结果通过持久事件携带任务标识和选择，按帧大小限制分批，保证其他客户端同步更新。
- 升级后创建的排队任务在后台重启后仍保留原选择，并继续遵守“队列暂停、人工恢复”的现有规则。数据库迁移不能自动启动任务。

会话设置采用版本比较：接口接收 `expected_version`，Store 在事务中校验版本、整组更新并写入 `session.model_selection_changed` 事件；写入失败全部回滚。相同版本、相同值的重复设置直接返回当前状态，避免无意义递增。异步认证检查在事务外完成，写入时重新检查版本。

### 3. 扩展控制协议和完整提交参数

在 [控制服务](../../../src/control/server.ts) 的现有认证调度路径增加 `list_models` 与 `set_session_model`。前者按提供方过滤并有界分页，返回安全字段；后者接收会话标识、完整选择与预期版本，返回保存后的会话选择及版本。目录按需读取，不塞入每次连接快照，遵守现有单帧大小限制。

会话快照携带后续任务的选择与版本，任务快照携带其固定配置。根快照的 `model` 改为含义明确的 `defaultModel`，仅表示后台启动默认值；更新 `session.created`、`task.queued` 事件，保证客户端不经额外查询也能构造完整记录。协议由当前 v4 升到 v5，同步握手、类型和测试数据。

[Runtime.submit/continueTask](../../../src/runtime/runtime.ts) 接收完整 `ModelSelection`。`submit/continue` 的外部调用必须显式传入该值，后台不得从会话当前值补齐丢失字段。会话设置的版本校验用于防止两个客户端覆盖选择；已经携带完整选择的任务提交不因会话版本后来变化而改用新值或被拒绝，这样断线前的请求仍可按原配置重试。

幂等处理按以下顺序实现：

1. 校验请求结构和身份后，先按 `(session_id, request_id)` 查找已接收任务；比较原输入、提交权限参数、授权路径、继续来源和模型选择，同参返回原任务，异参返回 `request_conflict`。幂等比较所用的提交参数应保持不可变，不能因任务之后切换访问模式而改变。
2. 仅对尚未接收的新任务校验模型、凭据和执行入口，在任务入队事务中保存配置并追加事件。配置或凭据后来失效，不应妨碍核实已经存在的同参任务。
3. 并发提交经过异步校验后，仍由入队事务中的唯一键与同参判断仲裁；不得在事务外查空之后直接插入。

`checkAuth` 是异步接口；据此将 `submit/continueTask` 及相关调用链改为显式等待，包含控制服务、内部调用和测试。数据库事务回调保持同步，模型检查不能跨越事务等待；返回成功必须发生在任务与事件提交之后。

复用 [SubmissionGuard](../../../src/control/submission.ts) 保存完整参数并进行重连核实，补齐相关路径：

- TUI 的 `submit` 与 `continue` 都在发送前保存模型选择和 `session_id`；继续任务同时保存 `task_id`。当前继续路径缺少 `session_id`，与 `find_task` 的核实参数不匹配，需要一并补齐。
- 已接收但应答丢失时，关联原任务；明确未接收时，用原键和原选择重发。后台明确拒绝且没有接收任务时，清理该待确认记录并恢复输入、显示错误；超时、断线及接收结果不明时继续保留待核实，不能把所有服务端错误都当作应答丢失。
- 对升级前缺少模型字段的 pending 记录，查到任务后可关联；明确未接收时保留原文、要求拥有者重新选择后提交，不能自动补入当前模型。旧 `continue` 记录缺少会话标识时，先用源任务查出所属会话，再核实；源任务不可读则保留记录并说明原因。
- 检查所有提交调用方，包括 CLI 和 `githubPublish` 创建审计任务的内部调用。内部调用沿用当前会话选择并保存；CLI 手工复用请求键时先核实已有任务，不能重新读取当前默认值覆盖旧请求。CLI 对结果不明的请求提示核实，不加入自动换键重试。

### 4. 在任务开始时应用配置，并同步预算

保留按会话复用的 [Driver](../../../src/agent/driver.ts) 和 SDK 会话。首次执行使用任务固定配置创建 SDK；后续任务在 `runInner(task)` 中、`sdk.prompt` 之前解析该任务的模型，按需调用 `setModel`，随后明确调用 `setThinkingLevel`，最后核对实际模型标识和档位。即使 `setModel` 自动带入 SDK 默认档位，也必须以任务记录为准。

切换会话的后续选择只写会话记录，不操作正在执行任务的 Driver；每个任务开始时应用一次，工具循环中保持不变。继续使用原 `piSessionId/sessionFile`、工具注册和流函数包装，复用 SDK 对跨模型消息的转换；JSONL 中的模型变更条目记录实际应用时机。

模型解析、认证、SDK 设置或核对失败要进入现有失败终结与清理路径，确保任务不滞留 `running`、目录占用被释放。不要把可失败逻辑直接放到调度器异常捕获之外的 `getDriver` 调用处。已经失效的任务配置不得回退到会话新选择；其他任务按各自配置执行。

同步修改三处仍依赖初始化模型的逻辑：`budgetConfig()`、溢出判断的 `contextWindow`、`finalCheckBeforeSend()`。它们统一使用本任务实际生效的模型与输出/思考参数；发送前还要核对模型、思考档位与任务记录一致，不一致时阻止请求并说明原因。

思考档位只表达强度，不能统一套用一张未经适配器验证的 token 表。计划按 pi `0.85.1` 实际适配器的输出上限语义核算预留：已包含在总输出上限内的思考不重复扣除，额外占用上下文的思考预算才追加；使用的请求参数与预算估算必须一致。本地 SDK 的 `simple-options.js`、`anthropic-messages.js` 及 `openai-completions.js` 已有将思考预算限制在响应上限内的路径，这些路径按完整响应上限预留即可，不能再次加同一份思考预算。将这项规则放在共享模型解析逻辑中，并保留现有校准和测试覆盖能力。若某个配置缺少可靠的窗口或预留依据，应在发送前明确失败。

上下文选择与最终检查继续成对执行；记录中保存实际模型及可追溯的任务选择。验证跨提供方切换后的思考块、工具调用与结果配对，以及更小窗口下的中断/暂停行为；完整会话历史继续保留，不通过重建历史解决兼容问题。

### 5. 接入 TUI 和 CLI

在 [TUI](../../../src/tui/app.ts) 增加 `/model` 和 `/thinking`，复用已有的命令补全、`SelectList`、`OverlayBox` 与焦点恢复。`/model` 列表显示“提供方 · 模型名（ID）”，跨提供方选择模型即完成提供方切换；选定模型和合法档位后提交完整组合。`/thinking` 仅展示当前模型支持的档位。Esc 取消不提交，列表名称沿用现有终端控制序列清理。

选择框提交期间显示等待状态，后台确认后才更新已生效选择。异步响应绑定打开时的会话标识，不能写入后来切换到的会话；设置版本冲突时刷新并提示，响应丢失时查询当前会话状态，不自动重发设置覆盖另一个客户端的修改。

[ViewState](../../../src/tui/state.ts) 按会话保存选择及版本；更新事件和应答仅在版本不旧于本地状态时应用。延续现有“快照确定当前状态、replay 补记录、live 更新状态”的纪律，防止重放旧事件回滚配置。状态栏显示后续任务选择，活动任务同时显示正在使用的配置，排队任务和继续任务详情也可查看各自选择。

CLI 复用同一控制接口提供最小的 `models`、`set-model` 操作，并让 `submit/continue` 传入完整选择。启动参数增加 `--thinking`，使用同一能力校验；`--model provider/model` 只按第一个斜杠拆分，保留模型 ID 中余下的斜杠。同步帮助和 [运行文档](../../../docs/runtime.md) 中的默认值、生效时机、队列恢复及错误处理说明。

### 6. 按端到端行为验证

扩展现有 mock 模型配置，覆盖两个提供方、同提供方多个模型、推理与非推理模型，记录实际请求的模型标识及思考参数。优先在一份 `test/18-model-selection.test.ts` 中覆盖完整切换流程；只在已有测试中补对应边界，不逐个函数复制测试。

- 目录、切换与执行：跨提供方/模型/档位切换后无需重启，实际请求匹配选择；不支持档位、缺凭据、未知模型和未认证修改被拒绝，原选择保持不变，响应与错误不泄露凭据。
- 任务与持久化：同会话先排队 A 再选 B，A 仍用原配置，新提交用 B；不同会话并行互不影响。重启恢复选择，排队任务仍暂停；旧库各版本迁移、旧任务未记录状态、旧队列显式补配置和写入失败回滚符合上述规则。
- 幂等与重连：在 `02-idempotency-reconnect`、`12-reconnect-pending` 中覆盖已接收和未接收两个丢应答窗口，中间切换会话选择；检查 `submit`、`continue`、同键异参、旧 pending 记录和明确拒绝后的输入恢复。
- SDK 与上下文：检查思考档位未被静默钳制、请求输出限制与预算一致、较小窗口的发送前阻断，以及带工具调用/结果和思考内容的历史跨模型继续；SDK 设置失败后占用释放。
- TUI 与多客户端：在 `13-tui-state`、`14-tui-app` 中检查选择框、取消、设置失败、较旧响应、版本冲突、跨会话异步返回和 replay 不回滚。使用现有 PTY 检查选择结束后的焦点与退出；真实终端确认窄窗口仍能辨认提供方、模型和档位。

先运行 `npm run typecheck` 与新增/受影响测试，再执行一次 `npm test` 检查协议和迁移影响。全部通过且没有新改动时结束验证；真实模型测试按下方授权范围执行，不能用模拟结果代替真实连通性结论。

## 交付与验证

交付切换入口、后台接口及必要持久化、帮助与使用文档。复用现有 mock provider、控制协议和 TUI 测试设施，验证：

- 切换提供方、同一提供方下的模型及思考强度后，实际模型请求与界面显示一致，后台无需重启。
- 不存在的模型、缺失凭据和不支持的思考强度得到明确错误，原选择保持不变。
- 运行中、排队及继续任务遵守确认后的生效规则，两个并行会话互不影响；提交应答丢失后的核实与重试不会改变原任务配置或重复创建任务。
- TUI 断开重连、后台重启和多个客户端连接后显示一致，未经认证的请求无法修改配置。
- 切换到较小上下文窗口或不同思考预算时，预算检查使用新配置，历史原文完整保留。

实施后运行相关测试与 `npm run typecheck`；真实模型连通性测试仅在已配置且获准使用的提供方上执行，分别记录模拟验证与真实验证结果。
