# 添加 `/prompt` 命令，查看模型请求列表与 prompt 详情

## 目标

在 TUI 输入 `/prompt` 后打开当前会话的模型请求列表悬浮层，选择一条请求后显示该次请求的 prompt 详情，便于检查每次模型调用使用了哪些输入内容。

## 当前情况

2026-09-22 当前工作区：

- [TUI](../../../src/tui/app.ts) 已有 `/context`，只查询最近一次上下文选择记录并展示预算、选入消息数量和排除原因；已有选择列表、悬浮层与长正文查看能力可复用。
- [SelectionRecord](../../../src/core/types.ts) 保存任务、会话、调用序号、模型、消息索引和预算等元数据，没有完整的 system prompt、消息正文与工具定义，无法仅凭现有记录准确还原某次请求的完整输入。
- [Driver](../../../src/agent/driver.ts) 在委托 SDK 发送函数前校验 `systemPrompt/messages/tools` 并保存选择记录，可以在这一调用边界关联请求输入快照。会话历史与模型上下文分别管理，沿用 [ADR 0001](../../../docs/adr/0001-preserve-session-history.md)。

## 实施范围

- 增加无参数 `/prompt` 命令及补全、帮助说明。默认列出当前会话各任务的模型调用，按时间从新到旧展示；一项对应一次模型调用，同一任务中的多轮调用分别列出。
- 列表展示时间、任务标识、任务内调用序号和提供方/模型，使用稳定的请求记录标识选择。支持键盘选择、翻页和 Esc 关闭；无当前会话、空列表及读取失败时给出明确提示。
- 选择后在详情悬浮层显示该次调用的 system prompt、按顺序排列的消息角色与正文、工具调用及结果、工具定义。项目指令、长期记忆和经过截取的工具结果按当时进入模型上下文的内容展示；另显示模型、思考强度及关联调用元数据。
- 详情支持滚动和分段加载长正文，返回列表时保留位置，关闭后恢复编辑器焦点和草稿。切换会话、关闭悬浮层或重新连接后，旧异步响应不能覆盖新的视图。
- 为新请求保存调用时的不可变输入快照，关联现有选择记录、任务和会话；后台重启后仍可查看。优先复用现有产物存储和有界读取能力，不从查看时的历史、记忆或配置重新拼接并声称是原始 prompt。
- 本工单以交给 SDK 提供方发送函数的 `systemPrompt/messages/tools` 为 prompt 范围，详情注明捕获位置；它不等同于经过提供方适配器转换后的 HTTP 请求体。图片等非文本内容显示类型、可读取引用及可用元数据，不把二进制编码当正文刷屏；未捕获内容明确标注。
- 旧调用若只有选择摘要，仍可列出，但详情明确显示“该次 prompt 正文未记录”，不得生成或猜测原文。记录发生在发送前时不能直接声称远端已收到；失败、中断或发送结果不明的请求保留可获得的输入，并如实标注已知状态。
- 列表和详情通过现有拥有者认证控制通道读取，后台校验记录与会话归属，列表分页、正文分段并遵守协议帧限制。读取失败或快照缺失给出明确错误，不能触发重新发送模型请求。
- 仅捕获明确列出的输入和元数据，不序列化整个 SDK 配置、请求 options、认证头或凭据。prompt 本身可能含工作区资料，快照沿用受保护的后台存储和访问边界，不写入普通日志；展示时清理终端控制序列，保存的正文保持原值。

## 验收标准

- `/prompt` 打开当前会话请求列表；同一任务连续两次模型调用可分别选择，详情准确对应各自的 system prompt、消息顺序、工具定义与调用参数。
- 使用可控 mock 请求核对捕获边界的输入内容；后续修改项目指令、记忆或切换模型后，先前请求的详情保持不变。
- 长 prompt 可以完整分段查看，无静默截断、中文乱码或单帧超限；旧记录、非文本内容、缺失快照、失败和中断状态如实显示。
- 查看、返回列表和关闭悬浮层均不提交任务、不调用模型、不改变当前运行任务；草稿及焦点恢复正常，跨会话异步返回不串用内容。
- 后台重启后记录仍可查询；未认证请求、错误会话归属和任意路径读取被拒绝，返回内容不包含请求认证材料。
- 复用现有 mock provider 和 TUI 测试设施验证以上行为，运行 `npm run typecheck` 及受影响测试。
