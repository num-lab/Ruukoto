# 支持普通 MCP 写工具与统一审批

## 已确认范围

本工单由 Q9、Q18 拆出，作为只读 MCP 接入后的后续能力，不阻塞 Issue 17 删除旧 GitHub 模块。GitHub 与其他 MCP 服务走同一执行路径，不设置专用发布意图、仓库适配层或草稿状态机。

- 有副作用或无法确定副作用的工具在 confirm 模式逐次审批；full_access 可跳过逐次审批，仍须满足服务启用、工具允许列表及凭据范围。
- auto-review 已实现时走同一审批桥，遵守 Issue 15 已确认策略；本工单不自行扩大其自动批准范围。
- 远端只读注解不是授权。批准绑定任务、服务、工具、具体不可变参数、权限及配置版本；修改参数或撤销权限后旧批准失效。
- 复用公共审批记录和单次消费；发送前登记执行开始，结果不明使用 effect_unknown，不因超时、重连或重启自动重发。
- 首批不指定真实写工具；先实现通用审批、单次消费、取消和 `effect_unknown` 框架，并使用模拟服务验证。本轮不启用真实写入。
- 未来首次启用的写工具必须使用按服务、项目和操作类别独立绑定的凭据；禁止复用 Tavily、旧 GitHub 或无 scope 的通用凭据。

## 后续实施与验收

在通用 MCP 入口接入 Driver.awaitApproval、Store.consumeApproval 和工具结果记录；补齐通用审批详情。使用两个不同服务的模拟工具验证人工批准、拒绝、模式切换、取消、配置撤销、重复响应、断线及崩溃；断言批准最多发送一次，拒绝零次，效果不明不重发。运行类型检查和受影响测试。真实写操作须由拥有者明确指定目标及范围后验证。

## 实施计划

计划日期：2026-09-22。依赖 [16：MCP 支持](16-mcp-github.md) 的只读客户端和工具装配；不恢复 GitHub 专用发布意图、仓库适配器或草稿状态机。

### 1. 固定通用操作与审批数据

- 在 `src/core/types.ts` 为普通 MCP 操作定义统一审批范围，至少包含服务 ID、服务配置版本、远端工具名、工具定义版本、规范化参数摘要、凭据引用名称及操作类别；凭据值不得进入事件或审批视图。
- 复用现有 `ConfirmationRequest`、`tool_ops`、权限版本和 `Store.consumeApproval()`。只有确有持久化缺口时才迁移 SQLite；不要为每个 MCP 服务新增表或分支。批准绑定任务、会话、服务、工具和不可变参数，任何版本或参数变化都必须重新申请。
- 将 `readOnly` 等远端注解视为不可信输入。由拥有者的工具允许列表和本地副作用策略决定是否需要审批；副作用不明时默认需要审批，未允许的工具直接拒绝。

### 2. 接入统一工具路由

- 在 `src/agent/mcp/` 复用 Issue 16 客户端，增加工具定义到宿主 `ToolDefinition` 的适配。动态工具使用稳定命名空间，发现结果与任务的服务配置/工具清单版本绑定。
- 在 `src/agent/driver.ts` 的 `ensureSdk()` 和任务边界装配 MCP 工具；每个调用通过 task/session 上下文取得项目、服务和权限，不使用可被并发调用覆盖的全局上下文。未知工具不能落入 mock `confirmTools` 分支。
- 在 `src/agent/tool-router.ts` 统一处理 MCP 调用：先记录宿主操作意图，再按模式执行。`confirm` 和副作用不明操作进入 `awaitApproval()`；批准后在真正发送前用 `Store.consumeApproval()` 原子消费；`full_access` 仍须通过服务、工具和凭据范围校验；`auto-review` 复用同一审批桥，不扩大自动批准范围。
- 调用参数必须来自已批准的不可变快照；工具返回文本、结构化数据和产物沿用现有有界捕获、归属校验及事件记录。不要让远端工具自行选择目标服务、凭据或新的工具。

### 3. 固定凭据和配置撤销语义

- 首次启用真实写工具时，使用按服务、项目和操作类别独立绑定的 `CredentialStore` scope；传输层额外核对目标 host，禁止复用 Tavily、旧 GitHub 或无 scope 的通用凭据。
- 调用前及批准消费前重新读取服务配置、工具允许列表、凭据绑定和权限版本。服务禁用、凭据撤销、工具定义变化或任务模式切换会使旧审批失效；已在发送后的调用不因配置变化被伪装成未执行。
- 写调用的超时、取消、断线或后台重启遵循现有 `effect_unknown` 规则：未消费批准的操作记录已知未执行，已消费或结果无法确认的操作记录未知效果；重连和重复控制请求不得自动重发。

### 4. 提供模拟服务与最小测试

- 增加本地模拟 MCP 服务/测试注入，至少包含两个服务的同名工具、一个有副作用工具和一个副作用未知工具；不依赖真实 GitHub 或网络写入。
- 扩展审批和生命周期测试：人工批准执行一次、拒绝执行零次、重复响应只有一次成功；参数/工具定义/配置版本变化使旧批准失效；`full_access` 跳过逐次确认但不越过服务范围；`auto-review` 失败转人工；取消、切换模式、断线、崩溃和迟到结果不重发。
- 验证工具结果、凭据引用和审批详情均不泄漏秘密，历史工具配对和产物归属正确；跨项目、未启用服务和未允许工具在网络请求前被拒绝。
- 运行 `npm run typecheck`、新增 MCP/审批测试及 `npm test`。真实写操作仅在拥有者明确指定服务、目标和凭据范围后进行一次单独验收。
