# 个人 Agent 原生受限执行：已确认规格

决策日期：2026-10-12。拥有者通过 grill-me / grilling 确认 Q1—Q5；实现与隔离验收完成。取舍归[决策记录](../../.agents/notes/implemented/architecture/2026-10-12-personal-native-sandbox.md)，实施顺序与验证归[工单 01](issues/01-personal-native-sandbox.md)。

## 目标与范围

将 ruukoto 的任务工具执行从 Docker 迁到与 ruukoto-code 共用的原生沙盒，同时移除已无正式使用者的 Docker worker 路径。个人产品继续面向 Linux 服务器；本次不扩大其平台承诺，也不迁移其他软件的容器部署。

| 项目 | 确认的交付要求 |
| --- | --- |
| 正式入口 | ruukoto 的 CLI、server 与开发入口默认且只接受 native 作为受限执行后端；ruukoto-code 沿用相同约束 |
| 旧配置 | 显式 container/local 参数和环境覆盖报迁移指引，不自动转换；缺原生能力明确拒绝受限执行 |
| 原生实现 | 复用现有 WorkerLauncher、Linux bubblewrap、namespace、seccomp 与 user scope/cgroup，使用宿主工具链 |
| 执行链 | 覆盖普通开发任务、main 与独立定时会话委派的 SubAgent、worktree 创建及汇总；请求确认、自动审查与计划模式共用受限边界 |
| 常驻部署 | 优先保留系统级 backend service，补齐运行账户的 user manager、开机与退出登录存活、bus 环境和 cgroup 委派；先验证后切换默认 |
| 旧路径清理 | 删除 Docker worker 启动器、专用配置及类型、镜像构建和失效验证入口；迁移仍有价值的场景用例，保留历史证据 |
| 临时资料 | 沿用原生独立 HOME/TMPDIR，不新增资源配额；停止未核实保留临时现场及目录占用 |
| 升级 | 先停止旧后台并核实旧 worker，再切换代码和配置；保留历史、审批、产物、工作副本及异常占用，不在线替换活动任务的环境 |

main 与独立定时会话的业务工具仍由宿主执行，只有其委派出的编码工具进入 worker。服务管理 helper、资料 API、通知和审批继续遵循既有身份与授权规则；不因后端迁移为 main 增加 bash。完全访问沿用启动后台账户的现行语义，库层 local 继续用于完全访问与离线测试。

## 安全与兼容要求

- 工作区、授予和只读根沿用真实路径、dev/ino、保护根与硬链接核实；共享 Git 目录对子任务只读，宿主不直接执行不可信仓库的 Git。
- 默认无网络、最小环境、继承 FD 与控制面隔离继续有效。user bus 仅供可信 launcher 管理 scope，不能传入受限 worker；宿主工具的依赖缺失不得以开放整个 HOME 或源码根兜底。
- 平台启动失败经现有 ExecutionError 报告；启动后失败保留执行单元身份。只有核实整个执行单元停止才释放占用并清理临时资料，停止未知不得启动替代环境。
- 后台异常沿用任务中断、队列暂停与效果未知不重放规则；无法核实旧执行停止时继续保留占用。后台系统单元的 KillMode 不能作为 user scope 后代已退出的证据。
- 原 Docker `/tmp` 的 64 MiB 上限不保留，原生临时资料使用宿主磁盘。现有两个后端都没有应用显式设置的 CPU、内存、PID 或工作区容量配额，本次不新增配额策略。
- 删除的是仓库中的 Docker worker 路径，不自动卸载服务器 Docker、删除其他容器或修改既有组成员；旧 worker 的核实和清理必须按实例识别。

## 完成条件

在 Docker 不可用的 Linux 环境中，通过实际服务账户、正式个人产品入口完成受限工具、委派、worktree、审批、取消和恢复验证；覆盖开机后无交互登录及退出登录后的常驻运行。共享代码还需通过 ruukoto-code 回归，具体清单由工单持有。

真实 OS/worker 证据与模型、IM、服务工具替身分别记录。缺少平台、凭据或隔离演练条件时记为不可用，不能用已有交互式原生报告或模拟结果替代本次常驻验收。当前已有的 Linux 原生实测基线是 Ubuntu 24.04 x64；其他平台按实际结果说明范围。

工单交付包含代码迁移、独立账户与可销毁 VM 的隔离部署验证和迁移说明；生产实例的实际切换另行安排。

## Comments

### 2026-10-12：规格访谈

- Q1：仅替换任务执行后端，其他软件的 Docker 部署不在范围。
- Q2：native 为唯一正式受限后端，旧配置报错，缺能力不回退。
- Q3：同时清理 Docker worker、镜像及专用配置，将有价值的场景测试迁到 native。
- Q4：沿用原生临时目录，不加配额，接受取消原容器 64 MiB 临时空间上限。
- Q5：确认完整规格、优先保留系统级后台服务并补齐 user manager 前置、四阶段计划，以及本次仅建立规划文件。工单可交给代理实施。
