# IO 与 Search 独立复核

独立于 IO/Search 作者，直接读取工单 29、规格、源码、调用方、相关旧批准执行器与测试；按单拥有者个人后台负载判断。此复核不覆盖本人编写的产物存储与 CLI/TG 叶模块，它们由其他上下文审查。

IO 的新文件创建通过已核实 Linux 目录句柄定位，祖先被替换也不能转向保护目录；Mac 对新建明确拒绝。既有文件沿原身份与原文哈希执行，短写循环及零字节写入保留未知；HTTP 固定审批前地址，不跟随跳转、不自动重试，凭据逐次核实，回显与截界前缀不进入证据。共享截短开始后的异常最终已归为未知，Linux 新窄例通过。

发现并修正的阻断是读取 open 的 FIFO 竞态：初始 lstat 后把普通文件换成 FIFO，缺少 O_NONBLOCK 会阻塞整个宿主。修复在个人 prepare/read 与共享批准执行器加入非阻塞打开和普通文件核实。独立子进程使用真实 mkfifo；恢复旧打开旗标的反例在两个入口均超时，修复后立即拒绝，见 review/ 下的原探针、前后 JSON 与 bundle。新增 `test/personal-tool-fifo.test.ts` 的三个入口在 Mac 和真实 Linux 均通过。

Search 的纯传输不加载旧工具装配，旧包装保留凭据范围与调用契约；完整脱敏原响应先于字段截断返回，超限、畸形与中断均保留有界片段并标 partial；明文、JSON 转义与 URL 编码秘密在截界处的前缀也被清理。逐条复核对应源码与新增反例，未发现未解决阻断。

亲跑本机 IO/Search 24 项通过；Linux 首轮 27 项与共享截短修复后的最终 28 项均通过，最终结果取后者，不相加。没有连接真实模型、IM 或 Tavily 服务。
