## 方案

- 模型工具只装入主会话，来源和稳定请求键由宿主从工具 Task、当前 run 和唯一原生拥有者 input 解析；模型不能传来源、权限或请求键。Harness 显式使用 one-at-a-time 队列设置，仍对多来源、回报来源、失活工具执行硬拒绝。Telegram 来源必须有原收件权限快照及有效绑定；委派保存原模式/版本，长期上下文不提供权限。原来源存在未知服务操作时拒绝换工作重试。
- 复用现有 `personalWork` 登记、指纹、长期独立子会话、background Task、单工作占用、取消及停止核实。模型可以列身份/当前工作、委派新工作或复用空闲身份、分页查询指定工作原 Submission 的结果、取消工作、关闭空闲身份。工具调用不等待后台模型，结果尚未就绪时结束本轮；子会话不获得工作管理工具，不创建下一层或联系拥有者。
- 本片通过工作查询返回原 Submission 的有界结果，不自动唤醒或外发；主 Agent 在当前拥有者请求中可查询并回答。固定最终回报涉及同一原输入多项子工作的汇总及取消竞争，由下一切片处理，不把子结果直接发送当作整项最终报告。
- 启动时在恢复前验证新工作来源和工具/Task/工作关系、版本、原绑定；旧程序因主会话的新扩展标记拒绝新档案。旧档案首次启用模型工具须无未决输入/任务，拒绝不固化新扩展或授权。已有旧工作及空工具子会话继续按原契约恢复。
- 改动面为个人 Harness、work、工作工具、Telegram 来源与服务未知检查、相关窄测试；不改共享包、Pi 版本、旧 Coding 装配或 helper。按实际变化同步 personal-durable/products/usage、已有工作笔记与新增决定、总工单和检查导航。
