# 个人 durable 后台分析的 IM 与 CLI 控制

Status: ready-for-human

## 目标与边界

接续[总工单](01-migration-plan.md)与[模型后台分析](10-model-background-work.md)，按[规格](../spec.md)的配置与运维要求，为已有单项后台分析提供可信宿主查询、原结果分页、取消与关闭空闲身份。拥有者本轮接手指令及总方案授权覆盖本片；追加说明、整项工作归属与原入口固定最终汇报继续由总工单推进，不把单项控制记作整项委托已完成。子会话保持空工具，正式入口和部署不变。

## 方案

- 在 `personal-work.ts` 共用原生工作引用、状态、停止证明、历史列表与原 Submission 回答读取；模型工具沿用既有输出。结果固定原工作，不随身份复用变化。列表/正文有界分页，内部引用由程序携带。
- 已认证本机接口添加后台分析查询、取消和关闭操作，CLI 以名称、说明与状态选择，不要求输入内部键。取消只提交原工作取消事实并立即应答；丢失应答后查询原工作。关闭同时核实菜单原工作仍为该身份最新工作、没有占用，避免旧选择作用于复用后的身份。
- Telegram 新增 `/工作` 和专用菜单动作，复用已发送原宿主菜单、原收件事务和固定发送任务；仅查询/控制 bot、owner、generation 全部相同的原工作。转发、引用摘录、伪造/未送达菜单不改变工作。控制消息不进入模型，发送未知不重发。动作与服务菜单的“下一项”分开。
- WorkTask 在等待原 Submission 时观察持久取消事实；取消沿现有停止子会话及后台执行、原子释放占用并收尾路径完成，不另建队列或控制状态机。只有正常终态且原占用已释放才显示停止已核实；faulted 保留占用。取消与完成竞争后仍复查取消事实；重启仍读原取消记录。
- 新 `personal-work-controls` 扩展标记阻止旧程序误读新宿主菜单；恢复前核实工作菜单引用与原入口。控制功能不改变旧 Task 输入/checkpoint，首次启用不额外要求清空已有工作。
- 文档落点：personal-durable/products/usage、既有工作笔记、[控制决定](../../../.agents/notes/implemented/architecture/2026-10-17-personal-work-controls.md)、总工单与检查导航。无共享包、依赖、helper 或 Coding 调用变化。
