# durable 服务检查的执行归属与恢复

Status: resolved

## 目标与边界

接续[总工单](01-migration-plan.md)及[检查身份协议](16-inspection-identity.md)，按[规格](../spec.md)的停止核实要求，将 `inspect-op` / `stop-inspect` 接入现有两处 durable 消费者。拥有者本轮接手指示授权范围内继续实施；不开放子工具，不切换正式入口或部署。

## 方案

- 共用 app 内检查实现；不新建 Task 状态机。现有工具 Task 或服务 Task 作为稳定归属，session family document 保存原 Task、会话、来源 Submission、原机器、尝试 ID、接纳 entry 与结果证据；另有 session 索引只保存未核实退出的 Task。工具来源使用原 generation 的完整输入集合，不取最新输入，也不新增唯一拥有者输入限制。
- 机器参数从宿主策略读取；helper 独立核对本机。任何 spawn 前同 commit 登记身份与占用；接纳/证据写失败不得继续。正常完成也须核实原 ID 退出；可信结果与停止证明齐全才能返回状态。已存结果且已停则复用原观察，缺结果时核实旧 ID 后才建立新尝试；旧 helper、错机器/ID/目标及畸形应答不形成停止证明，不回退 inspect。
- 取消使用独立有界信号核实原 ID，不能沿已取消信号跳过检查。记录通过 Harness 持有，不依赖已被取消的 tool invocation commit。终态/faulted 不清未核实索引。新检查及 restart 请求在同事务检查同目标或来源占用；主聊天、独立来源/目标继续。宿主可列出未决检查并重核停止；启动恢复前对全部记录做版本与双向关系核实，并对未决原 ID 做一次有界核实。
- 每次 runner invocation 最多派发一次 inspect-op。所有异步 inspect/stop 结果提交均比较原 inspectionId、machineId 与接纳 entry；迟到旧结果只保存证据，不更改新尝试或索引。宿主 stop 先手不能使原 invocation 换新 ID 再启动。
- 服务 prepare 与 abort 共用记录；未消费但检查未停时仍保留服务来源/目标占用。停止未核实返回明确结果，不能假报已安全取消或消费批准。共享传输与旧个人/Coding 的原 inspect/restart 协议保持。
- 服务配置 document 升版，拒绝无身份旧记录；新检查扩展使旧程序拒绝新档案。同步 Harness、停机配置检查、fake helper、相关断言、个人模块/工具说明与决策笔记；不增加依赖、命令或通用执行框架。

## 验收与证据

- 登记失败零 spawn；登记后到 spawn 前崩溃可被 stop 先手阻止；结果提交失败仍保留原占用。
- 真实后台 SIGKILL 后原 helper 仍活时不换 ID，重启、终态和新请求均不能绕过；原执行退出后才允许新观察。错 ID/机器/目标、旧 helper 不释放。
- 工具取消与服务 prepare 取消均核实原检查；未核实不释放，独立聊天与目标继续；覆盖可信结果提交到工具 settle 的恢复窗口。
- 精确覆盖迟到 I1 stop 应答在 I2 登记后返回，不得清 I2 占用或覆盖其结果。
- macOS 定向个人回归及静态/构建；Linux 隔离副本运行相同集合和真实进程恢复探针，区分命令桩与真实 systemd。独立方案审查后实施，独立实现审查无阻断后记工程通过。
- 报告等待与暂停证明区分服务操作键及检查 Task/接纳，核实停止后自动继续汇总；新增 admission 前及 HTTP 前暂停跨重启用例，历史服务暂停保持。
- 产品验收：本片可信宿主接口和模型失败指引不代替总工单真实模型/IM及拥有者体验，完整产品验收继续待验。
