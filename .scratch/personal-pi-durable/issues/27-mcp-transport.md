# MCP 传输脱离旧项目与凭据装配

Status: resolved

## 目标与边界

接续[总工单](01-migration-plan.md)和[规格](../spec.md)阶段 2、A1/A7/A9，拆出两个产品可以复用的 MCP HTTP 传输。现有公开接口要求旧 McpServiceConfig 与 CredentialStore，个人端直接调用需要伪造旧项目与配置；只复用无任务状态的底层实现，沿用已经确认的端点、范围、凭据和取消语义。本片不开放个人 MCP 工具，不接 durable 工作、审批、持久回执或配置，不启用 stdio，不切正式入口或部署。

## 方案

- 新建 `packages/agent/src/mcp/transport.ts`，移动现有 SDK 连接、发现、调用、错误分类与端点校验。连接仅接收具名端点对象（服务标识、endpoint）、超时和每次请求新鲜调用的 token resolver，不暴露自定义 fetch、headers、requestInit 或 OAuth。该模块不导入旧 core、Pi、McpStore 或 CredentialStore。
- `client.ts` 保留 `connectMcpService` 和旧 options，按原 projectId/mcp scope 与 host 核实凭据后委托新连接函数；重导出原符号，现有 Runtime、工具计划及路由器无需改调用。旧凭据校验、Bearer 注入、端点钉源、超时、分页、结果与错误码保持。新增 resolver 的普通异常或空 token 在网络前转成无秘密的 auth_failed；旧已分类 McpError 保留。只有未配置 resolver 才允许匿名，已配置后失效不能降级匿名；用例分别验证初始化和后续请求的零外调。
- 不扩展 HTTP 取消承诺：close、超时和取消只结束本地等待，不证明远端停止；已发调用不自动重发。远端完整应答、效果核实与停止证据应由下一片持久消费者分别处理，不能拿 LinuxExecutionRef 或 HTTP 关闭当远端证明。
- 恢复既有 16 页限额：锁定 SDK 的无 cursor listTools 会自行汇总，原手写分页循环实际未限到 16 页。使用 SDK 的 listMaxPages 固定为 MCP_LIMITS.maxListPages，删除重复分页循环，汇总后保留工具总数上限；ListPaginationExceeded 转为既有 too_many_pages。补 16 页接受、17 页只请求前 16 页后拒绝及 65 工具拒绝的窄用例。本项补充经过独立方案审查、实施与增量终审，旧实现审查在其余范围继续有效。
- 新窄用例直接走共享传输和真实回环 HTTP，覆盖匿名/认证连接、分页发现、钉版调用/isError/协议错误、逐请求凭据撤销或替换、resolver 异常脱敏、端点/重定向拒绝、超时/断线/取消不重发。保留并运行旧 `24-mcp`、`25-mcp-write` 与产品入口回归，运行构建、静态及 diff 检查。没有 OS 原生改动，不将本地 HTTP 替身计为真实 MCP 服务或 Linux 停止证据。
- 同步 MCP 原决定与 agent-tools 模块说明；不新增命令、依赖或配置，不引入平行运行状态机。记录实际检查、内容快照及独立实现审查。
