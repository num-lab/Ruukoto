- 复用 `packages/channels/src/scheduler/time.ts` 的时间计算，计划、版本、运行接纳和固定汇报目标用 durable documents/Tasks；计划/版本/原定时刻稳定去重，不复制另一份执行状态。

1. 新增个人调度 records 与执行扩展。计划保存不可变版本、时间规则、说明、创建来源、模式、工具/资料上限和可为空的固定 IM 目标；修改采用取消后重建。计划、版本和原定时刻形成稳定运行键，接纳独立 ownerless Conversation、运行 Task 与反链证据同 commit；durable Task/Submission 是执行权威。时间计算只复用 `scheduler/time.ts`，不引入旧 Store/Runtime/outbox。
2. 新增明确区分拥有者输入与定时运行的来源解析。定时输入使用自己的持久 entry 和 Submission，不创建 ROOT `pi.user`。共享解析供主/定时工具、子工作、服务/命令/MCP/通用工具/浏览器的执行与恢复核实使用；全局诊断 entry 和控制 Task 可继续留在 ROOT。模型发出前同时核实运行活动、取消、创建授权、原入口和整项未知暂停。
3. 定时上下文使用自身工具和业务说明，不复制主聊天。子工作沿运行来源和创建上限收窄，长期身份的历史工具/授权及 Harness 重启装配不能扩大本次范围。定时可安排和查询本轮子工作，宿主自动封组收尾；首次回答不是完成。最终汇总仍在独立定时会话，只有查询资格，不能从汇总输入取得新写入/委派授权。
4. 创建时工具与资料范围是上限，执行前继续核实当前配置、对象、撤销和凭据。新增工具/资料不能自动进入旧计划；配置或来源无法核实则保留可查询失败/暂停事实。审批目标不等于拥有者操作来源：定时及其子工作不匹配、创建或扩大长期服务授权，只能在原入口逐次批准具体操作。默认模式变化不改写计划。
5. 每计划最多一个未完成运行，包含审批、模型汇总及外部效果/停止核实；活动期间错过周期合并记入该运行，结束后从未来周期继续。无活动运行的重启至多接纳最近一期；保留原定时刻和合并范围。取消先同 commit 阻止未来接纳和派生，再停止独立会话及全部子工作/外部执行；迟到结果保存但不复活，不因原 Task 意外终态释放未核实占用。
6. 全部执行、外部核实及汇总结束后，同 commit 保存整项结果、关闭运行并按运行固定键登记唯一发送意图；发送器的离线/限流等待与未知状态不阻止下一周期。回报只发创建时的原平台/账号/owner/代次；无目标仅本机查询，后来配置不补目标。发送前复核取消、资料与原目标；明确未发送限流可沿原意图延后，已认领后的丢答/重启保留未知，不重发。主聊天与其他计划继续。创建、查询、取消、运行/完整报告查看均接主模型、双平台宿主菜单和已认证本机 CLI；用户选择，不输入内部键。
