## 方案

- 记忆以 durable documents/entries 保存稳定身份、版本、来源和撤销；复用已有校验规则，检索先使用有界简单实现。来源只指向可核实的新会话、产物或拥有者记录。
- 复用 `packages/agent/src/skills.ts` 的独立读取/解析部分；配置目录、内容版本、实际加载和动态提示持久化，技能只提供参考，不增加工具、资料或操作权限。
- 提供新主/子/定时会话适用的历史查找、原文读取与记忆接口，明确来源可见性；长期子 Agent 复用不得隐式读取父聊天或取得旧工作授权。已有个人角色配置的提示/技能需求纳入能力核对，不搬回编码角色流程。
- 采用 durable 原生压缩和已实现请求记录边界，注入前核实来源与版本；同步 personal-durable、agent-context、usage/CONTEXT 的新旧适用范围。

## 接手细化

- 历史只读新实例的 durable entries，主会话可读已登记的主/子/定时会话，子与定时仅可读自身；按 entry 精确读取与有界分页检索，不返回请求证据、审批或凭据数据。压缩只改变活动上下文，不改变检索原文。
- 记忆按产生会话隔离，主可管理本实例全部记忆，子/定时只管理自身记忆；复用子身份可参考自己的旧记忆，但不取得旧工作授权。每条记忆有稳定编号、递增版本、来源与不可变修订 entry；写入、修订和撤销与索引及工具幂等回执同 commit。来源仅接受可见原历史、已核实产物或可信本机拥有者记录；不能由模型伪造拥有者来源。修订时来源还须对记忆归属会话可见，防止主会话把父聊天写入子记忆绕过隔离。后续查询和注入排除撤销项，历史证据仍保留。
- 技能配置引用拥有者选择的目录，复用现有独立扫描/解析/引用读取；目录、正文版本和加载记录持久化，实际目录动态刷新仍先落盘再入请求。只提供参考文本，主/子/定时装配同一读取能力，引用文件保持目录边界、字节上限和文本校验。旧定时计划不能隐式取得新配置或新增工具。
- 参考在现有 provider 前 `prepareInput` 组装，来源与版本在两处请求记录边界复核，实际文字与工具定义进入原 `ruukoto.model-request`；不依赖会吞异常的 section/hook 拦截。证据失败、引用缺失或版本变化时停止发出 provider 请求。
- 同步主装配、子身份新建/重启配置、定时业务/汇总工具与范围快照，提供最小本机技能配置、记忆管理和历史查询向导；主模型可通过工具完成记忆/历史/技能操作，已有双平台 IM 自然语言入口可达。35 继续全局交互核对。
- 影响面：新增个人 memory/history/skills 模块、配置与控制；共享 memory 仅导出既有正文/类别校验，不引入旧 Db。验证新增窄用例、原技能/记忆调用方、personal-durable/work/scheduler/CLI 相关回归、静态及文档；真实模型重启引用与技能驱动单独记证据，缺配置保留待验。
