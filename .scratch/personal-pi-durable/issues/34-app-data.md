# 个人应用数据接入 durable

Status: ready-for-human

## 目标与边界

保留独立 SQLite 结构化数据、schema/revision、查询、变更与审计回执。覆盖 A5/A6/A7/A9；只替换绑旧 Task/ApprovalGate 的工具装配，不重写数据库或提供通用任意 SQL。

本单承接[已确认规格](../spec.md)；当前基线、共同实施规则与验收分工见[剩余工作评估](../remaining-work.md)。拥有者于2026-10-18指示接手实施；当前检出基线为 `8bbcbc4abb4d3c7c5268ef172b72798d09636ebb`，工作区干净。29/32/33的工程前置已具备；正式入口与生产切换仍不在本单范围。

## 方案

- 复用 `packages/agent/src/app-data/store.ts`、`query.ts` 和查询预算，为新实例登记固定业务库身份；引用 durable 会话/任务/Agent，而非伪造旧项目。
- 每个逻辑工具调用在执行前获得稳定 op_id，业务变更和回执在应用库同事务提交；durable 未记录结果时按原键核实，不以 taskId 合并同任务的不同操作，不声称两库原子。
- 保持破坏性结构变更、批量写与重写审批，三模式和单次消费沿原权限处理；绑定主/定时与明确获准子工作的适用能力，拒绝工具参数指定任意来源。
- 缺库、库身份变化、损坏回执与 schema/revision 冲突明确停止，不能新建空库证明旧操作未发生；同步 personal-durable、agent-tools、usage。

## 实施细化

- 新增个人应用数据扩展，沿六个 `app_data_*` 工具名装配；共享参数 schema 从旧适配器抽出，复用 AppDataStore、迁移分析和查询子进程，不传递两个版本的 SDK 对象，不引入旧 Db/Task/ApprovalGate。
- durable 保存固定应用库身份、每个 pi.tool Task 的接纳快照、完整参数、来源与权限、审批决定/消费和结果。稳定 `op_id` 由工具 Task 派生，同任务的多次工具各有不同原生 Task。应用库同事务审计记录完整请求指纹，恢复先核对原键、身份和回执；已开始的操作绝不再次执行，无回执且原库可核实只记已知未提交。
- 每次打开已绑定库先只读核实身份与结构，不允许打开缺失路径创建空库；查询子进程再次核实预期身份。缺库、换库或损坏回执停止应用数据能力，已开始操作保持未知；原库恢复后可从宿主管理重新核实。其他独立工作仍可继续。
- confirm/auto-review 的破坏性迁移、多行更新/删除与 rewrite_rows 人工批准；full_access 沿2026-10-12现行决定免逐次审批。批准前后核对固定参数、原权限/入口及 schema/revision，单次消费；审批期间不持有应用库锁。
- 主与独立定时会话可用；子工作须由委派参数 `appData: true` 显式授予，持久到该工作且复用身份不继承。定时创建范围保存应用库身份，汇总只开放 app_data_query；应用数据未知效果接入工作、委托、报告和定时收尾的硬暂停。
- 补齐双平台宿主菜单和本机认证/引导CLI的列表、详情、批准/拒绝及原库回执重核；内部操作键由程序管理。同步 personal-durable、agent-tools、usage 和受影响命令导航；新增决策笔记。

- 同键同参返回原结果、同键异参拒绝、同任务多调用分别执行；应用库提交后 durable 写结果前强杀只产生一次业务变更。
- 缺库/换库/回执损坏不自动重建执行，权限或修订在批准后变化拒绝；多行和破坏性变更有三模式回归。

- 真实模型通过个人工具完成一项有可读结果的结构化事务，定时来源接线由 32/39 组合验收。
