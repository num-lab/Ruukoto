# 配置与拥有者操作闭环

Status: planning

## 目标与边界

使保留能力都能由拥有者通过引导式 CLI 和适用 IM 入口配置、查看、授权、撤销、取消与核实。覆盖 A5/A10/A11；集中收尾跨能力体验，不重复实现各能力的配置存储和业务判定，不恢复旧 TUI/桌面协议。

本单承接[已确认规格](../spec.md)；当前基线、共同实施规则与验收分工见[剩余工作评估](../remaining-work.md)。本次只建单，工程与产品验收尚未开始。

## 方案

- 以能力清单核对 provider/model、凭据、QQ/TG、技能/MCP、命令目录/资料范围、权限/长期授权、服务、浏览器、计划、记忆和应用数据的配置/运行状态入口；为不适用操作说明实际路径。
- 补齐当前命令恢复主要依赖本机菜单的 IM 可操作路径，以及 MCP 等新能力的原入口审批/核实。选择项包含可理解的操作、目标和证据，不让用户填写 ID、版本或请求键；普通聊天不能被解析成批准。
- 配置启停/更换在未决工作前核实，当前配置与历史执行来源分开；本机离线配置须持锁，在线客户端不打开第二个 Harness。查询失败与应答丢失保留原动作并提供安全核实。
- 把旧 ready-for-human 切片的体验项目按实际受影响菜单合并成一次用户走查，结果写回各原工单并引用本单证据；同步 usage/development/products。

## 进展与交接

- 依赖：28–34 的能力和操作接口；优先沿已存在 CLI/Telegram 控制增量接线，不另起 UI 项目。
- 当前角色：方案交接；范围、依赖与验收已通过独立方案审查，记录见剩余工作评估。等待上述前置，下一角色在前置满足后接手；可先做不依赖前置接口的设计。接手须核对当前 HEAD 与本单基线之间的实际变化。
- 本单的实现、独立实现审查与适用产品体验均待执行；用户此次指令仅要求重新评估并建立剩余工单。

## 验收与证据

- 真实 PTY 与 IM 菜单覆盖首次配置、能力停用/凭据撤销、默认模式切换、长期授权管理及未知操作核实；自动驱动不代替拥有者体验确认。
- 跨入口、代次变化、旧菜单、重复点击和应答丢失不重复执行或升级权限；用户能查清效果与停止两个独立事实。
- 每项保留能力都有能从界面到达的管理路径，不能只提供可信宿主 API 就计作交付。
- 旧产品体验工单按实际证据逐项关闭，未体验项保持原待验状态；不得批量把 ready-for-human 改为 resolved。

工程验收：待验证。产品验收：按上述实际操作或真实环境要求待验收；纯内部改动不适用时说明原因，不豁免真实环境证据。
