# 配置与拥有者操作闭环

Status: ready-for-human

## 目标与边界

使保留能力都能由拥有者通过引导式 CLI 和适用 IM 入口配置、查看、授权、撤销、取消与核实。覆盖 A5/A10/A11；集中收尾跨能力体验，不重复实现各能力的配置存储和业务判定，不恢复旧 TUI/桌面协议。

本单承接[已确认规格](../spec.md)；当前基线、共同实施规则与验收分工见[剩余工作评估](../remaining-work.md)。拥有者于2026-10-18指示接手；接手基线为 `3d6e9b90588bf065940e5227acbf262690e8b57e`，工作区干净。28–34工程前置已具备，真实环境与产品验收仍按各单保留。

## 方案

- 以能力清单核对 provider/model、凭据、QQ/TG、技能/MCP、命令目录/资料范围、权限/长期授权、服务、浏览器、计划、记忆和应用数据的配置/运行状态入口；为不适用操作说明实际路径。
- 补齐当前命令恢复主要依赖本机菜单的 IM 可操作路径，以及 MCP 等新能力的原入口审批/核实。选择项包含可理解的操作、目标和证据，不让用户填写 ID、版本或请求键；普通聊天不能被解析成批准。
- 配置启停/更换在未决工作前核实，当前配置与历史执行来源分开；本机离线配置须持锁，在线客户端不打开第二个 Harness。查询失败与应答丢失保留原动作并提供安全核实。
- 把旧 ready-for-human 切片的体验项目按实际受影响菜单合并成一次用户走查，结果写回各原工单并引用本单证据；同步 usage/development/products。

## 实施细化

- CLI 按聊天、工作与计划、审批与核实、权限与授权、停机配置分组，复用现有管理函数；清除过期能力提示。增加本机默认模式查看/切换及长期服务授权查看/撤销，长期授权创建仍只在原 IM 的具体待审批中完成。本机与 Telegram 沿现有共享默认值，QQ 保持独立；变更只影响新接纳，不改历史工作。
- 双平台增加 `/帮助` 和 `/状态` 宿主入口，列明工作、审批、模式和管理路径；不调用模型。命令补 `/命令` 原入口列表、原命令与双流读取、效果证据及停止重核，复用已有命令事实与停止任务。所有动作固定已发送菜单、原平台/账号/owner/代次，拒绝跨入口、转发、摘录与普通聊天批准；恢复双向核对菜单/决定/停止回链，新增扩展使旧程序拒绝新记录。
- 提取现有技能配置的精确空闲检查，供模型、命令、服务、MCP、工具、浏览器及技能配置保存复用：只豁免登记一致的调度监督任务；未结束定时运行、其他未决任务/输入继续拒绝。Harness 启用/更换配置也使用相同空闲语义。模型保存改为异步，写文件前核实空闲，所有调用方同步；原配置相同可用于恢复。各能力的未知操作额外检查继续保留。
- 不新增记忆/技能/历史 IM 状态机，沿已确认的主会话工具与显式技能调用；CLI 仍可不经模型管理。服务路径与命令目录沿既有不可更换约定，停用/换凭据按现有 IM 停用、MCP移除、HTTP绑定移除、Tavily停用及部署白名单路径处理，不删除历史证据。能力入口矩阵与合并用户走查单写入本单证据，未体验项不关闭。
- 影响范围：个人 CLI/本机认证接口、命令控制与IM收件/恢复、配置保存及Harness启动、对应窄测试和smoke调用方；同步 personal-durable/products、usage/development、必要检查导航与决策笔记。无依赖、旧协议、共享运行时或生产变更。
