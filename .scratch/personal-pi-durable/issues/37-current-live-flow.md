# 现有个人流程的真实模型与 IM 验收

Status: ready-for-agent

## 目标与边界

尽早验证当前已实现的 Telegram → 主会话 → 长期子 Agent → 服务/命令 → 汇总回报，以及三模式和人工核实的实际使用。覆盖 A2/A3/A5/A6/A8/A10/A11 的当前子集；不宣称完成 QQ、MCP、调度或完整 A1–A12。

本单承接[已确认规格](../spec.md)；当前基线、共同实施规则与验收分工见[剩余工作评估](../remaining-work.md)。本次只建单，工程与产品验收尚未开始。

## 方案

- 以专用新档案、测试 bot/拥有者目标、可回收服务与命令目录准备可重复 smoke；沿仓库真实模型显式开关使用指定 provider，不自动发送至日常 IM 或操作生产服务。
- 用真实模型发起后台工作、在执行期间继续聊天、追加说明、取消后复用子 Agent，并完成固定原入口汇报。分别验证请求确认、自动审查和完全访问的已开放操作及长期服务授权撤销。
- 在真实外部效果与结果提交间中断后台，沿原工作查看效果与停止事实；证明恢复没有第二次效果，其他独立聊天继续。核实操作应走实际拥有者菜单而非只调用测试 API。
- 产出源码/环境/实际请求/平台记录、结果和清理清单；回写所覆盖旧 ready-for-human 工单。未覆盖菜单仍交给 35，最终全能力矩阵交给 39。
