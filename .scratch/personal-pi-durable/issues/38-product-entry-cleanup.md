# 正式入口、打包与旧个人装配退出

Status: planning

## 目标与边界

让正式 `ruukoto` bin/start/dev 与部署制品指向新个人装配，并删除只服务旧个人运行的代码和依赖。覆盖 A1/A9/A11；保留 Coding 及旧归档仍需的共享实现，不更改已提交会话或现有生产服务。

本单承接[已确认规格](../spec.md)；当前基线、共同实施规则与验收分工见[剩余工作评估](../remaining-work.md)。本次只建单，工程与产品验收尚未开始。

## 方案

- 改 `apps/ruukoto` bin/main/dev、根启动脚本、构建与 worker 解析及部署模板，使正式入口和隔离入口使用同一套新装配；默认新档案不得覆盖旧资料，识别旧档案时给出明确引导。
- 审计实际 import/构建图，移除个人端对旧 Runtime/Driver/Task Store、控制协议及旧开发/工作流/GitHub 入口的依赖；只删除无 Coding/历史调用方的代码，不按目录整包清空。
- 同步 `CONTEXT.md`、架构图、products/personal-durable 及旧模块适用范围，更新 README/development/usage、部署说明与 pre-push-checks 的实际命令；不引入第二套重复 CLI 或运行状态。
- 在隔离新档案和构建产物上验证正式 bin、重启/停止与两产品独立运行；部署模板产物可审查，但不启停现有服务。

- 依赖：28–35 保留能力工程验收、36 Coding 缺口关闭、37 现有真实流程验收；本单仅在隔离环境验证正式入口，生产接管由 40 执行。
- 当前角色：方案交接；范围、依赖与验收已通过独立方案审查，记录见剩余工作评估。等待上述前置，下一角色在前置满足后接手；可先做不依赖前置接口的设计。接手须核对当前 HEAD 与本单基线之间的实际变化。
