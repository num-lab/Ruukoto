# Pi MCP 迁移方案独立审查

日期：2026-10-26。审查对象为[规格](../spec.md)、[工单](../issues/01-pi-mcp-migration.md)和[决策提案](../../../.agents/notes/proposed/simplification/2026-10-26-mcp-host-responsibilities.md)。作者基点为`7d6ebbf0650358f98fbc0868f9160132eb42e03d`，上游固定Pi 1.3.0 commit `71023aec1546d6d677a65669c5665c0927ce0dd0`；最终被审内容保存在[快照](2026-10-26-plan-snapshot.json)。

## Code 接线审查

独立上下文`/root/mcp_plan_review`直接阅读本地实现、方案和固定上游源码，核对真实factory、加载器、调用ID、授权与发送、动态工具资格、持久结果、Cua生命周期和SDK升级。初审提出两项阻断和一项接线缺口，作者修订后由原审查者复审。

| 初审发现 | 最终修订 |
| --- | --- |
| DefaultResourceLoader即使no*仍枚举HOME/.agents/skills | 改公开discoverAndLoadExtensions、私有目录、显式宿主模块与每SDK局部依赖注入；不改HOME、不导入私有函数 |
| loadConfig只在启动读取，与取消SDK重建组合后无法发布配置更新 | loadConfig空，服务经公开register/unregister发布；撤销立即作用于调用门，连接更新避开在途调用，A3覆盖同SDK变更 |
| 原SDK销毁后Cua恢复观察无执行者 | 管理入口使用短期官方pi-mcp客户端，仅固定只读观察并核实停止，A9覆盖旧SDK已销毁 |

复审结论：三项已解决，无剩余阻断，可以进入P0。审查者未执行原型；封闭加载、调用关联与Cua寿命仍需P0实测，不能把方案通过记为实现通过。

## Personal 迁移审查

独立上下文`/root/mcp_plan_contract`直接核对Personal配置发布、旧操作／Task／IM收件、来源禁执行、人工收尾、报告与真实资源保护，初审要求补齐三个迁入契约。

| 初审发现 | 最终修订 |
| --- | --- |
| v3→v4顶层版本触发changedCua，可能与未迁入禁执行形成自锁 | 原有效配置先开放管理；格式变化不算Cua目标变化，旧身份可恢复；保存／生效间崩溃仍可进入管理 |
| 迁入时算新token摘要会因旧禁用服务凭据缺失阻断整个配置 | v4可携带旧认证引用及字节摘要语义；迁入不读取／重算，重新绑定时才采用规范化摘要 |
| 现有报告要等成员终态和停止核实，不能仅放开来源检查就提前送达 | 人工前只显示可查状态；人工收尾、本地停止和成员终态后，沿原报告账本发送最终未知摘要 |

复审结论：三项均通过，无剩余Personal契约阻断。配套笔记中旧摘要仅用于历史的措辞按审查意见同步为v4允许旧引用。A5/A6/A7包含相应失败窗口和顺序；尚未运行迁入试验。
