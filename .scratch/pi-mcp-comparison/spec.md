# Pi MCP 接入替换与宿主简化规格

## 目标与授权

2026-10-26，拥有者在[能力比较](research.md)与[过度设计筛选](../../.agents/notes/implemented/simplification/2026-10-26-mcp-host-responsibilities.md)后要求「制定方案，将 mcp 接入点换成 pi 的 mcp 扩展，同时删除／简化原有的过度设计部分」，随后要求接手[实施工单](issues/01-pi-mcp-migration.md)。方案已独立审查，实施从P0隔离验证开始；拥有者于2026-10-27明确要求提交当前迁移改动，真实档案切换、推送、部署与发布仍不在本次授权内。

成功标准是实际业务调用经过 Pi 官方实现，原来的通用协议、发现和搜索实现退出，同时保持授权、未知写不重放、历史可重建和 Cua 真实资源保护。只更换包名、外包一层后继续调用旧客户端，不算完成。

## S1：范围与依赖

- Code 使用 `@earendil-works/pi-coding-agent` 的 `createMcpExtension()` 与 `createToolSearchExtension()`；Personal 保持 `pi-durable`，使用同版独立 `@earendil-works/pi-mcp`，保留最薄 durable 工具接线。Personal 不安装 Coding Agent 运行时，不声称它可以直接加载该内置扩展。
- 目标固定 Pi `1.3.0`，上游源码基点为 `71023aec1546d6d677a65669c5665c0927ce0dd0`。根、core、agent、runtime、channels、tui 与 foundation 中当前 `0.85.1` 的 Pi 系列依赖一同核对并对齐，更新根与 foundation 两份锁文件；Personal 的 durable/chord 版本保持。实施时不浮动追最新版本。
- 本次保留普通 HTTPS／回环测试 HTTP、匿名／现有 Bearer 凭据及受管 Cua。通用 stdio、OAuth 登录、Resources、Prompts、Sampling、Codemode 产品入口不在本次范围；上游支持它们不代表默认对模型开放。正式扩展的工具和事件接入，默认配置命令不发布到宿主入口。
- Code 实例数据库、Personal 配置文件及其已有发布回执仍是各产品配置权威；不生成第二份 Pi `mcp.json`，不读取用户或工作区的 Pi 配置、包、技能和凭据，不自动创建默认 `mcp-auth.json` 或转存原始服务日志。HTTP 目标与秘密保护继续由宿主的唯一凭据解析入口持有。
- 不增加通用插件平台、连接池、全局资源锁、执行网关、新任务运行时或旧工具执行别名。代码移除以所有消费者已经切换为条件，历史读取需要的窄解析不算保留第二执行引擎。
- 2026-10-26，拥有者在P0反例后明确选择固定Pi 1.3.0并允许宿主保留只读SSE来源解析；本项是通用协议删除的唯一例外。解析器只观察Pi实际消费的原HTTP应答，按真实JSON-RPC ID记录远端答复，复用已维护的`eventsource-parser`并声明直接依赖；不建立连接、发请求、重试、续流或持有跨重启游标。

## S2：Code 的实际接线

### 封闭加载与 SDK 升级

继续由宿主提供模型、历史、提示、执行工具和权限，不使用 Pi CLI 的默认资源发现。使用公开 `discoverAndLoadExtensions`，configuredPaths 仅指向仓库内显式宿主扩展模块，cwd/agentDir 指向宿主私有空资源目录；它只枚举这两处 extensions 目录和显式模块，不经过 PackageManager。每个SDK自己的 EventBus 在加载前注入宿主依赖，模块同步取得后调用官方factory，缺绑定即失败，加载后撤掉注入监听，不建全局服务注册中心。把加载结果交给现有封闭 ResourceLoader，其他资源仍由宿主显式提供；`AgentSession` 的 cwd 仍是实际工作区。

不采用 `DefaultResourceLoader + no*`：固定版本仍会先枚举真实 HOME/.agents/skills。P0验证显式加载路径没有读取或枚举真实工作区／用户资源；不修改进程 HOME，不深层导入未公开的 `loadExtensionFromFactory`，不复制loader。公开路径不能满足时退回方案修订。

删除因 MCP 清单变化而重建 SDK 的逻辑，改用官方动态注册；保持宿主要求的权限／来源切换。升级须处理 `agent.shouldStopAfterTurn` 到 `finishTurn` 的变化，并组合保留 `AgentSession` 自己的终结钩子；模型重试、压缩与上下文装配继续沿现行宿主设置。旧 JSONL 只读重建，不改写历史工具名或图片。

P0实测补充：SDK显式工具清单须包含受宿主资格过滤的`mcp__*`或固定具名MCP要求，才能启用动态direct工具；允许通配注册不授予任务权限。HTTP即使匿名也会初始化上游OAuth状态对象，宿主提供无持久存储的薄凭据接口，实际传输只使用原resolver，不开放OAuth。官方404重连会脱离旧客户端而不关闭其transport；宿主沿既有受管传输归属，在原在途操作结束后清理退役句柄，并在SDK销毁前收齐所有自己创建的transport，不持有或复用第二MCP客户端。

### 官方扩展与宿主适配

`loadConfig` 只返回空文件配置并关闭自动Codemode，不读取默认文件。宿主通过公开 `registerMcpServer/unregisterMcpServer` 发布实例服务与允许列表的内存配置，使新建、修改和移除可进入已存在SDK；不混用同名loadConfig条目，因为后者会遮蔽注册项。服务默认hidden，仅获准工具设置deferred或direct；固定角色所需工具可直接开放。

保存后的撤销、停用和范围收紧立即由调用门生效，不撤回已经发出的调用。向Pi发布涉及连接变化的注册更新在该服务无在途调用的边界执行，最迟在下一任务工具选择前完成；不因保存中断原调用。新增／放宽不扩大旧任务或旧来源权限。宿主在任务选择、工具搜索及实际调用前同步当前资格，并包装每次动态注册／撤回；禁用项是hidden，不依赖active集合充当权限检查。资源三个入口一律hidden且在调用门拒绝，Codemode不装配。内置配置命令不绕过现有控制面；日志禁写默认原始服务日志，错误仍由宿主给出有界分类诊断。

宿主只包装官方工具的 `execute`，不替换其发现、连接或远端调用。包装使用 `AsyncLocalStorage` 绑定本次 `toolCallId` 与原操作身份，随后调用原 `execute`；官方实现不会把调用 ID 交给 transport，这一关联用于正确处理并发同名同参调用。映射绑定服务身份与原远端工具名，不从截断／转义后的模型工具名猜身份。最终发送前再次核对真实 `tools/call` 的名称和参数。

`tool_call` 负责资格、意图与批准快照。`createTransport` 的极薄发送包装在真正发出业务请求前核实信号、活动任务、权限、服务与凭据，并通过现有事务消费批准、保存开始事实；失败零业务发送。初始化和发现不算业务执行。之后的扩展 handler 即使改了输入，也不能改变已经批准的参数。网络与 stdio 取消在落盘等待后必须再次检查，不允许超时后首次发送。

原 `execute` 返回的 `structuredContent` 是完整 `CallToolResult` 去掉 `_meta`，在包装内、Pi 图片 normalize 之前，沿现有产物链保存原图和全文，形成模型预览与持久引用；不把临时路径当历史权威。必需持久化不依赖 `tool_result` 抛错，因为 Pi 会捕获该钩子异常后继续。坏图／存储失败不能引导重做原远端动作；模型实际所见定义、预览与图片引用仍由现有请求快照和会话记录重建。

HTTP fetch的只读应答观察在同一字节流交给Pi之前解析JSON或SSE，不使用异步tee抢跑，不改正文、状态、事件ID或重试参数。真实答复按原Pi客户端／transport实例和JSON-RPC ID共同关联，GET保留原连接归属；跨服务和过期重连的重复ID不能命中旧调用。同步parser回调收集答复后，等待必要持久化再交付原字节；仅正常EOF刷新decoder并向观察parser补虚拟终止空行，异常或取消不做此收尾。没有观察到完整原答复的`McpError`不能证明远端结束。观察解析或持久失败保留未知并阻断依赖动作，不补发业务请求；监听器按现有消息预算有界并随原调用结算清理。P0新增同HTTP元数据、错误码与文本的真实／合成对照、分块、多行及EOF、跨客户端／重连重复ID、并发与GET来源用例。

### 发现、命名与前置核实

采用官方 `tool_search` 和 `mcp__<server>__<tool>` 名称，删除本地 `search_tools` 搜索算法、激活集合及旧 MCP 命名算法。历史原名不改写，不增加执行别名；仓库内角色／工作流具名工具要求、工具族、说明和测试同步改名。用户自定义的旧具名要求若无法匹配，应明确报出需更新的项，不能忽略要求后继续；已发布工作流及旧能力快照不静默重写。

前置资格检查读取官方实际注册的 `getAllTools/getToolDefinition`，不再独立执行 `planMcpTaskTools` 构造第二清单。`bindExtensions()` 返回时远端可能尚未发现，原型须验证有界的注册完成／失败观察，或复用官方等待点，不能把暂时空清单当缺工具。固定角色的必需工具未确认前不调用模型；普通任务可继续并明确报告不可用服务。定义刷新只影响后续选择，旧调用保持自己的参数和授权快照；新工具不能扩大已固定的来源权限。

上游按分支保留的工具发现状态可以继续使用，发送声明仍每次与当前宿主资格求交。删除“每个宿主任务必须清空搜索激活”的独立状态机；这不允许历史工具取得当前没有的权限。

## S3：Personal 的薄适配与操作记录

保持 `mcp_tools`、`mcp_call`、`read_mcp_result` 三个工具名和原生 `pi.tool` 身份。普通 HTTP 保持当前按调用建立连接的方式，Cua 保持持续连接；改用 `pi-mcp` 的客户端、传输、分页和结果类型，不自建第二套发现／连接运行时。

新普通操作使用显式 `recordVersion: 2`，缺字段视为旧记录。保存操作身份、来源、服务与配置选择、工具、参数、本地效果类别、批准与开始事实、规范化结果／错误和产物引用；不再把 raw JSON-RPC、session ID、协议版本、SSE 游标作为每次普通操作的持久契约。发送前记录和批准消费仍在原事务完成，失败零发送。工具的安全恢复只读原记录，不是再次执行；重启见“已开始、无确定结果”时保持未知且不调用远端。

普通工具按本地 `read/write/unknown` 分类；旧普通工具迁入一律 unknown，不从远端 `readOnlyHint` 自动授权。拥有者已授权的 read 免逐次批准，读取中断记读取失败而非未知写；write/unknown 在 confirm/auto-review 下逐次批准，full_access 仍免逐次批准但复核资格与目标。Cua 类别仍由宿主固定。

Code 与 Personal 的错误定性统一遵循事实：发送前拒绝为未执行；完整远端结果包括工具报错都要保留其真实返回；已接纳后断线、超时或客户端合成失败不能说明未执行。上游原 POST 被过期会话明确拒绝后的有限恢复可沿用，同一逻辑调用不再次消费批准，但必须保留参数和目标并复核撤销。普通 5xx、流恢复失败和不明错误不能据此自动重放写操作；共享适配须保留远端／本地失败的来源区别。

## S4：删除无限占用与人工收尾

删除普通 MCP 的 origin+pathname 占用、同源 HTTP 联锁，以及“未取回原终结应答就永远不能结束工作”的等待。保留原操作未知事实与原工作自动执行禁令，不能只删 `mcpUnresolved()` 后放开所有消费者。

- Personal 的同一来源在未知 write/unknown 后不能换参数、请求键、工具、子 Agent 或委托自动重试。人工收尾前保留可查询的未知状态和当前错误说明，不新增非终态主动通知机制；人工收尾且本地执行停止、成员终态确认后，最终未知报告通过既有发送账本送回原入口，不授予新的业务工具资格。
- 拥有者从原调用管理选择“结束此工作，保留结果未知”，追加绑定原操作与来源的收尾事实；不改写 `effect_unknown` 或旧 `remoteEnded`。旧来源仍不可执行，新独立拥有者输入可建立新工作，不因同一服务 URL 被阻塞。
- 收尾按现有工作取消／结束路径停止本地执行；命令、服务、浏览器、应用数据、检查任务和 Cua 的真实资源核实照常。SubAgent 只有在自身执行停止且这些资源可释放时才可复用，报告终态不等于资源释放。
- Code 的未知写结果通过现有操作账本报告；本轮停止继续自动业务调用，不因新 SDK 的代理循环而重试。已开始的同批调用分别保存真实结果，不能假称全部未执行；新拥有者任务仍可处理独立工作。

删除跨重启 `resumeMcpCall`、新建 SSE 重核 Task、CLI／Telegram 的“核实原请求结束”入口与对应公开控制操作。保留普通 SSE 响应处理和 Pi 会话内断流恢复。现有报告等待、生成前和发送前的同来源检查需区分“报告未知”与“执行原业务”；定时工作、委托收尾及配置发布不能继续把已经人工收尾的普通操作当作永久运行。

## S5：配置、凭据和旧记录

Code 保留当前实例服务表、CredentialStore、允许列表、配置版本和引用保护；不增加新的凭据仓库，不因替换客户端扩大工作区或工具授权。Personal 沿当前逐服务配置发布机制增加 MCP 配置 v4，历史 v1/v2/v3 与原配置 entries 只读保留。配置迁入显式由拥有者管理入口发起，沿现有保存／生效回执，不全局重启后台，不阻塞无关设置。

新代码先用原有效配置启动历史读取、普通未知人工收尾和Cua管理；未迁入的普通服务不接纳新业务调用，但不禁止原Cua按旧身份stop/observe/accept。单纯v3→v4容器格式转换不算Cua目标或执行配置变化：比较归一后的实际目标、程序、允许范围和认证，不以顶层版本触发changedCua。旧Cua的执行身份、恢复观察和审批仍按原事实复核；实际目标改变照常等待核实。迁入通过现有发布事务先保存意图／候选，再结算普通旧未开始批准并选择新配置，旧普通未知不阻止这次格式迁入；中间崩溃依原回执恢复，始终允许进入管理，不把已保存v4与仍有效v3误判成档案损坏。

v4 的效果类别与远端定义分别保存。新增／显式重新绑定的凭据使用 `{path, tokenSha256}`，摘要覆盖 trim 后实际发送的 token；v4也允许迁入的旧 `{path, sha256}`，继续按原始文件字节语义读取，不暗换解释。格式迁入不读取或重算旧凭据，不要求缺失凭据的禁用服务补齐后才迁整个配置；引用及原启停状态保留，凭据失效的服务仍零发送，其他服务可正常迁入与管理。重新绑定时才读取并生成新规范化指纹，无效引用不能借迁入变匿名或取得启用资格。

规范化引用的同token换行变化不使服务失效；真正更换token须在现有设置保存中显式重新绑定／轮换，产生新的服务执行配置选择，使旧待审批和已批准未开始调用失效。普通同路径编辑仍保留旧绑定，不能自动采信替换后的文件。统一resolver继续检查私有普通文件、目标、秘密隔离与撤销，失败不退回匿名；不增加OAuth产品流程。

工具描述和无关元数据变化不再使业务调用失效；授权相关的服务目标、认证引用、允许范围、效果类别、参数 schema 与取消／权限变化仍复核。配置显示变更兼容、连续版本与 A→B→A 不复活旧授权沿现有配置更新规则，不退回整文件变化即全部失效。

| 切换对象 | 处理 |
| --- | --- |
| 普通旧已完成 MCP 调用、图片与配置历史 | 保留原字节和旧格式只读校验，查询可用，不重新调用或迁写历史 |
| 普通旧待审批／获批未开始调用 | 在显式配置迁入时追加失效且未执行的结算，不能借新配置执行；未迁入前不执行旧客户端 |
| 普通旧已开始无结果调用 | 保持原证据与未知，恢复只读，可走新人工收尾；不靠新版本伪造远端结束 |
| 旧 `ruukoto.mcp-recheck` v1 live Task | 保留短退役定义及原 phase，核对关联后无网络结束；不改变原操作结果，不保留旧 SSE 网络引擎 |
| 旧 IM 控制收件、重核回执 | 保留读取和验证，旧动作不能重新发起；有无重核函数不再作为 MCP 是否装配的判据 |
| 旧 Cua 未决与恢复观察 | 沿原执行身份继续停止核实／新图恢复；不自动接受、不解除真实资源占用，不把普通人工收尾用于 Cua |
| Code 正在执行的任务／工作流、旧具名能力快照 | 升级前正常收尾或按现有路径中断；不在运行中更换 SDK，不重放旧任务，不自动重写发布定义；重新运行前核实新工具要求 |

Personal 显式迁入 v4 后旧程序应拒绝当前配置，禁止降回旧格式；不抬整个档案格式，不要求另建档案。新旧操作的校验分支必须允许“未知事实保留、逻辑工作已人工收尾”同时成立。启动恢复不得自行联网退役旧重核或执行未迁入服务。Code 当前 SQLite schema 为53，未改表布局不升版本；接手检出实核控制协议为41，删除公开控制操作时升42，旧客户端明确拒绝。

## S6：Cua 与结果保留

保留固定程序及目标、宿主生成参数、主会话资格、单实例串行、模型视觉前提、原图、停止证明、未知冻结与具体新观察接受。Code 官方 MCP 扩展持有客户端，产品管理器只持有受监督执行身份、受管传输与恢复事实；不得同时保留旧 MCP 客户端再套 Pi 客户端。

拥有者触发的恢复观察不依赖旧SDK存活：Code管理器可建立短期官方pi-mcp客户端，使用独立受监督身份，仅调用固定只读截图工具，保存原图后核实该观察执行停止。它复用同一授权／产物／受管传输，不运行模型、不能调用其他业务工具，也不是旧客户端回退。普通业务调用仍只经官方扩展；验收覆盖旧任务终态且SDK已销毁后的管理恢复。

普通对话轮沿同一 SDK 保留 Cua 连接。确需重建 SDK 时，在没有在途调用的边界先停止并核实原 Cua 执行，再销毁连接；下一次建立新连接必须重新观察。停止无法核实时继续冻结，不把旧 stdio 流直接交给新客户端重新初始化，不用 SDK `close()` 代替停止证明。Personal 保持由其 Cua 管理器持有持续的 Pi 客户端。

对外恢复改为“停止核实 → 检查并恢复（取新截图）→ 接受此观察”。删除独立公开 begin 动作；合并 observe 内部仍记录既有 begin/ownerStartedAt 事实，避免为了减少一个按钮迁写旧历史。旧 begun 阶段可继续取图，失败或重观察使旧接受资格失效，接受绑定原操作及具体观察。Linux 停整个沙箱会丢未保存状态的明确选择保留。闲置断线能否放宽停止判据不在本次范围。

通用图片 MIME／编码／大小校验、持久产物、归属、原图进入实际模型请求和上下文预算保持；逐一删除等价 MCP 专用重复逻辑，不为迁移另建媒体系统。取消整服务64工具的拒绝门槛及独立发现／schema尺寸策略，以 Pi 客户端与现有模型、消息和产物预算承接资源约束；不是取消参数校验、消息限额或异常分页保护。
