## 一、定义加载与持久身份

在 agent 包持有角色解析与不可变定义类型，runtime 持有实例加载、角色选择及任务登记，core 持有必要持久数据。使用已有 frontmatter 解析依赖；文件读取参考 `workflow-library.ts` 的宿主配置保护，而不是直接复用允许符号链接的技能加载器。仅接收固定目录的普通 `.md` 文件，拒绝越界、符号链接、多硬链接和读取中身份变化；不新增 YAML 依赖。内置定义与覆盖文件走同一校验，读取用户目录不写回内置文件。

加载时完整解析有效定义与每个失败诊断；无效同名覆盖不能回落内置同名角色。诊断包含角色名、错误码与可行动说明，避免输出凭据或正文。有效角色可供主 Agent 选择，错误角色不可派发；错误默认 general 时省略角色同样失败。主会话仍可解释和查看加载错误，不因坏文件丢失既有运行。工作流启动固定有效目录和当时诊断，后续动态请求一个无效或不存在角色时明确失败，不读取后来修好的文件。

普通工具增加可选 `role`，缺省 general；新 SubAgent 绑定角色名、规范化内容、原文及内容摘要。继续同一工作、复用同一 SubAgent 和消息触发任务沿该身份的固定角色；请求不同角色明确冲突，需要新建 SubAgent。每次任务依其本次发起来源计算实际权限，不能把第一次的 full_access 保留成永久身份授权。工作流启动固定角色目录版本与可重建正文，其后步骤均引用该快照；重启不读当前文件替代已引用定义。

已有 GitHub hostReview 是宿主固定用途，继续由 orchestrator 的可信绑定提供固定提示与执行定义，不进入可被覆盖的 general/reviewer 选择。持久定义记录明确区分用户角色引用与宿主固定定义，并完整保存可重建内容；该区分由宿主入口给出，不是模型参数或角色文件。保留已完成来源任务的专用资格、固定 read/read_artifact 与只读 MCP、禁工作内消息、禁止普通复用及既有幂等/恢复。不得把 workflowSource 只接受活动来源的前提直接套到这个入口，也不能因 reviewer 必需 bash 而让固定评审无法启动。

保存内容而非仅路径或摘要。角色目录进入父模型输入，选中的正文进入子模型输入；实际有效工具、访问策略、来源与收窄原因写入持久执行记录并关联选择记录。JSONL 与 SQLite 无跨系统原子保证，沿现有任务登记、选择记录和 prompt 产物的顺序处理失败，不发出无法重建的请求。新增持久字段同步 schema、归档查询与两方向实例导入；旧数据库按现行版本策略明确拒绝，不回填角色或授权。

## 二、共同的来源能力与上下文

将工作流已有的来源能力保存与复核提取为普通委派也能使用的宿主机制；工作流运行仍拥有自身授权与生命周期。保存实际来源任务、入口代次、资料授权、允许委派的工具类别、配置摘要及工作区身份，不能由角色文件、模型参数或 task input 自报 main 身份。main 的受控编码委派资格继续可提供编码工具，不按主 Agent 是否直接装配 bash 判断；个人业务资格与执行任务身份分别核实，审批、效果和账本属于真实子 Task。GitHub hostReview 的来源资格与固定收窄继续由其宿主入口提供，共用工具计算但不继承用户角色默认值；其无 target/materials 的参数不能落入普通委派旧 guard。

有效工具取来源可委派能力、角色要求、产品与当前服务配置以及宿主执行约束的交集。角色未写 tools 表示使用交集；写了 tools 则每个名字必须可解析并通过全部条件。宿主消息等协作工具也走同一计算，保留一层委派与运行归属检查。工作流现有步骤 tools 可继续额外收窄，但若与角色显式必需工具冲突则报错，不能悄悄削减角色。MCP 在最终启动预检实际发现，显式必需工具缺失不得创建可运行步骤；排队期间配置撤销或变化仍在执行前复核，不以曾经发现成功为凭证。

访问模式按规格的收紧关系处理；来源路径授权、单次批准与长期授权不因角色复用而扩大。以 permissions.protect_source 表达技术保护要求，不按 reviewer 名字或缺少 edit/write 推断。只读来源根和工作目录约束必须同时覆盖原生命令、结构化文件工具及批准后的宿主操作；复制 cwd、隐藏 edit/write 或 prompt 禁止写入都不能替代这些限制。protect_source 与有效 full_access 或非 Git 原地 target 冲突时明确拒绝；内置 reviewer 指定 confirm，因此完全访问父级仍派生受限任务。full_access 自定义执行沿既有账户语义，不宣称物理隔离；宿主独立验证始终强制受限。实际策略变化需要更新 SDK 工具签名、工具激活、发送前校验和真实调用门，不引入两份可用性清单。

项目指令、技能目录与资料读取沿原来源范围装配，两个入口采用相同规则；不复制父聊天或无条件注入个人记忆。普通 main 委派保留显式材料解析，dev 保留明确读路径；来源不能提供的上下文不从父 prompt 偷渡。等待内部对话阶段只用已有持久快照，不现场重载角色文件、项目指令、技能或 MCP。角色/来源变化、撤销、缺失及损坏必须使受影响的新调用失败，既有结果不伪装成未执行后重跑。

## 三、目标快照、占用与增量

保留 target 与获准资料输入；无 target 的子代理工作目录为宿主独立目录，获准资料按只读来源接入，不自动创建 Git 副本。普通首次委派只给 request/key 即可，read_paths/materials 允许省略；没有显式资料时来源资料集合为空，保留按来源适用的项目指令/技能上下文，不伪造文件授权。移除旧 analyze 强制提供资料的 guard，模型工具说明必须要求代码修改和代码审查显式给 target，工作区映射由宿主提供并落盘。现有普通 target 与 read_paths/materials 的互斥规则可保留，不据此丢掉来源已授权的上下文。继续同一工作沿已登记目标，复用身份承接新工作重新准备目标。

Git target 从当前工作区捕获稳定基线，记录 HEAD、索引状态、已跟踪实际内容、非忽略新文件及二进制内容。捕获受源目录占用保护；原工作区文件、index、refs、hooks、config 不得被写入。复用 Git 与既有 workcopy/worker，不能直接对原目录调用现有 `freeze`，因为它执行 `git add -N --all`。优先以临时索引和独立暂存对象/补丁处理未跟踪内容；机制实验必须证明不向源 Git 对象或 index 写入。外部编辑造成捕获前后不一致时明确拒绝本次快照，不接受拼接时刻的内容；失败保留已登记引用及现场，不覆盖旧成果。

捕获与副本登记是不同宿主操作。捕获本身零写入；后续创建副本可沿现有规则登记宿主持有的 worktree 元数据或专属分支，但不得改原工作树、原 index、HEAD、当前分支指向、hooks 或 config。登记写入必须有独立宿主任务和账本，不能把现有 worktree add 原封不动当成零写入捕获，也不能将这项宿主准备资格交给 reviewer。机制实验分别核实捕获前后不变和创建阶段仅发生已登记的副本管理变更。

捕获基线与子代理新增改动分开保存。子副本从捕获内容开始，冻结和普通汇总计算相对该内容的增量；原有 staged/unstaged/untracked 内容不能被当成子代理成果重新套用。汇入前复核目标身份与预期内容，原工作区之后的修改导致冲突时拒绝受影响成果，保留现有内容和副本，不自动重置或承诺跨成果回滚。对普通汇总与工作流冻结/验证/组合检查都使用同一基线语义。

受限审查副本可写测试产物，原源码、原索引、共享 Git 目录与来源附加路径只读；批准、路径别名、绝对路径、符号链接和宿主文件工具不得绕开该限制。使用现有 native 执行边界，缺前提失败，不能回退 full_access。忽略文件和依赖目录不自动复制；检查缺依赖须明确报告并按现有授权准备副本环境，不偷偷写原项目或绕过沙箱。

非 Git 普通 general 沿已有 direct target 和目录占用串行；父 Agent 用现有 agent_wait 安全让出。需要受保护目标副本的角色执行及工作流修改/冻结验证仍要求 Git，在副作用前拒绝；不以角色名或缺少 edit/write 判断 shell 无写入风险。停止未核实保留实际任务占用，取消不删除副本和冻结产物。

先完成最窄机制实验：脏 Git 仓库含 staged/unstaged/untracked binary 时捕获不改原 index/对象；子任务新增修改可单独汇入且保留原改动；完全访问父级派发受限子任务时所有写回旁路被拒绝。失败退回实现方案与审查，不降低 R5/R10，也不先提交只有 HEAD 的版本。

## 四、工作流验证与接口替换

工作流 `agent(key, params)` 接受与普通委派同义的 role 与 target。保留 `verify` 对冻结步骤的引用作为独立验证操作语义，移除 mode：有 verify 时必须依赖对应已冻结步骤，不能同时指定任意 target；宿主准备独立验证副本并固定原有输出与账本核实。角色仍可自由选择，未指定沿 general，工具说明推荐审查选 reviewer；角色选择不能提供或撤销验证资格。

有 target 的修改成果使用新快照基线冻结，验证始终针对同一基线和冻结增量；汇入检查当前副本与冻结字节一致，再核实目标基线和组合检查。普通 subagent_integrate 继续不能汇入工作流成果，工作流 SubAgent 不能从普通入口续派或改归属。角色共享不合并两套工作生命周期或结果消费者。

普通委派与工作流明确拒绝旧 mode 字段，诊断指向 role、target 与 verify 的新用法。命名工作流定义/运行保存接口版本，旧版本保留可查但不能作为新接口启动，需保存新版本；不靠扫描任意 JavaScript 字串推测或重写程序。临时脚本在调用参数验证时拒绝旧字段，该调用尚未执行；若先前步骤已有副作用，保留其真实状态，不宣称整段无效果。更新所有源码调用、工具说明、workflow_instructions、测试 fixtures、示例和 smoke 脚本；历史 JSONL 和不可变已引用定义不改写。

恢复必须核实新记录具备角色和工作区基线快照；缺失、旧接口或摘要失配显式失败，不自动读最新版定义、补 general、重跑任务或换请求键。新增 schema/协议字段由实现选择必要版本并同步导入，保留旧档案供匹配版本读取，不自动清库。

## 五、失败归属与验证

| 失败 | 处理者与保证 | 用户可见结果 |
| --- | --- | --- |
| 角色解析、未知角色、不同角色复用 | 配置库/委派入口拒绝，未创建可执行任务 | 角色名、错误码、修正文件或新建子代理的下一步 |
| 显式工具不可用、权限提高、来源撤销 | 来源解析与统一工具门拒绝，未批准操作不执行 | 缺少能力与原因；已运行步骤保留已发生效果 |
| 快照变化、非 Git 不支持、隔离前提缺失 | workcopy/执行入口停止准备，源内容不改 | 受影响目标与重新准备条件，不降级原地或 full_access |
| 冻结不一致、汇入冲突、检查失败 | 成果持有者拒绝该份/报告组合失败 | 保留成果和先前成功汇入，不宣称回滚 |
| 配置/角色/基线记录损坏，旧格式恢复 | 持久记录持有者拒绝猜测，既有历史保留 | 明确不可恢复原因与匹配版本/新建运行入口 |
| 取消、停止未核实或外部效果未知 | 原任务生命周期/账本收尾，保留占用或未知效果 | 可查询事实；不自动重放副作用 |

跨层错误采用具名类型与 code，调用方不解析 message；诊断遵循 error-handling。文件准备与 SQLite 无原子性，准备产物只按已提交引用清理，已提交历史/成果不删除。角色、工具及来源预检在准备前与登记/启动时复核，避免异步准备期间权限或配置改变。

本轮规划运行 `npm run check:static`、`npm run verify-notes` 的包含项、差异与链接检查；不把静态通过称为产品通过。独立方案审查只读需求、源码和完整规划快照，结果记入 plan-review.md。01–04 按工单运行最小定向检查；05 按最终跨 core/agent/runtime/control 与两产品的实际范围决定是否运行一次完整 `npm run check`，不机械重复局部通过记录。

实现同步 docs/modules 的 runtime、agent-tools、agent-context、execution、workflows、core，涉及展示/协议时同步 control、tui，涉及业务来源变化时核对 scheduler、channels；使用更新 docs/usage.md、README.md，测试导航与命令更新 docs/development.md、pre-push-checks。本轮不把这些常驻文档提前改成已实现行为。保留[工作流 11](../agent-workflow/issues/11-experience-acceptance.md)的独立交互验收范围，新角色接线后的组合证据由 05 与该单交叉引用，不继承旧角色的验收结论。
