# TUI 事件流重写规格

来源：[用户说明文档](</Users/eitrous/Desktop/事件流 TUI.md>)，以及本次 grilling 中已由用户逐项接受的建议。用户已明确要求继续执行。

## 目标与边界

重新实现 TUI 事件流的状态模型和渲染逻辑，按本规格形成单一、顺序稳定的事件流；同步补齐后台事件与历史查询中必需的信息。沿用现有任务、会话、审批与 Markdown 能力，不以在旧事件渲染逻辑上逐项打补丁的方式实现。

遵循 ADR 0001 的完整会话历史与 ADR 0002 的后台任务生命周期：终端断开不影响任务执行，连接恢复不重放外部副作用。权限模式和审批入口继续遵循 ADR 0003、0005、0008，不因显示重写改变授权含义。

## 事件排版

- 用户输入与斜杠命令以 `❯` 开头，模型正文以 `●` 开头，工具以 `⚙︎` 开头，思考以 `⨳` 开头。
- 相邻独立事件之间恰好留一个空行；工具或命令的结果紧随其所属事件，不插空行。说明文档的文字规则优先于其中 Read 与 `/model` 紧贴的片段。
- 首列只显示图标。正文续行、Markdown 列表、代码块及结果内容均须缩进，不能侵入图标列。
- 工具或命令结果使用 `  ⎿ ` 前缀。

## 思考与正文

- 有公开思考内容时流式显示 `⨳ Thinking... <内容>`，思考内容呈灰色，单行展示；超过可用宽度时滚动保留最新内容。
- 没有公开思考内容时，从每轮模型请求发出开始显示 `⨳ Thinking...`，直到首次正文或工具调用开始。这个计时包含网络和模型等待，不能当作模型内部精确思考耗时。
- 有明确思考阶段事件时，按实际阶段计时。
- 每段思考结束后原位替换为 `⨳ Thought for Ns`，保留在原顺序中。“思考 → 工具 → 再思考 → 正文”须保留两段独立思考记录。
- 正文流式显示，完整保留已经生成的内容，支持向上滚动查阅，继续使用现有 Markdown 排版。
- `Thinking...` 与底部运行状态同时显示。

## 工具

- 所有工具显示工具名，下一行显示主要目标或简短操作说明；成功时不展开原始工具返回内容，失败时附明确错误。
- Read 显示读取目标；Edit 显示修改目标及实际成功修改的增删行数，例如 `script.py +114 -514`。新增数字使用绿色，删除数字使用红色；失败、未知或旧历史缺少统计时不虚构数字。
- Bash 显示命令，过长时从尾部截断并以 ASCII `...` 结尾。

## 命令

- 所有提交的斜杠命令保留命令回显；只有 `/mode`、`/model` 在事件流追加成功结果。
- `/mode` 示例：`⎿ Switched to Full access`；`/model` 示例：`⎿ Switched to deepseek/deepseek-flash · max`。
- 其他命令的正常内容由对应面板展示，但错误必须明确提示。`/thinking` 不追加成功结果；取消面板后只留下命令行。
- 斜杠命令回显只保留在当前客户端，不新增命令历史持久化。

## 运行与结束状态

- 执行期间底部显示 `⦿ Sweeping · Elapsed Ns`；等待审批期间仍显示运行状态，并明确标注审批等待。
- 总耗时从任务实际开始执行的 `startedAt` 计算，不计排队时间，计入审批等待。
- 成功显示 `  Done in Ns · At Tue 09:16 PM`；完成时间使用运行 TUI 的本地时区，格式遵循该示例。
- 失败显示红色 `✗ Failed`；取消和中断分别显示黄色 `Canceled`、`Interrupted`，附必要原因，不再统称 Done。
- 旧记录缺少可信开始时间时省略耗时，不由创建时间等字段猜测。

## 恢复与兼容

- 新任务断线重连或重新打开终端后，思考、工具、正文、完成状态恢复相同顺序、内容、样式与已知统计。
- 新任务的正文在生成中及历史恢复时均不得因为 8 KiB 尾部窗口丢失前文。
- 旧会话历史展示已有的可靠信息；缺少的思考阶段、耗时或 Edit 统计省略，不补造。
- 连接恢复应去重，不能将事件重放成重复的正文、思考或工具记录。

## 验收

1. 根据说明文档的 ping、斜杠命令、Read/Edit/Bash、思考示例验证字符、空行和图标列；Markdown 多行、代码块及窄终端仍遵循缩进规则。
2. 验证无公开思考、有公开思考及一项任务多轮思考；长思考只显示单行最新内容，每段完成后保留独立 Thought，运行状态始终可见。
3. 用超过 8 KiB 的正文验证生成中保留开头、中间和结尾；重连后内容及事件顺序一致，重复投递不重复显示。
4. 验证工具成功、失败、长 Bash 和 Edit 的真实增删统计及颜色；未知统计省略。
5. 验证 `/mode`、`/model` 成功结果，其他命令的面板内容、错误提示，以及 `/thinking`、面板取消行为。
6. 验证成功、失败、取消、中断、审批等待与排队后开始；耗时排除排队且包含审批，时间按客户端本地时区显示。
7. 验证新任务历史恢复与旧历史降级；采用与改动相匹配的现有测试及可运行检查，不引入新测试框架。
