# AGENTS.md

Ruukoto ships two products: the `ruukoto` Personal Agent and the `ruukoto-code` Coding Agent. Before changing `packages/`, read the [architecture](docs/architecture.md). For implementation, handoff or review, use [development-workflow](.agents/skills/development-workflow/SKILL.md) to establish the effective requirements and acceptance evidence; small changes take the lightweight path.

## Development And Verification

Run `npm run setup` on a fresh checkout. [Development](docs/development.md) covers prerequisites, test navigation, development instances, timings and external acceptance. Run `npm run check:static` and relevant tests while changing code. Before committing, choose the [smallest credible check set](.agents/skills/pre-push-checks/SKILL.md); use full `npm run check` only when explicitly requested, diagnosing CI, or the change genuinely spans the repository. Name files in targeted runs, for example `npx tsx --test test/71-product-entry.test.ts`. For tests requiring Linux, ask user for SSH alias of development server.

Pre-commit runs `git diff --cached --check`, `scripts/check-staged-eol.mjs`, then `npm run check:static`. CI pins Node 24.15.0 on macOS and Linux, with a 90-minute job limit, and runs `npm run setup -- --skip-hooks` followed by `npm run check`. Missing Python or PTY support is a failure, not a skip. Real model and IM checks are external acceptance: report missing prerequisites as unverified. End each authored text file with exactly one newline.

## Engineering Conventions

- Cross-package imports use package names and exports, declared in `dependencies`. Reverse type dependencies belong in `devDependencies`; inject callbacks for reverse runtime calls. ESLint enforces workspace dependencies and rejects cross-package relative imports.
- One writer per working copy. Parallel implementations use isolated copies; reassess verification after integration. Prefer maintained dependencies over equivalent handwritten implementations.
- Cross-layer errors have typed `code` values; discriminate with `instanceof` and `.code`, not message parsing. Keep `try` around the operation that may fail. Explain intentionally swallowed errors; no empty catches. Diagnostics use `process.stderr.write` with a `[ruukoto:*]` prefix; runtime `console.log` is limited to TUI `cli.ts`, `tui/index.ts` and `config-tui/index.ts`. Report failures at load time or where they can be interpreted best; missing referenced objects must not disappear silently. Use [error-handling](.agents/skills/error-handling/SKILL.md).
- Type escapes (`any`, `as unknown`) are limited to SQLite row mapping, JSON/wire parsing and third-party SDK boundaries. Use real types internally without duplicate runtime validation. Cross-boundary handles use named types, not bare strings. `noUncheckedIndexedAccess` is off; check out-of-range access explicitly.
- Persist state and its event in one transaction; acknowledge and broadcast after commit. Session JSONL is the sole message-history authority, read-only to core; SQLite and JSONL are not an atomic unit. `SCHEMA_VERSION` only increases; reject databases from newer code. Never move, overwrite or delete committed session records or sealed archived notes; record supersession in a new linked file.
- Tests are offline by default. Real models require `RUN_MODEL_CHECK=1`; `test:app` disables them. Direct SQLite reads and raw SQL assertions intentionally test persisted layout. Find tests by feature; numbers may repeat or skip. Every behavior change needs the narrowest regression test that fails without it; update obsolete tests with their behavior.
- Use ESM, `.ts` extensions for relative imports, and kebab-case file names. Human operations use selections and progressive guidance; programs manage internal IDs, versions and request keys. See [progressive interaction](.agents/notes/implemented/process/2026-10-14-progressive-human-interaction.md).
- Anything entering a model request must be reconstructible from session records. New model-visible input needs an event or persisted field. Follow [agent-facing-text](.agents/skills/agent-facing-text/SKILL.md) for product tool definitions, schemas, results and prompts.
- Use `FIXME` for release blockers, `TODO` for near-term work, and `XXX` for later work; each names the required action.

## Language And Communication

English is authoritative for maintained documentation, instructions, skills, notes, comments/JSDoc and agent-authored Issue/PR bodies. Chat follows the human's language. Optional translations are sibling `name.zh.md` files; a semantic source change updates or removes the affected translation in the same change. Sealed archives, frozen/third-party material, quotations and test samples retain their original text. Existing code comments migrate when their code is touched. Product UI text and runtime prompts are not subject to this technical-document language rule.

Follow Grice's maxims: provide enough relevant information, support claims with evidence, and be clear. Explain what changed and why; expand implementation detail when it answers the question. Report meaningful progress, blockers and decisions rather than repeated status or defensive disclaimers. Keep auditable acceptance evidence in the Issue/PR, not a recitation of its template in chat. [prose-standard](.agents/skills/prose-standard/SKILL.md) owns detailed writing guidance.

Use one physical line per paragraph and editor soft wrapping (`npm run verify-md-wrap`). Comments explain non-obvious invariants, ordering, ownership, security and failures, rather than narrating code or review history. Decision-bearing entry points carry `Note: See .agents/notes/<path>`, one note per line. Read [CONTEXT.md](CONTEXT.md) before exploration; use its domain terms in tasks, plans and tests. Prefer an existing term before adding a genuinely missing concept with `domain-modeling`; decisions still belong only in `.agents/notes/`.

## Knowledge And Work Tracking

[development-workflow](.agents/skills/development-workflow/SKILL.md) owns Issue creation, effective requirements, handoffs and independent review. Features, behavior fixes, architecture changes and work requiring ongoing tracking or handoff need an Issue; mechanical edits need no extra ticket. Use native GitHub Issue/PR states, without local mirrors or custom status machinery.

| Changed material | Required companion |
| --- | --- |
| Behavior, architecture, cross-file contracts, process/tooling, test strategy or persisted/wire/config formats | [Decision note](.agents/skills/maintain-notes/SKILL.md); `npm run verify-notes` |
| Observable module behavior | Corresponding `docs/modules/` page; new modules also update the architecture map; `npm run check:docs` |
| Comments, JSDoc, docs, notes, skills, prompts or diagnostics | [prose-standard](.agents/skills/prose-standard/SKILL.md); human docs also use [writing-docs-for-human](.agents/skills/writing-docs-for-human/SKILL.md) |
| Commands, scripts, dependencies or entry points | Update affected commands in `README.md`, `docs/development.md` and the pre-push skill together |
| This file or skills | Verify linked targets and commands against the actual tree and `package.json` |

Search existing notes by module and mechanism before adding a decision. A new decision that contradicts an existing one names the conflict and reason for reopening it; use the [notes lifecycle](.agents/notes/README.md), not silent replacement. Postmortems live in [.agents/postmortem/](.agents/postmortem/README.md); write one only for a non-obvious, systemic mechanism that is expensive to rediscover.

Resident-document character budgets live in `scripts/doc-budgets.manifest.json`. They are guardrails, not shortening targets: move misplaced detail to its proper home before compressing; justify any ceiling increase in the same change. Gates cannot prove semantic accuracy; review affected documents against actual behavior.
