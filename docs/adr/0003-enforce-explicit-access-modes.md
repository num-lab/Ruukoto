# 首期提供请求确认与完全访问两种模式

拥有者要求对操作权限实施技术约束。首期提供请求确认和完全访问两种模式，自动审批后续再加入。请求确认模式允许工作区内已授权的修改和验证，超出范围的操作等待确认；约束须覆盖文件、命令、网络和凭据访问，不能只依赖模型遵守提示词或专用发布工具的审批。

完全访问是拥有者明确选择的执行授权，任务可使用运行账户已有权限，无需逐次确认。工程默认采用请求确认模式，模式绑定任务；模型、工具和群成员不能提升模式，其他任务不继承临时授权。启用完全访问不放宽服务端对入口身份及会话访问的控制，但同一账户可读文件不能再被宣称与该完全访问任务隔离。

两种模式使拥有者可以在逐项控制与自主执行之间选择，代价是需要一个可验证的受限执行边界。Linux 隔离机制在基础验证中选择；缺少所需隔离能力时明确报错，不把请求确认模式静默降为完全访问。

授权控制面与项目命令分别保护，这一要求同样适用于完全访问：完整的任务执行权限不能用于伪造拥有者身份或提升其他任务权限。若执行账户能直接改写宿主授权状态，该部署就不满足此边界，需要通过不同系统身份或等效隔离调整，不能仅用应用内校验宣称已经隔离。
