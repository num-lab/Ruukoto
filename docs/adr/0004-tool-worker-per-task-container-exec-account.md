# 工具执行放入边界内的工作进程，按任务建容器，完全访问用专用执行账户

2026-10-02 范围说明：[ADR 0017](0017-two-agent-products.md) 要求 ruukoto-code 支持 macOS/Linux；下述 Linux 实现不能直接作为 macOS 受限执行的依据，跨平台实现须另行验证，技术权限边界与禁止静默降级的原则保留。

编码工具（read/edit/write/bash）的完整执行——包括上游工具内部的路径解析与 Shell 子进程——放进独立的工具工作进程：请求确认模式下工作进程在按任务建立的 Linux 容器内（固定镜像、非 root、cap-drop ALL、no-new-privileges、只读基础文件系统、默认无网络），完全访问模式下由 systemd 以固定执行 UID 启动。SDK、模型调用、审批与持久化留在后台。这样路径解析与自由 Shell 全部落在执行边界内，不存在"宿主替工具先解析好再委托"的夹缝；代价是要维护一条有界的进程间消息协议，以及把正文捕获放在工作进程侧完成。

容器按任务建立并在结束后回收，不复用给后续任务：按会话复用会让后续任务继承临时挂载、环境变量与残留进程，单次批准的额外能力也不应沉淀进常驻容器。完全访问任务不进入容器、不逐次确认，但也不以拥有者账户运行——若执行账户能读到 CLI 的授权材料就能冒充拥有者，违反 ADR 0003 的控制面分离；因此使用与拥有者、后台都不同的专用执行账户，完全访问提供的是该账户已有的系统权限，不承诺读取拥有者账户的全部文件，也不提供账户内部的文件隔离。

结构化越界操作（外部文件读写、单次 HTTP 请求）的批准只能消费一次：消费资格用 SQLite 条件更新原子校验（任务仍活动、权限版本匹配、批准未消费），执行参数完全取自审批保存的不可变请求；批准的 HTTP 请求不自动跟随重定向、连接固定到批准时解析出的地址。缺少执行后端或身份配置时明确失败，不回退到后台账户执行。
