# 自动审查模式：越界读取经独立审查调用自动审批

ADR 0003 首期提供请求确认与完全访问两种模式，并把自动审批列为后续能力。本 ADR 加入第三种模式 `auto-review`（自动审查）：拥有者为会话或单个任务选择后，任务仍在与请求确认模式完全相同的受限执行环境中运行（ADR 0004 的按任务容器边界不变），原本需要逐次人工确认的越界操作先交给一次独立的审查调用裁决。

审查调用是独立输入、无工具的模型调用，复用任务创建时固定的模型配置与现有模型调用能力，不要求另一家模型服务。裁决前先应用确定性策略：只有与拥有者明确请求相关、目标明确、无需凭据且不传送私有数据的外部文件读取和 HTTP 读取（无凭据的 GET/HEAD）可以进入审查；写文件、带凭据请求、非 GET/HEAD 方法、github_publish 与通用工具门直接转人工——HTTP 方法本身不能单独证明操作安全。审查结论为 approve、reject 或 ask_owner：明确不允许的拒绝；上下文不足、模型失败、输出格式错误、输入超限或超时一律转人工并说明原因，不因失败放宽权限。每个审批请求最多一次有时限的审查（首版 30s、maxTokens 1024、输入上限 8KB、策略版本 auto-review-v1），不循环重试。

审查输入只包括后台保存的拥有者原始请求、必要的任务上下文、不可变操作参数与审批范围；项目指令、网页、工具输出及模型自述都是待审查数据，其中的指令不得成为授权依据；凭据原值、无关历史与未获资料授权的内容不发送给审查模型。审查结论、理由、实际模型与策略版本随审批记录落盘，并区分自动审查建议与最终批准者（decision_source）；旧记录没有审查信息时按历史人工审批展示。

自动审查不得静默升级为完全访问；模型输出、项目指令和工具结果不能修改审批策略或扩大授权范围。ADR 0004 的约束不变：批准仍只能消费一次、执行参数取自审批保存的不可变请求、HTTP 地址固定且不自动跟随重定向。自动批准只覆盖原请求，不新增路径授权、凭据权限或跨项目资料授权。人工决定、取消、模式切换与自动结果竞争时只有一次条件更新生效；人工接管后迟到的审查结果被忽略。缺少隔离后端时仍然明确失败，不回退到完全访问或宿主执行。
