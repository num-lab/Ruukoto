# MCP 客户端：受控的外部工具入口

个人 Agent 需要接入拥有者配置的外部工具服务（首个接入对象为官方远程 GitHub MCP）。本 ADR 确立 Model Context Protocol（MCP）客户端的定位：MCP 是受控的外部工具入口，沿用 ADR 0003 的显式访问模式与 ADR 0004 的控制面/执行边界，不等同于授予项目命令任意网络或凭据访问权。

服务配置是拥有者在可信入口（认证控制协议/CLI）管理的项目级记录：HTTPS 端点、凭据引用、工具允许列表、启用状态与可比较配置版本；秘密值仍只存 CredentialStore，按 host、用途（mcp）与项目/操作 scope 约束，原值不进入模型上下文、工具结果、事件或日志。模型输出与任务内容不能自行添加服务或扩大授权；任务开始重读配置并钉版工具清单，禁用、撤销或版本变化立即阻止后续调用，新增工具从下一任务生效。

首版仅 Streamable HTTP 传输、手动凭据与只读工具：只注册允许列表内且通过 schema 校验的工具，工具的只读标注或描述不作为权限依据，写工具与未分类工具不注册也不执行。任意第三方 MCP 服务都是显式信任的远程执行方——客户端白名单约束的是模型可见面，不能证明服务端实现没有额外行为，因此端点钉源（拒绝跨源重定向与认证转发）与凭据用途限制是真正的边界。连接按任务持有并在结束/取消/后台关闭时回收；取消只表示本地停止等待，已发出但结果不明的调用不自动重试，沿用 effect_unknown 语义。

本地 MCP 子进程（stdio）需要补齐执行账户、文件/网络权限与回收设计后才能启用，不允许以后台身份直接 spawn；通用写工具需要具体操作范围、审批桥单次消费与未知结果恢复，由后续工单（issue 18）单独验收。旧 GitHub 专用模块的退役与数据迁移由 issue 17 跟踪，MCP 接入不依赖它。
