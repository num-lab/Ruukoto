# 退役专用 GitHub 模块：GitHub 作为普通 MCP 工具

issue 06 交付的专用 GitHub 模块（REST 采集、草稿与发布状态机、专用控制接口与 CLI/TUI 入口）由 issue 17 退役：GitHub 经通用 MCP 客户端接入（ADR 0006），与其他 MCP 服务共用同一套配置、发现、调用、审批、结果保存与展示流程，运行时不保留 GitHub 专属业务分支，也不存在 REST 与 MCP 两套实现并行。首版只读：写工具不注册、不执行；通用 MCP 写工具（具体操作范围、审批桥单次消费与未知结果恢复）由 issue 18 单独验收，不恢复旧模块的草稿或发布意图入口。旧模块的专用工作流保证（固定 PR/CI 修订复核、草稿状态机、发布意图只能由拥有者建立）不逐项复刻——这些步骤需要时由 Agent 在普通任务中组合工具完成，不能宣称普通 MCP 调用自动提供同等保证；MCP 覆盖不了的缺口如实记录，不以 REST 回退隐藏。

历史资料只读保留而非删除：旧库的三张表（github_repo_bindings / github_drafts / github_publish_ops）不 DROP，全新数据库不再创建；升级后首次启动执行一次性、可重复执行的退役迁移——旧 github_publish 审批（pending / approved 未消费）一律失效，未决发布操作按证据定终态（批准已消费或无审批记录 → effect_unknown 绝不重发；审批未消费 → canceled），草稿各版本正文、证据引用与发布记录导出为原任务产物，绑定仅导出无秘密配置，清单落盘 github-archive-manifest.json。旧凭据的 host/scope/秘密值不被迁移改变，旧仓库绑定不自动转为 MCP 授权；旧批准不得转换为新授权。旧控制接口移除（协议版本递增，旧客户端被拒绝），旧命令只保留静态迁移提示；历史 github.* 事件与 github_publish 审批范围在类型中保留为只读归档展示，不产生新实例。通用控制面身份、访问模式与单次授权仍遵守 ADR 0003/0004；自动审查的确定性策略不变（ADR 0005，github_publish 范围随模块退役不再产生，历史记录仍按转人工展示）。
