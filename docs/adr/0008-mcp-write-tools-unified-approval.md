# MCP 写工具：统一审批与单次消费

ADR 0006 将通用写工具推迟到 issue 18 单独验收。本 ADR 记录 issue 18 交付的决策：普通 MCP 写工具不引入专用发布意图、服务适配层或草稿状态机，GitHub 与其他 MCP 服务走同一执行路径。

副作用类别是拥有者在工具允许列表条目上的本地声明（`read` / `write` / `unknown`）；远端 `readOnly` 等注解是不可信输入，不作为权限依据，副作用不明默认需要审批，未允许的工具直接拒绝。写与副作用不明工具在 confirm/auto-review 模式经统一审批桥（`Driver.awaitApproval`）逐次授权：审批范围（`mcp_tool`）绑定服务 ID、配置版本、远端工具名、任务钉版的工具定义版本、规范化参数摘要、凭据引用名与操作类别，凭据值不进入审批视图或事件；批准后在真正发送前由 `Store.consumeApproval()` 原子消费，并在同一 SQLite 事务内重读服务配置——禁用、撤销、配置版本或权限版本变化使旧批准失效，操作按已知未执行记录。执行参数取自审批保存的不可变快照；full_access 跳过逐次审批但仍须通过服务启用、允许列表与凭据范围校验；auto-review 对 MCP 工具一律转拥有者（ADR 0005 的确定性策略不覆盖 `mcp_tool` 范围），不扩大自动批准范围。

写调用的超时、取消、断线与后台重启沿用 effect_unknown 语义：未消费批准的操作记录已知未执行；已消费或结果无法确认（已发出但传输类失败）的操作标 effect_unknown，重连、重复控制请求与重启不自动重发。远端已应答的错误（isError/HTTP 状态）是已知结果，不标 effect_unknown。

本轮只交付通用框架并以模拟服务验证，不启用真实写工具。首次启用真实写工具时，凭据必须按服务、项目和操作类别独立绑定（禁止复用 Tavily、旧 GitHub 或无 scope 的通用凭据），由拥有者明确指定目标与范围后单独验收。
