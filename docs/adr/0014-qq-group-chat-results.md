# QQ 群按宿主映射进入 chat，main 显式接收结果快照

日期：2026-09-24

daily-agent issue 09 将已有群聊接入角色与持久事件。chat 共用一份角色工具策略，各“登录账号 + 群”的项目、会话、空工作目录仍由 `qq_sessions` 独立绑定，保留 `qq_group` 类别。群消息先登记收件和 `source = qq_group` 入站事件，再由编排器使用原收件请求键派发；正文保留撤回标记。升级时先核实旧任务并补关联，避免换键重复执行。入站、收件恢复和任务队列以持久登记顺序打破同毫秒时间的平局。

ADR 0012 禁止 main/coding 直接读取原始群资料。本决策按 issue 09 为 main 显式接收的结构化结果增加窄例外：`chat_result_list` 只列来源元数据，`chat_result_accept` 保存已完成群任务的有界摘要、来源任务、接收任务、宿主操作与理由。摘要来自该 chat 任务自己的最终回答，最多 1000 个 Unicode 字符；不采集未触发的全群消息，不复制完整历史。接收仅开放固定快照，原始历史、产物与带群来源的记忆仍按 ADR 0012 拒绝；coding 的资料引用不能使用这个例外。

群任务完成不唤醒 main，也不登记 owner 回复。main 可以主动查询并接收结果，再用通知工具的 `chat_result` 来源引用固定快照。接收本身不构成外发授权；一次通知与通知计划仍按 ADR 0010 经拥有者审批，完全访问模式同样适用。原群普通回复继续使用独立 `qq_outbox`。

接收、通知批准提交、查询与发送前均复核来源及撤回。同群在源任务运行期间或结束后发生的相关历史撤回会保守地使摘要失效；新任务在撤回过滤后执行可产生新结果。此时间窗可能拒绝实际未引用被撤回消息的摘要，避免为首版增加逐条模型上下文的来源图。已经进入 main 历史或已经发送的副本不追溯删除，不承诺识别失去来源标记的自由文本转述。旧引用没有消息 ID，该群发生撤回后保守排除带引用的旧交互。

schema v17 增加结果接收表和群收件的配置版本、引用消息 ID、撤回时间。已有群会话、请求键、历史与发送账本保留。重启补核对完成任务与发送记录；任何已有发送记录都不重新发送，遗留或取消时在途的发送记 `unknown`，迟到回执只补记事实。真实 NapCat/QQ 收发另需拥有者授权，模拟测试不作为部署验收。
