# 固定范围的新闻计划由宿主采集，动态正文复用通知 outbox

日期：2026-09-25

daily-agent issue 07 要求 main 管理定时新闻、确认新增来源，并避免新闻采集读取个人资料。新闻计划复用调度计划、调度运行和 outbox：main 提议固定关键词、来源域名、时间窗口与时间规则，宿主直接调用现有 Tavily 搜索接口，按来源与发布时间过滤、按 URL 去重后，把搜索摘要合并为一条通知。采集过程不创建模型任务，不装配历史、项目资料、应用数据或记忆工具，也不自动写入长期记忆；摘要使用服务返回的文本，保留其来源而不生成额外事实。

这是 ADR 0010 第 5 条“批准固定正文”的特定扩展：`notification` 审批新增 `mode=news`，批准的是固定关键词、来源域名（含子域）、搜索窗口、时间规则、摘要模板、目标及配置版本与持续范围。TUI 明确显示动态新闻推送；完全访问和自动审查模式仍须 owner 确认。新增来源随整个计划一起确认，任何关键词、来源或时间变化均取消后重建、重新审批；获批计划的每次正文由宿主采集后固定，模型不能选择接收者或自行换键发送。

schema v18 仅扩展 `schedules.action` 并在 `schedule_runs.news_result` 保存有界采集快照与状态，不建立固定新闻业务表。每次到期仍用原运行键，未完成运行吸收漏过周期；快照与 outbox 同事务提交。多关键词结果合并在该次摘要内去重，不合并不同授权范围的计划。采集窗口以原定时刻为截止，缺少可解析发布时间、窗口外或不匹配批准域名的结果不进入摘要。

搜索失败、限流和结果未知保存采集状态及失败的发送记录；尚未向平台发送，因此 outbox 标为 `failed`，错误代码以 `news_` 开头。重启时 `searching` 变为 `unknown`，不自动重搜同一窗口；已登记的 `pending` 采集可以继续。外发沿用 ADR 0011：平台明确限流可以退回同一操作，实际发送结果未知才是 `effect_unknown`，不得换键重发。取消计划中止在途采集，取消后返回的结果不能登记发送。

首版不进行模型改写或逐条网页抓取，降低私人上下文泄漏与无依据补写的风险。来源 URL 保留完整的 HTTP(S) 链接，域名在宿主再次校验；搜索服务的引用不等于独立核实，页面后续失效和服务漏收不在可保证范围内。延迟采集仍受 Tavily 相对查询时间的窗口限制，不推断或补造漏过的新闻。
