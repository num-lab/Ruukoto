# 模型上下文有损压缩：压缩点、分层压缩与前缀稳定

日期：2026-09-26

2026-10-02 范围说明：[ADR 0017](0017-two-agent-products.md) 保留完整历史与有界模型上下文分离、复用压缩机制；下文 main/coding/dev/chat 的旧角色适用范围在双产品及 SubAgent 迁移时重新映射，不据此保留已取消的固定角色。

ADR 0001 决定初始方案不用有损摘要压缩历史。实际使用 1M 窗口的模型时，每次调用都带着整段历史（输入预算约 60.6 万估算 token，历史几乎不会移出），过时的工具输出分散模型注意力，也按次计费；超出预算后选择器每次调用移出最老一轮，前缀随之变化，整段历史不再命中提示缓存。本 ADR 取代 ADR 0001 中「初始方案不采用有损摘要来压缩历史」一句，其余不变：会话历史仍完整保存、只追加、可查阅，有损处理只作用于模型上下文。

main、coding 与普通开发会话采用上下文压缩。每个会话至多一个生效的压缩点，落盘保存摘要与清理的边界、滚动摘要正文和所覆盖消息的指纹；选择器把压缩点当作输入，确定性地组装每次调用的视图。视图估算越过高水位（20 万估算 token，输入预算更小时取输入预算）才新建压缩点，并一次压到低水位：先把较早的工具结果换成占位说明，仍不够再把更早的对话并入滚动摘要，压缩后仍超出输入预算才整轮移出。两次压缩之间视图前缀不变，提示缓存只在每次压缩时失效一次。有损处都注明覆盖范围和找回原文的方法（`history_read`、`history_search` 或重新执行工具）。摘要由拥有者可选配置的摘要模型生成，未配置时用会话当前模型；配置了摘要模型，较早的对话（含工具结果）就会发给它的提供方。摘要失败时只保留清理结果，任务照常继续；必留内容超出预算与 provider 上下文超限仍按原规则中断，不触发压缩。

不启用 pi 自带的 compaction：它把压缩条目写进会话文件、改变 SDK 给出的分支消息，会打乱选择器、Jev 候选和选择记录的消息序号，触发条件也不了解本项目的预算与必留项。本项目只复用它导出的摘要生成函数。摘要可能遗漏或出错，也可能转述工具结果里的指令，所以它是参考内容，不是拥有者指令或授权依据，与拥有者原话冲突时以原话为准。chat（QQ 群会话与 chat 角色）已定另用更简单的窗口方案：旧对话整批移出窗口，需要时查本群历史找回。该方案暂缓实施，实施时另写 ADR；在此之前 chat 维持现状。
