# 入站图片先暂存，按任务提升并在模型发送前恢复

日期：2026-10-07。状态：已接受，依据 agent-direction 工单 25 已确认的产品边界。

Telegram 与 QQ 拥有者私聊的图片必须在登记普通入站事件前下载、校验并持久化，但任务产物需要已有任务归属。因此新增独立入站媒体暂存与拒绝账本，按来源、外部消息 ID 与图片顺序去重；不提前创建任务产物，也不把下载 URL 或凭据持久化。首版只接收 JPEG、PNG、WebP，每条最多 4 张、单图最多 8 MiB，按声明 MIME 与 magic bytes 一致性校验，网络错误最多尝试 3 次。

任务创建后先准备不可变产物文件，再在同一 SQLite 事务内提交事件的 task_id、artifact_refs、图片产物元数据和暂存归属。文件与数据库没有跨文件事务：确定的产物 ID、内容哈希及重启复核让文件已经存在而元数据尚未提交的窗口可以重试。下载完成未登记、登记未建任务和任务已建未提升均沿原消息键恢复；没有可恢复下载来源的未完成下载明确拒绝。未绑定任务的暂存超过 24 小时清理并保留状态，已绑定任务的图片保留。

会话历史只保存稳定图片引用与元数据；模型上下文选择时使用图片占位块估算预算，真正发送前从任务产物恢复图片并复核归属、MIME、字节数和哈希。沿 resumesTaskId 继续的任务保留源图片，prompt 快照也只保存引用。采用此路径以避免把 base64 重复写入 JSONL，并保留完整历史与模型上下文的既有边界（ADR 0001/0016）。

含图片消息的文字不进入 IM 审批命令路径。模型不支持 image 时明确拒绝并保留原因，不发送缺图请求，不切换模型。下载耗尽、格式或上限拒绝、模型不支持使用三种宿主固定纯文本回执，按拒绝账本消息 ID 使用公共 outbox 去重；模型生成内容不参与错误说明。两种实例导入均排除暂存与拒绝账本，已提升的图片随任务产物导入并保留媒体元数据；个人实例导入的既有外发失效规则继续适用。
