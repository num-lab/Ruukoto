# 工作流执行基础

## 职责与边界

`packages/runtime/src/workflows.ts` 持有固定脚本的后台运行、持久步骤、共享名额、计费、重放和取消。core 保存事实，agent 提供隔离脚本、结果 schema 校验与实际执行边界。`packages/runtime/src/workflow-steps.ts` 默认接入真实 Driver、来源能力与冻结成果汇总；测试可注入执行器。产品启动工具、CLI/TUI/IM 控制、调度整体收尾及最终回报尚未接线。

## 对外接口

| 入口 | 调用者与用途 |
| --- | --- |
| `WorkflowCoordinator.start` | 宿主核实来源任务并固定脚本、参数、模型、来源及更小的预算；同键同参先返回原运行 |
| `recover` / `onEvents` / `stop` | Runtime 在任务账本收尾后恢复，按提交事件调度，关闭库前停止并等待所持有的执行 |
| `control` / `answer` | 可信宿主控制预算、暂停、恢复、取消与业务回答；版本/请求键或问题版本在事务内仲裁，脚本不能调用资源调整 |
| `Runtime.workflowHostOperation` | 宿主按运行与步骤派生短期操作任务、复用完整缓存；callback 负责调用固定工作副本操作 |
| `HostExecutionManager` | 绑定实际任务、登记起始/实际单元、核实活动资格、快照账本并停止；不创建模型会话 |
| core `workflow.ts` | 定义版本、运行、步骤、执行、问题、控制回执及事务内启动/交付原语 |

脚本只调用 `agent(key, params)`、`ask(key, params)`、`integrate(key, params)` 和 `progress(key, params)`。四类都可声明 `dependsOn`，依赖必须已登记；Agent 参数含非空 `request`，输出默认文本，或 `{output:{format:"json",schema:...}}`。有界基础 schema 支持对象、数组、标量及属性、必填、数组项、枚举/常量、长度和数值范围；拒绝正则、引用与复杂组合，避免阻塞后台校验。失败与跳过返回具名状态，格式不符保留原输出。

Agent 参数 `mode` 为 `analyze`（默认）、`modify` 或 `verify`；修改要 `target`，验证要 `verify` 指向本运行已冻结的修改步骤并列入 `dependsOn`。`tools` 只收窄来源工具。验证返回含 `passed` 布尔值的 JSON，可附 `reason`；脚本结果不能伪造验证记录。`integrate` 的 `steps` 列出已完成验证步骤，并列入 `dependsOn`，`check` 保存汇总后实际执行的检查命令。

注入的 Agent 执行器使用真实 Task 的操作账本；在启动实际单元前调用 `context.register` 登记起始句柄，其 stop 必须等待启动收尾，取得实际身份后用 `context.updateIdentity` 更新原句柄。适配器不能先启动 worker 再补登记，取消期间的新登记会被拒绝，已登记单元的迟到实际身份仍保存。

## 数据与状态

`workflow_definitions` 保存完整脚本和内容摘要；`workflow_runs` 固定来源、脚本版本、参数/摘要、模型、预算、累计墙钟、计时与脚本停止核实、结果与版本。状态为 `queued`、`running`、`waiting`、`paused`，终态为 `succeeded`、`partial`、`failed`、`canceled`。

`workflow_steps` 按运行/稳定键唯一，保存类别、登记序号、完整参数与摘要、依赖、状态、输出、交付序号和尝试数；`workflow_executions` 绑定真实 Task、执行类别/编号、单元身份及停止事实。`workflow_questions` 保存问题、来源、版本与回答，`workflow_controls` 保存稳定请求键、输入摘要与接收结果。状态及其事件在同一事务内写入，提交后才调度和广播。

脚本限 128 KiB，单个参数/结果限 512 KiB；更大原始输出进入产物，保存完整字节、字节数与 SHA-256，脚本得到超限失败。正文、SQLite 与会话 JSONL 没有跨文件原子保证。步骤的工作、SubAgent、会话、任务和工具操作继续保留各自归属；宿主操作任务模型选择为空，历史条目为空。

运行来源另固定实际工具类别、资料授权 ID、配置摘要及工作区路径/dev/ino。修改步骤保存冻结补丁产物、SHA-256、长度、基线与工作/任务归属；验证步骤保存冻结摘要、产物、基线、独立验证任务及真实结论。新资料授权不扩大旧运行，依赖闭包的旧资料撤销会阻断后续模型请求与结果交付。

## 主要流程

1. 核实可信来源，固定不可变定义与运行输入。发起任务结束不撤销已经登记的运行授权。
2. 从固定脚本登记步骤，先核对旧键、参数及序号，再按依赖派发。失败依赖记跳过，独立分支继续；重放完成结果按已记录交付顺序逐个回复。
3. Agent 启动事务同时抢来源名额、尝试预算及目录占用，创建/关联既有工作与身份；满额排队。完成与停止按真实操作账本分类，结果先持久后交付。
4. 运行累计墙钟；仅脚本最新 idle、无待交付结果、无可执行/活动工作且等待人工时停计。宿主发送回复前同步恢复活动计费，人工问题旁的脚本计算与其他分支仍计费；超限先暂停与保存计费，再停止执行并保留成果。
5. 宿主操作按稳定键建立短期任务，取得源/副本占用，沿运行模式启动真实 worker。完整缓存可复用；尚未启动的登记按原键恢复，已生效写入缺结果不重做。
6. 脚本返回后核对所有登记步骤、结果和退出事实，再保存包含失败/跳过项的覆盖清单。步骤结果不进入原有逐个父模型唤醒或下一轮注入。

修改先创建独立 Git 副本，停止核实后在占用下冻结原始补丁；非 Git 修改在 worker 与模型前拒绝，分析仍可读来源工作区。验证新建 Agent 与按冻结基线/补丁构建的副本，命令始终用原生沙箱，仅写验证副本，附加路径只读。汇总宿主任务持续占用副本与全部目标，比较当前字节后只套冻结补丁，再运行组合检查并复核副本摘要；冲突只拒该份，此前汇入成果保留，检查失败作为失败结果报告。

## 不变量与失败处理

默认同来源三个 Agent 名额、每运行 100 次 Agent 尝试和一小时；安全重试最多两次，缓存与宿主操作不消耗 Agent 次数。普通 SubAgent 实际出队也在同一启动事务核实名额，停止未核实的占用继续计入。宿主操作时间属于运行墙钟。

来源、资料或固定定义失效，调用/交付记录分歧、结果/产物缺失、格式失败后的写入、已知写入缺输出和未知效果均暂停保留现场。恢复复核真实 Task、操作分类和停止状态；只读或全部批准未消费才可有限重试。停止和计时分别核实，拥有者需先通过既有占用核实出口确认旧执行停止，再从可信控制提供相应确认；不能把旧运行的用量清零。

取消先提交状态和事件，再停止脚本及所属执行，阻止新登记、回答和迟到结果推进。原外部效果不回滚，停止未核实保留实际身份、账本与占用。重发历史控制键只返回已有事实，不再停止已经恢复的执行。工作流步骤拒绝普通任务继续/模式切换、普通任务中断/取消及工作委托取消，运行控制持有其生命周期。

跨实例导入拒绝含工作流执行记录的源，不能通过丢掉绑定把步骤当普通 SubAgent 继续；原实例保留可查。操作见[导入说明](../usage.md#6-导入旧实例)。
