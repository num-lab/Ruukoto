# 事故复盘（postmortem）

事故复盘是一次**失败**的回溯记录：缺陷到达了不该到达的地方，而值得记录的是**流程为什么放它过去**，不只是那一行修复。

## 与决策记录的分工

| 位置 | 写什么 |
|---|---|
| 本目录 | 事故：什么坏了、机制是什么、为什么每道防线都漏掉了它、据此加了什么护栏 |
| [`.agents/notes/`](../../.agents/notes/) | 决定：为什么这样设计、放弃了什么 |
| [`.scratch/`](../../.scratch/) | 工单：当时的计划与验证记录 |

决策记录写「我们选择这么做」；事故复盘写「我们以为这么做是安全的，结果不是」。同一件事可能两者都有：护栏本身是一个决定时，写一篇决策记录，事故复盘链接过去。

## 什么时候写

同时满足三条才写：

- **机制非显然**：一个仔细的工程师也要费一番功夫才能重新推导出来；
- **系统性**：它能逃逸是因为测试、工具或约定的缺口，而不是一次性的笔误；
- **重新发现代价高**：它已经花掉了真实的调试时间，再发生还会再花一次。

一次性的拼写错误、有明确报错的配置失误、已经被单测覆盖的普通回归都不写。

## 格式

文件名是 `NNNN-slug.md`，编号从 `0001` 起，四位补零，按加入顺序递增。

正文固定如下结构，`## 执行摘要` 必须在最前——忙碌的读者三十秒内应当能读完它：

```markdown
# 事故复盘 NNNN：<一句话说清什么坏了>

Status: resolved | open

## 执行摘要

<一段话：什么坏了、根因、为什么逃逸、持久的教训>

## 影响

<受影响的用户可见行为、数据、范围；明确说没有影响的部分>

## 时间线

<按顺序的关键事实，含哪一步查到了什么、哪一步推翻了什么猜想>

## 根因

<机制本身。有多个独立根因就分小节>

## 为什么没被发现

<逐条列出应当拦住它的防线，以及每条为什么失效>

## 护栏

<据此新增或收紧的检查、测试、约定；链接到它们的归属文档>
```

## 写法

- **只写有据可查的事实。** 时间线、机制与护栏都要能在仓库里找到证据：提交、测试、决策记录或工单。找不到证据的细节不写。
- **执行摘要是给忙碌读者的**，不要只是正文的复制；它要能独立读完。
- **「为什么没被发现」是这份文档的重点**，不是附带。只写修复而不写逃逸路径，等于放弃了这个层级的价值。
- **护栏要可验证**：写明它是一条测试、一道门禁、一条约定，还是流程变化，并链接过去。
- 文风与其他文档一致：现在时陈述事实，一段一物理行。
