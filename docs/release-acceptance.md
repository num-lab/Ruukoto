# Cutover and Acceptance Evidence

[Issue #58](https://github.com/num-lab/Ruukoto/issues/58) owns the single-product cutover criteria and current evidence. This page explains evidence boundaries; it does not declare the integrated candidate accepted. Historical two-product counts, baseline upgrades and Personal checks do not establish current behavior.

## Source Preservation

The pre-cutover source archive receipt is recorded in Issue #58. It covers the complete Git bundle and actual source manifest, independently read without the original object store before removal. It contains no runtime-profile backup and makes no install/build or runnable-Personal restoration promise. Existing sealed decision records remain immutable; newly retired completed notes are sealed through the note lifecycle.

## Required Evidence

| Criterion | What acceptance must establish |
| --- | --- |
| Independent source archive | Verified bundle, isolated history/source read and matching manifest before deletion |
| Sole product | Clean build and unpacked workspace launch of `ruukoto` only; no old alias, PA target/RPC or PA-only dependency |
| Stable fresh identity | Configuration-first/no-model activation, restarts, concurrent starters and all entries resolve one reserved ID; raw handoff, partial overrides and long control storage work |
| Old data unchanged | Recognized stopped predecessors yield blank isolated state without changing database/WAL/session/configuration or actual work files; old requests/work never replay |
| Unsafe starts reject | Live/unverifiable ownership, residual execution, unknown/newer formats, conflicting roles and endpoint/path failures reject; crash recovery preserves one ID and no partial activation |
| Retained behavior | Actual workspace, queue/question/reconnect, SubAgent/work-copy, workflow, scheduled, permissions and MCP/native consumers run |
| Actual clients | PTY/TUI, Electron and MyGo interact with isolated state, including settings, schedules, terminal and retained browser paths |
| Repository agreement | Integrated build/static/scoped behavior and documentation/note checks, with independent review |

## External Prerequisites

[Development acceptance](development-acceptance.md) separates offline/mock checks from real models, Linux native stopping and actual hosts. Use explicit model configuration, a separate verification checkout and fresh raw profile tuple. Managed Electron and signed-development MyGo need verified native application/browser-state isolation; use a disposable macOS account when that cannot be established without daily-state access. Production signature/startup negatives remain separate tests, not development overrides.

Obtain the isolated Linux development SSH alias when required; an existing Personal service is not a test target. Missing prerequisites are acceptance gaps with a recovery condition, not skips or passes. Tool/prompt changes require actual model-visible request evidence. A source-level selector removal or mock bridge does not prove native interaction.

## Operations and Historical Limits

There is no old-instance import, credential transfer or history-continuity commitment. [Fresh profiles](usage.md#6-fresh-profiles-and-old-data) leave old committed sessions and actual workspace/work-copy sources untouched and reject unresolved execution. Rejected predecessors require separate owner action; repository verification does not stop their processes.

Retirement closes PA-only work as not planned after acceptance; it does not satisfy its former acceptance criteria. Mixed work retains software-work portions and existing gaps. Commit, publication, replacement of daily installations, service/autostart and account changes require separate authorization. Git history, the independent source archive and sealed notes preserve historical evidence without retaining obsolete operational commands in current guidance.
