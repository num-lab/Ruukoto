Ruukoto 可视化文档

后台运行时里状态最多、边界最密的机制，各画成一页。代码库现在有两个产品：服务器上的个人 Agent ruukoto 与开发机上的 Coding Agent ruukoto-dev（ADR 0017），两者共用这里描述的大部分运行时；各页会注明只属于其中一个产品的部分，以及哪些是即将迁移的旧架构实现。页面和 docs/ 下的其他文档一样随代码维护：每页列出它描述的源码，npm test 会拦下源码改名或新增状态而页面没跟上的情况。

运行时核心

任务生命周期

任务怎样在排队、执行与终态之间转换，审批与 IM 决定怎样结束等待、长期授权怎样免去等待，SubAgent 执行任务有哪些不同，停止、重启与模式切换时怎样保证只有一个终态、不重放任何执行。

编排器

主 Agent 怎样登记工作委托、委派只读分析或按工作隔离修改的 SubAgent，SubAgent 的状态怎样转换、结果怎样交回，整项工作怎样取消；旧架构的 main、coding、chat 角色，子任务回传、GitHub 评审编排与群聊结果。

orchestrator.ts

入站事件

IM 消息、定时唤醒与 GitHub 事件怎么先落库再变成任务，每个来源怎样去重、核对身份，派发与启动前的门怎样放行或丢弃；绑定拥有者怎样在 IM 私聊里查看与回应审批；结束后怎么登记 owner 回复，重启后怎样不换键地接着做。

怎样维护

改了 src/ 或 deploy/ 下的文件后，按 .skills/visual-docs/SKILL.md 同步页面：找出描述改动的页面与 section，读整节，修改，逐条对照代码核实，再跑检查并渲染查看。

test/67-visual-docs.test.ts（也在 npm test 里）核对源码锚点仍然存在、页面覆盖了代码里的状态、表、op 与事件、站内链接与锚点有效，并要求新页面被本页链接。

检查只能发现「代码结构变了而页面没跟上」，发现不了「页面说错了」。语义上的变化要靠改代码的人顺手更新。直接用浏览器打开本文件即可阅读，不需要服务器。
