存储布局

每个产品实例三份根目录：数据、配置、控制面。消息历史以 pi JSONL 会话文件为唯一权威副本，ruukoto.db 存元数据、事件与各类账本；应用数据空间另有一个独立库。锁与令牌决定「谁在写」；schema 版本与目录归属决定「这份库属于谁、哪个版本的程序能开」。

根目录：按产品分开，归属登记在库内

个人 Agent（ruukoto）默认档案根是 ~/.ruukoto，Coding Agent（ruukoto-dev）是独立的 ~/.ruukoto-dev-agent；开发本项目的隔离实例继续使用 ~/.ruukoto-dev（不属于任一产品）。路径环境变量同样按产品隔离：RUUKOTO_DATA_DIR 等只被 ruukoto 读取，RUUKOTO_DEV_DATA_DIR 等只被 ruukoto-dev 读取。归属还登记在库内：首次启动把产品写进 product.ts · PRODUCT_META_KEY 指定的 meta 键，之后跨产品开同一个数据目录直接拒绝。

目录内容要点
<dataDir>（默认 ~/.ruukoto/data）ruukoto.db、sessions/ JSONL、产物文件、agent-data/main.db、runtime.lock全部运行期状态；实例锁保证同一时刻只有一个后台
<agentDir>（默认 ~/.ruukoto/agent）models.json、auth.json、默认/摘要模型选择、服务凭据、config.lock模型目录与秘密；配置锁让在线后台与离线配置中心互斥
<controlDir>（dataDir 兄弟目录 control/）control.sock、owner.token、（ruukoto-dev 按需拉起时）spawn.log控制面 socket（0660）与拥有者令牌（0600，owner-token.ts · ensureOwnerToken）；spawn.log 是 TUI 按需拉起后台时该进程 stdout/stderr 的追加日志（ensure-backend.ts · ensureBackend），ruukoto 档案一般没有
<pendingDir>（默认 ~/.ruukoto/pending）TUI 待核实提交记录客户端侧的去重锚点，秘密不落盘
dataDir 兄弟目录qq-work/<账号>_<群>/、agent-work/<角色>/群会话工作目录与角色工作目录，随数据根迁移
不变量

两个产品的数据、锁、socket 与令牌路径都不重叠；开发实例的档案根与两个产品根都分开。互不引用对方的目录是「同机并存不串用」的物理基础。

ruukoto.db：一份核心库，按职责分组

核心库为 WAL + 全同步（db.ts · Db）。schema 版本当前为 v20（v19 → v20 是 projects 加 settings_version 的加列迁移，旧项目按列默认值取初始版本 1）：旧程序打开更新的库直接拒绝；同版本内的兼容扩展只做加法（加列带默认值、加 meta 键），不重建既有表，旧记录保持可读。

分组表职责
会话与工作projects · sessions · tasks项目（指令列表与 Web Search 开关带乐观并发版本 settings_version，v20，保存同事务核对并递增；工作区根目录归属 root_* 四列，v19；同一真实目录至多一个工作区）/会话边界与任务本体（状态、请求键、提交摘要）

应用数据空间：独立库、独立身份

main 的个人结构化数据放在 <dataDir>/agent-data/main.db，与核心库分离（app-data/store.ts · AppDataStore）。库内三张表：app_meta 存库自身身份（实例绑定登记回核心库 meta，换库会被发现）、app_tables 存 main 声明的表定义与版本、app_audit 存每次变更的审计回执（按宿主操作 id 幂等核实）。能力不可用时保持停止并记事件，不自动重建库。

锁、令牌与归属

机制位置保证什么
实例锁（instance-lock.ts · acquireInstanceLock）<dataDir>/runtime.lock同一数据目录只有一个在线后台；呆锁按持有者存活与进程命令名识别后接管
配置锁<agentDir>/config.lock在线后台与离线配置中心互斥；socket 不可达不能证明后台已停，必须走锁
拥有者令牌<controlDir>/owner.token（0600）控制面认证；部署时以 0400 复制给拥有者，或用环境变量指向拷贝
产品归属核心库 meta 的 product.type首次启动登记；另一产品再开同一数据目录直接拒绝（issue 01，旧库无此键照常打开并补记）
schema 版本核心库头部（当前 v20）比程序新的库拒绝打开；同版本只做加法扩展，旧记录保持可读
已知限制

锁按 pid 与进程命令名判断存活，命令名被刻意伪装时可能误判；数据目录归属只防误用，不代替备份 —— 备份与迁移仍是拥有者的显式操作。
